# Koobiq `sidebar` Component — Code Review & Improvement Plan

> Scope: `packages/components/sidebar` (component, animations, template, SCSS, Jest spec, NgModule, user guides, API guard report, docs examples, dev app) · Commit `b665e503` · 2026-08-28
> Generated by a multi-dimension review (architecture, correctness, accessibility, performance, public API/types, styles, tests, docs) with manual verification of every finding against the source, the three in-repo consumers, `@angular/core`'s own `refreshView` implementation, and the workspace compiler settings. 11 findings confirmed (P0×0, P1×3, P2×4, P3×4); 6 candidate findings refuted during verification (see Appendix A). This document is a review + roadmap; no source is modified by it.

---

## 1. Executive Summary

`KbqSidebar` is a 224-line collapsible container plus two marker directives (`KbqSidebarOpened`, `KbqSidebarClosed`), an 11-line stylesheet and a 31-line animation trigger. It swaps between two projected panes driven by an Angular animation, and it registers a document-wide `keypress` shortcut (`[` / `]`) to toggle itself. Per the cross-cutting inventory it has **no `e2e.ts`, no Playwright spec, no `sidebar-tokens.scss` and no `_sidebar-theme.scss`** — all four confirmed. The missing theme file is legitimate: `grep 'var(--'` over the whole package returns **zero hits**, so the component paints nothing and a theme mixin would have nothing to emit. Every colour comes from the consumer (both docs examples set `background-color` themselves), and the component's only owned dimensions are two string literals in TypeScript.

- **The most serious defect is that `opened` is a plain `@Input` the component mutates behind the parent's back.** `toggle()` writes `_opened` directly (`sidebar.component.ts:168-171`) and there is no `openedChange` output, so the parent's bound expression goes stale and Angular — which compares against the *previously written* value — silently swallows the next parent-driven change. This is not theoretical: the shipped `file-upload-local-dropzone` docs example binds `[opened]="true"` as a literal (`file-upload-local-dropzone-example.ts:34`) and provides no toggle button, so one `]` keypress anywhere on that docs page collapses the sidebar **permanently** — nothing can ever write `opened` again. The `sidebar-overview` example demonstrates the milder form: mixing its "Toggle left model" and "Toggle left" buttons makes one click do nothing (SDB-BUG-01).
- **The keyboard shortcut is a WCAG 2.1.4 (Level A) failure and it collides with the library's own type-ahead.** Every `<kbq-sidebar>` registers a `document` `keypress` listener unconditionally (`:147-148`, `:191-197`); it cannot be turned off, remapped, or scoped to focus, and the only guard is `isInput()`, which recognises `INPUT` and `TEXTAREA` and nothing else (`core/keycodes/keycodes.ts:177-181`). Five components in this repo run `withTypeAhead()` on non-input hosts (`list-selection.component.ts:569`, `navbar.component.ts:91`, `dropdown.component.ts:358`, `select.component.ts:2123`, `app-switcher.ts:351`) — typing into any of them can collapse the sidebar (SDB-A11Y-01). Worse, `isLeftBracket`/`isRightBracket` test `event.code`, the **physical** key, so on a Russian, German or French layout the documented `[` / `]` never fires and unrelated characters (`х`/`ъ`, `ü`/`+`, `^`/`$`) do (SDB-BUG-03).
- **The component ships no semantics and no focus management.** The host block declares one class and two animation callbacks and nothing else (`:67-75`): no `role`, no landmark, no `aria-expanded`, no `aria-controls`. When the sidebar collapses, the opened pane is removed from the DOM by `@if` (`sidebar.component.html:1-5`); if focus was inside it, focus falls back to `<body>` with nothing catching it (SDB-A11Y-02).
- **Coverage is thin and one-legged.** Six shallow Jest cases plus one **disabled** `xit` carrying commented-out code (`sidebar.spec.ts:74-88`) — and that disabled test is the *only* one that would have covered `stateChanged`, the component's sole output. Nothing covers `params`, the pane swap, `saveWidth()`, the right-hand position, or the `isInput` guard; the host declares a `showContainer` flag and a `jest.fn()` that are never used (`:131, 139`). With no Playwright suite either, an animation- and measurement-driven component is verified entirely on JSDOM, where `offsetWidth` is always `0` (SDB-TEST-01).

Genuine strengths worth preserving: the SSR story is careful and deliberate — `afterNextRender` for listener registration (`:148`), `inject(DOCUMENT)` rather than a global, `Renderer2.listen` rather than raw `addEventListener`, and an explicit `Platform.isBrowser` guard before the only geometry read (`:220`, added by DS-5266). The listener is registered outside the Angular zone and torn down idempotently. The two-pane swap is genuinely well timed: the opened pane appears at animation *start* while the closed pane only appears at animation *done* (`:176-189`), so the expanding sidebar never shows a blank frame. And `saveWidth()` preserving a splitter-dragged width across a collapse cycle is a thoughtful touch that most libraries get wrong.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

None.

### P1 — High

**SDB-BUG-01 · `opened` is a plain `@Input` that the component writes to itself, so the parent binding desyncs and the next parent-driven change is swallowed** — `sidebar.component.ts:93-106, 168-171`; consumers `packages/docs-examples/components/file-upload/file-upload-local-dropzone/file-upload-local-dropzone-example.ts:31-46`, `packages/docs-examples/components/sidebar/sidebar-overview/sidebar-overview-example.ts:12-28, 74-83`.
`opened` is declared as an accessor `@Input` (`:93-104`) over a private `_opened` field, and `toggle()` mutates it through that setter (`:169`). There is no `openedChange` output and `opened` is not a `model()`, so nothing propagates the internal change back to the caller. Angular writes an input only when the *bound expression* differs from the value it last wrote, so after an internal toggle the two are out of step and the next parent change is absorbed: with `[opened]="leftOpened"` and `leftOpened === true`, pressing the component's own `[` shortcut sets `_opened = false` while `leftOpened` stays `true`; the user then clicks the parent's toggle, `leftOpened` becomes `false`, Angular sees `false !== true` and writes `opened = false` — which the sidebar already is. The click does nothing. That exact sequence is reachable in the shipped `sidebar-overview` example, which deliberately offers both a model-driven button (`:24`, `toggleLeft()`) and a component-driven one (`:25`, `leftSidebar.toggle()`). The severe form is in `file-upload-local-dropzone`: it binds `[opened]="true"` — a **literal**, so Angular writes it exactly once and never again — with `[position]="position.Right"` and no toggle control anywhere (`:31-46`). A single `]` keypress on that docs page closes the sidebar and there is no code path in the application that can reopen it short of a reload. `stateChanged` is the only escape hatch, and it is documented nowhere (see SDB-DOC-01).
**Fix:** replace the accessor input with `readonly opened = model(true);` — `model()` emits `openedChange` automatically, enables `[(opened)]`, and makes `toggle()` a one-liner (`this.opened.update((v) => !v)`). Move `saveWidth()` out of the setter into an `effect()` (or into `toggle()`) that runs when the value transitions `true → false`, so a redundant `opened = true` no longer triggers a layout read. This changes the API report (accessor pair → `ModelSignal`), so run `yarn run build:components` then `yarn run approve-api`. Guard it with a spec that binds `[opened]` to a host field, calls `sidebar.toggle()`, asserts the host field followed, and then asserts that a subsequent host-driven change still takes effect — a plain "toggle flips the flag" assertion, which is what `sidebar.spec.ts:51-63` does today, cannot catch this.

**SDB-A11Y-01 · An always-on, undisableable, document-wide single-character shortcut that collides with the library's own type-ahead** — `sidebar.component.ts:147-148, 191-197, 206-217`; `packages/components/core/keycodes/keycodes.ts:177-181`; consumers `list/list-selection.component.ts:569`, `navbar/navbar.component.ts:91`, `dropdown/dropdown.component.ts:358`, `select/select.component.ts:2123`, `app-switcher/app-switcher.ts:351`.
Every instance registers a `keypress` listener on `document` from `afterNextRender` (`:148`), unconditionally — DS-4003 (`93b2a2a1a`) removed the earlier `ngOnInit` guard that only registered when `position` was `Left`/`Right`, so a sidebar with no `[position]` now installs a global listener that runs on every keystroke in the application and then returns. There is no input to disable the shortcut, no way to remap it, and no restriction to focus being inside the sidebar. WCAG 2.1.4 *Character Key Shortcuts* (Level A) requires at least one of those three, and AGENTS.md states WCAG AA minimums as a mandate; note this is a WCAG judgement, not an automated failure — axe-core has no rule for it. The only guard is `isControl(event) || isInput(event)` (`:207`), and `isInput` matches exactly `tagName === 'INPUT' || tagName === 'TEXTAREA'` (`keycodes.ts:177-181`) — it does not recognise `contenteditable`, `role="textbox"`, or any of this library's own keyboard-searchable widgets. Five components run `withTypeAhead()` on non-input hosts (`list-selection.component.ts:569`, `navbar.component.ts:91`, `dropdown.component.ts:358`, `select.component.ts:2123`, `app-switcher.ts:351`), and type-ahead reads `keydown` while the sidebar reads `keypress`, so both fire for the same physical keystroke: searching a list, tree, navbar or dropdown by typing can collapse the sidebar underneath it. DS-4003 also silently dropped the capture phase (`addEventListener('keypress', fn, true)` → `renderer.listen`), so the shortcut is now additionally defeatable by any `stopPropagation()` on the way to `document`. The one workaround — omitting `[position]` — removes the shortcut entirely, and `position` has no other effect whatsoever (see SDB-API-02).
**Fix:** three moves, in order. (1) Add `readonly shortcutsDisabled = input(false, { transform: booleanAttribute })` and check it first in `handleKeydown`, satisfying the WCAG "turn off" branch. (2) Restore the conditional registration DS-4003 removed — register only when `position()` resolves to `Left` or `Right`, and re-register reactively via an `effect()` so a late `[position]` still works; this removes the dead per-instance listener. (3) Widen the guard: skip when the event target is `contenteditable`, has `role="textbox"`, or sits inside an element with an active type-ahead — the cheapest correct version is `event.target.closest('[contenteditable], input, textarea, [role="textbox"], [role="listbox"], [role="tree"], [role="menu"]')`. Cover with specs that dispatch `keypress` from inside a `contenteditable` host and from a `<kbq-list>` host and assert `toggle` was **not** called; the two existing keypress specs (`sidebar.spec.ts:90-108`) already provide the dispatch pattern.

**SDB-A11Y-02 · No semantics, no state announcement, and no focus management when a pane is destroyed** — `sidebar.component.ts:61-78` (host block), `sidebar.component.html:1-5`; examples `sidebar-overview-example.ts:12-20`, `sidebar-with-splitter-example.ts:14-23`.
The host block sets `class: 'kbq-sidebar'` and two animation callbacks and declares nothing else (`:67-75`). A `<kbq-sidebar>` is therefore an unknown element with no role: assistive technology sees neither a `complementary` landmark nor a region boundary, and there is no `aria-expanded`, no `aria-controls`, no `aria-label`, and no ARIA text sourced from `kbqInjectA11yLocaleConfiguration()` as AGENTS.md requires. Two consequences follow. First, the collapsed/expanded state is invisible non-visually: `stateChanged` fires (`:188`) but nothing in the DOM changes in a way AT can observe, and neither shipped example puts `aria-expanded` on its toggle button (`sidebar-overview-example.ts:24-27` — four bare `<button kbq-button>`s). Second, and more concretely, collapsing destroys the opened pane: the template renders exactly one of the two projections through `@if (internalState)` (`sidebar.component.html:1-5`), and `internalState` flips to `false` on animation done (`:186`). Any element that had focus inside that pane is removed from the document with no `focus()` call anywhere in the package, so focus resets to `<body>` and the keyboard user's position is lost — the more so because the collapse can be triggered by a global keypress from *outside* the sidebar (SDB-A11Y-01). WCAG 2.4.3 (Focus Order) and 1.3.1 (Info and Relationships) are the criteria at stake; again, both are judgements rather than axe failures.
**Fix:** add to the host block `role: 'complementary'` (or document that consumers should host the sidebar inside their own `<aside>`), `'[attr.aria-expanded]': 'opened'`, and an `ariaLabel` input defaulting to text from `kbqInjectA11yLocaleConfiguration()`. Before `internalState` flips in `onAnimationDone()`, check whether `this.elementRef.nativeElement.contains(this.document.activeElement)` and, if so, move focus with the CDK `FocusMonitor` to the host (make it `tabindex="-1"`) so the keyboard user lands adjacent to where they were rather than at the top of the page. Expose a documented `toggleAriaAttributes` recipe in the guide and add `aria-expanded`/`aria-controls` to the toggle buttons in both docs examples. Cover with a Jest case that focuses a button inside `kbq-sidebar-opened`, toggles, and asserts `document.activeElement` is the sidebar host rather than `document.body`.

### P2 — Should fix

**SDB-BUG-02 · `params` is computed one change-detection phase after the binding that consumes it, and is never recomputed** — `sidebar.component.ts:110-119, 151-162`, host binding at `:69-72`; verified against `refreshView` in `node_modules/@angular/core/fesm2022/debug_node.mjs`.
`params` is initialised to `{ openedStateWidth: 'inherit', openedStateMinWidth: 'inherit', openedStateMaxWidth: 'inherit', closedStateWidth: '32px' }` (`:113-119`) and only replaced in `ngAfterContentInit` from the two content children (`:151-162`). But the `[@state]` host binding that reads it (`:69-72`) belongs to the **parent's** `TView`, and Angular's `refreshView` runs `processHostBindingOpCodes(tView, lView)` *before* `detectChangesInChildComponents(...)` — the ordering is explicit in the framework source. The sidebar's `ngAfterContentInit` runs inside that later step, so on the first pass the animation trigger is evaluated with the defaults and the declared `width="170px"` / `width="44px"` never reaches that evaluation. `ngAfterContentInit` then reassigns `params` and calls nothing — `toggle()` calls `this.changeDetectorRef.markForCheck()` (`:170`) but `ngAfterContentInit` does not — so the corrected object is picked up only if something else causes the parent view to be checked again. It does not throw `NG0100`, because `devModeEqual` treats two non-iterable objects as equal in check-no-changes mode; the reassignment is entirely silent. Separately, `params` is a plain field derived from signals that are never re-read: changing `[width]` on `kbq-sidebar-opened` after init, or resolving the content child late (a `@if`-wrapped pane), has no effect for the lifetime of the component.
**Fix:** make it derived rather than assigned — `protected readonly params = computed(() => ({ openedStateWidth: this.openedContent()?.width() || 'inherit', … }))` and drop `ngAfterContentInit` entirely. A signal read inside a host binding is tracked by the host-binding reactive consumer, so a later width change refreshes the trigger on its own, and the first evaluation reads the resolved content children instead of the defaults. If `computed()` is rejected for animation-param reasons, the minimum fix is to add `this.changeDetectorRef.markForCheck()` at the end of `ngAfterContentInit` — `markViewDirty` marks all ancestors dirty, so the parent-owned host binding is re-evaluated. Guard with a spec that renders `<kbq-sidebar>` with `width="170px"` inside an `OnPush` host, runs a single `detectChanges()`, and asserts the animation params carry `170px` — and with an e2e case (SDB-TEST-01) asserting the rendered width on first paint.

**SDB-BUG-03 · The documented `[` / `]` shortcut checks the physical key, so it is wrong on every non-US layout** — `packages/components/core/keycodes/keycodes.ts:183-189`, `sidebar.component.ts:211-214`, `sidebar.en.md:7-10`, `sidebar.ru.md:7-10`.
`isLeftBracket` and `isRightBracket` are `event.code === 'BracketLeft'` / `'BracketRight'` (`keycodes.ts:183-189`). `KeyboardEvent.code` identifies the *physical* key position, not the character produced, so the mapping between the shortcut and the documented character holds only on US QWERTY. On the Russian ЙЦУКЕН layout those two physical keys produce `х` and `ъ`; on German QWERTZ, `ü` and `+`; on French AZERTY, `^` and `$`. Both consequences are wrong and both are user-visible: the guide's keyboard table promises that `[` and `]` open and close the sidebar (`sidebar.en.md:9-10`, `sidebar.ru.md:9-10`) and on those layouts they never will — while pressing an ordinary letter does. Given that this library ships Russian-first documentation, the ЙЦУКЕН case is the default case, not an edge case, and it compounds SDB-A11Y-01: `х` is a common letter, and typing it into a list or tree type-ahead collapses the sidebar. Note the guide also never mentions that `[position]` must be set for the shortcut to exist at all.
**Fix:** decide which contract the docs are stating. If the promise is the *character* `[`, test `event.key === '['` (and `']'`), which is layout-correct by definition and is what the documentation says. If the promise is the *key position* — a defensible choice for a game-like binding — then say so in both guides and drop the bracket glyphs from the table. Either way the two helpers in `core/keycodes` are shared, so change them behind new names (`isLeftBracketChar`) rather than in place, and add specs dispatching `new KeyboardEvent('keypress', { key: '[', code: 'KeyX' })` (a Russian-layout bracket press) and `{ key: 'х', code: 'BracketLeft' }` (a Russian-layout `х` press) asserting the intended one toggles and the other does not.

**SDB-BUG-04 · `saveWidth()` can pin the opened width to `0px`, and freezes a relative width into pixels** — `sidebar.component.ts:98-104, 219-223`; consumer `file-upload-local-dropzone-example.ts:38` (`width="100%"`).
`saveWidth()` writes `params.openedStateWidth = `${this.elementRef.nativeElement.offsetWidth}px`` (`:222`) whenever `opened` is assigned while currently open (`:99-101`). Two problems. (1) There is no check that the element is actually laid out: `offsetWidth` is `0` for a host inside a `display: none` ancestor, an inactive tab, or a collapsed parent — and because the toggle can be driven by a **document-wide** keypress (SDB-A11Y-01), a hidden sidebar receives that keypress and records `'0px'` as its opened width, permanently. It will then reopen at zero width. (2) It converts whatever the consumer declared into a pixel constant. `file-upload-local-dropzone-example.ts:38` declares `width="100%"`, and `sidebar-with-splitter-example.ts:21` declares `maxWidth="50%"`; after the first collapse the responsive width is gone and the sidebar is pinned to whatever it happened to measure. The intent — preserving a splitter-dragged width across a collapse — is good, but it should not fire when nothing was dragged. Note also that `saveWidth()` runs inside an input setter, so it forces a synchronous layout read in the middle of change detection, and it fires even for a redundant `opened = true` assignment because the guard tests the *old* value only.
**Fix:** guard the write — `const width = this.elementRef.nativeElement.offsetWidth; if (!width) return;` — and only overwrite when the measured width actually differs from the declared one, so a consumer's `100%` survives an untouched collapse cycle. Narrow the trigger to a genuine `true → false` transition (`if (this._opened && !value)`) so no-op assignments stop reading layout. Cover with a Jest case that mocks `offsetWidth` to `0`, closes and reopens, and asserts `params.openedStateWidth` is unchanged; the real behaviour needs an e2e case (SDB-TEST-01) since JSDOM reports `0` for everything.

**SDB-TEST-01 · A disabled test hides the only output, six shallow cases cover the rest, and there is no browser coverage at all** — `sidebar.spec.ts:74-88, 90-108, 112-140`; missing `packages/components/sidebar/e2e.ts` and `e2e.playwright-spec.ts`.
The spec has six active cases and one `xit` (`:74-88`) that still carries a commented-out `// sidebarComponent.stateChanged.emit(true);` line — dead code inside a disabled test. That test is the only coverage of `stateChanged`, the component's sole output, so the output's contract is entirely unverified; the likely reason it was disabled is that `@state.done` resolves asynchronously even under `NoopAnimationsModule`, which `fakeAsync` + `flush()` would fix in one line. The active cases are shallow: `:30-35` asserts four getters return truthy, `:37-49` and `:51-63` assert the boolean flipped without checking that the rendered pane changed, and `:65-72` asserts that a signal input returns what was bound to it — a test of Angular, not of the sidebar. Untested entirely: `params` derivation from `KbqSidebarOpened`/`KbqSidebarClosed`, the `internalState` pane swap and its animation-start/done timing, `saveWidth()`, `SidebarPositions.Right` with `]`, the `isInput`/`isControl` guards, and listener teardown on destroy — the test host even declares `showContainer` (`:131`) for exactly that destroy test and never sets it to `false`, and its `onStateChanged = jest.fn()` (`:139`) is bound in the template but never asserted. On top of that the package has **no `e2e.ts` and no Playwright spec**, so a component whose entire behaviour is an animated width transition plus an `offsetWidth` measurement is verified only on JSDOM, where `offsetWidth` is always `0` and animations never run.
**Fix:** re-enable the `stateChanged` case under `fakeAsync` with `flush()` after `detectChanges()`, delete the commented-out line, and assert both the emitted value and that it fires once per transition. Add cases for: the pane swap (`kbq-sidebar-opened` present when open, `kbq-sidebar-closed` when closed, asserted on the rendered DOM rather than on `internalState`); `params` after `ngAfterContentInit` with declared widths; right-position toggling on `]`; the `isInput` guard by dispatching from an `<input>` target; and listener teardown by flipping `showContainer` to `false` and asserting a subsequent keypress does not call `toggle`. Then add `e2e.ts` + `e2e.playwright-spec.ts` modelled on `packages/components/sidepanel`, covering opened/closed at declared widths, left and right, light and dark — the first-paint width case is the regression guard for SDB-BUG-02. Baselines must be produced with `yarn run e2e:docker:update-snapshots`; a native run fails on font rasterization alone.

### P3 — Nice to have / hygiene

**SDB-CSS-01 · The component's only two dimensions are hardcoded string literals in TypeScript, and all three in-repo consumers override one of them** — `sidebar.component.ts:113-119, 156-161`, `sidebar.scss:1-11`; consumers `sidebar-overview-example.ts:19, 37` (`width="44px"`), `sidebar-with-splitter-example.ts:22` (`width="44px"`), `file-upload-local-dropzone-example.ts:45` (`width="100px"`).
`grep 'var(--'` across the package returns nothing: the sidebar consumes zero design tokens. Its stylesheet is eleven lines of layout (`display: inline-block; height: 100%; overflow: hidden`) with no colour at all, which is why the absent `_sidebar-theme.scss` is correct rather than a defect — a theme mixin would have nothing to emit. But the two dimensions the component *does* own live as TypeScript string literals: `closedStateWidth: '32px'` appears twice (`:118` and `:160`) and cannot be themed, and the opened defaults are `'inherit'` (`:114-116`). `width: inherit` copies the parent's *computed* width, so an opened sidebar with no declared width is `auto` under one ancestor and pinned to an unrelated ancestor's pixel width under another — parent-dependent, undocumented, and not a value anyone would choose deliberately. The evidence that `32px` is the wrong default is that **every** in-repo consumer overrides it: `44px` twice and `100px` once. `height: 100%` on `.kbq-sidebar` (`sidebar.scss:4`) carries the same percentage-resolution hazard as the divider's, and all three examples work around it by declaring `height` on their own `:host`.
**Fix:** add `sidebar-tokens.scss` with `--kbq-sidebar-size-collapsed-width` (default `var(--kbq-size-xl)` or whichever token equals the 44px every consumer actually wants) and read the fallback from it instead of the duplicated `'32px'` literal. Replace the `'inherit'` defaults with `'auto'`, which is the value that behaves predictably in every layout, and state the default in the guide. Consider `align-self: stretch` alongside `height: 100%` so the sidebar sizes correctly as a flex item without the consumer declaring a height. Verify against all three examples before removing their local overrides — the removal is the acceptance criterion.

**SDB-API-01 · Two unexported types leak into the public signature, and every member is `(undocumented)`** — `tools/public_api_guard/components/sidebar.api.md:11-83` (warnings at `:14, :29`), `packages/components/sidebar/public-api.ts:1-2`, `sidebar.component.ts:29-35, 110-143`.
The committed API report carries two `ae-forgotten-export` warnings: `KbqSidebarAnimationState` (returned by the public `animationState` getter, `sidebar.api.md:14-15`) and `KbqSidebarParams` (the type of the public `params` field, `:29-30`). Both are declared in files that `public-api.ts` never re-exports (`public-api.ts:1-2` forwards only `./sidebar.component` and `./sidebar.module`), so a consumer using `#s="kbqSidebar"` can read `s.animationState` but cannot name its type, and `kbqSidebarAnimations` — a reusable trigger — is unreachable from the package entry point. Separately, four members marked `@docs-private` in the source are fully public in the report and are mutable: `params` (`:30`), `internalState` (`:18`), `onAnimationStart`/`onAnimationDone` (`:23-24`), plus `protected document` (`:17`). `internalState` is the template's only condition (`sidebar.component.html:1`), so a consumer assigning it desynchronises the rendered pane from `opened` with no error. Nothing in the whole report carries documentation — every entry is `// @public (undocumented)` or `// (undocumented)`, which is what the docs site's API tab renders for `apiId: 'sidebar'` (`apps/docs/src/app/structure.ts:894-896`).
**Fix:** export `./sidebar-animations` from `public-api.ts` and export the `KbqSidebarParams` interface (or make `params` `protected`, which is the better answer — nothing outside the class needs it). Make `internalState`, `onAnimationStart` and `onAnimationDone` `protected`; they are referenced only from the component's own template and host block, so no consumer breaks. Add `/** */` blocks to `opened`, `position`, `stateChanged`, `toggle()` and the three width inputs. Note that adding JSDoc removes the `(undocumented)` markers and therefore changes `sidebar.api.md`, so fold this into one `yarn run build:components && yarn run approve-api` cycle together with SDB-BUG-01's `model()` migration rather than churning the report twice.

**SDB-API-02 · `input<string>(undefined!)` lies about nullability, `position` positions nothing, and the accessor TODO is untrue** — `sidebar.component.ts:45-47, 58, 91-93, 108, 206-217`; contrast `packages/components/sidepanel` (`KbqSidepanelPosition`).
Four related type and naming issues. (1) All four width inputs and `position` are declared `input<string>(undefined!)` / `input<SidebarPositions>(undefined!)` (`:45-47, 58, 108`). The `undefined!` cast types the signal as non-nullable while its actual runtime value is `undefined`; the code then defends against exactly that with `?.` and `||` (`:156-160`), and `handleKeydown` silently no-ops when `position` is unset (`:211-214`). `input<string>()` yields the honest `string | undefined` and costs nothing. (2) `position` has no positioning effect whatsoever — `this.position()` is read in exactly one place, the shortcut selector (`:209`), and the stylesheet has no left/right rules at all. A consumer reasonably expects `[position]="'right'"` to place the sidebar; it only chooses which bracket key toggles it. (3) The accessor input carries the auto-generated `// TODO: Skipped for migration because: Accessor inputs cannot be migrated as they are too complex.` (`:91-92`); the accessor is nine lines whose only side effect is `saveWidth()`, and SDB-BUG-01 replaces it with `model()` — the comment is both false and actively discouraging. (4) The exported enum is `SidebarPositions` (plural, unprefixed) while the closest sibling package exports `KbqSidepanelPosition` (singular, prefixed) for the same concept; unprefixed enums do exist elsewhere in the library (`Direction`, `ModalSize`, `PopUpPlacements`), so this is a consistency nit rather than a rule violation.
**Fix:** drop every `undefined!` in favour of `input<string>()` / `input<SidebarPositions>()` and let the existing `||` fallbacks do their job. Rename the input to something truthful — `shortcutPosition`, or better, fold it into the `shortcutsDisabled` work from SDB-A11Y-01 as a `toggleShortcut: 'left' | 'right' | null` input — and if a real positioning behaviour is wanted, add `.kbq-sidebar_left` / `.kbq-sidebar_right` modifiers so the name becomes true. Delete the migration TODO as part of the `model()` change. Any rename is breaking and needs an `ng-update` migration in `packages/schematics`; confirm the intent with the maintainers before scheduling.

**SDB-DOC-01 · A ten-line guide that omits the whole API, plus `console.log` in both shipped examples** — `sidebar.en.md:1-10`, `sidebar.ru.md:1-10`; `sidebar-overview-example.ts:86`, `sidebar-with-splitter-example.ts:78`.
The guide is one sentence, one example embed and a two-row keyboard table. It documents nothing about `opened` (including that the sidebar mutates it — SDB-BUG-01), `stateChanged` (the only way to stay in sync), the `width` / `minWidth` / `maxWidth` attributes on `kbq-sidebar-opened` and `kbq-sidebar-closed` (which are the component's whole configuration surface and appear only inside the example source), the `32px` collapsed default, or the fact that the keyboard shortcut requires `[position]` to be set and is otherwise inert. Since every member is `(undocumented)` in the API report (SDB-API-01), the docs site's API tab adds no prose either, so `width="170px"` is discoverable only by reading an example. The keyboard table is additionally untrue on non-US layouts (SDB-BUG-03). Unlike several sibling packages, `examples.sidebar.en.md` / `.ru.md` are **not** stubs — they carry a real embed (`sidebar-with-splitter`) and `structure.ts:896` sets `hasExamples: true`, so that surface is healthy. Both shipped examples do, however, end in `console.log` inside `onStateChanged` (`sidebar-overview-example.ts:86`, `sidebar-with-splitter-example.ts:78`), which users copy into their own code.
**Fix:** extend both guides with an inputs/outputs section covering `opened`, `position`, `stateChanged` and the three width attributes with their defaults; add an explicit note that the shortcut only exists when `[position]` is set, and correct the key description once SDB-BUG-03 is decided. Replace the two `console.log` calls with a visible binding (e.g. a `signal` rendered next to the buttons), which also makes the example demonstrate the `stateChanged`-based sync that SDB-BUG-01's fix relies on. The dev app (`packages/components-dev/sidebar/module.ts:7-12`) currently just re-renders the two docs examples; add a playground case with no `[position]`, a percentage width, and a sidebar inside a hidden container so SDB-A11Y-01, SDB-CSS-01 and SDB-BUG-04 are reproducible by hand.

## 4. Recommended Remediation Phases

**Phase 1 — Make the state contract honest.**
IDs: SDB-BUG-01, SDB-BUG-02. Migrate `opened` to `model()` so internal toggles propagate and `[(opened)]` works, and convert `params` to a `computed()` so declared widths reach the first paint and stay reactive. These two are what an integrator hits first, and both must land before the accessibility work — the `shortcutsDisabled` input and the `aria-expanded` binding are cleanest on top of a signal-based state. Requires one `build:components` + `approve-api` cycle.

**Phase 2 — Accessibility and the keyboard contract.**
IDs: SDB-A11Y-01, SDB-A11Y-02, SDB-BUG-03. Add the shortcut opt-out, restore conditional listener registration, widen the input guard past `INPUT`/`TEXTAREA`, and decide `event.key` versus `event.code` for the bracket check. In the same pass add `role`, `aria-expanded` and focus restoration on collapse, and update the toggle buttons in both docs examples. The type-ahead collision is the acceptance criterion: typing in a list, tree or dropdown must not move the sidebar.

**Phase 3 — Measurement and styling hardening.**
IDs: SDB-BUG-04, SDB-CSS-01. Guard `saveWidth()` against a zero measurement and against overwriting a relative width, narrow it to a real `true → false` transition, introduce `sidebar-tokens.scss` for the collapsed width, and replace the `'inherit'` defaults with `'auto'`. Acceptance is the deletion of the `width="44px"` overrides from the two sidebar examples once the token default matches reality. Needs updated Playwright baselines via Docker, so schedule after Phase 4 introduces the fixture.

**Phase 4 — Test and API surface completion.**
IDs: SDB-TEST-01, SDB-API-01, SDB-API-02, SDB-DOC-01. Re-enable and repair the `stateChanged` case, add the pane-swap / `params` / teardown / right-position cases, create `e2e.ts` + `e2e.playwright-spec.ts`, tighten member visibility, export the animation module, drop every `undefined!`, and fill both guides. Fold the API-report churn into the single `approve-api` run from Phase 1 if the phases ship together; otherwise budget a second one here.

## 5. Verification Strategy

General gates, run sequentially — never in parallel (see `project_no_parallel_heavy_builds`):
- `npx jest packages/components/sidebar`, plus the packages whose type-ahead the shortcut collides with: `packages/components/list`, `packages/components/navbar`, `packages/components/dropdown`, `packages/components/select`, `packages/components/app-switcher`.
- `yarn run eslint`, `yarn run stylelint`, `yarn run prettier` on touched files.
- `yarn run build:components`, then `yarn run check-api` (the guard reads `dist/*.d.ts`, so build first); `approve-api` only in the phases where the surface intentionally changes.
- `yarn run e2e:docker` for anything visual once the fixture exists; regenerate baselines only with `yarn run e2e:docker:update-snapshots`.
- Manual smoke: `yarn run dev:sidebar`, plus `yarn run dev:file-upload` for the `[opened]="true"` literal-binding case that currently strands the sidebar closed.

Per-phase assertions:
- **Phase 1:** with `[(opened)]="state"` bound in the dev app, `sidebar.toggle()` updates `state`, and a subsequent host-driven change still takes effect — no swallowed click. On the `file-upload-local-dropzone` example, pressing `]` and then re-opening from the host works. A single `detectChanges()` on an `OnPush` host renders the sidebar at its declared `width="170px"`, not at `inherit`; changing `[width]` afterwards moves it.
- **Phase 2:** typing `х` (Russian layout) or `[` into a `<kbq-list>` type-ahead, a `<kbq-tree>` and a `contenteditable` leaves the sidebar untouched; with `shortcutsDisabled` set, no keystroke moves it; with no `[position]`, no `keypress` listener is attached to `document` (assert via a spy on `Renderer2.listen`). Focusing a button inside the opened pane and collapsing leaves `document.activeElement` on the sidebar host, not `document.body`. `aria-expanded` flips with the state.
- **Phase 3:** collapsing a sidebar inside a `display: none` container and reopening it restores the declared width, not `0px`. A sidebar declared `width="100%"` is still `100%` after a collapse cycle. With `--kbq-sidebar-size-collapsed-width` in place, the three consumer `width="44px"` / `width="100px"` overrides can be deleted and all three examples render unchanged.
- **Phase 4:** `npx jest packages/components/sidebar` shows zero `xit`/`xdescribe`; deliberately hardcoding `internalState = true` makes at least one case fail (mutation check — a pane-swap suite that passes against a broken condition is worth nothing). `npx playwright test packages/components/sidebar/e2e.playwright-spec.ts` is green on CI browsers. `check-api` reports only the intended visibility changes and the removal of `(undocumented)` markers, with both `ae-forgotten-export` warnings gone.

## Appendix A — Review Methodology

Findings were gathered by reading every file in the package (13 files: component, animations, template, SCSS, spec, module, public API, index, ng-package, and four Markdown files), then cross-checking each candidate against five independent sources: the workspace compiler and test settings (`tsconfig.json:114-118`, `jest.config.js:13-14`); the committed API guard report and `tools/api-extractor/config.json:46`; every in-repo consumer of `<kbq-sidebar>` found by grep across `packages/` and `apps/` (three docs examples, one dev app, no library-internal consumers); the docs navigation entry (`apps/docs/src/app/structure.ts:66, 886-897`); and the package's git history (16 commits, the two behaviourally significant ones being DS-4003 `93b2a2a1a` "fix(sidebar): keybindings" and DS-5266 `e702d5549` "guard DOM geometry calls with isBrowser"). Where a claim depended on framework behaviour rather than repository code — the ordering of `processHostBindingOpCodes` against `ngAfterContentInit`, and whether `markForCheck()` outside the Angular zone schedules a tick — it was checked against the installed `@angular/core` 20.3.29 sources in `node_modules` rather than asserted from memory, and two candidate findings were dropped as a result. Consumer evidence is what upgraded SDB-BUG-01 from a design opinion to a confirmed defect: the `[opened]="true"` literal binding in the file-upload example makes the desync unrecoverable on a page the project publishes.

Refuted during verification:
- **"The missing `_sidebar-theme.scss` and `sidebar-tokens.scss` are structural defects (AGENTS.md lists both)"** — refuted as stated. `grep 'var(--'` over `packages/components/sidebar` returns zero hits and `sidebar.scss` is eleven lines of pure layout with no colour, so a theme mixin would emit nothing; the colours in every example come from the consumer's own stylesheet. The real gap is narrower — two hardcoded dimension literals — and is filed as SDB-CSS-01 at P3, not as a missing-file defect.
- **"`toggle()` fires from a listener registered inside `runOutsideAngular`, so `markForCheck()` never schedules change detection"** — refuted. The workspace is on Angular 20.3.29 (`package.json:25`), where the built-in `ChangeDetectionScheduler` notifies on `markForCheck()` regardless of zone, and `markViewDirty` (`@angular/core` `debug_node.mjs`) marks *all ancestors* dirty, so the parent-owned `[@state]` host binding is re-evaluated. DS-4003 removing the old `ngZone.run(...)` wrapper was safe.
- **"Reassigning `params` in `ngAfterContentInit` throws `NG0100` (ExpressionChangedAfterItHasBeenChecked)"** — refuted. `devModeEqual` returns `true` for any two non-iterable objects in check-no-changes mode, so a new `params` object is never reported as a change. The reassignment is completely silent, which is precisely why SDB-BUG-02 has survived — it is filed on the ordering, not on an error.
- **"Mutating `params` in `saveWidth()` is invisible to the `[@state]` binding, because the object literal is memoized by `pureFunction2` on the unchanged `params` reference"** — refuted. `saveWidth()` is called from the `opened` setter immediately before `_opened` flips (`sidebar.component.ts:99-103`), so `animationState` changes in the same pass and invalidates the memoized tuple. The mutation does reach the animation engine.
- **"`sidebar.component.ts` starts with a UTF-8 BOM"** — true but refuted as a sidebar defect: 59 files under `packages/components` carry a BOM, including `core/pop-up/pop-up-trigger.ts` and `core/option/option.ts`. This is a repository-wide encoding artefact and belongs in a repo-level cleanup, not in a component review.
- **"`SidebarPositions` violates the library's `Kbq` naming prefix"** — partially refuted. Eight exported enums under `packages/components` lack the prefix (`Direction`, `ModalSize`, `PopUpPlacements`, `PopUpTriggers`, `ThemePalette`, `TimeFormats`, `TimeParts`, `TransitionCheckState`), so this is a library-wide inconsistency, not a sidebar rule violation. Retained only as the naming contrast with the sibling `KbqSidepanelPosition` inside SDB-API-02.

Corrected on verification:
- **SDB-A11Y-01** was initially drafted as **P0** on the grounds that AGENTS.md mandates WCAG AA and the shortcut cannot be disabled. Reading `handleKeydown` showed the shortcut is inert when `[position]` is unset (`sidebar.component.ts:209-216` is the input's only consumer), so a workaround does exist — at the cost of all keyboard operability. Downgraded to P1.
- **SDB-BUG-02** was initially drafted as "declared widths never reach the DOM". Reading `refreshView` in `@angular/core` showed the *next* check of the parent view does apply the corrected `params`, so the claim was narrowed to a first-paint defect plus a permanent reactivity gap, and the severity settled at P2.
- **SDB-BUG-01** was initially scoped to the `sidebar-overview` example's swallowed click. Grepping the other consumers found the `[opened]="true"` literal binding in `file-upload-local-dropzone`, which turns the same mechanism into an unrecoverable state, and the finding was rewritten around that case.
