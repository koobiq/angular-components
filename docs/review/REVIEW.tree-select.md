# Koobiq `tree-select` Component — Code Review & Improvement Plan

> Scope: `packages/components/tree-select` + its embedding contract with `@koobiq/components/tree` (`KbqTreeSelection`) and the shared `core/select` abstractions · Commit `c183a1bb` · 2026-07-06
> Generated by a sequential single-context deep review with adversarial re-verification of every finding against source (file:line re-checked); cross-referenced against `REVIEW.select.md`, `REVIEW.tree.md` and the monorepo `REVIEW.md`. 29 findings confirmed (2×P0, 3×P1, 13×P2, 11×P3). The Jest suite was executed as part of the review: **147 passed, 0 skipped**.
> Findings tagged **(shared)** have a sibling twin in `select` / `core` / `tree` and should be fixed together. This document is a review + roadmap; no source is modified by it.

## 1. Executive Summary

- **Accessibility is the single biggest risk and the only release blocker.** The component implements literally zero ARIA semantics: not a single `role` or `aria-*` attribute exists anywhere in `tree-select.html` or the component's host bindings (verified by exhaustive grep). No `role="combobox"`, no `aria-expanded`, no panel role, and the host never renders an `id`, so the form-field label's `[attr.for]="control().id"` (`form-field.html:2`) dangles. This violates the project's own "MUST pass AXE / WCAG AA" mandate (AGENTS.md). **2×P0 + 2×P1** cluster here, on top of the tree's own zero-ARIA substrate (`REVIEW.tree.md` A1–A14).
- **The monorepo review's disputed leak is resolved.** `REVIEW.md` BUG-03 (bare `selectionModel.changed` / search `valueChanges` subscriptions, first "disputed", then confirmed real in its Appendix F) was fixed by commit `f14a571c` (2026-07-02): all three subscriptions now pipe `takeUntilDestroyed` (`tree-select.component.ts:745`, `:753-755`, `:1483-1486`). The locale subscription is also guarded (`:678`) — unlike select's still-open SEL-LEAK-01. This closes the monorepo review's follow-up #3.
- **The tree embedding contract is the main structural weakness.** tree-select swaps the embedded tree's `SelectionModel` (`:743`), then manually re-runs `tree.ngAfterContentInit()` (`:758`) — so the tree's content-init body executes twice, leaving duplicate `unorderedOptions.changes` / `renderedOptions.changes` / `tabOut` subscriptions live for the component's lifetime (every options change does its render-sync work several times — the search-filtering hot path). It also monkey-patches `tree.onKeyDown` (`:1417-1419`) and ships a dead `{ provide: KbqTree, useExisting: KbqTreeSelect }` provider that is a structural type lie (`:156`).
- **The public API surface is untyped and leaks internals.** `value`/`selected`/`writeValue`/`KbqTreeSelectChange.value` are `any`; the `valueChange` output is declared, documented as "two-way binding for the value input" — but there is no `value` input and the output is never emitted; `selectionModel`, `overlayDir`, `triggerRect`, `changeDetectorRef`, `panelDoneAnimatingStream` and friends are all public. Importing the standalone `KbqTreeSelect` without `KbqTreeSelectModule` crashes at DI (`KBQ_SELECT_SCROLL_STRATEGY` has no default provider).
- **Performance hotspots are inherited from select.** `calculateHiddenItems` does the same double DOM-clone read/write thrash with synchronous `detectChanges()` (`:1133`, `:1308`, `:1324`), and the template binds DOM-reading/allocating getters every CD cycle (`colorForState` `:643`, `getPanelClasses()` `:1088`).
- **What's strong.** RxJS hygiene was just remediated (5 fixes landed in the last month — the component is actively maintained); `panelWidth`/`panelMinWidth`/`multiline`/`selectAllToggle` are already signal inputs (the migrated sibling that `REVIEW.select.md` credits); the invalid-state theme token already uses `--kbq-foreground-error` (`_tree-select-theme.scss:12`) — the target state SEL-TPL-01 asks select to converge to; and the fresh Karma→Jest migration (147 tests) plus a genuinely strong Playwright suite (positioning incl. RTL overflow, scrolling, keyboard) give a solid regression net — except for a11y, which has zero coverage.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

**TS-A11Y-01 · No combobox semantics and no `id` on host** — `tree-select.component.ts:161-173` (host object).
The host exposes only `tabindex`/`disabled`/classes — no `role="combobox"`, `aria-haspopup="tree"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-required`, `aria-invalid`, `aria-disabled`, `aria-labelledby`. Worse than select: the host also never binds `[attr.id]`, while the `id` accessor (`:464-474`) maintains a uid that the form-field label targets via `[attr.for]="control().id"` (`form-field.html:2`) — the association dangles (and `for` cannot target a non-labelable custom element anyway). A screen reader announces an unnamed focusable group (WCAG 4.1.2, 1.3.1).
**Fix:** add host bindings `[attr.id]="id"`, `[attr.role]="'combobox'"`, `[attr.aria-haspopup]="'tree'"`, `[attr.aria-expanded]="panelOpen"`, `[attr.aria-controls]="panelOpen ? panelId : null"`, `aria-required/invalid/disabled`; give the form-field label an `id` and wire `aria-labelledby` to it. Mirrors SEL-A11Y-01 — land as one shared change.

**TS-A11Y-02 · Overlay panel and embedded tree expose no semantics for the combobox chain** — `tree-select.html:106-134` (`#panel`, `#optionsContainer`); substrate: `tree-selection.component.ts:123-131` host.
The panel div and options container have no `role`/`id`; the projected `kbq-tree-selection` has no `role="tree"` and its options no `role="treeitem"` (that substrate is `REVIEW.tree.md` A1–A14 — not re-filed here). Nothing exists for the host's `aria-controls` to point at, and selection state (`aria-selected`, `aria-multiselectable`) is conveyed only visually (pseudo-checkboxes).
**Fix:** give the tree container a stable `panelId`; land tree A1–A14 (`role="tree"`/`treeitem`/`aria-selected`/`aria-expanded` on options) first or together, then wire the combobox → tree chain here. Keep search input and footer outside the tree's accessibility subtree.

> TS-A11Y-01/02/03 are one logical unit — the combobox → tree → treeitem → activedescendant chain must land together to be coherent and pass AXE.

### P1 — High

**TS-A11Y-03 · Focus model: real DOM focus contested between options and search; no `aria-activedescendant`; Tab is swallowed** — `tree-select.component.ts:1474-1476` (`scrollActiveOptionIntoView` forces `activeItem.focus()`), `:1271-1273`, `:713-718` and `:790-794` (search auto-focus), `:1209-1213` (Tab → `preventDefault` + close).
Keyboard navigation moves real focus into tree options while the search field steals it back after every selection (`:790-794` doesn't even check `shouldShowSearch()`, unlike `:1275-1279`); `aria-activedescendant` is never rendered. Tab inside the open panel is `preventDefault`-ed, deviating from the ARIA combobox pattern (Tab should close and move focus on).
**Fix:** keep DOM focus on the combobox host (or the search input when present) and bind `[attr.aria-activedescendant]="keyManager.activeItem?.id"`; replace `activeItem.focus()` with scroll-into-view that does not steal focus; guard the `:790-794` focus call with `shouldShowSearch()`; let Tab close the panel without `preventDefault`. Mirrors SEL-A11Y-04.

**TS-A11Y-04 · Tag-remove icon not keyboard operable and unnamed** **(shared)** — `tree-select.html:37-43`; `KbqTagRemove` hard-codes `tabindex: -1`, click-only.
In multiple mode a selected value can only be removed by mouse; the icon has no `role="button"`/`aria-label`, and the host tag is non-focusable (`[selectable]="false"`). WCAG 2.1.1 + 4.1.2. Identical to SEL-A11Y-05 — one shared fix in tags/select/tree-select.
**Fix:** make the remove control focusable, add `role="button"` + a localized `aria-label` (e.g. `Remove {{ option.viewValue }}`), handle Enter/Space → `onRemoveSelectedOption`; mark the glyph `aria-hidden`.

**TS-BUG-01 · Manual `tree.ngAfterContentInit()` re-run double-initializes the embedded tree** — `tree-select.component.ts:757-758`; body: `tree-selection.component.ts:286-334`.
Angular calls `KbqTreeSelection.ngAfterContentInit()` naturally; tree-select then swaps the tree's `selectionModel` (`:743`) and re-runs the hook manually (with an eslint-disable). Consequences, all live until destroy: `unorderedOptions.changes` is subscribed twice (`tree-selection.component.ts:287` — `updateRenderedOptions` runs twice per options change), `renderedOptions.changes` twice (`:312` — with two `notifyOnChanges()` calls the select/deselect + `resetOptions` sweep executes up to 4× per underlying change), `keyManager.tabOut` twice (`:304`), and the first run's `keyManager`/`selectionModel.changed` subscriptions are orphaned on discarded objects (`:289`, `:306`). Search filtering and lazy-load expansion — the paths that mutate options — pay the multiplied cost. The monkey-patch `this.originalOnKeyDown = tree.onKeyDown; tree.onKeyDown = () => {}` (`:1417-1419`) is part of the same fragile contract.
**Fix:** give `KbqTreeSelection` an explicit, idempotent embedding API — e.g. an `initialize(selectionModel)` method (or an injected `KBQ_TREE_EMBEDDING` config) that tears down and re-creates its subscriptions, plus a public keyboard-delegation hook instead of instance-property monkey-patching. Short-term: make `ngAfterContentInit` re-entrant (drop previous subscriptions before re-subscribing). Add a regression test asserting `updateRenderedOptions` runs exactly once per `unorderedOptions` change.

### P2 — Should fix

- **TS-A11Y-05 · Cleaner control unnamed** **(shared)** — `tree-select.html:72-81` + projected `kbq-cleaner`. Keyboard works (focusable inner button + bubbling `keydown.enter/space` handlers), but the control is announced without a name (WCAG 4.1.2). Same as SEL-A11Y-06 — fix once in `KbqCleaner` (`role="button"` + localized `aria-label`, icon `aria-hidden`).
- **TS-LEAK-01 · `closeSubscription` accumulates one subscription per panel open** — `tree-select.component.ts:1079`. `onAttached()` reassigns `closeSubscription = this.closingActions().subscribe(...)` without unsubscribing the previous one; `backdropClick`/`outsidePointerEvents`/`detachments` of the persistent `overlayRef` never complete, so N opens leave N live subscriptions each invoking `close()` (idempotent, so invisible — but a real leak). **Fix:** `this.closeSubscription.unsubscribe()` before reassigning, or unsubscribe in `close()`. Mirrors SEL-LIFE-01/SEL-LEAK-02.
- **TS-BUG-02 · Locale service clobbers the `hiddenItemsText` input; `hiddenItemsTextFormatter` is a method decorated `@Input()`** — `tree-select.component.ts:1292-1296`, `:295-297`, `:840-843`. `updateLocaleParams` unconditionally overwrites the user-supplied `@Input() hiddenItemsText` on every locale change (two sources of truth — the "Your application code writes to the input" TODO at `:295` documents the smell instead of fixing it), and `hiddenItemsTextFormatter` is an input-decorated method. **Fix:** keep an `input()` for `hiddenItemsText` plus a `computed()` for the locale-merged effective text; convert the formatter to `readonly hiddenItemsTextFormatter = input<(text, count) => string>(...)`. Identical twin: SEL-API-04.
- **TS-PERF-01 · `calculateHiddenItems` double-clones the trigger and thrashes layout + `detectChanges`** — `tree-select.component.ts:1133-1182`, `getTotalItemsWidthInMatcher` `:1308-1322`, `getTotalVisibleItems` `:1324-1348`, `buildTriggerClone` `:1363-1372`. Two deep clones appended to the live trigger, interleaved `getComputedStyle`/offset reads per tag (`getItemWidth` `:1374-1382`), up to 2 synchronous `detectChanges()` per pass; `refreshTriggerValues` also calls `detectChanges()` on every selection change (`:1391`). **Fix:** single off-DOM clone, batch all reads in one loop, one `markForCheck` at the end; prefer a `ResizeObserver` on the matcher list. Mirrors SEL-PERF-02 — extract one shared measurement helper for both components (see TS-ARCH-05).
- **TS-PERF-02 · Template binds DOM-reading/allocating members every CD cycle** — `colorForState` `:643-651` (reads `classList` — twice per cycle: tag color + arrow color), `getPanelClasses()` `:1088-1101` (allocates + joins while open), `hiddenItemsTextFormatter(...)` method call (`tree-select.html:65`). **Fix:** convert to `computed()` signals driven by `errorState`/inputs. Mirrors SEL-PERF-04/SEL-TPL-02.
- **TS-API-01 · Untyped `any` across the public surface** — `value`/`selected`/`selectedValues` getters (`:458`, `:995-1003`), `writeValue(value: any)` (`:952`), `new SelectionModel<any>` (`:743`), `KbqTreeSelectChange.value: any` (`:132-139`), `clearValue($event)` and `onRemoveSelectedOption(selectedOption: any, $event)` untyped params (`:845`, `:1116`), `panelKeydownHandler` returns `any` (`:1203`, via the `return this.originalOnKeyDown.call(...)` branch), `panelClass` `any` index signature (`:331-338` — the SEL-API-05 mirror). **Fix:** introduce `KbqTreeSelect<T>`/`KbqTreeSelectChange<T>` (default `any` keeps source compatibility), type the handlers, make `panelKeydownHandler` return `void`. API-snapshot change → `approve-api`.
- **TS-API-02 · Dead `valueChange` output and phantom `value` input** — `tree-select.component.ts:323-328`. The output's JSDoc says it exists "to facilitate the two-way binding for the `value` input", but there is no `value` input (only a getter `:458`) and `valueChange` is never emitted (zero `valueChange.emit` in the file). `(valueChange)` compiles and silently never fires; `[(value)]` doesn't compile. **Fix:** either implement `value` as a `model()` (emitting on every change) or delete the output + doc; breaking → SemVer window.
- **TS-API-03 · Standalone import crashes at DI: `KBQ_SELECT_SCROLL_STRATEGY` has no default provider** **(shared)** — `tree-select.component.ts:197`; token: `core/select/constants.ts:17`; provider only in the NgModules (`tree-select.module.ts:36`, `select.module.ts:43`). `imports: [KbqTreeSelect]` without `KbqTreeSelectModule` throws `NullInjectorError` at construction — contradicting the repo's standalone-first policy (all 14 docs examples are forced through the module). **Fix:** give the token a `providedIn: 'root'` factory default (or a component-level fallback like `tabs/tab.component.ts:38` does); keep the module provider for overrides.
- **TS-ARCH-02 · Dead `KbqTree` provider is a structural type lie** — `tree-select.component.ts:156`. `{ provide: KbqTree, useExisting: KbqTreeSelect }` while `KbqTreeSelect` does not extend `KbqTreeBase` (`tree/tree.ts:21`); no code in the repo injects `KbqTree`, so today it only misleads — but any future consumer gets a broken instance. Cross-ref `REVIEW.tree.md` AR8. **Fix:** remove the provider (or provide the actual embedded `KbqTreeSelection` once a real consumer exists); run `approve-api`.
- **TS-ARCH-03 · `multiline` silently turns a single-select into multi-select semantics** — `tree-select.component.ts:585-587` (`multiSelection = multiple || multiline()`), `:743` (selection model multi flag), `:999-1003` (value becomes an array). A user setting only `multiline` (documented as a display option) gets checkboxes and array values without ever setting `multiple`. **Fix:** decouple display from selection semantics, or throw/warn when `multiline && !multiple`; document the coupling in the meantime.
- **TS-TPL-01 · Token ownership tangle with select** **(shared)** — `tree-select.component.ts:153` pulls `'../select/select-tokens.scss'` (a cross-package relative `styleUrls` reach); `select-tokens.scss:2` declares `.kbq-tree-select` tokens; `tree-select-tokens.scss:3-4` re-declares the same `--kbq-select-panel-dropdown-background/shadow` mapping. This is SEL-TPL-06 seen from the other side. **Fix:** move shared token declarations into one `core` partial both packages consume; delete the cross-package styleUrl. Note: the invalid-state color here already uses `--kbq-foreground-error` (`_tree-select-theme.scss:12`) — SEL-TPL-01 should converge select to this, not the reverse.
- **TS-TEST-01 · No ARIA/role/AXE coverage** — `tree-select.component.spec.ts:1706` (`describe('accessibility')` is tabindex/keyboard only; zero `aria`/`role` assertions in 4710 lines). The highest-risk area (P0s above) is the least guarded. **Fix:** add an a11y suite asserting the combobox/tree/treeitem chain + `aria-*` states (failing until TS-A11Y-01..03 land); adopt jest-axe together with select (SEL-TEST-02).
- **TS-TEST-02 · Feature coverage gaps: multiline, RTL, tag-remove, footer, lazy-load untested in Jest; e2e lacks error/invalid states** — `tree-select.component.spec.ts` has zero matches for `multiline`/`rtl`/`TagRemove`/`footer`/`lazy`; `e2e.ts` fixtures include search/cleaner/footer but no error-state fixture for screenshots. `onRemoveSelectedOption` (`:1116-1131`) has no test at all. **Fix:** add Jest suites for multiline trigger, tag removal, footer projection and lazy-load open; add error/invalid panel screenshots to `e2e.playwright-spec.ts` (multiline states exist there already).

## 4. Recommended Remediation Phases

**Phase 1 — Accessibility blockers (must land together, coordinated with tree).**
IDs: TS-A11Y-01..05 + TS-TEST-01 (regression guards). The combobox → tree → treeitem → activedescendant chain (01/02/03) ships as one coherent change and depends on `REVIEW.tree.md` A1–A14 landing first or simultaneously; 04/05 are shared tags/cleaner fixes that parallelize with select's Phase 1 (SEL-A11Y-05/06). Write the failing a11y specs first. This unblocks the release.

**Phase 2 — Embedding contract & lifecycle.**
IDs: TS-BUG-01 (idempotent tree init — the only fix requiring a change in `tree`), TS-LEAK-01, TS-LIFE-01, TS-RX-01. TS-BUG-01 needs a regression test on subscription counts; the rest are mechanical.

**Phase 3 — API & correctness (SemVer-gated, batch `approve-api` once).**
IDs: TS-API-01..03, TS-ARCH-02/03, TS-BUG-02/03. Batch the snapshot-changing items (generics, dead output, dead provider) into one API window; TS-API-03 (scroll-strategy default) unblocks standalone adoption and is non-breaking.

**Phase 4 — Performance.**
IDs: TS-PERF-01/02 + TS-TPL-03. Do TS-PERF-01 as the shared measurement extraction with select (SEL-PERF-02) so both components migrate once.

**Phase 5 — Modernization, styles & test debt.**
IDs: TS-ARCH-04/05/06, TS-API-04/05, TS-TPL-01/02, TS-A11Y-06, TS-TEST-02. TS-ARCH-05 (decomposition) precedes/accompanies TS-ARCH-04 so extracted code is migrated once; TS-TPL-01 lands with select's SEL-TPL-06 to avoid re-divergence.

## 5. Verification Strategy

**General gates (per phase):**

- `npx jest packages/components/tree-select/tree-select.component.spec.ts` (baseline: 147 passed, 0 skipped)
- `npx jest packages/components/tree/tree-selection.component.spec.ts` (embedding contract — Phase 2)
- `yarn run eslint && yarn run stylelint && yarn run prettier`
- `yarn run check-api` (and `yarn run approve-api` only when the public API intentionally changes — Phase 3/5)

**Phase 1 (a11y):** new Jest specs — host `role="combobox"` + `id` + `aria-haspopup/expanded/controls`; panel/tree `role` chain + `aria-multiselectable`; `aria-activedescendant` tracks the active option; tag-remove and cleaner focusable + named; label association resolves (form-field `for`/`aria-labelledby`). If jest-axe is adopted: `toHaveNoViolations()` in closed and open states, single and multiple modes. Manual NVDA/VoiceOver pass. Playwright: re-run `npx playwright test packages/components/tree-select/e2e.playwright-spec.ts` and verify focus-ring visibility.

**Phase 2 (contract/lifecycle):** spy on `updateRenderedOptions` — exactly one execution per `unorderedOptions.changes` emission after init; open/close the panel N times, fire one outside click, assert `close()` invoked once (TS-LEAK-01); create/destroy with a pending open-`setTimeout`, assert no errors.

**Phase 3 (API):** `yarn run check-api`, review `tools/public_api_guard/components/tree-select.api.md`, `approve-api`; type-check a typed consumer (`KbqTreeSelect<MyNode>`); a standalone `imports: [KbqTreeSelect]` TestBed without the module must construct (TS-API-03).

**Phase 4 (performance):** assert a single DOM clone and no `detectChanges` inside `calculateHiddenItems` (spy on CD); tag views are reused across `refreshTriggerValues` (track-by test); rely on the existing e2e states/scroll suites for layout truth.

**Phase 5:** `yarn run styles:build-all` after TS-TPL-01; visually diff select vs tree-select panels in both themes; full regression `yarn run unit:components` + `yarn run e2e:components` before merge.
