# Koobiq `button` Component Family — Code Review & Improvement Plan

> Scope: `packages/components/button` (`KbqButton`, `KbqButtonCssStyler`, `KbqButtonGroup`, `KbqButtonGroupRoot`, `KbqButtonPrefix`/`KbqButtonSuffix`, `KbqButtonDropdownTrigger`) + the shared `core` abstractions it composes (`KbqColorDirective`, `KBQ_TITLE_TEXT_REF`/`KbqTitleTextRef`, `getNodesWithoutComments`, the `_groups-mixins`/`_animation` SCSS partials) · Commit `18ea72fe` · 2026-06-29
> Generated by an automated multi-agent review (8 review dimensions + adversarial verification of every finding). 38 findings confirmed (0×P0, 5×P1, 7×P2, 26×P3); 2 refuted. Treat as a high-signal starting point; spot-check before acting.
> Findings tagged **(shared)** live in `core`/`dropdown` and also affect siblings (`button-toggle`, `split-button`, `toggle`, every `[kbqDropdownTriggerFor]`). This document is a review + roadmap; no source is modified by it.

## 1. Executive Summary

- **No release blockers.** Unlike `select`/`tree`/`tabs`, the button family ships no P0. The hard parts are genuinely well done: the icon-button detection algorithm (slot flattening of `.kbq-button-text`, left/right placement, `≤2` icon rule), the dual native-`<button>` / `<a kbq-button>` disabled handling (capture-phase `click`/`keydown` halting with `stopImmediatePropagation`, `aria-disabled`, `tabIndex=-1`), and the prefix/suffix slots are all correct and well-tested.
- **Lifecycle is leak-free (RxJS grade A−).** The capture-phase listeners are added in the constructor and removed in `ngOnDestroy` with stable arrow references and a matching `capture` flag; `FocusMonitor.monitor`/`stopMonitoring` are paired across `ngAfterViewInit`/`ngOnDestroy`; both `effect()`s and `CdkObserveContent` auto-tear-down. There is **no** undisposed subscription anywhere in the family.
- **`prefers-reduced-motion` is already honored.** The only animation — the `.kbq-progress` loading state — is gated behind `@media (prefers-reduced-motion: reduce)` in core's `_animation.scss`. A naive "button ignores reduced motion" claim is a **false positive**.
- **Accessibility is the top risk (2×P1).** An `<a kbq-button>` used as an action trigger is announced as a *link*, never a *button* (no `role="button"`), and a button used as `[kbqDropdownTriggerFor]` exposes **no** `aria-haspopup`/`aria-expanded` — the canonical menu-button pattern is mute to assistive tech. A third gap (P2): nothing surfaces icon-only buttons shipped without an accessible name, so an empty AXE `button-name` violation is one `<button><i kbq-icon></i></button>` away (and already lives in the repo at `e2e.ts:195`).
- **The button-group propagates state by clobbering child inputs (2×P2).** `KbqButtonGroupRoot` writes `button.color`/`button.kbqStyle`/`button.disabled` directly onto every child from setters **and** a content-children `effect()`. This contradicts its own "individual button's style preserved" comment, and `group.disabled = false` actively **re-enables** a button that was individually disabled.
- **The public input surface is mid-migration and has one real type trap (P1).** Every input is still a legacy `@Input` getter/setter pair with stale "Skipped for migration" TODOs. The standout defect: `kbqStyle` does not round-trip — the setter stores `'filled'` but the getter returns the CSS class `'kbq-button_filled'`, and the type is bare `string`. The same asymmetry is duplicated in `button-group` and `split-button`.
- **Styles are strong but not RTL-safe (P1, shared).** Tokenization, BEM/`kbq-` namespacing, and the per-variant×subtype theme mixin are clean, but icon/prefix/suffix spacing and grouped-button corner collapse use **physical** `margin-left/right` + `border-*-left/right-radius` rather than logical properties, so leading icons and corner rounding mirror incorrectly under `dir="rtl"`.
- **Tests cover the hard logic but skip focus and a11y (P1).** Icon-detection branches, disabled-event halting, slots, and group propagation are exercised with real assertions — but `FocusMonitor`/`focus()`/`focusViaKeyboard()`/`hasFocus`/`ngOnDestroy` teardown have **zero** coverage, there is no AXE assertion anywhere, and Playwright fakes `:hover`/`:focus`/`:active` via CSS classes while omitting most dark-theme and all reduced-motion variants.

## 3. Prioritized Findings (deduplicated, verified)

### P1 — High

**BTN-A11Y-01 · Button-as-dropdown-trigger exposes no `aria-haspopup`/`aria-expanded`** **(shared)** — `dropdown/dropdown-trigger.directive.ts:108` (host) + `button.dropdown-trigger.directive.ts:13`.
A `kbq-button` used as `[kbqDropdownTriggerFor]` is the canonical menu-button pattern, yet `KbqDropdownTrigger`'s host sets only `class.kbq-pressed`/`(mousedown)`/`(keydown)`/`(click)` and `KbqButtonDropdownTrigger` adds only `[class.kbq-active]="dropdownTrigger.opened"`. A grep for `aria-haspopup|aria-expanded|aria-controls` across both packages returns **zero** matches, so a screen reader announces neither that the control opens a popup nor whether it is open. Affects every dropdown trigger in the monorepo.
**Fix:** on `KbqDropdownTrigger` add `[attr.aria-haspopup]` (use `'true'` — the dropdown panel currently has no `role="menu"`, so `'menu'` over-claims; ideally add `role="menu"` + `aria-controls` to the panel in tandem) and `[attr.aria-expanded]="opened"` (`opened` is a public getter). Mirror `aria-expanded` on `KbqButtonDropdownTrigger` if the trigger-side host is preferred.

**BTN-A11Y-02 · `<a kbq-button>` acting as a button has no `role="button"`** — `button.component.ts:197` (host object).
`KbqButton` matches `[kbq-button]` on both `<button>` and `<a>` (tested: `button.component.spec.ts:726`, `:925`). For the anchor host the component fully emulates button behaviour (capture-phase activation, `ENTER`/`SPACE` handling, `tabIndex` management) but the host sets `disabled`/`aria-disabled`/`tabIndex` and **no** `role`; `KbqColorDirective`/`KbqButtonDropdownTrigger`/`KbqDropdownTrigger` add none either. An anchor that behaves like a button but is announced as a link is a name/role mismatch (WCAG 4.1.2).
**Fix:** key off the real host tag — `'[attr.role]': "isAnchor ? 'button' : null"` where `isAnchor = nodeName.toLowerCase() === 'a'` — so a native `<button>`'s implicit role is never clobbered. Pairs naturally with BTN-A11Y-01 for the anchor-dropdown-trigger case.

**BTN-API-01 · `kbqStyle` input does not round-trip and is typed `string`** **(shared)** — `button.component.ts:222`; same pattern `button-group.ts:34`, `split-button.ts:51`.
The setter stores the raw value (`this._kbqStyle = value || KbqButtonStyles.Filled`) but the getter returns a derived CSS class (`` `kbq-button_${this._kbqStyle}` ``). So `btn.kbqStyle = KbqButtonStyles.Filled; btn.kbqStyle` yields `'kbq-button_filled'`, not `'filled'`, and the getter type is bare `string` rather than `KbqButtonStyles`. `KbqButtonGroupRoot` reads the private `_kbqStyle` (`button-group.ts:41,92`) precisely to dodge this. The asymmetry is frozen into `button.api.md:45-46` and asserted by `button.component.spec.ts:641`.
**Fix:** make the input getter+setter both `KbqButtonStyles` returning `this._kbqStyle`; expose the class string via a separate `protected` member (computed/getter) for the `[class]` host binding. Mirror to `KbqButtonGroupRoot` and `KbqSplitButton`. Breaking change → SemVer-gated; update the spec assertion at `:641` and run `approve-api`.

**BTN-TEST-01 · Focus management is entirely untested** — `button.component.spec.ts` (no references); source `button.component.ts:280-341`.
`runFocusMonitor`/`stopFocusMonitor`, the `disabled`-guarded `focus()`/`focusViaKeyboard()`, and the `hasFocus` toggling via `onFocus`/`onBlur` have no unit coverage; the Playwright suite is screenshot-only. A regression that breaks the `disabled` guard, drops the `FocusMonitor` teardown (a real leak), or stops updating `hasFocus` (consumed by `navbar`) would pass silently.
**Fix:** add specs — `focus()`/`focusViaKeyboard()` are no-ops when disabled and move focus when enabled (spy `FocusMonitor.focusVia`); dispatching `focus`/`blur` toggles `hasFocus`; destroying the fixture calls `focusMonitor.stopMonitoring` (spy) to guard the teardown path.

**BTN-STYLE-01 · No RTL support: physical margins and border-radii** **(shared)** — `_button-base.scss:64-78` + `core/styles/common/_groups-mixins.scss`.
Icon/prefix/suffix spacing uses physical `margin-right` (`.kbq-icon_left`, `.kbq-button-prefix`) / `margin-left` (`.kbq-icon_right`, `.kbq-button-suffix`), and the shared group mixin collapses first/last-child corners with physical `border-*-left/right-radius`. Under `dir="rtl"` the leading icon lands on the wrong side and grouped-button corner rounding mirrors incorrectly; there is no `[dir=rtl]` override anywhere in the button styles (the library does support RTL — `core/styles/common/_rtl.scss`). The negative-margin border overlap itself is direction-symmetric; only the radius collapse and inline gaps break.
**Fix:** switch to logical properties — `margin-inline-start/end` for the gaps in `_button-base.scss`; `margin-inline-start` + `border-start-end-radius`/`border-end-end-radius` (first-child) and `border-start-start-radius`/`border-end-start-radius` (last-child) in the group mixin — or wrap the existing rules in `[dir='rtl']` overrides via `_rtl.scss`.

### P2 — Should fix

- **BTN-BUG-01 · Button-group clobbers per-button `color`/`style`/`disabled` despite a "preserved" comment** — `button-group.ts:97-109` (+ setters `:41,62,76`, `effect` `:88-94`). `updateColor`/`updateStyle`/`updateDisabledState` unconditionally write each child's input, and the content-children `effect()` re-applies on every add/remove — so a `<button kbq-button [color]="...">` inside a group cannot keep its own value, directly contradicting the doc comments at `:29`/`:48`. No test guards the promised preservation (the specs only assert propagation). **Fix:** drop the misleading wording, or track an explicit-set flag per `KbqButton` and skip flagged buttons; the clean form is DI — expose `KbqButtonGroupRoot` (or a token) and have each `KbqButton` read a `computed()` that falls back to the group signal only when the local input is unset, removing the write-back loop entirely.
- **BTN-BUG-02 · `group.disabled = false` force-enables individually-disabled buttons** — `button-group.ts:105-109`. `updateDisabledState` only guards `state === undefined`, so any bound `false` calls `button.disabled = false` on **every** child (and again from the `effect()` for dynamically-added ones), overriding a button disabled for its own reasons — an interaction/a11y consequence the destructive `color`/`style` overrides don't carry. **Fix:** model group-disabled additively (`button.disabled = ownDisabled || groupDisabled`) rather than as a destructive write; "propagate `true` only" leaves buttons stuck disabled on re-enable, so prefer the additive form.
- **BTN-A11Y-03 · No accessible-name safeguard for icon-only buttons** — `button.component.ts:79-83,139-141`. The styler explicitly flags icon-only buttons (`isIconButton`) and `KbqIcon` renders `aria-hidden="true"` glyphs, so an icon-only button with no `aria-label`/`aria-labelledby` is an empty AXE `button-name` violation. The repo hand-adds `aria-label` on every icon-only button (`e2e.ts:146,168,210,213`, docs examples) — and `e2e.ts:195` is a live nameless one — proving the failure mode is easy to hit. **Fix:** in dev mode, when `_isIconButton` is true and the host has neither text content nor `aria-label`/`aria-labelledby`, `console.warn` (mirroring the existing "imported together with KbqButton" warning at `:112`); place it in `updateClassModifierForIcons` where the host, icons, and `.kbq-button-text` are already in hand.
- **BTN-API-02 · Public `icons` content-children signal is typed `readonly any[]`** — `button.component.ts:74`. `contentChildren(forwardRef(() => KbqIcon))` erases the element type, so `button.api.md:79` exports `Signal<readonly any[]>` — an `any` on the public surface (violates AGENTS.md) that also drops type safety at the in-directive `icon.getHostElement()` call. **Fix:** `contentChildren<KbqIcon>(forwardRef(() => KbqIcon))`; re-run `approve-api`.
- **BTN-STYLE-02 · Orphaned design tokens declared but never consumed** — `button-tokens.scss:9-10`. `--kbq-button-icon-size-vertical-padding` and `--kbq-button-icon-size-content-padding` are declared on `.kbq-button`/`.kbq-button-icon` but referenced nowhere (verified by grep); the icon button only sets horizontal padding and inherits the generic content-padding. They are publicly-overridable theming API, so a consumer overriding them gets no effect — actively misleading. **Fix:** wire them up (`--kbq-button-icon-size-content-padding` → `.kbq-button-icon .kbq-icon_left/_right` margins; `--kbq-button-icon-size-vertical-padding` → `.kbq-button-icon`) or delete both.
- **BTN-TEST-02 · Duplicate test: `'should handle a click on the button'` appears twice** — `button.component.spec.ts:81` and `:218`. The top-level copy is logically identical (create `TestApp`, click, assert `clickCount === 1`) and adds zero coverage. **Fix:** delete `:218-226`.
- **BTN-TEST-03 · Playwright fakes hover/focus/active via CSS classes; omits dark + reduced-motion** — `e2e.ts:49-52`, `e2e.playwright-spec.ts:12-53`. States are toggled via `kbq-hover`/`cdk-keyboard-focused`/`kbq-active`/`kbq-progress` rather than driving real pseudo-states; `01-light`/`02-light` have no dark counterpart; there is no `prefers-reduced-motion` screenshot even though `.kbq-progress` (rendered in the matrix) is reduced-motion-gated. (Note: `:hover`/`:active` are co-located with `.kbq-hover`/`.kbq-active` in `_button-theme.scss:26-32` so they can't silently diverge today, and focus is *legitimately* class-based via `FocusMonitor` — the strongest gaps are the dark and reduced-motion variants.) **Fix:** add a `locator.hover()` + Tab-focus screenshot against a live button, `01-dark`/`02-dark`, and an `emulateMedia({ reducedMotion: 'reduce' })` capture.

### P3 — Nice to have / hygiene

**Architecture & conventions**
- **BTN-ARCH-01 · Legacy `@Input` accessor pairs with stale "Skipped for migration" TODOs** — `button.component.ts:222,239,253`; `button-group.ts:33,52,68`; inherited `KbqColorDirective.color` (`core/.../color.ts:100`, shared). `disabled` already proxies a `WritableSignal`; `tabIndex` could be a `computed`. Deferred-by-design (`@todo 20` major-release note) and load-bearing for cross-component writes, so plan it, don't rush it.
- **BTN-ARCH-02 · `@ViewChild` → `viewChild()` signal queries** — `button.component.ts:215,218`. `textElement`/`parentTextElement` must **stay public** (they implement `KbqTitleTextRef` / `KBQ_TITLE_TEXT_REF`, read by `KbqTitleDirective`); migrate the query mechanism only.
- **BTN-ARCH-03 · `KbqButtonCssStyler`↔`KbqButton` two-class reach-across coupling** — `button.component.ts:64-183`. The directive reads the component's `.kbq-button-wrapper` via `querySelector` (runtime dev-warn instead of a type-checked contract) and the component drives the directive back via `projectContentChanged()`. Always co-bundled, so no runtime risk; fold the styler into the component, or pass the wrapper element explicitly, if revisited.
- **BTN-ARCH-04 · `haltDisabled*` listeners hand-managed in the constructor** — `button.component.ts:264-329`. The capture-phase approach is correct and documented; the manual `addEventListener`/`removeEventListener` pairing could use `Renderer2.listen`/`takeUntilDestroyed` so teardown can't drift. No behaviour change.
- **BTN-ARCH-05 · `[attr.tabIndex]` host key uses camelCase** — `button.component.ts:201`. Works (attributes are case-insensitive) but inconsistent with the lowercase siblings; rename to `[attr.tabindex]` (and the spec reads at `:171/:175`).
- **BTN-ARCH-06 · `isIconButton` getter wraps a signal** — `button.component.ts:79-83`. Cosmetic only (host-binding class reads are pull-based on CD, not reactive-effect-driven, in either form — see *Refuted*). If touched, expose `readonly isIconButton = signal(false)` and bind `isIconButton()` directly; widens the public signal API → `approve-api`.
- **BTN-ARCH-07 · Redundant focus channel (`FocusMonitor` + manual `hasFocus`)** — `button.component.ts:290-296,335-341`. `FocusMonitor.monitor(el, true)` already applies `cdk-*-focused`; `hasFocus` duplicates state but **cannot be removed** (public; read by `navbar-item.ts:264`). If unified, derive `hasFocus` from the monitor stream while preserving its synchronous semantics.

**Correctness**
- **BTN-BUG-03 · Icon-only detection depends on `preserveWhitespaces:false`** — `button.component.ts:129-141`. `effectiveNodes` keeps whitespace text nodes (`getNodesWithoutComments` strips only comments), so under a consumer compiling with `preserveWhitespaces:true` an icon-only button gets `effectiveNodes.length > icons.length` and silently loses `kbq-button-icon` styling + left/right placement. **Fix:** drop whitespace-only text nodes (`node.nodeType === Node.TEXT_NODE && !node.textContent?.trim()`) when building `effectiveNodes`.
- **BTN-BUG-04 · `tabIndex` getter never yields null; `NaN` passthrough** — `button.component.ts:201,253-262`. Every native `<button>` renders a redundant `tabindex="0"`, and a non-numeric `[tabIndex]` (→`numberAttribute` `NaN`) renders `tabindex="NaN"`. **Fix:** return `null` for a native enabled host at the default, and clamp `NaN`→`0`.
- **BTN-BUG-05 · `KbqButtonGroupRoot._disabled` typed `boolean` but `undefined` until first set** — `button-group.ts:80`. A type lie rescued only by the `state === undefined` guard; `strictPropertyInitialization` is off so it compiles silently. **Fix:** type the field/getter `boolean | undefined` (don't initialise `false` + drop the guard — that would push `disabled=false` onto children when the group was never bound).

**Accessibility**
- **BTN-A11Y-04 · Invalid native `disabled` attribute on `<a kbq-button>`** — `button.component.ts:198`. `[attr.disabled]` is applied to whatever matches `[kbq-button]`; on an anchor `disabled` is invalid HTML (the real disabling is `aria-disabled` + `tabIndex=-1` + the JS halts). Harmless to AT but trips strict validators / `[disabled]` CSS. **Fix:** gate the native `disabled` attribute to button/input hosts by `nodeName`.

**Public API & types**
- **BTN-API-03 · Implementation-only fields exposed public/mutable** — `button.component.ts:76,314`. Only two are safely tightenable: `nativeElement` → `readonly` (assigned once), `haltDisabledEvents` → `private` (only called internally). Leave `hasFocus`, `textElement`, `parentTextElement` public — they are intentional cross-component / `KbqTitleTextRef` contracts.
- **BTN-API-04 · Exported constants/enum carry no doc comment** — `button.component.ts:42-49`. `KbqButtonStyles`, `buttonLeftIconClassName`, `buttonRightIconClassName` are `@public (undocumented)` and used only internally + in specs; the two class-name constants also coexist confusingly with core's `leftIconClassName`/`rightIconClassName`. **Fix:** add one-line JSDoc declaring them public CSS hooks, or `@docs-private` + drop from `public-api.ts` if not intended for consumers; `approve-api`.

**Templates & styles**
- **BTN-STYLE-03 · Global `.kbq-progress` emitted via a side-effecting unreferenced `@use`** **(shared)** — `button.scss:1`. `@use '.../animation'` references no member, but the partial's top-level `.kbq-progress`/`@keyframes` are injected globally under `ViewEncapsulation.None` (the same duplicated into `toggle.scss:2`). The feature is intentional; the ownership is murky. **Fix:** move the shared `.kbq-progress` into a clearly-owned global entry that button/toggle document as a dependency (do **not** scope it under `.kbq-button` — it is a shared utility).
- **BTN-STYLE-04 · Fragile double negated-`:has()` group-gap rule** — `button-group.scss:12-16`. Two overlapping `&:not(:has(> :not(.kbq-contrast[-fade].kbq-button_filled)))` selectors with an uninformative `@TODO tech debt (#DS-4847)` comment. `:has()` is an adopted baseline here (52 usages), so the concern is readability, not support. **Fix:** replace the DOM-introspection with an explicit modifier class toggled by `KbqButtonGroupRoot` (which already iterates its buttons).
- **BTN-STYLE-05 · `kbq-button-icon_left/_right` host classes are styled only by `dropdown.scss`** **(shared)** — `button.component.ts:178`. The styler maintains these host classes but they have no styling in button's own SCSS; the sole consumer is `dropdown/dropdown.scss:18` — an undocumented cross-component contract (guarded by button's own tests + the API snapshot, but invisible in the styles). **Fix:** add a comment noting the dependency, or give the classes a home in button's SCSS.
- **BTN-STYLE-06 · 1px zero-offset keyboard focus ring recolors the border** **(shared)** — `_button-theme.scss:88-92`. `outline: 1px solid var(--kbq-states-line-focus-theme)` + same-token `border-color`, no `outline-offset` — a weak indicator, and the same convention spans 28 files. **Fix:** raise ring weight/offset and verify 3:1 non-text contrast (WCAG 1.4.11/2.4.11) **at the shared focus token**, not per-component.

**Performance**
- **BTN-PERF-01 · `kbqStyle` getter allocates a string every CD cycle** — `button.component.ts:202,223-225`. `[class]: 'kbqStyle'` re-invokes the template-literal getter each pass. **Fix:** cache `` `kbq-button_${value}` `` in the setter (resolves naturally with BTN-API-01).
- **BTN-PERF-02 · Icon-class recompute runs twice on init (effect + `ngAfterContentInit`)** — `button.component.ts:97-106`. The full DOM walk runs twice per button on first render with identical input. **Fix:** keep `ngAfterContentInit` as the init path (the wrapper is guaranteed rendered by then) and guard the `effect()`'s first run.
- **BTN-PERF-03 · `updateClassModifierForIcons` re-queries the DOM and re-allocates node arrays each call** — `button.component.ts:108-162`. Two `querySelector`s (stable for the component lifetime) + two `getNodesWithoutComments` allocations + an O(icons×nodes) `indexOf` scan, on every content mutation. **Fix:** lazily memoize the wrapper/text refs in the styler; derive left/right from first/last node position without per-icon `indexOf`.
- **BTN-PERF-04 · Group `effect()` re-applies color/style/disabled to all buttons on any membership change** — `button-group.ts:88-94`. `color`/`disabled` writes are equality-guarded (core `color` setter; signal `set`) so they no-op, but `kbqStyle`'s setter calls `markForCheck()` unconditionally. **Fix:** apply group state only to newly-added buttons, or add an equality guard to `KbqButton`'s `kbqStyle` setter.

**Tests**
- **BTN-TEST-04 · No AXE / accessibility assertions anywhere** — `button.component.spec.ts`, `e2e.playwright-spec.ts`. A real coverage gap, but a **repo-wide infrastructure** item — `axe-core`/`jest-axe`/`axe-playwright` are not installed in any package. **Fix:** adopt `axe-playwright` `analyze()` over the existing e2e pages library-wide, then assert button states (icon-only ±`aria-label`, disabled anchor, group).
- **BTN-TEST-05 · `KbqButton.kbqStyle` getter + falsy→`Filled` fallback not directly unit-tested** — `button.component.spec.ts:603-642`. The host `[class]="kbqStyle"` binding *is* covered indirectly via the group-propagation tests (`outline`); only the button-level default `kbq-button_filled` and the `'' / null` fallback lack a direct assertion. **Fix:** on a plain `<button kbq-button>` assert `kbq-button_filled` by default and after setting `kbqStyle=''`.
- **BTN-TEST-06 · Two tests share the title `'should toggle additional classes on icon removal/reveal'`** — `button.component.spec.ts:365` & `:382` (left vs right). Ambiguous reporter output. **Fix:** rename to distinguish left/right.
- **BTN-TEST-07 · Colliding `@Component` selectors + dead `avoidCollisionMockTarget()` stubs** — `button.component.spec.ts:752-901` (selectors), `:775,:806` (dead methods). Multiple distinct test wrappers reuse the same selector string; the selectors are never used as element tags. **Fix:** make each selector unique or drop it; remove the stubs.
- **BTN-TEST-08 · Custom (enabled) `tabIndex` input untested** — `button.component.spec.ts:166-176`. Only `disabled → -1` is asserted; the `numberAttribute` setter and the enabled getter are never exercised with a real value. **Fix:** assert `[tabIndex]="3"` reflects `3` when enabled, then `-1` when toggled disabled.

**Refuted on verification (excluded):**
- *"`isIconButton` host class needs `markForCheck` (stale under zoneless)"* — refuted. On Angular 20 the `_isIconButton.set(...)` write marks the host LView for traversal via the host-binding's reactive consumer, so the class updates without `markForCheck`; `untracked()` only scopes the effect's own tracking, not the signal's producer→consumer notification.
- *"`parentTextElement` overflow measurement is a per-CD layout hotspot"* — refuted (and confirmed as **correct design**). All `offset*`/`scrollWidth`/`getBoundingClientRect` reads live in the opt-in `KbqTitleDirective`, triggered only by `mouseenter`/keyboard-focus/debounced `resize`/throttled `ContentObserver` — never by Angular CD. `KbqButton` performs zero layout reads.

## 4. Recommended Remediation Phases

**Phase 1 — Accessibility (highest value, no SemVer risk).**
IDs: BTN-A11Y-01 (dropdown `aria-haspopup`/`expanded` — coordinate with the `dropdown` package), BTN-A11Y-02 (anchor `role="button"`), BTN-A11Y-03 (icon-only dev-mode name warning), BTN-A11Y-04 (gate native `disabled`). Land BTN-TEST-04 tooling alongside so the new ARIA is regression-guarded. 01/02-dark + reduced-motion screenshots (BTN-TEST-03) verify the visual side.

**Phase 2 — Correctness of the button-group.**
IDs: BTN-BUG-01 (stop clobbering per-button overrides) + BTN-BUG-02 (additive group-disabled) + BTN-BUG-05 (type honesty) + BTN-PERF-04 (membership-change re-apply). The DI/`computed`-fallback refactor resolves BUG-01/02/PERF-04 together; add tests asserting a per-button `[color]`/`[disabled]` survives inside a group.

**Phase 3 — Robustness & test hardening.**
IDs: BTN-BUG-03 (whitespace-independent icon detection), BTN-BUG-04 (tabindex null/NaN), BTN-TEST-01 (focus suite — do first, it guards a real teardown leak), BTN-TEST-02/05/06/07/08 (hygiene + gaps), BTN-PERF-02 (single init compute), BTN-PERF-03 (memoize icon walk).

**Phase 4 — Styles & RTL.**
IDs: BTN-STYLE-01 (logical properties — shared with the group mixin in `core`), BTN-STYLE-02 (orphaned tokens), BTN-STYLE-03 (own the global `.kbq-progress`), BTN-STYLE-04 (explicit group-gap modifier), BTN-STYLE-05 (document the dropdown contract), BTN-STYLE-06 (raise at the shared focus token). Run `yarn run styles:build-all` and visually diff LTR/RTL + light/dark.

**Phase 5 — Modern-Angular migration & API hardening (SemVer-gated).**
IDs: BTN-API-01 (`kbqStyle` round-trip — breaking; batch with `button-group`/`split-button`), BTN-API-02 (`icons` generic), BTN-API-03 (`readonly`/`private` tighten), BTN-API-04 (doc/`@docs-private` the exports), BTN-ARCH-01/02/06 (input/viewChild/signal migration), BTN-ARCH-03/04/05/07 (coupling, listener lifecycle, attr casing, focus channel), BTN-PERF-01 (cached class string — falls out of API-01). Run `check-api`, review `tools/public_api_guard/components/button.api.md`, then `approve-api` once; schedule breaking pieces for a major.

## 5. Verification Strategy

**General gates (per phase):**
- `npx jest packages/components/button/button.component.spec.ts`
- `yarn run eslint && yarn run stylelint && yarn run prettier`
- `yarn run check-api` (and `yarn run approve-api` only when the public API intentionally changes — Phase 5) — build `build:components` first (the guard reads `dist/*.d.ts`).

**Phase 1 (a11y):** new specs — `<a kbq-button>` (no `href` and `href="#"`) carries `role="button"`; a native `<button kbq-button>` does **not**; `[kbqDropdownTriggerFor]` exposes `aria-haspopup` and `aria-expanded` that track `opened`; an icon-only button with no name dev-warns; the native `disabled` attribute is absent on `<a>` but `aria-disabled` present. If `axe-playwright` is adopted: `analyze()` over the e2e button pages in light/dark.

**Phase 2 (group):** select a group with a per-button `[color]`/`[kbqStyle]`/`[disabled]` override and assert the override survives group input changes and child add/remove; toggle `group.disabled` true→false and assert an individually-disabled child stays disabled.

**Phase 3 (robustness/tests):** focus suite per BTN-TEST-01; compile a fixture with `preserveWhitespaces:true` and assert an icon-only button still gets `kbq-button-icon`; `[tabIndex]="3"`→`'3'` when enabled, `'-1'` when disabled, and a non-numeric input never renders `NaN`; assert `updateClassModifierForIcons` runs once on init (spy).

**Phase 4 (styles):** `yarn run styles:build-all`; Playwright screenshots of an icon+text button and a horizontal group under `dir="ltr"` vs `dir="rtl"` (leading icon side + corner rounding), plus `01-dark`/`02-dark` and a `reducedMotion: 'reduce'` capture of the `.kbq-progress` state.

**Phase 5 (API/migration):** after `kbqStyle`/`icons` changes → `yarn run check-api`, review `tools/public_api_guard/components/{button,split-button}.api.md`, then `approve-api`. Type-check that `btn.kbqStyle` now round-trips to `KbqButtonStyles`. Full regression: `yarn run unit:components` + `yarn run e2e:components` before merge.

## Appendix A — Review Methodology

Produced by 8 parallel review agents (architecture, RxJS/lifecycle, correctness, accessibility, public API/types, tests, templates/styles, performance), each reading the source directly. Every raw finding was then adversarially verified by an independent agent against the actual code (line numbers re-checked, severities re-rated, proposed fixes validated).
