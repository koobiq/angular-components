# Koobiq `clamped-text` Component — Code Review & Improvement Plan

> Scope: `packages/components/clamped-text` (both public components — `KbqClampedText` and `KbqClampedList` — plus the shared `constants.ts` token/interface layer, SCSS, two Jest suites, e2e fixture + Playwright spec, four user guides, the five docs examples, the dev app and the API guard report) · Commit `b665e503` · 2026-08-28
> Generated by a multi-dimension review (architecture, RxJS/lifecycle, correctness, accessibility, performance, public API/types, styles, tests, docs, SSR) with manual verification of every finding against the source, the in-repo examples, `apps/docs` navigation and prerender routes, and the workspace compiler/test configuration. 16 findings confirmed (P0×0, P1×3, P2×7, P3×6); 6 candidate findings refuted during verification (see Appendix A). This document is a review + roadmap; no source is modified by it.

## 1. Executive Summary

`packages/components/clamped-text` ships two unrelated-looking but token-sharing primitives: `KbqClampedText` (a 211-line `OnPush` component that clamps projected text to `rows` lines and offers an expand/collapse control) and `KbqClampedList` (a 70-line directive that slices an item array), joined by `KbqClampedRoot`/`KbqClamped` in `constants.ts` and by a shared `KbqClampedListTrigger`. There are **no release blockers** — the component works, and its measurement engine is far better built than the library's other truncation primitive. What it lacks is disclosure semantics, and one piece of its styling lives in the wrong package.

- **The expand/collapse control has no disclosure semantics, and the state is published on the element that cannot be operated.** `aria-expanded` is bound on the host of `<kbq-clamped-text>` (`clamped-text.ts:74`) and on the `[kbqClampedList]` container (`clamped-list.ts:11`) — both role-less wrappers — while `KbqClampedListTrigger`, the directive that actually receives the click and the Enter/Space keys, binds no `role`, no `aria-expanded` and no `aria-controls` (`clamped-list.ts:58-67`). Every other disclosure in this library puts the state on the trigger (`accordion-trigger.directive.ts:8-20`, `dropdown-trigger.directive.ts:124`, `navbar-toggle.component.ts:116`, `datepicker-toggle.component.ts:51`); these two are the only exceptions. The library's own examples then diverge: `clamped-text.ts:53` hand-writes `role="button"` on the span, while both clamped-list examples render the trigger as a bare `<a>` with no role at all (CLT-A11Y-01).
- **Pressing Space on the toggle both activates it and scrolls the page.** `'(keydown.space)': 'root?.toggle($event)'` (`clamped-list.ts:64`) routes into a `toggle()` that calls only `event.stopPropagation()` (`clamped-text.ts:170`, `clamped-list.ts:49`). Neither implementation calls `preventDefault()`, so the browser's default Space scroll still runs on the focusable, non-native-button host. The in-repo precedent is one line long: `accordion.ts:292` calls `event.preventDefault()` before toggling (CLT-A11Y-02).
- **The toggle's only styling is owned by a different component's stylesheet.** `KbqClampedListTrigger` puts two classes on its host (`clamped-list.ts:61`), but `.kbq-clamped-list__trigger` has **zero** rules anywhere in the repository — the spacing comes from `.kbq-clamped-text__toggle` in `clamped-text.scss:14-17`, which `ViewEncapsulation.None` injects only when a `KbqClampedText` is instantiated. So `kbqClampedList` renders differently depending on whether an unrelated component happens to be on the page, and both in-repo examples independently cancel that margin — one with a `styles:` override (`clamped-list-overview-example.ts:46-51`), one with `style="margin-top: 0px !important"` (`clamped-list-example.ts:36`) (CLT-CSS-01).
- **The whole state machine converges only on the first `ResizeObserver` delivery, and the docs site is prerendered.** `hasToggle` is initialized to `true` (`clamped-text.ts:109`) and `collapsedState` to `undefined` (`:103`); nothing reads `isCollapsed` into the rendered state except `updateCollapsedState()`, which runs from the observer callback (`:159-165, 186-194`) behind a `Platform.isBrowser` gate (`:155`). `apps/docs/src/prerender-routes.txt:45` prerenders `/en/components/clamped-text/overview`, so the shipped HTML for that page contains the full ~700-character paragraph, expanded, next to an "Expand" link — corrected only after hydration (CLT-BUG-01, and `clamped-text-overview-example` is in the SSR dev app at `components-dev/ssr/module.ts:163`).
- **The Jest suite mostly asserts jsdom's absence of layout.** `getRowsCount()` reads `getClientRects()` (`clamped-text.ts:207`), which returns an empty list in jsdom, so `hasToggle` computes to `false` and `collapsedState` to `false` in every unmocked case. The test named `should default to expanded state on init` (`clamped-text.spec.ts:78-88`) therefore asserts the *opposite* of the production default for the long string it renders, and the sole case that mocks geometry (`:90-110`) contains one assertion (CLT-TEST-01).

Genuine strengths, and they are real: this package solves the adjacent problem far better than `ellipsis-center` does (see `REVIEW.ellipsis-center.md`). Invalidation is a CDK `SharedResizeObserver` on the measured element (`clamped-text.ts:159-160`) rather than a per-instance `(window:resize)` listener, so container-driven resizes — splitter drags, sidepanel toggles — are caught, and one observer is shared across all instances. Teardown is correct on all four subscriptions (`takeUntilDestroyed()` at `:129, 137, 144` and `takeUntilDestroyed(this.destroyRef)` at `:161`). DOM geometry is behind `Platform.isBrowser` (`:155`, added deliberately by `e702d5549`, DS-5266). Locale strings come from `kbqInjectClampedTextLocaleConfiguration()` (`constants.ts:54-56`) with a typed override provider, exactly as AGENTS.md requires, and the component is reactive to locale changes. And unlike `ellipsis-center` it ships a real e2e pair — including two *behavioural* Playwright assertions (`e2e.playwright-spec.ts:25-44`) covering auto-collapse and expanded-state persistence across a container widening, which is precisely the class of bug a screenshot cannot catch.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

None.

### P1 — High

**CLT-A11Y-01 · Disclosure state is published on a role-less wrapper and the actual trigger carries no semantics at all** — `clamped-text.ts:52-64, 74`, `clamped-list.ts:11, 58-67`; examples `clamped-list-overview-example.ts:31-43`, `clamped-list-example.ts:30-44`; in-repo precedent `accordion/accordion-trigger.directive.ts:8-20`, `form-field/cleaner.ts:56-65`.
`KbqClampedText` binds `'[attr.aria-expanded]': 'collapsedState() ? "false" : "true"'` on its own host element (`clamped-text.ts:74`), and `KbqClampedList` does the same on the `[kbqClampedList]` container (`clamped-list.ts:11`). Neither host has a `role`, and neither is operable — the element a user clicks and focuses is the `KbqClampedListTrigger` host, whose directive metadata (`clamped-list.ts:58-67`) declares two classes and three event bindings and nothing else: no `role`, no `aria-expanded`, no `aria-controls`. `aria-expanded` is not a global ARIA attribute, so on a role-less custom element it conveys nothing to assistive technology, and even where it is exposed it is attached to a node the user cannot act on. Every other disclosure control in this library gets this right — `accordion-trigger.directive.ts:10-12` binds `role="button"`, `aria-expanded` **and** `aria-controls` on the trigger itself, and `form-field/cleaner.ts:60` shows the convention of the directive owning its own `role` rather than delegating it to call sites. The consequence of *not* owning it is visible inside this very package: `clamped-text.ts:53` hand-writes `role="button"` into the component template, while the two clamped-list examples render the trigger as `<a kbq-link kbqClampedListTrigger pseudo>` (`clamped-list-overview-example.ts:32`, `clamped-list-example.ts:31-37`) — an anchor with no `href`, therefore no role, announced by a screen reader as an unlabelled focusable text node. Two consumers in the library's own documentation, two different answers. Note this is a WCAG 4.1.2 (Name, Role, Value) judgement backed by in-repo inconsistency, not a claim that axe-core currently fails the package — nothing in either Jest suite runs axe at all (CLT-TEST-02).
**Fix:** move the semantics onto `KbqClampedListTrigger`, where the interaction already lives. Add to its host block: `'[attr.role]': '"button"'`, `'[attr.tabindex]': '0'` (harmless alongside `KbqLink`, and correct when the trigger is used without it), `'[attr.aria-expanded]': 'root ? (root.isCollapsed() ? "false" : "true") : null'` and `'[attr.aria-controls]': 'root?.contentId'`. Give `KbqClamped` (`constants.ts:35-47`) a `contentId: string` member, have `KbqClampedText` generate one and put it on the `#textContainer` div (`clamped-text.ts:40-50`), and have `KbqClampedList` expose the id of its own host. Then delete the hand-written `role="button"` at `clamped-text.ts:53` and add the role to neither example — the directive should be the single source. Guard with Jest cases asserting `role`, `aria-expanded` on the *trigger* in both states, and an `aria-controls` target that resolves, mirroring `accordion.spec.ts:1019-1045`; add a `jest-axe` run over both fixtures.

**CLT-A11Y-02 · Space activates the toggle and scrolls the page, because neither `toggle()` calls `preventDefault()`** — `clamped-list.ts:62-64`, `clamped-text.ts:169-171`, `clamped-list.ts:48-51`; precedent `accordion/accordion.ts:287-293`.
`KbqClampedListTrigger` binds `'(click)'`, `'(keydown.enter)'` and `'(keydown.space)'` to `root?.toggle($event)` (`clamped-list.ts:62-64`). Both implementations of `toggle()` begin with `event.stopPropagation()` and never call `event.preventDefault()` — `clamped-text.ts:170` and `clamped-list.ts:49`. The hosts these bindings land on are a `<span>` (`clamped-text.ts:53`) and an `<a>` with no `href` (both examples); neither is a native button, so the browser applies its default Space behaviour — scroll the nearest scroll container by a page. The user therefore expands the text *and* is thrown a screenful down the document, which for a component whose stated purpose is revealing more text on the spot is the exact opposite of the intended effect. `KbqLink` supplies `tabindex="0"` (`link.component.ts:47, 80-89`), so the host is genuinely focusable and this path is reachable by any keyboard user. The one-line fix already exists in the repo: `accordion.ts:292` calls `event.preventDefault()` before `activeItem.toggle()`. `Enter` is unaffected on these hosts, but preventing it costs nothing and matters if the directive is later applied to a `<button type="submit">`.
**Fix:** call `event.preventDefault()` at the top of both `toggle()` implementations (`clamped-text.ts:170`, `clamped-list.ts:49`), or — better, since the concern belongs to the key binding rather than the state change — change the host bindings at `clamped-list.ts:63-64` to `'$event.preventDefault(); root?.toggle($event)'` and leave `toggle()` callable programmatically without side effects on the event. Add a Jest case per key that dispatches a `keydown` with `SPACE`/`ENTER` on the trigger and asserts both the state flip and `event.defaultPrevented === true`; today the second assertion fails.

**CLT-CSS-01 · The trigger's only styling lives in another component's stylesheet, and both in-repo examples override it** — `clamped-list.ts:61`, `clamped-text.scss:14-17`; consumer workarounds at `clamped-list-overview-example.ts:46-51` and `clamped-list-example.ts:36`.
`KbqClampedListTrigger` sets `class: 'kbq-clamped-list__trigger kbq-clamped-text__toggle'` on its host (`clamped-list.ts:61`). Grepping every `.scss` and `.css` file under `packages/` and `apps/` returns exactly one rule for either class: `.kbq-clamped-text__toggle { margin-top: var(--kbq-size-xxs); align-self: flex-start; }` (`clamped-text.scss:14-17`). `.kbq-clamped-list__trigger` — the name the directive is actually about — has no rule at all. Because `KbqClampedText` uses `ViewEncapsulation.None` (`clamped-text.ts:71`), that stylesheet is injected into the document only when a `KbqClampedText` instance is first created, so an application that uses `kbqClampedList` alone gets a trigger with no spacing, while the same markup in an application that also renders a `kbq-clamped-text` somewhere gets `margin-top` and `align-self: flex-start` applied to a directive that has no idea why. Worse, `align-self` is meaningless outside the `flex-direction: column` host that `.kbq-clamped-text` establishes (`clamped-text.scss:1-4`), so in a `layout-row` list it is inert while the margin is not. Both of the library's own clamped-list examples hit this and patched it independently and differently: `clamped-list-overview-example.ts:47-50` adds a `styles:` block resetting `.kbq-clamped-list__trigger { margin-top: 0; display: inline-block; }`, and `clamped-list-example.ts:36` writes `style="margin-top: 0px !important"` inline. Two authors, two workarounds, same margin — the textbook signature of a rule that belongs to the wrong owner.
**Fix:** stop borrowing. Either (a) move the spacing out of the directive's class list entirely — drop `kbq-clamped-text__toggle` from `clamped-list.ts:61`, keep `.kbq-clamped-text__toggle` as a rule the *component template* applies to its own `<span>` (`clamped-text.ts:53`), and leave `kbqClampedList` consumers to space their trigger like any other content; or (b) give the trigger a stylesheet of its own (`clamped-list.scss`, imported by a thin `styleUrls`-bearing wrapper or by the package's theme entry) that defines `.kbq-clamped-list__trigger` and drives the gap through a component token — `--kbq-clamped-text-size-toggle-margin`, defaulting to `var(--kbq-size-xxs)` — so a consumer can retune it without `!important`. (b) also gives the package the token surface it currently lacks. Either way, deleting `clamped-list-overview-example.ts:47-50` and the inline `!important` at `clamped-list-example.ts:36` with no visual change is the acceptance criterion; guard it with a clamped-list row in `e2e.ts`, whose baseline must come from `yarn run e2e:docker:update-snapshots`.

### P2 — Should fix

**CLT-BUG-01 · The rendered state is undefined until the first `ResizeObserver` delivery, so the initial `[isCollapsed]` is ignored and the prerendered docs page ships expanded** — `clamped-text.ts:103, 109, 128-134, 148-152, 154-166, 186-194`; `apps/docs/src/prerender-routes.txt:45, 241`; `packages/components-dev/ssr/module.ts:163`.
`collapsedState` starts as `undefined` (`:103`) and `hasToggle` as `true` (`:109`). The constructor's `toObservable(this.isCollapsed).pipe(pairwise())` (`:128-134`) needs two emissions before it fires, so a static `[isCollapsed]="true"` never reaches `collapsedState` through that path — the author knew this and left the explanation at `:149-151`, seeding `isToggleCollapsed` in `ngOnInit` instead. That seed is only *consumed* by `updateCollapsedState()` (`:186-194`), which runs exclusively from the `SharedResizeObserver` subscription in `ngAfterViewInit` (`:159-165`) — behind `if (!this.platform.isBrowser) return;` (`:155`). Three consequences follow. (1) In the browser there is a window between first paint and the first observer delivery in which the text is fully expanded and the toggle is rendered regardless of content length; `[debounceTime]` (`:161`) widens that window by exactly its value, so `[debounceTime]="300"` means 300 ms of unclamped text. (2) For short content the toggle is rendered and then removed, because `hasToggle` optimistically starts `true`. (3) On the server the window never closes: `apps/docs/src/prerender-routes.txt:45` and `:241` prerender `/en|ru/components/clamped-text/overview`, so the shipped HTML for the docs page contains the whole ~700-character DDoS paragraph, expanded, beside an "Expand"/"Развернуть" link whose label contradicts what is on screen. The same example is wired into the SSR dev app at `components-dev/ssr/module.ts:163`. This is not a hydration mismatch — the client's initial render agrees with the server's, which is exactly why it has gone unnoticed — it is a visible content shift on every load.
**Fix:** make the pre-measurement state honest instead of optimistic. Initialize `hasToggle` to `false` (`:109`) so nothing renders a toggle before it is known to be needed, and derive the initial `collapsedState` from the input synchronously — replace the `pairwise()` chain with the `model()` migration from CLT-API-01 plus a `computed()`/`linkedSignal()` that reads `isCollapsed() ?? true`, so `collapsedState` is correct at first render and the observer only *corrects* it. Additionally apply the collapsed class optimistically when `isCollapsed()` is `true` or unset, so the server emits clamped text. Acceptance: `yarn run docs:build` output for `clamped-text/overview` contains `kbq-clamped-text__content_collapsed` and no toggle markup for content whose length is unknown at build time; a Jest case with `[isCollapsed]="true"` asserts the class before any observer emission (today the `MockResizeObserver` at `clamped-text.spec.ts:8-14` seeds one immediately, which hides the gap).

**CLT-API-01 · Two-way binding is hand-rolled from `input()` + `output()`, against AGENTS.md and against its own sibling directive** — `clamped-text.ts:85, 92, 128-134, 148-152`; contrast `clamped-list.ts:17`; consumer `clamped-text-external-state-example.ts:14, 33`.
`KbqClampedText` declares `readonly isCollapsed = input<boolean>()` (`:85`) and `readonly isCollapsedChange = output<boolean>()` (`:92`) — the exact pairing AGENTS.md forbids ("Use `model()` for two-way bound properties with `[(prop)]` syntax instead of pairing `input()` with `output()`"). The cost is not stylistic. Because the input is one-way, the component must mirror it into an internal `collapsedState` signal, and it does so through `toObservable(...).pipe(pairwise())` (`:128-134`), which by construction discards the first value; `ngOnInit` then exists solely to paper over that (`:148-152`, with a three-line comment saying so). The result is a state machine with three signals (`isCollapsed`, `collapsedState`, `isToggleCollapsed`) where one would do, and the pre-measurement gap of CLT-BUG-01 is a direct consequence. `KbqClampedList`, 140 lines away in the same package, does it correctly with `readonly isCollapsed = model<boolean>(true)` (`clamped-list.ts:17`) and needs no mirror, no `pairwise()` and no `ngOnInit`. The docs example already writes the banana-box form against the manual pair (`clamped-text-external-state-example.ts:14`), which Angular supports, so the migration is source-compatible for `[(isCollapsed)]` users.
**Fix:** replace `:85` and `:92` with `readonly isCollapsed = model<boolean | undefined>(undefined)` and delete the `pairwise()` subscription and `ngOnInit`. Write the toggle result straight into the model in `toggle()` (`:169-180`) and let `updateCollapsedState()` write the measured value; the `isCollapsedChange` output name is generated identically by `model()`, so templates do not change. `isToggleCollapsed` can then collapse into the model as well. This alters the API report (`InputSignal` + `OutputEmitterRef` → `ModelSignal`, `clamped-text.api.md:66-67`), so run `yarn run build:components` then `yarn run approve-api` — build first, the guard reads `dist/*.d.ts`. Keep the existing spec cases at `clamped-text.spec.ts:112-129` green as the compatibility check.

**CLT-BUG-02 · `isCollapsedChange` fires for measurement-driven and parent-driven changes alike, so it cannot express user intent — which is what the guide recommends using it for** — `clamped-text.ts:136-141, 186-194`; `clamped-text.en.md:23`, `clamped-text.ru.md:23`; asserted as intended by `clamped-text.spec.ts:67-76, 112-129`.
The output is emitted from `toObservable(this.collapsedState).pipe(skip(1))` (`:136-141`), i.e. from *every* transition of the internal state. Three different causes all produce the same event and are indistinguishable to the parent: the user clicking the toggle (`:172`), the component's own first measurement (`:193`, which fires on mount for any content long enough to clamp), and the parent writing `[isCollapsed]` (`:131`, which echoes the parent's own value straight back out). The package's tests encode all three as intended — `should emit collapsed change on init` (`:67-76`) and `should emit isCollapsedChange when isCollapsed input changes` (`:112-129`). That is defensible for a `model()`-style two-way channel, but the published guide recommends it for something else: "The `isCollapsedChange` output allows you to sync the state back" for state "controlled from outside — for example, from route query params" (`clamped-text.en.md:23`, same at `clamped-text.ru.md:23`). Wire that up literally and every mount of the page writes a query parameter the user never asked for, and every navigation that sets the parameter triggers a write of the same value back into the URL. Nothing in either guide warns about this, and there is no separate "user toggled" signal to subscribe to.
**Fix:** once CLT-API-01 lands, `isCollapsedChange` becomes the `model()` write-back channel with well-understood semantics, and the remaining gap is documentation plus one honest emission rule: do not emit for the *initial* measurement when the resulting value equals `isCollapsed() ?? true` — the parent already knows it. If a genuine user-intent event is wanted, add a distinct `output<boolean>()` named `toggled`, emitted only from `toggle()` (`:169-180`). Document in both guides which causes emit. Cover with a Jest case that mounts with `[isCollapsed]="true"` on clamping content and asserts the output did **not** fire.

**CLT-API-02 · Internal state is published as writable signals, and five exported symbols carry no documentation** — `clamped-text.ts:95-97, 109`; `tools/public_api_guard/components/clamped-text.api.md:21, 29, 57, 60, 65, 76-77, 91`; interface at `constants.ts:41-42`.
`hasToggle` is declared `readonly hasToggle = signal(true)` with only a `@docs-private` tag (`clamped-text.ts:108-109`), so the API report publishes it as `readonly hasToggle: _angular_core.WritableSignal<boolean>` (`clamped-text.api.md:65`). `@docs-private` hides a member from the docs site; it does not change TypeScript visibility. Any consumer can call `clampedText.hasToggle.set(false)` and desynchronize the component from its own measurement — and will, because `hasToggle` is the natural thing to read when writing a custom trigger. The `KbqClamped` interface deliberately narrows it to `Signal<boolean>` (`constants.ts:42`), so the class widens the very contract the package defines. The same applies to the two view queries `text` and `textContainer` (`clamped-text.ts:95-97`, report at `:76-77`): both are `viewChild.required` handles to internal DOM, published. Separately, five exported symbols reach the report with no doc comment at all — `KbqClamped` (`api.md:21`), `KbqClampedList` (`:29`), `KbqClampedRoot` (`:57`), `KbqClampedText` (`:60`) and `KbqClampedTextModule` (`:91`) are each `// @public (undocumented)`, which for the two classes a consumer types by name is the worst place for the gap.
**Fix:** expose `hasToggle` as a read-only projection — keep a `private readonly hasToggleState = signal(false)` and publish `readonly hasToggle = this.hasToggleState.asReadonly()`, which satisfies `KbqClamped` exactly; make `text` and `textContainer` `protected`. Add class-level JSDoc to `KbqClampedText`, `KbqClampedList`, `KbqClampedTextModule`, the `KbqClamped` interface and the `KbqClampedRoot` token. Both changes churn `clamped-text.api.md` (visibility *and* the removal of `(undocumented)` markers — see `project_jsdoc_on_public_member_changes_api_md`), so fold them into one `yarn run build:components && yarn run approve-api` cycle together with CLT-API-01 and CLT-API-03 rather than three.

**CLT-CSS-02 · Both clamp properties are bound unconditionally, so nothing in the code keeps the expanded state unclamped** — `clamped-text.ts:43-45`, `clamped-text.scss:6-12`.
The content div binds `[style.-webkit-line-clamp]="lineClamp()"` and `[style.line-clamp]="lineClamp()"` (`:43-44`) with no dependence on `collapsedState()`, while the collapsed *class* — the thing that actually enables clamping — is bound separately at `:45` and supplies `display: -webkit-box; overflow-y: hidden; -webkit-box-orient: vertical` only (`clamped-text.scss:7-11`). Today the expanded state survives by accident: `-webkit-line-clamp` is inert without `display: -webkit-box`, so the leftover property does nothing. The standard `line-clamp` longhand has no such requirement — it applies to any block container — so in a browser that implements it the expanded state stays clamped to `rows` lines and the toggle appears to do nothing at all. The repository pins no `browserslist` (no `.browserslistrc`, no `browserslist` key in `package.json`), so the effective target is whatever Angular's default is at build time, and it moves. Independently of the browser question, a style binding whose whole purpose is the collapsed state and which is applied in both states is wrong on its face, and there is no test that would notice: `e2e.playwright-spec.ts:33-44` asserts only the presence and absence of the collapsed class, never the rendered height.
**Fix:** gate both bindings on the same condition as the class — `[style.-webkit-line-clamp]="collapsedState() ? lineClamp() : null"` and the same for `line-clamp` — or, cleaner, drop the bindings from the template and set the clamp through a custom property (`[style.--kbq-clamped-text-line-clamp]="rows()"`) consumed inside `.kbq-clamped-text__content_collapsed`, which makes the coupling structural rather than conventional. While there, delete the `lineClamp` signal and its mirroring subscription (`clamped-text.ts:107, 143-145`): it holds nothing `rows()` does not already hold. Extend the Playwright expanded case at `:33-44` with an assertion on the content element's `scrollHeight === clientHeight` after expanding — that is the assertion that fails when a clamp survives expansion.

**CLT-CSS-03 · `overflow-y: hidden` makes the collapsed block a horizontal scroll container** — `clamped-text.scss:6-12`, specifically `:9`.
`.kbq-clamped-text__content_collapsed` sets `overflow-y: hidden` and leaves `overflow-x` at its initial `visible`. Per CSS Overflow, when one axis is `visible` and the other is not, the `visible` value computes to `auto` — so the collapsed block is a scroll container in the inline axis. Two effects follow, both only in the collapsed state, which is what makes them confusing to debug. First, content that cannot wrap (a long URL, a hash, a path — realistic for this library's security-product consumers) produces a horizontal scrollbar that vanishes when the user expands, changing the block's height as a side effect of scrollbar gutter. Second, becoming a scroll container changes containment for any `position: sticky` or absolutely-positioned descendant of the projected content, and makes the element a scroll target the user can pan even though it is meant to look like plain text. `-webkit-line-clamp` requires `overflow: hidden` on the box in any case, so the narrower property is not buying anything.
**Fix:** change `clamped-text.scss:9` to `overflow: hidden`. Add an `e2e.ts` cell with an unbreakable 80-character token inside a 200 px container so the screenshot suite pins the behaviour; regenerate the baseline only with `yarn run e2e:docker:update-snapshots`. `yarn run stylelint` covers the file already.

**CLT-TEST-01 · The Jest suite asserts jsdom's absence of layout, and one case's name states the opposite of production behaviour** — `clamped-text.spec.ts:66-129`, especially `:78-88` and `:90-110`; `clamped-text.ts:206-210`.
`getRowsCount()` counts distinct `top` values among `this.text().nativeElement.getClientRects()` (`clamped-text.ts:207-209`). jsdom performs no layout and returns an empty `DOMRectList`, so `getRowsCount()` is `0`, `updateToggleVisibilityState()` evaluates `0 > 5 + 1` to `false`, and `updateCollapsedState()` writes `false && … = false`. Every unmocked case in the suite therefore exercises the "nothing to clamp" branch — including `should default to expanded state on init` (`:78-88`), which renders a 100-word string in a 1000 px container (`:32-36, 41`) and asserts `collapsed()` is `false`. In a real browser that content clamps and the default is *collapsed*; the test is named after, and locks in, the jsdom artefact rather than the component's contract. Its first assertion (`expect(...).not.toEqual(previousCollapsedState)`, `:86`) is `undefined !== false`, which holds for any non-`undefined` result. The one case that does mock geometry (`:90-110`) patches `HTMLElement.prototype.getClientRects` globally for a 20-line result and then makes a single assertion on `aria-expanded`; nothing covers `rows`, `debounceTime`, `hasToggle` transitions, the toggle click path, `scrollIntoView`, or the `isEventFromToggle` re-entrancy guard. Note the `MockResizeObserver` (`:8-14`) returns a `BehaviorSubject` seeded with `[]`, so measurement runs synchronously on subscribe — convenient, but it also erases the pre-measurement window that CLT-BUG-01 is about, so no unit test can currently observe it.
**Fix:** hoist the `getClientRects` mock into a helper that takes a row count, and use it in every case so both branches are reachable; rename `should default to expanded state on init` to state what it checks (`should stay expanded when content does not exceed rows`) and add its counterpart with a mocked 20-row result asserting `aria-expanded="false"` and the collapsed class. Add cases for: `[rows]="3"` changing the threshold, clicking the toggle flipping the class and the attribute, a resize arriving immediately after a toggle not re-collapsing (the `isEventFromToggle` path, `clamped-text.ts:186-194`), and a `ReplaySubject`-based mock observer that lets the test render *before* the first delivery so CLT-BUG-01's window is assertable. Mutation check: making `updateToggleVisibilityState()` a no-op must fail at least three cases — today it fails none.

### P3 — Nice to have / hygiene

**CLT-API-03 · `rows` has no `numberAttribute` transform while `debounceTime` does, and the guide calls it an attribute** — `clamped-text.ts:83, 90`; `clamped-text.en.md:7`, `clamped-text.ru.md:7`; contrast `clamped-list.ts:24, 29`.
`readonly rows = input<number>(kbqClampedTextDefaultMaxRows)` (`:83`) takes no transform, while its neighbour `debounceTime` (`:90`) and both numeric inputs on `KbqClampedList` (`clamped-list.ts:24, 29`) use `{ transform: numberAttribute }`. Under `strictTemplates: true` (`tsconfig.json:117`) that makes `<kbq-clamped-text rows="3">` an NG8002-class type error while `<kbq-clamped-text debounceTime="300">` compiles — an inconsistency inside one component with no stated reason. Both guides describe it in attribute language ("The `rows` attribute controls how many lines are shown", `clamped-text.en.md:7`; "Атрибут `rows` задает", `clamped-text.ru.md:7`) even though the snippet immediately below uses the property form.
**Fix:** `readonly rows = input(kbqClampedTextDefaultMaxRows, { transform: numberAttribute })`. This changes `clamped-text.api.md:75` from `InputSignal<number>` to `InputSignalWithTransform<number, unknown>` (and bumps `tools/check-public-api-any/baseline.json:11` from 3 to 4), so fold it into the single `approve-api` cycle with CLT-API-01/02. No template in the repo binds `rows` statically, so there is no migration cost.

**CLT-LIFE-01 · `debounceTime` is read once, and a boolean re-entrancy flag can swallow a genuine resize** — `clamped-text.ts:154-166, 175, 182-194`.
Two lifecycle issues in the observer path. (1) `debounceTime(this.debounceTime())` (`:161`) evaluates the input signal once, while building the pipe in `ngAfterViewInit`; later changes to `[debounceTime]` have no effect, which is invisible from the outside because the input is a signal and looks reactive. (Static bindings do apply — inputs are set before `ngAfterViewInit` — so this is a narrow but real contract gap.) The member also shadows the RxJS operator imported at `:22`; the call at `:161` resolves to the import only because it lacks `this.`, which is legible but one refactor away from a confusing bug. (2) `isEventFromToggle` (`:125`) is set in `toggle()` (`:175`) and consumed by the *next* observer delivery (`:187-191`), whichever that is. If the user toggles and then resizes the window before the debounce window closes — or if the toggle does not itself change the observed box — the flag is spent on the resize, and `updateCollapsedState()` is skipped for a measurement that genuinely needed it. `updateToggleVisibilityState()` runs unconditionally either way (`:163`), so `hasToggle` and `collapsedState` can be computed from different measurements.
**Fix:** read the debounce lazily — `debounce(() => timer(this.debounceTime()))` — or document the input as init-only in its JSDoc (`:86-89`). Rename the member to `resizeDebounceTime` to remove the shadowing. Replace the boolean with a positive check: compare the observed box against the last measured one and skip `updateCollapsedState()` only when the size change is the one the toggle itself caused, or drop the flag entirely once `collapsedState` is derived from a single source per CLT-API-01. Cover with a `fakeAsync` case that toggles, ticks past the debounce, then delivers a resize and asserts the state survived.

**CLT-BUG-03 · Collapsing hijacks the page scroll on both axes, with no opt-out and an uncancelled timeout** — `clamped-text.ts:169-180`, specifically `:177-179`.
`toggle()` ends with `if (this.collapsedState()) { setTimeout(() => this.elementRef.nativeElement.scrollIntoView({ block: 'center', inline: 'center' })); }`. Three problems. The behaviour is unconditional and undocumented — neither guide mentions that collapsing moves the viewport, and a consumer who wants a purely local collapse (a clamped description inside a modal, a table cell, a sidepanel) has no input to turn it off. `inline: 'center'` scrolls the *horizontal* axis too, so any ancestor with horizontal overflow — including the collapsed block itself, per CLT-CSS-03 — is panned as a side effect of a vertical interaction. And the `setTimeout` handle is never stored or cleared, so a component destroyed in the same tick still runs the callback; `scrollIntoView` on a detached node is a harmless no-op, but under Zone.js the timer still schedules an application-wide change-detection tick. Nothing in either test suite exercises this path — note that `playwright.config.ts:101` forces `reducedMotion: 'reduce'` on every context, which does not affect this call (the default `behavior: 'auto'` is instantaneous) but does mean no screenshot would show it either.
**Fix:** replace `setTimeout` with `afterNextRender()` (SSR-safe and cancelled with the injector), narrow the call to `{ block: 'nearest', inline: 'nearest' }` so it scrolls only when the element has actually left the viewport and never pans horizontally, and add a `scrollOnCollapse = input(true, { transform: booleanAttribute })` opt-out documented in both guides. Cover with a Jest case spying on `scrollIntoView` for both values of the new input.

**CLT-DOC-01 · Neither guide documents the inputs a consumer needs, and both docs entries point at the same package path and API id** — `clamped-text.en.md:1-25`, `clamped-text.ru.md:1-25`, `clamped-list.en.md:1-15`, `clamped-list.ru.md:1-15`; `apps/docs/src/app/structure.ts:434-457`.
The clamped-text guide documents `rows`, `isCollapsed` and `isCollapsedChange` in prose and says nothing about `debounceTime` (`clamped-text.ts:86-90`) — the one input whose effect (a visible delay before clamping, per CLT-BUG-01) a consumer is most likely to be surprised by. The clamped-list guide is 15 lines of narrative and three example embeds; it names none of `items`, `collapsedVisibleCount`, `hiddenThreshold`, `visibleItems`, `exceededItemCount`, `hasToggle` or `showMoreCountText`, and never mentions that `kbqClampedListTrigger` must be placed on an element the consumer makes operable — the omission that CLT-A11Y-01 is about. Separately, both `structure.ts` entries carry `path: 'packages/components/clamped-text'` and `apiId: 'clamped-text'` (`:441-443`, `:452-455`), so the "Clamped list" page's API tab renders the whole package, `KbqClampedText` included. Both are `hasExamples: false` (`:444`, `:456`), which is correct — the package ships no `examples.*.md` stubs and both guides embed their examples inline, so unlike most sibling packages there is nothing dead to clean up here. Note also that `moreText` (`core/locales/types.ts:287`, five locale files) is consumed only by two docs examples (`clamped-list-example.ts:39`, `clamped-list-dotted-example.ts:54`) and by no component — a locale key the library defines for its own documentation.
**Fix:** add an input table to each guide (both languages) covering every published input with its default, and a short "writing a custom trigger" section for `kbqClampedListTrigger` showing the required host element once CLT-A11Y-01 has decided what the directive supplies. Give `KbqClampedList` its own `apiId` if the docs API pipeline supports per-entry filtering, or state in the clamped-list guide that the API tab is shared. Decide whether `moreText` is library API or example-only and either use it or document it as a convenience string.

**CLT-TEST-02 · The keyboard bindings the trigger declares are never exercised, and no suite runs AXE** — `clamped-list.spec.ts:53-131`, `clamped-text.spec.ts:66-129`; bindings at `clamped-list.ts:62-64`.
`clamped-list.spec.ts` is the healthier of the two suites — 8 cases covering slicing, the threshold, the toggle text and `aria-expanded` — but every activation goes through `nativeElement.click()` (`:76, 87, 98, 122, 127`). The `(keydown.enter)` and `(keydown.space)` bindings at `clamped-list.ts:63-64` have no coverage in either suite, which is why CLT-A11Y-02 survived. Neither suite imports `jest-axe`, so the disclosure semantics of CLT-A11Y-01 are unverified by anything automated, and AGENTS.md states AXE conformance as a mandate. The `clamped-list.spec.ts` host is correctly named without the `Kbq` prefix (`:47`), matching repo convention.
**Fix:** add a keyboard case per key to `clamped-list.spec.ts` using `dispatchKeyboardEvent` (or the repo's testing helper) with `ENTER` and `SPACE`, asserting the state flip and `defaultPrevented`; add the equivalent for `KbqClampedText`'s in-template trigger. Add a `jest-axe` assertion over each fixture in both collapsed and expanded states — with the current markup the expanded/collapsed pair is the cheapest regression guard for the CLT-A11Y-01 fix.

**CLT-ARCH-01 · Package layout deviates from the AGENTS.md convention, and one package ships two independently documented components** — `packages/components/clamped-text/` file list; `module.ts:1-15`, `index.ts:1-4`; `apps/docs/src/app/structure.ts:434-457`.
AGENTS.md prescribes `<component-name>.module.ts` and `public-api.ts` per package. This package has a bare `module.ts` (the only other bare `module.ts` in `packages/components` belongs to `skeleton`) and no `public-api.ts` at all — `index.ts` re-exports the four source files directly (`index.ts:1-4`), so *everything* in `constants.ts` and both component files is public by default, which is how `KbqClampedRoot` and the `KbqClamped` interface ended up on the published surface undocumented (CLT-API-02). The package also hosts two components that the docs treat as separate products with separate navigation entries, separate guides and separate SEO descriptions (`structure.ts:434-457`, `seo-descriptions.ts:58-65`), while sharing one API report and one `ng-package.json` entry point. That is a defensible decision — they share `KbqClampedRoot`, `KbqClampedListTrigger` and the locale section — but it is nowhere recorded, and the naming (`clamped-text` as the package for a component called `clamped-list`) will keep surprising readers. The absence of `-tokens.scss` and `_-theme.scss` is *not* a defect here (see Appendix A).
**Fix:** rename `module.ts` to `clamped-text.module.ts` and add a `public-api.ts` that names the intended exports explicitly, with `index.ts` re-exporting only that — this is the mechanism that lets `KbqClampedRoot` stay internal if that is the intent, and it changes the API report, so schedule it with the CLT-API-01/02/03 `approve-api` cycle. Add a one-paragraph header comment to `constants.ts` stating why both components live in one entry point.

## Appendix A — Review Methodology

Findings were gathered by reading the complete package — all 14 source, style, spec, fixture and guide files, plus `index.ts`, `module.ts` and `ng-package.json` — then following each candidate outward to three independent sources. First, the consumers: `grep` for `kbq-clamped-text`, `kbqClampedList`, `KbqClampedText`, `KbqClampedList` and `clamped-text` across `packages/` and `apps/` returns no shipping consumers at all, only the five docs examples, the dev app, the SSR dev app and the locale layer — so consumer evidence here comes from the library's own examples, which is exactly where the two independent margin overrides behind CLT-CSS-01 were found. Second, the in-repo precedent for every accessibility and lifecycle claim: `accordion-trigger.directive.ts`, `accordion.ts`, `form-field/cleaner.ts`, `dropdown-trigger.directive.ts`, `navbar-toggle.component.ts` and `datepicker-toggle.component.ts` establish what this library already considers correct, which is what turns "missing ARIA" into a demonstrable inconsistency. Third, the delivery surfaces: `apps/docs/src/app/structure.ts`, `seo-descriptions.ts`, `prerender-routes.txt`, `tools/api-extractor/config.json`, the API guard report and `tools/check-public-api-any/baseline.json`. The package's 19-commit history was read for regression patterns; the only functional fixes are `059008a6e` (DS-5279, "proper external state control" — the origin of the `pairwise()`/`ngOnInit` scaffolding behind CLT-API-01) and `e702d5549` (DS-5266, the `Platform.isBrowser` guard). Comparison with `REVIEW.ellipsis-center.md` was used deliberately as a calibration baseline for the resize, teardown and SSR dimensions.

Refuted during verification:
- **"The missing `clamped-text-tokens.scss` and `_clamped-text-theme.scss` are defects"** — refuted. The package paints nothing of its own: `clamped-text.scss` is 17 lines with no colour, border or typography declaration, and every visual property of the toggle comes from `KbqLink` and `KbqIcon`, which carry their own theme mixins. The single themable value is `margin-top: var(--kbq-size-xxs)` (`clamped-text.scss:15`), a global size token that resolves in both `@koobiq/design-tokens/web/new/css-tokens-light.css` and `-dark.css`. So there is nothing for a theme mixin to do. What *is* missing is a component-scoped override point for that one gap, which is folded into CLT-CSS-01's fix rather than filed separately.
- **"The toggle is not keyboard-focusable — it is a `<span role=button>` with no `tabindex`"** — refuted. `KbqLink` binds `'[attr.tabindex]': 'tabIndex'` (`link.component.ts:47`) over a getter defaulting to `0` (`:80-89`), and every trigger in the package and its examples carries `kbq-link`. Focus reachability is fine; the finding was re-aimed at what the focused element *announces* (CLT-A11Y-01) and at what Space does once it is focused (CLT-A11Y-02).
- **"The `SharedResizeObserver` subscription leaks, or the observer is never disconnected"** — refuted. `ngAfterViewInit` pipes through `takeUntilDestroyed(this.destroyRef)` (`clamped-text.ts:161`) and all three constructor streams through `takeUntilDestroyed()` (`:129, 137, 144`); CDK's `SharedResizeObserver` refcounts per element and disconnects when the last subscriber unsubscribes. Teardown in this package is correct and is one of its strengths.
- **"The package uses the global `window` and therefore breaks SSR"** — refuted. There is no `window` reference anywhere in the package, `KBQ_WINDOW` is not needed, and DOM geometry is already gated on `Platform.isBrowser` (`clamped-text.ts:155`), added deliberately by `e702d5549` (DS-5266). The genuine server-rendering problem is that the pre-measurement state is wrong rather than absent, which is CLT-BUG-01 and is equally visible in the browser.
- **"Three untyped members are on the public surface (`tools/check-public-api-any/baseline.json:11` records 3)"** — refuted. All three are the `unknown` in `InputSignalWithTransform<number, unknown>` at `clamped-text.api.md:31, 34, 64` (`collapsedVisibleCount`, `hiddenThreshold`, `debounceTime`) — the shape `numberAttribute` always produces. Not the author's to remove, and CLT-API-03 will legitimately raise the count to 4.
- **"The `examples.clamped-text.*.md` stubs are dead files, as in sibling packages"** — refuted. The package ships no `examples.*.md` files at all, both `structure.ts` entries set `hasExamples: false` (`:444`, `:456`), and both guides embed their examples inline with `<!-- example(…) -->` (`clamped-text.en.md:3, 25`, `clamped-list.en.md:7, 11, 15`). Nothing is dead here; the docs shortfall is the missing input tables, filed as CLT-DOC-01.

Corrected on verification:
- **CLT-A11Y-01** was drafted as "the expand control is a `<span>` a keyboard user cannot reach". Reading `link.component.ts:47, 80-89` showed `KbqLink` supplies `tabindex="0"`, so reachability is fine. The finding was re-aimed at the placement of `aria-expanded` and the absence of `role`/`aria-controls` on the trigger — and grew stronger, because the two docs examples turned out to omit the role entirely while the component template hand-writes it.
- **CLT-CSS-01** started as a hygiene note ("the toggle's margin is not overridable"). Grepping every `.scss`/`.css` under `packages/` and `apps/` for `.kbq-clamped-list__trigger` returned zero rules, and the two examples turned out to cancel the same borrowed margin in two different ways — which moved the finding from P3 to P1 and gave it a concrete acceptance test.
