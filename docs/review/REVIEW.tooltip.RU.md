## 1. Краткое резюме

- **Компактная, широко переиспользуемая триггер-директива, функционально надёжная для пользователей мыши и структурно немая для всех остальных.** У tooltip нет P0 и — в отличие от popover — нет P1 по корректности: hover-поток по умолчанию корректно показывает, позиционирует и скрывает, гигиена жизненного цикла в основном соблюдена, а два легаси-подкласса (warning/extended) чисто объединены в input `modifier` без дублирования. Все четыре P1 чинятся аддитивно: три провала доступности и одна ловушка dependency-injection.
- **Доступность — главная проблема: для вспомогательных технологий тултип не существует.** У попапа нет `role="tooltip"`, а триггер никогда не ставит `aria-describedby`, поэтому пользователь скринридера, сфокусировавший `<button kbqTooltip="Delete permanently">`, слышит только «button» (TIP-A11Y-01 — прежние A11Y-07/A11Y-20 из `REVIEW.md`, обе всё ещё открыты). Вдобавок дефолт `ignoreTooltipPointerEvents=true` делает каждый hover-тултип «прозрачным» для кликов — указатель не может на него встать, провал WCAG 1.4.13 _hoverable_ в конфигурации по умолчанию (TIP-A11Y-02), — а hover-тултип на нефокусируемом элементе невозможно закрыть Escape, потому что единственный обработчик Escape висит на `keydown` самого триггера (TIP-A11Y-03, 1.4.13 _dismissable_).
- **Чисто standalone-импорт падает.** У `KBQ_TOOLTIP_SCROLL_STRATEGY` нет фабричного значения по умолчанию, а его единственный провайдер живёт в `KbqToolTipModule`, поэтому `imports: [KbqTooltipTrigger]` — собственный standalone-first мандат репозитория — бросает `NullInjectorError` при создании директивы (TIP-ARCH-01; проверенная tooltip-копия паттерна POP-ARCH-01 о 8 копиях на репозиторий).
- **Хвост по корректности реален, но весь уровня P2, поровну между унаследованным долгом базы и собственной обвязкой inputs.** Из `core/pop-up`: вотчдог `hideWithTimeout` вырождается в busy-loop `interval(0)`, потому что tooltip по умолчанию ставит `leaveDelay=0` (TIP-BUG-01, экс-POP-BUG-03 с переквалификацией); повторное наведение в окно leave-задержки не может отменить запланированное скрытие, а неотслеживаемый таймер может сработать после destroy (TIP-BUG-02); слушатель `keydown` обходит `createListener`, оставляя устаревший `triggerName`, который может ошибочно подавить открытый с клавиатуры тултип (TIP-BUG-06). Собственное: реактивность inputs реализована тремя несовместимыми способами, из-за чего `[kbqTooltipArrow]`/`[kbqTooltipOffset]` инертны при открытом тултипе (TIP-BUG-05); `applyRelativeToPointer` безвозвратно обнуляет пользовательский `placementPriority` (TIP-BUG-03); а эффект `forDisabledComponent` молча затирает явно привязанный `kbqTooltipDisabled` (TIP-BUG-04).
- **Один общий объект незаметно связывает все тултипы приложения.** `KBQ_TOOLTIP_OPEN_TIME_PROVIDER` использует `useValue: { value: 0 }` — единственный литерал уровня модуля — поэтому _все_ тултипы делят один `openTime`, а магическое `MIN_TIME_FOR_DELAY = 2000` заставляет любой тултип, показанный в пределах 2 с после любого другого, пропустить собственный `enterDelay` (TIP-ARCH-02). Вероятно, задуманный UX быстрого повторного показа — но недокументированный, ненастраиваемый, с ложной областью видимости на компоненте — и он молча обрушил тайминг тестов: каждый `tick(410)` в spec проверяет задержку 0 мс, так что задокументированные 400 мс `enterDelay` реального покрытия не имеют (TIP-TEST-01).
- **Существующие тесты честные; пробелы — широкие.** 15 DOM-first Jest-тестов покрывают show/hide по hover/focus, disabled, контекст TemplateRef, математику arrow-offset, `forDisabledComponent` и реактивные `modifier`/`header` — но Escape, закрытие click-триггера, `relativeToPointer`, тайминг `hideWithTimeout`, императивный API `showForMouseEvent`/`showForElement`, эмиссии outputs и негативный сценарий focus-origin не покрыты вовсе (TIP-TEST-02), а Playwright поставляет ровно два скриншот-теста против фикстуры, принудительно показывающей тултипы программно (TIP-TEST-03).
- **Гигиена API несёт тяжёлый хвост P3.** Семейство алиасов inputs расщеплено на `kbqTooltip*` и беспрефиксные (`kbqPlacement`, `kbqTrigger`, …) без правила (TIP-API-06); `context` — это `any` от начала до конца, а falsy-контексты молча отбрасываются (TIP-API-04); императивный show-API одновременно `@docs-private` и официально демонстрируемый динамический паттерн (TIP-API-02); геттер `kbqTooltipColor` возвращает не то, что принимает сеттер (TIP-API-01); а в документации вовсе нет таблицы API — `hideWithTimeout`, `ignoreTooltipPointerEvents` и `forDisabledComponent` не упомянуты в прозе ни на одном языке (TIP-API-08).
- **Что сильно.** Нулевая XSS-поверхность (ни `innerHTML`, ни `bypassSecurityTrust` во всей цепочке); база standalone + OnPush + host-объект + единообразный `inject()` с нативным `@if` в шаблоне; заложенная гигиена жизненного цикла (потоки триггера под `takeUntilDestroyed`, подписки viewport-ruler и вотчдога корректно ограничены `destroyRef` _экземпляра_, `FocusMonitor.monitor`/`stopMonitoring` парные, `KbqPopUp.ngOnDestroy` чистит оба таймера и завершает свои subjects); два легаси-подкласса заменены одним input `modifier` с задокументированной реактивностью (зеркало в `ngOnChanges`) вместо дублирования кода; покрытие JSDoc на inputs заметно выше, чем у popover; 16 доков-примеров по размещениям, отступам, вариантам и динамическому использованию; дисциплинированные BEM-стили на CSS-токенах с миксинами темы/типографики.

## 3. Приоритизированные находки (дедуплицированы, проверены)

### P0 — Блокеры релиза

Не найдены. Ни один поток по умолчанию не падает и не теряет данные: единственный найденный краш-путь (`showForElement` на disabled-триггере, TIP-BUG-08) сидит за `@docs-private` императивным API без внутрирепозиторных вызовов; standalone-`NullInjectorError` (TIP-ARCH-01) реален, но каждое внутрирепозиторное и задокументированное использование импортирует NgModule, так что он бьёт только standalone-first потребителей; а a11y-P1 блокируют группы пользователей, но не основной указательный поток.

### P1 — Высокий приоритет

**TIP-A11Y-01 · Нет `role="tooltip"` и `aria-describedby` — для скринридеров тултип не существует, а динамические обновления никогда не озвучиваются** — `tooltip.component.html:1`; `tooltip.component.ts:131-136` (host), `:490-502` (updateData).
Корень попапа `<div #tooltip class="kbq-tooltip">` несёт только презентационные классы — ни `role`, ни `id`. Host триггера биндит только `[class.kbq-tooltip_open]`, `(keydown)`, `(touchend)`; ничто в цепочке не ставит `aria-describedby` и не вызывает CDK `AriaDescriber` (grep по пакету возвращает ноль совпадений `aria-`/`role`). Оверлей рендерится в конце `<body>`, отсоединённый от триггера в дереве доступности, поэтому пользователь NVDA/VoiceOver, сфокусировавший `<button kbqTooltip="Delete permanently">`, видит появившийся тултип, а слышит только «button» (паттерн WAI-ARIA APG tooltip; WCAG 4.1.2, 1.1.1). В довершение `updateData()` мутирует контент открытого тултипа с `detectChanges()`, но нигде нет `aria-live`/`LiveAnnouncer`, так что изменение текста при открытом тултипе («Saving…» → «Saved») тоже немо. Прежние A11Y-07 и A11Y-20 из `REVIEW.md`, обе всё ещё открыты, слиты сюда.
**Исправление:** перенять паттерн `MatTooltip` — инжектировать `AriaDescriber`, на показ вызывать `describe(triggerEl, message, 'tooltip')` / на скрытие-destroy `removeDescription` для строкового контента; добавить попапу `role="tooltip"` + стабильный сгенерированный `id` и указывать на него `aria-describedby` для шаблонного контента; при смене контента перевызывать describe (или использовать polite live-регион для по-настоящему динамического статуса). Добавить Jest-проверки `aria-describedby` на триггере и `role="tooltip"` на оверлее.

**TIP-A11Y-02 · `ignoreTooltipPointerEvents` по умолчанию `true` — каждый hover-тултип «прозрачен» для кликов и ненаводим (WCAG 1.4.13 _hoverable_ проваливается в конфигурации по умолчанию)** — `tooltip.component.ts:167` (дефолт), `:434-436` (push класса панели), `:358-360` (overlayConfig).
`ignoreTooltipPointerEvents = input<boolean>(true)`, и `ngAfterViewInit` пушит `cdk-overlay-pane_ignore-pointer-events` в классы панели, так что по умолчанию у pane `pointer-events: none`. WCAG 1.4.13 требует, чтобы содержимое, вызванное указателем, было наводимым («указатель можно переместить на дополнительное содержимое без его исчезновения»); с отключёнными pointer events пользователь экранной лупы, двигающийся к тултипу, чтобы прочитать его, никогда на него не встанет — `mouseleave` триггера срабатывает, и тултип прячется под указателем. Это дефолт каждого hover-тултипа (частичная компенсация: opt-in `hideWithTimeout` держит его открытым при пересечении; один верификатор голосовал за P2 на этом основании — P1 сохранена 2:1 как провал конфигурации по умолчанию). Вторичная гигиена: push — мутация массива `overlayConfig.panelClass` на месте, полагающаяся на однократность `ngAfterViewInit` до первого `createOverlay`; popover вместо этого пересобирает конфиг в геттере.
**Исправление:** перевернуть дефолт в `false` (или спарить его с hover-персистентностью, чтобы указатель мог встать на тултип), оставить click-through как задокументированный opt-in с оговоркой про 1.4.13; вычислять `panelClass` иммутабельно из сигнала в геттере/`computed` вместо push в лайфсайкле.

**TIP-A11Y-03 · Hover-тултип нельзя закрыть Escape — единственный обработчик Escape висит на несфокусированном триггере (провал WCAG 1.4.13 _dismissable_) (shared)** — `pop-up-trigger.ts:335-339`; `tooltip.component.ts:134`; `tooltip.en.md` (список триггеров закрытия).
Единственная обработка Escape — `keydownHandler`, привязанный к host `(keydown)` триггера: `if (this.isOpen && event.keyCode === ESCAPE) this.hide()`. События клавиатуры приходят только сфокусированному элементу, поэтому при дефолтном триггере `hover, focus` наведение на нефокусируемый host (`<span kbqTooltip>`, иконка) открывает тултип, пока фокус в другом месте; Escape уходит сфокусированному элементу, и тултип остаётся. Pane оверлея не в фокусе и не имеет обработчика keydown. Документация перечисляет только уход курсора/blur/scroll как механизмы закрытия, подтверждая пробел. Сценарий: большой тултип перекрывает соседний контрол; пользователь жмёт Escape; ничего не происходит. Один верификатор голосовал за P2 (тултипы, открытые клавиатурным фокусом, закрываются) — P1 сохранена 2:1, потому что проваливается именно дефолтный hover-режим.
**Исправление:** пока открыт любой тултип, слушать Escape на уровне документа (вне зоны, со снятием на hide/destroy) и/или подписаться на `overlayRef.keydownEvents()`; покрыть тестом, диспатчащим document-level ESCAPE над hover-тултипом.

**TIP-ARCH-01 · Чисто standalone-импорт `KbqTooltipTrigger` бросает `NullInjectorError` — NgModule несёт на себе scroll strategy (shared — 8 копий на репозиторий)** — `tooltip.component.ts:110` (токен), `:144` (необязательный inject), `tooltip.module.ts:14,17` (единственный провайдер).
`KBQ_TOOLTIP_SCROLL_STRATEGY` создан без `factory`/`providedIn`-значения по умолчанию, триггер инжектирует его не-опционально при конструировании, а единственный провайдер живёт в `KbqToolTipModule`. ### Скорректировано при проверке

Ни одна находка не опровергнута полностью; восемь утверждений скорректированы при состязательной верификации:

1. **Серьёзность и цитата TIP-BUG-01** — понижена P1→P2: `hideWithTimeout` по умолчанию `false`, так что busy-loop `interval(0)` — opt-in и instance-scoped, а не дефект конфигурации по умолчанию или всего времени жизни приложения. Цитируемый воспроизводящий пример был неверен: `tooltip-hide-with-timeout-example.ts` вовсе не ставит `hideWithTimeout`; настоящий внутрирепозиторный репродюсер — `tooltip-interactive-example.ts:18`. Подутверждение «первый тик срезает грейс-период» сужено — hover-фильтр блокирует эмиссию до mouseleave.
2. **TIP-TEST-01 понижена P1→P2** — общий синглтон `openTime` даёт ложное покрытие тайминга, но скрываемое им поведение — задуманный UX, так что планка P1 («тестовая инфраструктура маскирует отгруженный баг») не достигнута.
3. **Механизм TIP-BUG-05 скорректирован** — заявленный путь «сеттер offset → updateData» не существует (у offset нет сеттера); настоящий дефект в том, что `arrow`/`offset` — плоские поля, отсутствующие в самодельном `ngOnChanges`, а потому полностью инертные при открытом тултипе.
4. **TIP-LIFE-01 сужена** — половина «(and `afterHidden`)» опровергнута собственными же доказательствами находки: `afterHidden` завершается через `onHideSubject.complete()` и чисто дерегистрируется; копится только `visibleChange`, и накопление ограничено временем жизни триггера.
5. **Ослаблено утверждение о вреде TIP-LIFE-03** — `reapplyLastPosition` CDK делает no-op на disposed-стратегии (гард `_isDisposed` сверен в `overlay-module.mjs`), так что неотслеживаемый таймер не может подействовать на разбираемый оверлей; остаточный дефект — гигиена, не гонка.
6. **TIP-TPL-08 развёрнута с «мёртвого кода»** — `border-radius` контейнера несёт нагрузку: он скругляет углы `box-shadow` вариантов arrowless и contrast-fade; слепое удаление регрессировало бы скругление тени (находка сохранена 2:1 в суженном виде).
7. **Понижено WCAG-утверждение TIP-A11Y-08** — фактический AA-контраст нельзя ни подтвердить, ни опровергнуть из одного SCSS; подтверждённое ядро — асимметрия композитинга стрелка/тело плюс пробел покрытия на уровне классов («grep ничего не находит» тоже скорректировано: spec проверяет `.kbq-tooltip_warning`, но для `modifier`, не для `color`).
8. **TIP-TPL-03 понижена P2→P3 и сужена** — тултипы navbar сегодня рендерятся корректно; рассуждение «9 px поверх маржина элемента» было неточным (маржин панели и 4-пиксельный arrowless-маржин элемента компонуются в раскладке оверлея; navbar передаёт `offset=0`). Сохранённая находка — связка + дублирование миксина + магическое число.

Особые мнения по серьёзности зафиксированы на трёх из четырёх P1 (по одному верификатору за P2 на TIP-A11Y-02 — компенсирует `hideWithTimeout`; TIP-A11Y-03 — фокус-тултипы закрываются; TIP-ARCH-01 — задокументированных standalone-использований нет) и на TIP-API-02 (один голос за P3); все четыре сохранены большинством 2:1. По тексту применены мелкие правки цитат: корень TIP-TPL-01 — `_tooltip-theme.scss:18-20` (не `:23`); тест disabled в spec открывает программно через `show()`, а не mouseenter-идиомой; `components-dev/tooltip/styles.scss` переопределяет CSS-свойство, а не токен; вводящий в заблуждение tick TIP-TEST-06 — в `:101`.

## 5. Стратегия верификации

**Общие ворота (на фазу):**

- `npx jest packages/components/tooltip/tooltip.spec.ts`
- Для любого изменения `core/pop-up` или поведения триггера — зависимые сьюты: `npx jest packages/components/popover packages/components/select packages/components/title packages/components/form-field packages/components/notification-center` (последовательно), либо полный `yarn run unit:components`
- `npx playwright test packages/components/tooltip/e2e.playwright-spec.ts` (после однократного `yarn run e2e:setup`)
- `yarn run eslint && yarn run stylelint && yarn run prettier`
- `yarn run build:components && yarn run check-api` — сначала сборка (гвард читает `dist/*.d.ts`); `approve-api` — только при намеренном изменении поверхности (фаза 3)

**Фаза 1 (P1):** прогон AXE на открытом тултипе (проверки role/name проходят); Jest-проверки `aria-describedby` на триггере, `role="tooltip"` + id на панели и повторного describe при смене контента; document-level ESCAPE, отправленный над hover-открытым тултипом на нефокусируемом хосте, закрывает его; тест hover-персистентности — перенос указателя с триггера на панель, панель остаётся открытой (сегодня падает при click-through дефолте); TestBed, импортирующий только `KbqTooltipTrigger`, создаётся без `NullInjectorError`. Ручной проход: NVDA/VoiceOver озвучивают текст тултипа при фокусе; `yarn run dev:tooltip` → указатель может встать на hover-тултип. Переутвердить Playwright-скриншоты, если переворот дефолта меняет визуал: `npx playwright test packages/components/tooltip/e2e.playwright-spec.ts --update-snapshots`, отсмотреть диффы light+dark перед коммитом.

**Фаза 2 (P2):** fakeAsync-регрессии — после энейблера TIP-TEST-01: первый показ отсутствует на `tick(399)` и присутствует на `tick(400)`; с `hideWithTimeout` + `kbqLeaveDelay=1000`: уход и возврат на t=500 → всё ещё открыт на t=1500 (сегодня падает); проверка отсутствия `interval(0)` (период вотчдога ≥ разрешённой задержки); смена `[kbqTooltipArrow]`/`[kbqTooltipOffset]` при открытом тултипе обновляет DOM без переоткрытия (сегодня падает); `placementPriority` цел после pointer-relative показа (сегодня падает); закреплён приоритет одновременных `kbqTooltipDisabled` + `forDisabledComponent`; focus-после-mousedown НЕ открывает (страхует рефакторинг TIP-A11Y-04); `visibleChange`/`placementChange` шпионятся со счётом эмиссий; destroy внутри leave-окна не вызывает поздний `hide()`. Визуал: решение по теням TIP-TPL-01 переутверждается скриншот-диффами.

**Фаза 3 (API/доки):** дифф `check-api` показывает только намеренные типизационные изменения (`unknown`, `KbqPopUpPlacementValues`, типизированный `updateClassMap`); старые биндинги алиасов по-прежнему компилируются в потребительской фикстуре; сборка доков рендерит новую таблицу API на обоих языках (`yarn build:docs-examples-module` при изменении примеров).

**Фаза 4 (полировка/дорожная карта):** `yarn run styles:build-all` после работ с токенами/SCSS; проверка эмуляции reduced-motion после приземления миграции анимаций (никакой scale-анимации при `prefers-reduced-motion: reduce`); скриншот-дифф arrowless/contrast-fade после консолидации TIP-TPL-08 подтверждает сохранение скругления углов тени. Полная регрессия перед мержем каждого пакета: `yarn run unit:components`, затем `yarn run e2e:components` (последовательно, никогда параллельно).

## Приложение A — Методология ревью

Ревью подготовлено 8 параллельными агентами-измерениями — корректность и баги, доступность, RxJS/жизненный цикл, производительность, архитектура и соглашения, API и типы, тесты, шаблоны/стили — каждый читал пакет tooltip и исходники `core/pop-up` напрямую на HEAD `c183a1bb`, а прежние находки из `REVIEW.md` и `REVIEW.popover.md` получал как зацепки для подтверждения, опровержения или пересмотра области (не для копирования). 86 сырых находок дедуплицированы агентом-слиянием по правилу атрибуции категорий из ревью popover (видимое пользователю неверное поведение → BUG независимо от измерения-источника; гигиена teardown → LIFE; a11y с i18n-корнем → A11Y), что дало 50 канонических пунктов. Каждый канонический пункт затем состязательно проверяли 3 независимых верификатора с непересекающимися линзами — опровержение (активно опровергнуть по исходникам), воспроизводимость/влияние (проследить конкретный рантайм-сценарий, сверяя внутренности CDK/Angular/RxJS в `node_modules`: `focus-monitor.d.ts` для утверждения о приватном поле, `overlay-module.mjs` для disposal-гардов, семантика RxJS `interval`, `@koobiq/design-tokens` для резолюции токенов) и аудит серьёзности и цитат (каждый `file:line` переоткрыт, серьёзности откалиброваны по общей шкале). Вердикты сведены большинством голосов: 0 из 50 пунктов опровергнуто полностью, 8 утверждений существенно скорректированы (§3, «Скорректировано при проверке»), 4 понижения серьёзности применены большинством (включая две заявленные P1), 4 особых мнения по серьёзности зафиксированы и раскрыты. Один канонический пункт — намеренная не-находка: P1-утечка scroll-подписки из ревью popover сверена с цепочкой tooltip и определена как неприменимая, что оставляет 49 действенных находок (0×P0, 4×P1, 16×P2, 29×P3). Оценки в §2 выводятся из числа P1 и хвоста серьёзностей каждого измерения с поправками на системные паттерны и проверенные сильные стороны — по рубрике ревью popover.
