# 3. Один согласованный способ подключения стилей в документации

**Приоритет:** P1 · **Где:** docs · **PR:** `docs: describe one way to include the tokens, the theme and the icons`

> Из разбора внешнего отзыва об использовании UI-кита. Состояние на 2026-10-08, `main` @ `7c3761794`.
> Все задачи — в [README](README.md).

**Проблема.** Инструкции противоречат друг другу и сами порождают ошибки, о которых пишет отзыв:

- `theme.css` в установке подключается через `angular.json` (`docs/guides/installation.ru.mdx:63`), в темизации — через
  `@use` в своём файле стилей (`docs/guides/theming.ru.mdx:22`). Сделать оба — получить стили дважды;
- установка подключает только светлые токены, темизация — светлые и тёмные;
- темизация велит удалить компонентные токены «из ваших копий» `css-tokens*.css` (`theming.ru.mdx:235`), хотя эти
  файлы берутся прямо из пакета, и подключить их без компонентных токенов нельзя;
- шаблон StackBlitz (`apps/docs/src/assets/stackblitz/angular.json:34–41`) тоже на старом наборе;
- сайт документации сам подключает устаревшие skeleton-токены из пакета (`apps/docs/src/main.scss:3–4`), хотя у skeleton
  в библиотеке свои токены.

**Что сделать** (EN и RU одинаково):

- один способ подключить `theme.css` и одна ссылка на него из темизации;
- светлые и тёмные токены из того же набора, что ставит `ng add` ([задача 2](02-ng-add-web-new-tokens.md));
- раздел «Что не нужно делать»: не копировать шрифты и иконки в `assets` (CLI сам забирает файлы из `url()`
  подключённого CSS), не подключать `theme.css` повторно в lazy-модулях и библиотеках, не подключать
  `css-tokens-font.css`;
- переписать абзац на `theming.ru.mdx:235`;
- перевести шаблон StackBlitz на тот же набор, убрать skeleton-импорты из `apps/docs/src/main.scss` и проверить
  skeleton на сайте.

**Готово, когда** установка, темизация, `ng add` и StackBlitz перечисляют один и тот же набор файлов, а `cspell`,
`docs:build` и `check-llms` зелёные.
