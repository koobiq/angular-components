# 9. RFC: как объявлять дефолты компонентных токенов

**Приоритет:** P3 · **Где:** все `*-tokens.scss`

> Из разбора внешнего отзыва об использовании UI-кита. Состояние на 2026-10-08, `main` @ `7c3761794`.
> Все задачи — в [README](README.md).

**Проблема.** Компонентные токены объявлены на селекторе компонента, а не в `:root`: всего 1880 деклараций
в 61 файле `*-tokens.scss`. Из-за этого:

- все декларации попадают на каждый экземпляр компонента — это шум в DevTools;
- переопределить токен в `:root` нельзя — гайд это прямо признаёт (`docs/guides/theming.ru.mdx:106`);
- правила переопределения разные: `:where()` (нулевая специфичность) есть только в 16 файлах из 61, в остальных 45
  селектор — обычный класс.

**Варианты.**

- **A. Привести всё к `:where()`.** Дешёво, безопасно (специфичность только снижается), переопределение одинаковое у всех
  компонентов. `:root` по-прежнему не работает.
- **B. Дефолт как запасное значение в месте использования:** `color: var(--kbq-alert-title-color, var(--kbq-foreground-contrast))`.
  Деклараций на элементах нет, токен можно задать на любом предке, включая `:root`. Минусы: дефолт повторяется в каждом
  месте использования, его не видно в DevTools, нужен список токенов в документации. Так уже сделано у токенов scrollbar.
  Примечание: в отзыве синтаксис неверный — `var(--a, --b)` подставит строку `--b`, нужно `var(--a, var(--b))`.

**Результат RFC:** выбранный вариант, план по компонентам, правка гайда по темизации. Вариант B — breaking для тех, кто
переопределяет токены селектором слабее текущего: нужны миграция или предупреждение и раздел в гайде.

**Проверка** — файлы токенов без :where():

```bash
grep -L ':where(' packages/components/*/*-tokens.scss packages/components/*/*/*-tokens.scss
```
