> Подготовлено автоматическим многоагентным ревью (8 измерений + состязательная проверка каждой находки; все P0/P1 дополнительно проверены вручную по исходникам и установленным адаптерам дат / CDK). ## 1. Краткое резюме

- **Главный блокер — баг класса «краш».** Любое уведомление, чью строку `date` настроенный `DateAdapter` не может распарсить (для Luxon это включает собственный отображаемый формат библиотеки `dd.MM.yyyy` — `parse(value, '')` принимает только ISO/RFC2822/SQL), заставляет `makeGroup` вызвать `format(null)`, который **бросает исключение внутри `map` потока `groupedItems`, «убивает» Observable и навсегда оставляет панель пустой** — переоткрытие переподписывается на тот же мёртвый поток (NC-BUG-01). Соседний `compareByDateDesc` защищается ровно от этого случая — инвариант был известен, но не применён.
- **Клавиатурная доступность блокирует релиз.** Панель вычисляет `isTrapFocus`, но ловушка фокуса нигде не применяется (прежняя A11Y-24 — всё ещё открыта; Tab уходит из оверлея, а Escape, повешенный на host панели, после этого умирает), а кнопки удаления элемента/группы — `display: none` до `:hover`/`:focus-within`, при этом они **единственный** фокусируемый элемент своего контейнера, так что клавиатурный фокус их никогда не раскроет: **пользователь с клавиатуры не может ничего удалить** (NC-A11Y-01/02). Иконочные кнопки шапки (закрыть, удалить всё) не имеют доступного имени и даже тултипа (NC-A11Y-03).
- **Класс утечек «на каждое переоткрытие» из прежнего ревью структурно устранён.** Компонент панели создаётся на каждое открытие и уничтожается на каждое закрытие (ComponentPortal dispose), все его подписки ограничены `takeUntilDestroyed` — прежние BUG-10/BUG-33 закрыты. Осталась одна дорожка **destroy-while-open**: вложенная подписка `closingActions()` снимается только по `visibleChange(false)`, который при уничтожении триггера никогда не эмитится, — подписка остаётся навсегда и бросает `TypeError` на каждом последующем скролле где угодно в приложении (NC-LEAK-01; тот же паттерн в app-switcher).
- **Протокол «не закрывать по внутреннему скроллу» отравляет всё приложение.** Обработчик мутирует общие экземпляры `CdkScrollable`, эмитируемые корневым `ScrollDispatcher` (`kbqPopoverPreventHide`/`type` записываются и никогда не сбрасываются), без проверки принадлежности — после единственного открытия центра close-on-scroll молча перестаёт работать у *других* оверлеев (popover `closeOnScroll`) на любом скроллируемом контейнере (NC-BUG-02).
- **DI-топология подрывает собственный standalone-мандат репозитория.** У токена scroll-strategy нет фабрики по умолчанию, а его провайдер (плюс переопределения focus-trap) живёт только в легаси `KbqNotificationCenterModule` — чисто standalone-импорт падает с `NullInjectorError`: NgModule несущий, и все 6 docs-примеров вынуждены идти через него (NC-ARCH-01). Сервис одновременно `providedIn: 'root'` **и** пере-провайдится этим модулем — задокументированная ловушка двух экземпляров, которую обходит собственный spec пакета (NC-ARCH-02).
- **В производительности одно главное исправление.** `@for (… track group)` трекает свежесозданные объекты групп по идентичности, поэтому каждый push/удаление/подгрузка страницы сносит и перестраивает DOM **всего** списка (правдоподобно 200–500 мс на push при масштабах бесконечного скролла); сохранение уже вычисленного ключа `yyyyMMdd` на группе и трекинг по нему превращает это в инкрементальное обновление (NC-PERF-01). Рядом: даты перепарсиваются O(n log n) на каждую эмиссию, а геттер `unreadItemsCounter` аллоцирует новый Observable на каждое чтение, переподписывая async pipe каждый цикл CD (NC-PERF-02/03).
- **Группировка по датам работает только на Luxon.** Ключ группы строится *отображаемым форматированием* `'yyyyMMdd'`; в Moment-адаптере `dd` — это краткое имя дня недели, так что 2026-07-04 и 2026-07-11 получают общий ключ `202607Sa` и сливаются в одну группу (NC-BUG-03). Группировать нужно по `getYear/getMonth/getDate`.
- **Что сильно.** Дизайн потока бесконечного скролла по-настоящему хорош (audit, дедупликация, тройной гейт, дозапрос коротких страниц через `pairwise`, удержание фокуса при retry), а его тестовый блок образцовый — у каждого гейта есть отдельный негативный тест с проверкой по DOM. Соглашения почти идеальны (standalone, OnPush, нативный control flow, host-объекты, `inject()`, без ngClass/ngStyle), темизация на 100% токенная, шаблоны чисто неймспейснуты. *Качество* тестов выше среднего по репозиторию; разрыв — в *широте* покрытия (клавиатура/фокус, inputs/outputs триггера, e2e-состояния).

## 3. Приоритизированные находки (дедуплицированы, проверены)

### P0 — Блокеры релиза

**NC-BUG-01 · Нераспарсиваемая `date` рушит `groupedItems` — панель навсегда пустая** — `notification-center.service.ts:241-242`, также `notification-item.ts:67`.
`makeGroup` вызывает `adapter.parse(item.date, '')` → в Luxon-адаптере пустой формат уходит в фолбэк ISO/RFC2822/SQL и возвращает **`null`** для всего остального (включая `dd.MM.yyyy`); `adapter.format(null, 'yyyyMMdd')` затем бросает (`DateTime: Cannot format invalid date.`; Moment-адаптер бросает аналогично). Исключение происходит внутри `map` потока `groupedItems` и **«убивает» Observable**: подписка `| async` в `notification-center.html:63` умирает, список пуст, переоткрытие переподписывается на тот же ошибочный поток. Тот же незащищённый parse-затем-format рушит отрисовку времени элемента (`notification-item.ts:67`). `compareByDateDesc` (`:260-262`) от null защищается — инвариант был известен.
**Исправление:** валидировать результат парсинга в `makeGroup` и сеттере `data` элемента (пропускать или складывать в группу «неизвестная дата»; для времени — фолбэк на сырую строку); добавить `catchError` (или try на элемент), чтобы один плохой элемент не убивал поток; задокументировать допустимый формат `date` (см. NC-API-08); регрессионные тесты с мусорной датой и `dd.MM.yyyy`.

**NC-A11Y-01 · Ловушка фокуса вычисляется, но не применяется — Tab уходит из открытой панели (прежняя A11Y-24, всё ещё открыта)** — `notification-center.ts:151`, `:282-284`, `:498`.
`isTrapFocus` выставляется в `true` при каждом открытии (`trigger` — `'click, keydown'`), но его никто не потребляет: в `notification-center.html` нет `cdkTrapFocus` (единственный потребитель паттерна в репозитории — `popover.component.html:5`), а `notification-center.module.ts:18-19` даже поставляет провайдеры `ConfigurableFocusTrapFactory`/`EmptyFocusTrapStrategy` для ловушки, которая никогда не создаётся. Оверлей висит в конце `<body>`: Tab за последним контролом покидает панель, пока она открыта; Escape повешен только на host панели (`:111`) и перестаёт работать, когда фокус снаружи.
**Исправление:** повторить popover — обернуть контент панели в `[cdkTrapFocus]="isTrapFocus"` (рассмотреть `focusFirstTabbableElement()`); покрыть jest-тестами ловушку + Escape.

**NC-A11Y-02 · Кнопки удаления элемента и группы недостижимы с клавиатуры (`display: none` — замкнутый круг)** — `notification-item.scss:16-25`, `:116-123`; `notification-center.scss:72-84`.
Обе кнопки — `display: none`, раскрываются по `:hover`/`:focus-within` контейнера, но `display: none` исключает их из tab-порядка, а они — **единственный** фокусируемый элемент своего контейнера (у саб-хедера всегда; у элемента — если потребитель не спроецировал фокусируемые `actions`), так что `:focus-within` с клавиатуры недостижим. Пользователь с клавиатуры не может удалить ни уведомление, ни группу и вообще не может добраться до кнопок (WCAG 2.1.1). Вдобавок они иконочные с метками только в тултипах (см. NC-A11Y-03/09).
**Исправление:** держать кнопки фокусируемыми (визуально приглушать через `opacity`/clip вместо `display: none`) и раскрывать по `:focus-visible` самой кнопки; спарить hover-подложку темы с фокусным двойником (`notification-item.scss:141-143`); добавить `aria-label`.

### P1 — Высокий приоритет

**NC-A11Y-03 · У иконочных кнопок шапки нет доступного имени (провал AXE `button-name`)** — `notification-center.html:4-20` (переключатель silent mode), `:24-33` (удалить всё), `:38-47` (закрыть).
Все три содержат только глифы `<i kbq-icon>`; у «удалить всё» и «закрыть» нет ни `aria-label`, **ни тултипа**. Первый же элемент, получающий фокус при открытии (`switcher().focus()`, `notification-center.ts:198`), объявляется безымянной кнопкой. В локализации нет ключей для «закрыть»/«удалить всё» — строки нужно добавить (`core/locales/*.ts`, секция `notificationCenter`).
**Исправление:** добавить `[attr.aria-label]` из `localeData` всем трём (плюс кнопкам удаления группы/элемента); расширить локаль недостающими ключами.

**NC-A11Y-04 · У панели нет роли, доступного имени и объявления** — `notification-center.ts:108-112`; `notification-center.html:1-3`.
На host — только биндинг класса и `keydown.escape`; нет `role="dialog"` (или `complementary`), нет `aria-labelledby` на заголовок «Уведомления» (у него нет `id`), нет `aria-modal`. Фокус телепортируется в оверлей при открытии без какого-либо контекста для пользователей скринридеров.
**Исправление:** `role="dialog"` + `aria-labelledby` на host; `id` заголовку; связать с NC-A11Y-01, чтобы паттерн диалога был цельным.

**NC-LEAK-01 · Destroy-while-open теряет вложенную подписку `closingActions` — затем TypeError на каждом скролле во всём приложении** — `notification-center.ts:470-479`.
Вложенная подписка (`// eslint-disable-next-line rxjs-x/no-nested-subscribe`) снимается только в ветке `visibleChange(false)`. Уничтожение триггера при открытой панели (смена маршрута) `false` не эмитит (`KbqPopUpTrigger.ngOnDestroy` лишь освобождает оверлей, `pop-up-trigger.ts:276-282`); dispose оверлея завершает `outsidePointerEvents`/`backdropClick`, но `scrollDispatcher.scrolled()` — корневой синглтон-поток, который не завершается никогда, — merge-подписка живёт вечно, удерживает документный слушатель скролла и на следующем скролле любого зарегистрированного контейнера разыменовывает `this.instance.setStickPosition()` при `instance === null` → повторяющийся `TypeError` вне зоны. Идентичный паттерн — `app-switcher.ts:541-549`.
**Исправление:** `this.visibleChange.pipe(switchMap((visible) => visible ? this.closingActions() : EMPTY), takeUntilDestroyed(this.destroyRef)).subscribe(...)` (заодно убирает eslint-disable) + `this.instance?.setStickPosition()`. Отзеркалить в app-switcher.

**NC-BUG-02 · Обработчик внутреннего скролла навсегда отравляет общие `CdkScrollable` — ломает close-on-scroll другим оверлеям** — `notification-center.ts:470-477`.
`scrollDispatcher.scrolled()` эмитит *один и тот же живой экземпляр `CdkScrollable`* всем подписчикам; обработчик пишет в него `event['kbqPopoverPreventHide'] = true; event['type'] = 'click'` и никогда не сбрасывает. Гейт `event['scrollDispatcher']` совпадает с **любым** CdkScrollable (проверки принадлежности нет), поэтому: (1) скролл любого постороннего контейнера при открытой панели считается «внутренним» и не закрывает её; (2) однажды помеченный долгоживущий контейнер навсегда удовлетворяет базовый гейт скрытия (`pop-up-trigger.ts:655`), молча отключая close-on-scroll у *других* оверлеев семейства pop-up (например, popover `closeOnScroll`, `popover.component.ts:545`) даже после закрытия центра.
**Исправление:** не мутировать payload — фильтровать по принадлежности (сравнивать элемент пришедшего scrollable с элементом панели) внутри собственной подписки триггера; если протокол флагов должен остаться — сбрасывать флаги при закрытии и дать `KbqPopUpTrigger` явный хук `shouldPreventHide(event)` **(shared)**.

**NC-PERF-01 · `track group` по идентичности объекта перестраивает весь DOM списка на каждую эмиссию** — `notification-center.html:63`, `:86`; корень — `notification-center.service.ts:92-106`.
`groupedItems` создаёт свежие объекты групп на каждую эмиссию `originalItems` (каждый `push`/`remove`/`removeGroup`/`removeAll`/`items=`), поэтому `track group` уничтожает и пересоздаёт embedded view каждой группы — вместе с вложенным `@for (item …; track item)` и каждым `<kbq-notification-item>` (триггеры тултипов, иконки, подписки read-state, перепарсинг даты в сеттере `data`), хотя ссылки на элементы при `push` стабильны. Один push при открытой панели = снос+перестройка всего списка: десятки мс при ~100 элементах, правдоподобно 200–500 мс при 1000 (целевой масштаб бесконечного скролла) — каждая подгрузка страницы перестраивает всё уже загруженное. Hover/tooltip-состояние каждый раз теряется.
**Исправление (главное):** сохранить уже вычисленный дневной ключ на объекте группы (сейчас он выбрасывается через `Object.values`) и `track group.id`; внутренний `track item` оставить или перевести на `track item.id` **после** NC-BUG-06 (сегодняшние коллизии id дадут NG0955). В перспективе: `cdk-virtual-scroll` при неограниченном росте (осложнено sticky-заголовками дней).

**NC-ARCH-01 · Чисто standalone-импорт падает: NgModule — несущий** — `notification-center.ts:69-71`, `:315`; `notification-center.module.ts:16-21`.
У `KBQ_NOTIFICATION_CENTER_SCROLL_STRATEGY` нет фабрики по умолчанию, а провайдер живёт только в `KbqNotificationCenterModule` — потребитель, следующий standalone-мандату репозитория (`imports: [KbqNotificationCenterTrigger]`), получает `NullInjectorError` при создании директивы. Модуль также несёт переопределения focus-trap (`FocusTrapFactory`/`FOCUS_TRAP_INERT_STRATEGY`), так что два пути импорта ведут себя по-разному. Все 6 docs-примеров вынуждены импортировать модуль. Тот же паттерн у tooltip/popover — чинить консистентно.
**Исправление:** дать токену `factory:` по умолчанию (`new InjectionToken(..., { factory: () => inject(Overlay).scrollStrategies.reposition({ scrollThrottle: 20 }) })`) или провайдить на `providers` директивы; провайдеры focus-trap вынести в функцию `provideKbqNotificationCenter()` либо в `providers` компонента, чтобы standalone === module.

**NC-ARCH-02 · Сервис провайдится дважды: `providedIn: 'root'` + `providers` модуля — ловушка двух экземпляров** — `notification-center.service.ts:42` vs `notification-center.module.ts:20`.
Standalone-компонент, импортирующий NgModule, получает провайдеры модуля в собственном standalone-инжекторе — свой экземпляр сервиса, — тогда как код уровня приложения (задокументированный паттерн `push()` из сервиса) говорит с корневым: отправленные уведомления не доходят до видимого центра, счётчики расходятся. Собственный spec пакета документирует обход (`notification-center.spec.ts:78-79`: «The rendered center resolves the service from the module provider … so drive that exact instance»).
**Исправление:** удалить `KbqNotificationCenterService` из `providers` модуля; оставить `providedIn: 'root'`. Отметить в changelog (поведенческое исправление).

**NC-BUG-03 · Ключ группы `'yyyyMMdd'` специфичен для Luxon — Moment-адаптер группирует по дню недели** — `notification-center.service.ts:242`.
Ключ строится *отображаемым форматированием*. Moment получает строку как есть (`format()` → `newDate.format(displayFormat)`), где `dd` — **краткое имя дня недели**, а не день месяца: 2026-07-04 (сб) и 2026-07-11 (сб) получают ключ `202607Sa` и сливаются в одну группу под датой первого элемента. На Luxon работает по совпадению.
**Исправление:** не строить ключи через display-форматы — использовать `adapter.getYear/getMonth/getDate(parsedDate)` (адаптер-независимо), например `${year}-${month}-${date}`. Добавить тест группировки на Moment-адаптере.
