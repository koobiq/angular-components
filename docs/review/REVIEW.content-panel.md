# Koobiq `content-panel` Component — Code Review & Improvement Plan

> Scope: `packages/components/content-panel` (8 exported classes in one file, 6 SCSS files, Jest spec, e2e fixture + Playwright spec, en/ru guides, API guard report, docs examples, dev app) · Commit `b665e503` · 2026-08-28
> Generated by a multi-dimension review (architecture, RxJS/lifecycle, correctness, accessibility, performance, public API, templates & styles, tests, docs) with manual verification of every finding against the source. 16 findings confirmed (P0×0, P1×3, P2×8, P3×5); 6 candidate findings refuted during verification (see Appendix A). This document is a review + roadmap; no source is modified by it.

## 1. Executive Summary

`content-panel` is a *non-modal, inline* slide-out panel: `KbqContentPanelContainer` hosts the page content in a scrollbar, animates its `margin-right` aside, and reveals an absolutely positioned panel on the right ([content-panel.ts](../../packages/components/content-panel/content-panel.ts), 410 lines, 8 exported classes). The panel itself is a composition kit — `kbq-content-panel` + `-aside` / `-header` (+ `[kbqContentPanelHeaderTitle]` / `[kbqContentPanelHeaderActions]`) / `-body` / `-footer`. It is used by 2 documented examples, the dev app and 2 e2e fixtures; it does not compose with `sidepanel` or `splitter` in any way (`sidepanel` is an overlay/service component with a `FocusTrapFactory`, `content-panel` is inline flow layout; no shared code, no cross-imports).

- **The most serious defect is accessibility, and it is structural.** The panel appears and disappears with no focus management at all: nothing captures the previously focused element on open, nothing focuses the panel, and the close button destroys *itself* when clicked — `close()` flips `openedState` and the whole `@if` subtree (button included) is torn down, dropping focus onto `<body>` (CP-A11Y-01). On top of that the panel has no `role` and no accessible name, and `[kbqContentPanelHeaderTitle]` only applies `title` typography via CSS — in all five shipped usages the panel heading is a plain `<div>`, invisible to heading and landmark navigation (CP-A11Y-02).
- **The opened state has two sources of truth and they can desync permanently.** `opened` is a plain `input()` mirrored into a private `openedState` signal through `toObservable(...).subscribe(...)`; once the user closes the panel, a one-way `[opened]="true"` binding can never reopen it because the input value never *changes* (CP-BUG-01). AGENTS.md mandates `model()` for two-way bound properties, and two `// TODO: Should use linked signal` comments already admit the shape is wrong.
- **Geometry and animation are subtly inconsistent.** `width` is never validated against `minWidth`/`maxWidth`, so `width="1000" maxWidth="800"` reserves a 1016 px content margin next to an 800 px panel (CP-BUG-03), and the two animation triggers have their durations crossed — the content margin animates for 125 ms while the panel slides in for 150 ms, and vice versa on close (CP-BUG-02).
- **Style ownership is inverted.** `content-panel-tokens.scss` declares the *container's* tokens but is loaded by `KbqContentPanel`, the opposite of the convention every sibling package follows (`sidepanel`, `modal`, `badge` all co-locate) (CP-CSS-01).
- **Test coverage does not reach the risky parts.** 10 Jest cases include one tautology that never touches the component and one strict duplicate; nothing covers the resizer, `openedChange`, `disableResizer`, focus or the animation states, and the Playwright suite only ever renders the panel already open (CP-TEST-01).

Genuine strengths: the component is fully signal-based and modern (`input()`/`output()`/`computed()`/`contentChild()`/`viewChild()`, `OnPush` on every component, native `@if`/`@for`, `host` object instead of decorators, no `window` access); it correctly sources the close button's accessible name from `kbqInjectA11yLocaleConfiguration()` as AGENTS.md requires; both RxJS subscriptions are torn down with `takeUntilDestroyed()`; the overflow-shadow wiring reuses the core `KbqOverflowShadowContainer` rather than reimplementing scroll math; and the Playwright suite includes three real behavioural assertions about the shadows (not just screenshots), which is above average for this repo.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

None.

### P1 — High

**CP-A11Y-01 · Opening and closing the panel strands keyboard focus** — `content-panel.ts:96-106, 225-244, 373-378, 402-409`.
Nothing in the package touches focus: a repo-wide grep of the component source for `focus`, `tabindex`, `FocusMonitor` or `FocusTrap` returns zero hits (the only a11y attribute in the whole package is the close button's `[attr.aria-label]` at `content-panel.ts:100`). On open — via `open()`, `toggle()` or the `opened` input — focus stays wherever it was, so a keyboard user who activates a "preview row" trigger has to Tab through the entire remaining page content to reach the panel that just appeared. On close the failure is worse and fully deterministic: the close button lives inside `@if (openedState())` (`content-panel.ts:225-244`), its own `(click)` handler calls `contentPanelContainer.close()` (`:103`), `close()` sets `openedState` to `false` (`:376`), the embedded view is destroyed and the focused button is removed from the document — focus resets to `<body>`, i.e. the user is silently returned to the top of the document with no announcement. Pressing `ESCAPE` while focus is inside the panel does the same (`:402-409`). AGENTS.md states accessibility as a mandate and names focus management explicitly ("It MUST follow all WCAG AA minimums, including focus management…"); this is WCAG 2.4.3 (Focus Order). Note this is *not* an automated AXE failure — axe cannot observe where focus went — so a jest-axe pass would not catch it. `sidepanel`, the closest sibling, does address this: it provides `ConfigurableFocusTrapFactory` and exposes `trapFocus`/`trapFocusAutoCapture` config (`sidepanel.module.ts:1, 35`, `sidepanel-config.ts:24, 27`).
**Fix:** in `KbqContentPanelContainer`, inject `FocusMonitor`/`_getFocusedElementPierceShadowDom` and record `document.activeElement` at the start of `open()`/`toggle()`-to-open; after the panel view is created (`afterNextRender` or an `effect` on `openedState`) move focus into the panel — either onto the first tabbable element via CDK `FocusTrapFactory().focusInitialElement()` (without `trapFocus`, since this panel is explicitly non-modal) or onto the panel host given `tabindex="-1"`. In `close()`, if `document.activeElement` is inside the panel, restore focus to the recorded element via `focusMonitor.focusVia(el, origin)` so the focus ring is preserved (see `project_kbq_focus_ring_mechanism`); guard against the element having been removed. Add opt-outs (`autoFocus`, `restoreFocus`) mirroring `sidepanel-config.ts`. Guard with a Jest spec that focuses a trigger outside the panel, opens, asserts `document.activeElement` is inside `.kbq-content-panel`, clicks the close button and asserts focus is back on the trigger — and a Playwright scenario that Tabs to the close button, presses `Enter` and asserts `:focus` is not `body`.

**CP-A11Y-02 · The panel has no role, no accessible name, and its title is not a heading** — `content-panel.ts:69-76, 184-203`, `content-panel-header.scss:22-24`.
`KbqContentPanel`'s host block carries only `class: 'kbq-content-panel'` (`content-panel.ts:200-202`) — no `role`, no `aria-label`/`aria-labelledby`. `KbqContentPanelHeaderTitle` is a class-only marker directive (`content-panel.ts:69-76`) whose entire effect is the CSS rule `.kbq-content-panel-header-title { @include tokens.kbq-typography-level-to-styles-css-variables(typography, title); }` (`content-panel-header.scss:22-24`) — it styles text as a heading without making it one. Every shipped usage therefore renders the panel's title as a plain `<div>`: `e2e.ts:15`, `content-panel-overview-example.ts:23`, `content-panel-with-grid-example.ts:143`, `packages/components-dev/content-panel/module.ts:43` and `content-panel.spec.ts:46` — five of five. The user-visible impact: a screen-reader user cannot reach the panel by landmark navigation (no region), cannot reach its title by heading navigation (no heading), and gets no announcement that a new region appeared; the panel is an anonymous `<div>` that materialises mid-document. Like CP-A11Y-01 this is a WCAG judgement (1.3.1 Info and Relationships, 2.4.6 Headings and Labels), not an axe rule — axe does not flag a role-less custom element.
**Fix:** add `role: 'region'` (or `'complementary'`) plus `'[attr.aria-labelledby]'` to `KbqContentPanel`'s host block, and have `KbqContentPanelHeaderTitle` generate an id via CDK `_IdGenerator` (already used in `scrollbar.ts:1`) that the panel picks up from a narrow injection token; when no title directive is projected, fall back to a documented `ariaLabel` input on `kbq-content-panel`. Give `KbqContentPanelHeaderTitle` `'[attr.role]': "role() ?? 'heading'"` and an `[attr.aria-level]` input defaulting to `2`, so consumers who project a real `<h2>` can opt out. Document the accessible-name contract in `content-panel.en.md`/`.ru.md`. Cover with a Jest spec asserting `getByRole('region', { name: 'Title' })` resolves, and add `jest-axe` to the suite (5 packages already do — `accordion`, `app-switcher`, `button-toggle`, `list`, `navbar`).

**CP-BUG-01 · `opened` is mirrored into private state, so a one-way binding desyncs permanently** — `content-panel.ts:266, 271, 314, 324, 336-350, 355-378`.
`opened` is a plain `input()` (`:266`) paired with an `openedChange` output (`:271`) and mirrored into a private `openedState` signal seeded from the input's *default* (`:314`), kept in sync by `toObservable(this.opened).pipe(takeUntilDestroyed()).subscribe(...)` (`:336-342`). `open()`/`close()`/`toggle()` write `openedState` directly and emit `openedChange` (`:355-378`). With `[(opened)]` this round-trips correctly. With a **one-way** `[opened]="expr"` binding it does not: after the user closes the panel (close button or `ESCAPE`), `openedState` is `false` while `opened()` is still `true`; setting the parent expression back to `true` produces no *change*, Angular skips the input write, `toObservable` never emits, and the panel can never be reopened through the input. This is reachable in shipped code — `e2e.ts:11` binds a literal `[opened]="true"`, so once that fixture's panel is closed nothing can reopen it. AGENTS.md is explicit: "Use `model()` for two-way bound properties with `[(prop)]` syntax instead of pairing `input()` with `output()`", and the two `// TODO: Should use linked signal` comments (`:337`, `:344`) acknowledge the shape is wrong. The gap is invisible to the suite because the "two-way binding" spec (`content-panel.spec.ts:112-122`) sets the *host's* model and asserts the *host's* model without ever consulting the container.
**Fix:** replace `opened: input()` + `openedChange: output()` + `openedState: signal()` with a single `readonly opened = model(false, { transform: booleanAttribute })`; delete both `toObservable` subscriptions and both TODOs; have `open()`/`close()`/`toggle()` write `this.opened`; keep `isOpened` as `this.opened.asReadonly()` for the exported read-only handle. Note this removes `openedChange` from the API report, so it is a breaking change requiring an `ng-update` schematic entry (`packages/schematics`) — although `[(opened)]` consumers are unaffected. Do the same for `width`/`widthState` (`:302, 319, 344-349`) with `linkedSignal(this.width)`. Guard with a spec that binds `[opened]` one-way to a signal held at `true`, calls `container.close()`, then re-sets the signal to `true` and asserts the panel is rendered.

### P2 — Should fix

**CP-BUG-02 · The two animation triggers have their durations crossed** — `content-panel.ts:31-36, 38-52`.
`KBQ_CONTENT_PANEL_CONTAINER_PANEL_ANIMATION` is correct: `:enter` uses `Entering` (150 ms) with `DecelerationCurve` (`:41-44`), `:leave` uses `Exiting` (125 ms) with `AccelerationCurve` (`:46-50`). `KBQ_CONTENT_PANEL_CONTAINER_CONTENT_ANIMATION`, which animates the page content's `margin-right` in lockstep with that panel, has the durations the other way round: `'true => false'` (the panel is *leaving*) uses `KbqAnimationDurations.Entering` (`:34`), and `'false => true'` (the panel is *entering*) uses `KbqAnimationDurations.Exiting` (`:35`). Values verified in `core/animation/animation.ts:23-24` — `Entering = '150ms'`, `Exiting = '125ms'`. The curves are paired correctly, so this is a pure copy/paste inversion of the two duration constants: on open the content stops sliding 25 ms before the panel arrives, on close the content is still moving 25 ms after the panel has gone — a 17-20 % mismatch on every open/close, visible as the content "arriving early" and "trailing late" against the panel edge. It is invisible to the test suite: the Jest spec imports `NoopAnimationsModule` (`content-panel.spec.ts:3, 8`), and `playwright.config.ts:101` sets `reducedMotion: 'reduce'` for every context, so all committed screenshots capture the settled state.
**Fix:** swap the two duration constants at `content-panel.ts:34-35` so `'false => true'` uses `Entering`/`DecelerationCurve` and `'true => false'` uses `Exiting`/`AccelerationCurve`, matching `KBQ_CONTENT_PANEL_CONTAINER_PANEL_ANIMATION`. Since `reducedMotion: 'reduce'` makes this unobservable in Playwright, guard it with a Jest spec built on `BrowserAnimationsModule` + `TestBed.inject(AnimationBuilder)`, or simply assert the two trigger metadata objects declare the same duration for the same direction.

**CP-BUG-03 · `width` is never clamped to `[minWidth, maxWidth]`, desynchronising the content margin from the panel** — `content-panel.ts:295-309, 319, 329-334, 344-349, 383-387, 392-397`, `content-panel-container.scss:14-22`.
The three width inputs are declared independently with no cross-validation (`:295-309`). `widthState` is seeded from `width()` (`:319`) and re-set from it on every input change (`:344-349`) and on resizer double-click (`:383-387`) — always unclamped. Clamping exists in exactly one path, `handleResizerSizeChange` (`:392-397`), i.e. only for pointer drags. Meanwhile the rendered panel *is* clamped, because the template also binds `[style.min-width.px]`/`[style.max-width.px]` (`:230, 232`) and the element is `box-sizing: border-box` (`content-panel-container.scss:21`). The result is a split between the real panel width and the space reserved for it: `contentAnimationState` computes `marginRight: this.widthState() + 16` (`:329-334`), so `<kbq-content-panel-container width="1000" maxWidth="800">` renders an 800 px panel while pushing the page content 1016 px — a 216 px dead strip. The same happens whenever a consumer narrows `maxWidth` (or widens `minWidth`) after a drag, since `widthState` is not re-clamped when the bounds change. No spec covers it: `content-panel.spec.ts:188-203` sets `minWidth/width/maxWidth` to a consistent 222/333/444 and only asserts the three inline styles are echoed back.
**Fix:** make the resolved width a single `computed()` that clamps in one place — `Math.min(Math.max(widthState(), minWidth()), maxWidth())` — and read it from both `[style.width.px]` and `contentAnimationState`; drop the ad-hoc clamping in `handleResizerSizeChange` so the resizer just records the raw drag value. Additionally warn in dev mode (`ngDevMode`) when `width` falls outside `[minWidth, maxWidth]` or `minWidth > maxWidth`. Guard with a spec that sets `width` above `maxWidth` and asserts both the inline `width` and the computed `margin-right` of `.kbq-content-panel-container kbq-scrollbar` agree with `maxWidth`.

**CP-A11Y-03 · `ESCAPE` only closes the panel while focus is inside the container, but the guide states it unconditionally** — `content-panel.ts:252, 402-409`, `content-panel.en.md:23-31`, `content-panel.ru.md:23-31`.
The key handler is a host listener on the container element: `'(keydown.escape)': 'handleEscapeKeydown($event)'` (`content-panel.ts:252`). It therefore only fires for `keydown` events that originate inside the container subtree and bubble up. When the panel is opened programmatically from a control that lives *outside* the container (a toolbar above it, a row action in a separate header), or when the page loads with `[opened]="true"` and focus is still on `<body>` (exactly the `e2e.ts:11` configuration), `ESCAPE` reaches `document` without ever passing through the container and nothing happens. This interacts with CP-A11Y-01: because closing drops focus onto `<body>`, any subsequent keyboard interaction starts from outside the container. Both guides document the behaviour without qualification — "By default, the `ESCAPE` key closes the panel" (`content-panel.en.md:25`, `content-panel.ru.md:25`) — and neither mentions that `disableClose` also suppresses `ESCAPE` (`content-panel.ts:403`), even though the `disableClose` JSDoc does (`:274`). The three `ESCAPE` specs (`content-panel.spec.ts:157, 170, 184`) all dispatch the event directly on the container element, so they exercise the one path that always works and none of the paths that fail.
**Fix:** move the listener to the document via CDK `OverlayKeyboardDispatcher`-style handling, or subscribe to `fromEvent(document, 'keydown')` filtered on `ESCAPE` while `openedState()` is true (outside the zone, re-entering only on a match), keeping `event.stopPropagation()` so a `content-panel` inside a `kbq-modal` still wins over the modal — the documented `content-panel-with-grid-example.ts:121-122` nesting depends on that ordering. Update both guides to state the `disableClose` interaction. Add a spec that dispatches `ESCAPE` on `document.body` with the panel open and asserts it closes.

**CP-A11Y-04 · The resize handle is pointer-only and has no ARIA identity** — `content-panel.ts:234-241`, `resizer.ts:149-172, 296-309`.
The handle is a bare `<div class="kbq-content-panel-container__panel-resizer" [kbqResizer]="[-1, 0]">` with no `tabindex`, no `role`, and no keyboard handler (`content-panel.ts:235-240`); `KbqResizer` binds only `pointerdown`/`pointermove`/`pointerup`/`pointercancel`/`lostpointercapture` (`resizer.ts:151-169`). The double-click reset (`content-panel.ts:239, 383-387`) is likewise pointer-only. A keyboard or switch user therefore cannot change the panel width at all, and a screen reader sees an unlabelled empty `div` sitting between the content and the panel. WCAG 2.1.1 (Keyboard) has no "cosmetic enhancement" exemption. The gap is shared with `packages/components/resizer` rather than unique to this package, which is why it is P2 here and not P1.
**Fix:** in `packages/components/resizer`, add keyboard support to `KbqResizer` — `tabindex="0"`, `role="separator"`, `[attr.aria-orientation]` derived from `direction()` (valid on `role="separator"`, unlike `role="group"`), `aria-valuenow`/`aria-valuemin`/`aria-valuemax` fed by the host, and `ArrowLeft`/`ArrowRight` (± a step, ×10 with `PageUp`/`PageDown`), `Home`/`End` for min/max and `Enter` for the reset that `dblclick` performs today. In `content-panel`, wire `aria-valuenow` to the clamped width from CP-BUG-03 and source the accessible name from `kbqInjectA11yLocaleConfiguration()`, as the close button already does. Guard with a Jest spec driving `ArrowLeft` on the handle and asserting `widthState` moved, plus an axe assertion on the opened panel.

**CP-CSS-01 · The token block targets the container but is loaded by a different component** — `content-panel-tokens.scss:1-9`, `content-panel.ts:194-197, 246`.
`content-panel-tokens.scss` opens with `.kbq-content-panel-container { … }` and declares all eight component tokens there, including `--kbq-content-panel-resizer-width` which only the *container's* own stylesheet consumes (`content-panel-container.scss:27-28`). But the file is listed in `KbqContentPanel`'s `styleUrls` (`content-panel.ts:194-197`), while `KbqContentPanelContainer` loads only `content-panel-container.scss` (`:246`). Every sibling package co-locates the two: `sidepanel-container.component.ts:35` loads `sidepanel-tokens.scss` whose selector is `.kbq-sidepanel-container`; `modal.component.ts:76` ↔ `.kbq-modal`; `badge.component.ts:117` ↔ `.kbq-badge`. The concrete failure mode: a `kbq-content-panel-container` that is opened without a projected `kbq-content-panel` never instantiates `KbqContentPanel`, so the token stylesheet is never injected, `--kbq-content-panel-resizer-width` is undefined, and `width: var(--kbq-content-panel-resizer-width)` / `left: calc(var(--kbq-content-panel-resizer-width) / -2)` become invalid at computed-value time — the drag handle silently collapses to `width: auto` (0 px for an empty absolutely-positioned box) with no hit area and no error anywhere. The inverse coupling is just as bad in principle: `kbq-content-panel` used outside a container inherits none of its own colours (`content-panel.scss:3-5` reads `--kbq-content-panel-border-radius`, `-background-color`, `-border`) and none of its padding (`--kbq-content-panel-vertical-padding` in header/body/footer), rendering as a transparent, border-less, flush-padded block.
**Fix:** split `content-panel-tokens.scss` in two — a `.kbq-content-panel-container` block loaded by `KbqContentPanelContainer` (`--kbq-content-panel-resizer-width`) and a `.kbq-content-panel` block loaded by `KbqContentPanel` (radius, background, border, padding, both overflow shadows) — or, simpler, move the whole file into `KbqContentPanelContainer.styleUrls` and re-scope the panel-facing tokens to `.kbq-content-panel`. Verify with a Playwright fixture that renders an opened container with no projected panel and asserts the resizer's `getBoundingClientRect().width` equals 16.

**CP-PERF-01 · The panel is created with the container and only detached while closed** — `content-panel.ts:225-244`, `scrollbar.ts:431-433, 591-592, 607-608`.
`@if (openedState())` wraps `<ng-content select="kbq-content-panel" />` (`content-panel.ts:225-244`). Because Angular instantiates a component's content children in the *declaring* view, not at the projection slot, the `@if` controls only whether those already-created DOM nodes are attached — the `kbq-content-panel`, its header/body/footer and every consumer node inside them are constructed as soon as the container is constructed, stay in the change-detection tree while the panel is closed, and are never destroyed by closing it. For the use case the guide leads with — "a quick preview mode for entities from a table" (`content-panel.en.md:1`) — that means the whole preview view is built on page load rather than on first open. The measurable cost is in the body's scrollbar: `KbqScrollbar` runs three permanent `requestAnimationFrame` polling loops (`scrollbar.ts:431-433` throttled to 100 ms, `:591-592` and `:607-608` throttled to 300 ms), each performing layout reads, and `KbqOverflowShadowContainer` keeps a `SharedResizeObserver` subscription on a detached element (`overflow-shadow.ts:118-127`). A closed panel therefore keeps ~3 rAF loops and a resize observation alive indefinitely, on top of the container's own scrollbar. (State preservation across open/close is the one upside, and may well be intentional — but it is neither documented nor opt-out.)
**Fix:** decide and document the contract. If lazy construction is wanted, project through an `ng-template`/`ngTemplateOutlet` or `@defer` rather than a bare `<ng-content>` inside `@if`, so the panel is created on first open; if eager construction is wanted, say so in the guide and note that consumers should hydrate panel data from `openedChange`. Either way stop the polling: `KbqScrollbar` should suspend its rAF streams when the viewport is not connected (`isConnected` / `IntersectionObserver`). Verify with a spec that queries `contentChild(KbqContentPanelBody)` on a *closed* container and asserts the documented behaviour either way.

**CP-TEST-01 · The Jest suite contains a tautology and a duplicate, and misses every risky path** — `content-panel.spec.ts:79-203`, `e2e.playwright-spec.ts:1-46`.
The suite is 204 lines / 10 cases. `should open/close panel by two-way binding` (`:112-122`) sets `componentInstance.opened` and asserts `componentInstance.opened()` — it never reads the container, so it would pass with the component deleted from the template; this is precisely the case that would have caught CP-BUG-01. `should open panel by KbqContentPanelContainer instance` (`:103-110`) is a strict subset of `should open/close panel by KbqContentPanelContainer instance` (`:91-101`). Everything asserts through the *host's* model rather than `container().isOpened()`. Nothing at all covers: `openedChange` emissions, `disableResizer` (the input has zero references outside `content-panel.ts:288` and the API report), `handleResizerSizeChange` clamping, `handleResizerDBLClick`, focus, or the aside. `NoopAnimationsModule` (`:3, 8`) means the animation states are never evaluated. The Playwright side (`e2e.playwright-spec.ts`, 46 lines, 4 tests) has three good overflow-shadow assertions, but both fixtures hard-code `[opened]="true"` (`e2e.ts:11, 57`), so the closed state, the open/close transition, the resizer handle and `disableClose`/`disableResizer` have no visual coverage — the package ships exactly two baselines (`__screenshots__/01-light.png`, `01-dark.png`).
**Fix:** delete `:103-110` as a duplicate; rewrite `:112-122` to assert through `container().isOpened()` and to cover the one-way-binding path from CP-BUG-01; add cases for `openedChange` emission counts on `toggle()`/`open()`/`close()` (including the no-op early returns at `:364` and `:374`), for width clamping (CP-BUG-03), for `disableResizer` hiding `.kbq-content-panel-container__panel-resizer`, and for the focus contract from CP-A11Y-01. Add a `jest-axe` assertion on the opened panel. On the Playwright side add a closed-state screenshot and a `disableResizer` screenshot to `e2e.ts`; regenerate baselines only with `yarn run e2e:docker:update-snapshots`.

**CP-DOC-01 · Every exported class is undocumented, and the guides omit half the public surface** — `tools/public_api_guard/components/content-panel.api.md:15, 24, 32, 42, 74, 83, 96, 104, 112`, `content-panel.en.md:1-31`, `content-panel.ru.md:1-31`.
All nine exported symbols carry `// @public (undocumented)` in the API report — no class has a TSDoc block. The docs site generates its API tab from the TypeScript sources (`tools/api-gen/generate-api-docs.ts`, `tools/api-gen/extraction`) and `structure.ts:478-479` sets `hasApi: true` with `apiId: 'content-panel'`, so the published Content panel API page renders eight class entries with empty descriptions and no guidance on how they compose. The 31-line guides fare little better: they document `toggle()`/`open()`/`close()`, `width`/`minWidth`/`maxWidth` and `disableCloseByEscape`, and nothing else — `opened`, `openedChange`, `isOpened()`, `disableClose`, `disableResizer`, `kbq-content-panel-aside`, `[kbqContentPanelHeaderTitle]`, `[kbqContentPanelHeaderActions]` and the required `container > panel > header/body/footer` nesting are all absent, even though two of those (the aside and the header directives) are used in every shipped example. There is no mention anywhere that `kbq-content-panel-header` hard-requires both `KbqContentPanel` and `KbqContentPanelContainer` ancestors (`content-panel.ts:125, 127`), so getting the nesting wrong yields a bare `NG0201: No provider for KbqContentPanelContainer`.
**Fix:** add class-level TSDoc to all eight components/directives describing role and required nesting (mirroring `resizer.ts:44-54`, which documents its own composition with an `@example`), then re-run `yarn run build:components && yarn run approve-api` — adding JSDoc removes the `(undocumented)` markers and *will* change the API report, failing the `api` CI job until approved. Extend both guides with a structure section (a full markup skeleton), an "Aside" section, and rows for `opened`/`openedChange`/`disableClose`/`disableResizer`.

### P3 — Nice to have / hygiene

**CP-API-01 · Dead default initializer, redundant read-only wrapper, and inconsistent `exportAs`** — `content-panel.ts:280-283, 314, 324`, `content-panel.api.md:19, 34, 37, 78, 91`.
`disableCloseByEscape = input(this.disableClose(), { transform: booleanAttribute })` (`:283`) reads the `disableClose` input signal during field initialisation, long before any binding is applied, so it always evaluates to the declared default `false` — the intent ("default to `disableClose`") is never realised. The behaviour happens to be correct only because `handleEscapeKeydown` ORs both flags (`:403`); the initializer is dead code that reads as a contract. Its JSDoc (`:280-282`) also omits the `@default` tag that all six sibling inputs carry. `isOpened = computed(() => this.openedState())` (`:324`) is a computed that forwards a signal verbatim — `openedState.asReadonly()` expresses the same thing without a reactive node. `exportAs` is present on `KbqContentPanelAside` (`:65`), `KbqContentPanelHeaderTitle` (`:74`), `KbqContentPanelHeaderActions` (`:83`), `KbqContentPanelBody` (`:156`) and `KbqContentPanelContainer` (`:258`) but missing on `KbqContentPanel`, `KbqContentPanelHeader` and `KbqContentPanelFooter` — visible in the API report as `never` in their `ɵcmp` export-as slots (`content-panel.api.md:19, 78, 91`). Finally, `KbqContentPanelBody.scrollbar`/`overflowContainer` are `public` and tagged `@docs-private` (`content-panel.ts:159-162`, `api.md:34, 37`) yet the package's own e2e fixture uses `scrollbar()` as public API (`e2e.ts:139`) — the tag contradicts the intended usage.
**Fix:** replace the `disableCloseByEscape` initializer with `input(false, …)` plus `@default false`, and either implement the inheritance in `handleEscapeKeydown` (already done) or drop the pretence from the docs; swap `isOpened` for `openedState.asReadonly()` (which becomes unnecessary entirely once CP-BUG-01 lands `model()`); add the three missing `exportAs` values; drop `@docs-private` from `KbqContentPanelBody.scrollbar` and document it as the supported programmatic-scroll handle. Re-run `approve-api` after.

**CP-ARCH-01 · Projected children inject concrete parent classes; eight classes share one file with no `public-api.ts`** — `content-panel.ts:125, 127, 181`, `index.ts:1-2`.
AGENTS.md states: "When a projected child depends on its host component, inject a narrow `InjectionToken` scoped to the members it uses, not the host's concrete class." `KbqContentPanelHeader` injects both `KbqContentPanelContainer` (`:125`, uses `disableClose()` and `close()`) and `KbqContentPanel` (`:127`, uses `bodyOverflow()`); `KbqContentPanelFooter` injects `KbqContentPanel` (`:181`, uses `bodyOverflow()`). Two consequences follow: the DI edges are wider than the three members actually consumed, and — because `KbqContentPanelHeader` (declared at `:121`) references classes declared later in the same module (`:204`, `:260`) — all eight classes are locked into a single 410-line file, which is why the package has no `public-api.ts` (54 of 64 component packages have one) and no per-concern file split. Both parent injections are also non-optional, so the only feedback for wrong nesting is a raw `NG0201`.
**Fix:** define `KBQ_CONTENT_PANEL_CONTAINER` (`{ disableClose: Signal<boolean>; close(): void }`) and `KBQ_CONTENT_PANEL` (`{ bodyOverflow: Signal<KbqOverflowShadowState> }`) injection tokens, provide them from the two host components with `useExisting`, and inject the tokens in header/footer with `{ optional: true }` plus an `ngDevMode` error naming the required ancestor. That breaks the circular reference and lets the file split into `content-panel.ts`, `content-panel-container.ts`, `content-panel-header.ts`, `content-panel-body.ts`, `content-panel-footer.ts`, `content-panel-aside.ts` and `public-api.ts`, matching the AGENTS.md package layout.

**CP-CSS-02 · A token named `vertical-padding` is applied horizontally; a BEM modifier uses element syntax; geometry bypasses the token file** — `content-panel-tokens.scss:8`, `content-panel-header.scss:6`, `content-panel-body.scss:6`, `content-panel-footer.scss:4`, `content-panel.ts:251`.
`--kbq-content-panel-vertical-padding` (`content-panel-tokens.scss:8`) is used exclusively as the *second* value of a two-value `padding` shorthand — `padding: var(--kbq-size-l) var(--kbq-content-panel-vertical-padding)` in the header (`content-panel-header.scss:6`) and footer (`content-panel-footer.scss:4`), and `padding: 0 var(--kbq-content-panel-vertical-padding)` in the body (`content-panel-body.scss:6`) — i.e. it sets left/right padding in all three places. A consumer overriding it to fix vertical rhythm gets horizontal insets instead. Separately, the opened-state host class is `kbq-content-panel-container__opened` (`content-panel.ts:251`): `__` is BEM's *element* delimiter, while the repo uses a single `_` for modifiers (`kbq-scrollbar-track_hover` at `scrollbar.ts:583`, `.kbq-link_multiline`), so the class reads as a child element that does not exist. It is already load-bearing for consumers — the shipped grid example selects on it (`content-panel-with-grid-example.ts:226`, `:has(.kbq-content-panel-container__opened)`) — so renaming needs a deprecation window. Finally, most of the component's geometry never reaches the token file at all: the container `gap` (`content-panel-container.scss:3`), the panel padding (`:18`), the resizer offset (`:27`), the header/footer block padding, the close-button margin (`content-panel-header.scss:19`) and the aside padding/gap (`content-panel-aside.scss:4-5`) all reference global `--kbq-size-*` tokens directly, unlike `sidepanel-tokens.scss:5`, which exposes named component tokens (`--kbq-sidepanel-size-header-padding-vertical`, …) for exactly these values.
**Fix:** rename to `--kbq-content-panel-horizontal-padding` (keeping the old name as an alias for one minor release); emit both `kbq-content-panel-container_opened` and the legacy `__opened` class for one release, deprecating the latter in the guides; and promote the hard-coded geometry into named tokens in `content-panel-tokens.scss` following the `sidepanel` naming scheme.

**CP-STYLE-01 · `standalone: true` in the e2e fixture, and a JS constant duplicating a CSS token** — `e2e.ts:50`, `content-panel.ts:29, 332`.
AGENTS.md: "Must NOT set `standalone: true` inside Angular decorators. It's the default in Angular v19+." `E2eContentPanelState` sets it (`e2e.ts:50`); its sibling `E2eContentPanelScrollOverflow` in the same file correctly does not. In `content-panel.ts`, `contentAnimationState` computes `marginRight: this.widthState() + (parseInt(SizeL) || 16)` (`:332`), importing `SizeL` from `@koobiq/design-tokens` (`:29`). `SizeL` is the string `'16px'` (`node_modules/@koobiq/design-tokens/web/js/index.js:304`), so `parseInt` always yields `16` and the `|| 16` fallback is unreachable; `parseInt` is also called without a radix. More importantly this hard-wires the JS value of a token whose CSS counterpart, `--kbq-size-l`, is used for the container `gap` (`content-panel-container.scss:3`) — a consumer who overrides `--kbq-size-l` in CSS moves the layout but not the animated margin, silently desynchronising the two.
**Fix:** delete `standalone: true` from `e2e.ts:50`; replace the JS token import with a CSS-only expression — animate a custom property and let the stylesheet compose `calc(var(--kbq-content-panel-width) + var(--kbq-size-l))`, or read the resolved value once via `getComputedStyle` through `inject(KBQ_WINDOW)` (never the global `window`, per AGENTS.md). If the constant must stay, use `parseInt(SizeL, 10)` and drop the dead fallback.

**CP-DOC-02 · Dead example stubs, and two unrelated examples importing this module for nothing** — `examples.content-panel.en.md:1-5`, `examples.content-panel.ru.md:1-5`, `structure.ts:480`, `file-upload-dropzone-example.ts:3, 20`, `file-upload-local-dropzone-example.ts:3, 16`.
Both `examples.content-panel.*.md` files are the standard "🚧 Documentation in progress 🚧" placeholders. Because `structure.ts:480` sets `hasExamples: false`, the Examples tab never renders for this component, so these are dead files rather than a broken user surface — the two real examples (`content-panel-overview`, `content-panel-with-grid`) are embedded inline in the guides at `content-panel.en.md:3, 7` and registered in `packages/docs-examples/example-module.ts:1369, 1382`. Separately, `KbqContentPanelModule` is imported into two file-upload examples (`file-upload-dropzone-example.ts:3, 20` and `file-upload-local-dropzone-example.ts:3, 16`) whose templates contain no `kbq-content-panel*` element at all — dead dependencies that pull the whole module into those examples' bundles.
**Fix:** either delete the two stub files or flip `structure.ts:480` to `hasExamples: true` and populate them with the two existing `<!-- example(…) -->` embeds; drop the unused `KbqContentPanelModule` import from both file-upload examples.

## 4. Recommended Remediation Phases

**Phase 1 — Accessibility.**
IDs: CP-A11Y-01, CP-A11Y-02, CP-A11Y-03. Add focus capture/move-in/restore around `open()`/`close()`, give the panel a role and an accessible name derived from the header title, make the title directive an actual heading, and move the `ESCAPE` listener off the container host. Highest user impact, no dependency on the other phases, and it defines the behaviour the Phase 4 tests will assert. Ship the `content-panel.en.md`/`.ru.md` `ESCAPE` correction with it.

**Phase 2 — State model and geometry correctness.**
IDs: CP-BUG-01, CP-BUG-03, CP-BUG-02. Collapse `opened`/`openedChange`/`openedState` into a single `model()` and `width`/`widthState` into a `linkedSignal`, then route all width consumers through one clamped `computed()`, then swap the two crossed animation durations. Order matters: the clamp fix is trivial once there is a single width source. Removing `openedChange` from the public API is breaking — schedule with the next major and add an `ng-update` schematic (`packages/schematics`).

**Phase 3 — Style ownership, structure and API hygiene.**
IDs: CP-CSS-01, CP-CSS-02, CP-ARCH-01, CP-API-01, CP-STYLE-01, CP-PERF-01. Re-home the token block onto the components that own the selectors, introduce the two injection tokens so the file can be split and `public-api.ts` added, fix the token/class naming with an alias window, and settle the eager-instantiation contract (lazy projection or documented + rAF suspension). Requires `yarn run build:components` then `yarn run approve-api`.

**Phase 4 — Keyboard resizing, tests and docs.**
IDs: CP-A11Y-04, CP-TEST-01, CP-DOC-01, CP-DOC-02. Add keyboard/ARIA support to `KbqResizer` upstream and wire it here; then rewrite the Jest suite around the new contracts (deleting the duplicate and the tautology, adding `jest-axe`), extend the Playwright fixtures to the closed and `disableResizer` states, add class TSDoc, and clean the docs stubs. Last because the assertions encode decisions made in Phases 1-3.

## Appendix A — Review Methodology

Findings were gathered by reading every file in the package line by line (`content-panel.ts`, all six SCSS files, the Jest spec, the e2e fixture and Playwright spec, both guides, both example stubs, `index.ts`, `module.ts`, `ng-package.json`), then widening to the composition surface: `packages/components/resizer/resizer.ts`, `packages/components/core/overflow-shadow/overflow-shadow.ts`, `packages/components/scrollbar/scrollbar.ts` and `packages/components/core/animation/animation.ts` for the four dependencies the component actually uses; `packages/components/sidepanel/**` and `packages/components/modal/**`, `badge/**`, `link/**` for the conventions it is measured against; `tools/public_api_guard/components/content-panel.api.md`, `tools/api-extractor/config.json`, `tools/api-gen/generate-api-docs.ts` and `apps/docs/src/app/structure.ts` for the published surface; and every consumer in the repo (the dev app, two docs examples, two e2e fixtures, plus two file-upload examples that import the module and never use it). Token resolution was checked against `node_modules/@koobiq/design-tokens/web/new/css-tokens-light.css`, `-dark.css` and `css-tokens.css`; the animation-state semantics against `node_modules/@angular/animations/fesm2022/browser.mjs`. Git history for the package (18 commits since `00dada5e9`) was reviewed for repeated regression areas — the only clustered one is the overflow shadow (`c6d149219`, then `2d9a212ad` extracting it into core, then `3e49f593b` rewriting the scrollbar underneath it), which is now the best-tested part of the package.

Refuted during verification:
- **"Missing `_content-panel-theme.scss` is a defect"** (flagged by the cross-package inventory) — it is not. The global aggregator `packages/components/core/styles/_koobiq-theme.scss:6-27` includes only 8 component theme mixins; every other package themes itself through CSS custom properties. `content-panel` does exactly that: `content-panel-tokens.scss:4-7` maps its colours onto `--kbq-background-card`, `--kbq-line-contrast-less` and the two `--kbq-shadow-overflow-normal-*` tokens, all of which are defined in both `css-tokens-light.css` and `css-tokens-dark.css` and flip with the theme. No theme mixin is needed or missing. (The *scoping* of that file is a real defect — see CP-CSS-01 — but that is a different claim.)
- **"An undefined `var()` silently computes to nothing"** — checked all 14 custom properties the package consumes. `--kbq-background-card`, `--kbq-line-contrast-less`, `--kbq-shadow-overflow-normal-top`/`-bottom` resolve in the light and dark token files; `--kbq-size-border-width`, `--kbq-size-s`, `--kbq-size-m`, `--kbq-size-l`, `--kbq-size-xxl` resolve in `css-tokens.css`/`index.bundled.css`. Nothing dangles.
- **"`state('true')`/`state('false')` never match a boolean trigger value"** — they do. `normalizeTriggerValue` leaves booleans untouched (`browser.mjs:3299-3304`), `AnimationTransitionFactory.buildStyles` looks up `this._stateStyles.get(stateName?.toString())` (`browser.mjs:1595`), and `AnimationTrigger`'s constructor aliases `'true'`↔`'1'` and `'false'`↔`'0'` (`browser.mjs:1751-1752`). The `contentAnimation` state styles do apply; only the durations are wrong (CP-BUG-02).
- **"The header/footer should use the core `KbqOverflowShadowTop`/`KbqOverflowShadowBottom` directives instead of hand-rolled `[style.box-shadow]` bindings"** — the deviation is justified. Those directives take the container instance as an input (`overflow-shadow.ts:152, 173`), and the container instance lives inside `KbqContentPanelBody`'s *view* while the header and footer are content-projected siblings — there is no template reference that crosses that boundary. Routing through `KbqContentPanel.bodyOverflow()` (`content-panel.ts:211-213`) is the correct workaround.
- **"`handleResizerSizeChange` clamping is defeated by `KbqResizer` writing `style.width` imperatively"** — `KbqResizer.updateSize` does write the raw drag width straight onto the element (`resizer.ts:305`) while the template also binds `[style.width.px]` (`content-panel.ts:231`), and Angular only rewrites on change, so the last imperative value survives a drag past the bounds. But the same element also carries `[style.min-width.px]`/`[style.max-width.px]` (`:230, 232`), and CSS clamps the used width regardless, so nothing is visible. The real width defect is the unclamped `width` *input* (CP-BUG-03), not the drag path.
- **"Protected members leak into the public API report"** — `contentAnimationState`, `openedState`, `widthState` and the three `handle*` methods do appear in `content-panel.api.md:46-57, 64, 67`, but they are `protected`, so they are only reachable by subclassing, not by consumers. Report noise, not an API leak. (`KbqContentPanelBody.scrollbar`/`overflowContainer` *are* public — folded into CP-API-01.)
- **"`module.ts` violates the AGENTS.md `<component-name>.module.ts` naming rule"** — 12 packages use a bare `module.ts` (`actions-panel`, `clamped-text`, `content-panel`, `dynamic-translation`, `flag`, `inline-edit`, `overflow-items`, `resizer`, `skeleton`, `time-range`, `top-bar`, `username`). It is the newer convention, not a per-package slip; raising it here would be noise.

Corrected on verification:
- **CP-BUG-01** was first drafted as "`openedChange` is not emitted when the `opened` input changes". That is deliberate and correct — emitting there would echo the parent's own write back at it under `[(opened)]`. Reading the constructor showed the real defect is the one-way-binding desync, which is both more serious and reachable in the repo's own `e2e.ts:11`.
- **CP-PERF-01** was first drafted as "the panel content is lazily created on open, so the first open is slow". Verification of Angular's content-projection semantics showed the opposite: content children are created in the declaring view regardless of the `@if`, so the cost is eager construction plus never-stopping scrollbar polling while closed. The finding was rewritten and re-scoped from a latency claim to a lifetime/contract claim.
- **CP-A11Y-01** was first filed as "add a focus trap like `sidepanel`". Reading `sidepanel-config.ts:24-27` and re-reading the guide's positioning ("shifts adjacent content" — the surrounding page stays interactive) made clear a trap would be *wrong* here; the finding was narrowed to focus move-in and restore, with the trap explicitly ruled out.
- **CP-CSS-01** was initially graded P3 ("token file in the wrong `styleUrls`"). Tracing `--kbq-content-panel-resizer-width` to `content-panel-container.scss:27-28` produced a concrete silent-failure mode (a zero-width, unclickable drag handle), which lifted it to P2.
