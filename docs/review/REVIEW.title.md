# Koobiq `title` Component — Code Review & Improvement Plan

> Scope: `packages/components/title` · Commit `af6e64fe` · 2026-07-04
> Generated by a multi-dimension review (parallel research passes + manual adversarial verification of every finding against source). 11 findings confirmed (P0×0, P1×1, P2×4, P3×6); 3 candidate findings refuted during verification (see Appendix A).

---

## 1. Executive Summary

`kbq-title` is a single-directive package (`KbqTitleDirective`, [title.directive.ts](../../packages/components/title/title.directive.ts), 296 lines) that shows a tooltip with the full text of its host **only when the content is actually truncated** — horizontally, or vertically under `-webkit-line-clamp`. It extends `KbqTooltipTrigger` and is one of the most widely consumed building blocks in the library: 55+ files use it (dropdown items, list/tree options, tags, buttons, filter-bar pipes, breadcrumbs, toast, username, notification-center).

- **The single serious defect is an accessibility one**: the tooltip never opens on keyboard focus. The `trigger` getter is hard-locked to `Hover`, so the base class binds no focus listeners, and the directive's own `FocusMonitor` subscription only flips `disabled` without ever calling `show()`. Both the JSDoc and the published user docs (`title.en.md`) explicitly promise keyboard-focus behavior that does not exist, and the unit tests assert only that the handler is *called*, not that the tooltip opens (TTL-A11Y-01).
- **Reactivity and scale have gaps**: the `titleContent` input signal is read only on hover / content mutation, so programmatic changes leave an open tooltip stale (TTL-BUG-01), and every directive instance registers its own `(window:resize)` host listener — a dropdown with hundreds of options runs hundreds of in-zone handlers per resize event (TTL-PERF-01).
- **Test coverage is deep but one-legged**: 55 Jest cases cover the overflow math thoroughly, yet everything runs on JSDOM where all element sizes are mocked, and there is no `e2e.ts` / Playwright spec — despite 4 of the last 10 commits being sub-pixel overflow regressions (TTL-TEST-01).

Genuine strengths: modern DI (`inject()`, `KBQ_WINDOW` for SSR safety), exemplary JSDoc coverage, correct teardown of all three subscriptions plus focus monitoring, and a thoughtful sub-pixel/ellipsis-aware measurement algorithm hardened by several rounds of bug fixes (DS-4292, DS-4466, DS-4517, DS-2561).

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

None.

### P1 — High

**TTL-A11Y-01 · Tooltip never opens on keyboard focus, contradicting docs and JSDoc** — `title.directive.ts:69-80, 269-271, 286-289`.
The `trigger` getter is locked to `PopUpTriggers.Hover` (`title.directive.ts:78-80`), so `KbqPopUpTrigger.initListeners()` binds no `focus`/`blur` listeners (`core/pop-up/pop-up-trigger.ts:499-503`). The directive's own compensation — `focusMonitor.monitor(...).subscribe(origin => origin === 'keyboard' ? this.handleElementEnter() : this.hideTooltip())` (`title.directive.ts:269-271`) — calls `handleElementEnter()`, which only sets `content` and `disabled` (`title.directive.ts:286-289`) and never calls `show()`. Setting `disabled = false` does not display anything (the `disabled` setter only *hides* on `true`, `tooltip.component.ts:246-252`). Net effect: a keyboard-only user tabbing onto a truncated element gets no tooltip at all. Meanwhile the class JSDoc ("opens on hover and on keyboard focus", `title.directive.ts:27-29`) and the user guide ("Accessibility: the tooltip opens on keyboard focus", `title.en.md:12`, same in `title.ru.md`) promise the opposite, and the two focus specs assert only that the handler was invoked, not that an overlay appears (`title.directive.spec.ts:536-562`). Violates WCAG 2.1.1 (Keyboard); custom `titleContent` is doubly lost because screen readers get no association either (see inherited A11Y-07/A11Y-20).
**Fix:** in the keyboard branch call `this.show()` after `handleElementEnter()` (and `this.hide()` in the non-keyboard/`null` branch alongside `hideTooltip()`); alternatively drop the `trigger` lock (resolve the TODO, TTL-API-01) and let the base `hover, focus` trigger work — `KbqTooltipTrigger.show()` already suppresses non-keyboard focus origins (`tooltip.component.ts:450-453`). Add a spec that drives `focusMonitor.focusVia(el, 'keyboard')` on an overflown host and asserts the tooltip element exists in the overlay container (the helper `getTooltipElement()` already exists in the spec).

### P2 — Should fix

**TTL-BUG-01 · `titleContent` input signal is not reactive** — `title.directive.ts:66, 211-213, 242-243, 286-287`.
`titleContent` is an `input()` signal, but nothing watches it: `content` is written only in `ngAfterViewInit` (`:243`), on hover (`:287`) and on host DOM mutations (`:266`). A programmatic binding change (`[kbq-title]="value"` where `value` changes) does not mutate the host DOM, so an *open* tooltip keeps showing the previous content, and `disabled` is not re-evaluated. This is inconsistent with the base class, where the `kbqTooltip` content setter pushes updates into an open tooltip via `updateData()` (`tooltip.component.ts:232-236`).
**Fix:** add an `effect()` (or `toObservable(this.titleContent)` subscription) that assigns `this.content = this.resolvedContent` and re-evaluates `this.disabled = !this.isOverflown`; keep the existing hover-time refresh as a fallback. Cover with a spec that rebinds `[kbq-title]` while the tooltip is open.

**TTL-PERF-01 · A `(window:resize)` listener and in-zone handler per directive instance** — `title.directive.ts:44, 217, 257-259`.
The host binding `'(window:resize)': 'resizeStream.next($event)'` registers one window listener per instance and runs it inside the Angular zone; the `debounceTime(100)` only throttles the downstream subscriber, not the per-event zone entries. `kbq-title` sits on every dropdown item, list option and tree option — a virtual-scrolled tree or a 500-option list means hundreds of listeners each firing (and triggering change detection) on every resize frame. The umbrella review already tracks the pattern as ARCH-14 (`Subject + (window:resize)` instead of `SharedResizeObserver`); the title case is the most instance-heavy of the three.
**Fix:** replace the host binding with a single shared stream — CDK `ViewportRuler.change()` or `SharedResizeObserver` on `parent` — subscribed outside the zone (`runOutsideAngular`), re-entering only when the computed `disabled` value actually changes. Element-level observation would additionally catch container resizes that happen without a window resize (splitter drag, sidebar collapse), which the current code misses entirely.

**TTL-ARCH-01 · DOM mutation inside the `isOverflown` getter, without try/finally** — `title.directive.ts:99-117`.
The sub-pixel branch of the getter appends a probe `<span>` to `parent`, measures it, and removes it (`:104-114`). A getter that mutates the DOM is a hidden side effect (already flagged as ARCH-04 in the umbrella review): it can fire mutation observers of ancestors, invalidates layout, and — because `wrapper.remove()` is not in a `finally` block — an exception between `appendChild` and `remove()` (e.g. inside `getBoundingClientRect` on a detached tree) strands the probe in the DOM. Note the probe insertion can also re-trigger the directive's own `ContentObserver` stream when `parent` is inside the observed subtree, causing a redundant re-measure 100 ms later.
**Fix:** extract the probe logic into a private method (`measureTextWidth()`), wrap append/measure in `try { … } finally { wrapper.remove(); }`, and consider a mutation-free measurement via `document.createRange().selectNodeContents(child)` + `range.getBoundingClientRect()`, which avoids both the DOM write and the observer echo.

**TTL-TEST-01 · No e2e/Playwright coverage for a measurement-driven component** — `packages/components/title/` (missing `e2e.ts`, `e2e.playwright-spec.ts`).
All 55 unit tests run on JSDOM, where every `offsetWidth`/`scrollWidth`/`getBoundingClientRect` is mocked by hand — the real layout engine is never exercised. Yet the component's entire value is real-browser measurement, and its history proves the risk: 4 of the last 10 commits are overflow-detection regressions (DS-4292 sub-pixel clip, DS-4466 1–2 characters, DS-4517 vertical overflow, DS-2561 placement). The umbrella review inventory lists `title` among the 7 components without a visual spec.
**Fix:** add `e2e.ts` + `e2e.playwright-spec.ts` following the tooltip package's pattern: fixed-width truncated string (tooltip appears on hover), non-truncated string (no tooltip), sub-pixel case with `text-overflow: clip` vs `ellipsis`, `-webkit-line-clamp` vertical case, and — after TTL-A11Y-01 — a keyboard-focus scenario. Update the umbrella inventory row afterwards.

### P3 — Nice to have / hygiene

**TTL-BUG-02 · Multi-element branch skips the sub-pixel/ellipsis logic** — `title.directive.ts:91-96, 144-146`.
When several `#kbqTitleText` elements are projected (filter-bar pipes, two-line list options), `isOverflown` uses raw `offsetWidth < scrollWidth` comparisons and never reaches the `isWidthOverflown()` rounding/ellipsis-awareness path that single-element hosts get. The DS-4292 class of bugs ("tooltip for imperceptible sub-pixel clip") therefore still exists for multi-text consumers.
**Fix:** extract a per-element check that funnels through `isWidthOverflown()` (and the `getBoundingClientRect` fallback) and reuse it in both branches.

**TTL-API-01 · `trigger` setter silently swallows assignments; stale TODO** — `title.directive.ts:68-80`.
Assigning `kbqTrigger` on a `[kbq-title]` host is accepted and ignored — the getter always returns `Hover`. The workaround is deliberate (co-hosting `kbq-title` with a popover) but is invisible to consumers and carries a `// todo need rename kbqTrigger in popover, tooltip and title` from the original author. Resolving it is also the cleanest fix for TTL-A11Y-01.
**Fix:** implement the TODO (namespaced trigger inputs per pop-up type) or, short-term, `console.warn` in dev mode when a non-default value is assigned, and document the behavior in the class JSDoc and `title.en.md`/`title.ru.md`.

**TTL-API-02 · Internal machinery leaks into the public API** — `tools/public_api_guard/components/title.api.md:17-31`.
`resizeStream` (a raw `Subject<Event>`), the measurement getters (`child`, `parent`, `hasOnlyText`, `isHorizontalOverflown`, `isVerticalOverflown`), and the event handlers (`handleElementEnter`, `hideTooltip`) are all `// @public`. Consumers can (and eventually will) push into `resizeStream` or call handlers directly, freezing implementation details. The `@docs-private` JSDoc tags already on most of them do not affect TypeScript visibility.
**Fix:** make `resizeStream` and the handlers `protected`, the purely internal getters `protected` or `private`, keep `isOverflown`/`viewValue` public (legitimately useful via `exportAs: 'kbqTitle'`), then run `yarn run build:components && yarn run approve-api` (build first — the guard reads `dist`).

**TTL-ARCH-02 · Decorator queries and mutable injected fields** — `title.directive.ts:50, 59, 230-235`.
`@ContentChildren('kbqTitleText')`/`@ContentChild('kbqTitleContainer')` predate the repo convention of signal queries (`contentChildren()`/`contentChild()`); `componentInstance` (`:50`) and `contentObserver` (`:59`) lack `readonly` unlike their siblings. When migrating, prefer the *optional* signal-query form with a guard — the earlier repo-wide signal-queries migration showed that over-tightening to `.required` throws NG0951 in prod builds.
**Fix:** migrate both queries to signal queries (optional + guard), add `readonly` to the two injected fields.

**TTL-DOC-01 · `examples.title.*.md` are placeholder stubs** — `packages/components/title/examples.title.en.md:1-5`, `examples.title.ru.md`.
Both files still show "🚧 Documentation in progress 🚧" although six live examples exist under `packages/docs-examples/components/title/` and sibling packages (e.g. `examples.tooltip.en.md`) demonstrate the expected `<!-- example(…) -->` format. The main guides embed most examples inline, so the Examples tab is the only broken surface.
**Fix:** populate both stubs with the six example embeds (overview, custom-content, multiple-text, vertical-overflow, list-option, plus the split-button text-overflow cross-link) in both languages.

**TTL-STYLE-01 · Type and null-handling hygiene** — `title.directive.ts:66, 94, 101, 130, 135, 150, 167-168, 211`.
`TemplateRef<any>` is used in the input and `resolvedContent` where `TemplateRef<unknown>` suffices; `parent` is optional-chained everywhere (`parent?.offsetWidth`) although the getter can never return a falsy value (`:157-163` always falls back to the host element), while `child` — which *can* be `undefined` if the `#kbqTitleText` query is emptied at runtime — is dereferenced unguarded (`:101, 130, 135`). The inconsistency hides the one real hazard behind noise.
**Fix:** drop the dead `?.` on `parent`, add a guard (or early return) for an empty `childElements`, replace `any` with `unknown`.

## 4. Recommended Remediation Phases

**Phase 1 — Keyboard accessibility & reactivity.**
IDs: TTL-A11Y-01, TTL-BUG-01. Restore the documented keyboard-focus behavior (show/hide from the focus-monitor branch or via the un-locked trigger) and make `titleContent` reactive with an `effect()`. Both land with new specs asserting real overlay behavior. Highest user impact, no API changes.

**Phase 2 — Measurement & scale hardening.**
IDs: TTL-PERF-01, TTL-ARCH-01, TTL-BUG-02. Replace per-instance window listeners with a shared, zone-free resize source; extract a mutation-safe (try/finally or Range-based) measurement helper and route both the single- and multi-element branches through it. Verify no behavior change against the existing 9 `isOverflown` specs.

**Phase 3 — API hygiene.**
IDs: TTL-API-01, TTL-API-02, TTL-ARCH-02, TTL-STYLE-01. Tighten member visibility, resolve or document the `trigger` workaround, migrate to signal queries, clean types. Requires `yarn run build:components` + `yarn run approve-api`; visibility tightening is technically breaking, so schedule with the next minor/major.

**Phase 4 — Test & docs completion.**
IDs: TTL-TEST-01, TTL-DOC-01. Add `e2e.ts` + Playwright visual spec (including the keyboard scenario from Phase 1) and fill the examples stubs. Update the umbrella review inventory (`title` visual-spec cell) once merged.

## 5. Verification Strategy

General gates (after every phase, sequentially — never in parallel):
- `npx jest packages/components/title` — all unit specs, plus consumer suites for dropdown, list, tree and filter-bar (heaviest `kbq-title` integrations).
- `yarn run eslint` and `yarn run prettier` on touched files.
- `yarn run build:components`, then `yarn run check-api` (build first — the guard validates `dist/*.d.ts`); `approve-api` only in Phase 3 where the surface intentionally changes.
- Manual smoke in the dev app: `yarn run dev:title` (template covers plain text, buttons, selects, nested dropdowns).

Per-phase assertions:
- **Phase 1:** Tab onto a truncated button in the dev app — tooltip appears; Tab away — it hides. A spec rebinds `[kbq-title]` while the tooltip is open and asserts the overlay text updates. AXE pass on the dev page.
- **Phase 2:** open a dev page with 200+ titled options, resize the window continuously — change-detection profile shows a single shared handler; all existing `isOverflown` sub-pixel specs stay green; a new spec covers the multi-`#kbqTitleText` sub-pixel case.
- **Phase 3:** `check-api` diff contains only intended removals/visibility changes; consumers in the repo still compile (`build:components` covers them).
- **Phase 4:** `npx playwright test packages/components/title/e2e.playwright-spec.ts` green on CI browsers; docs site Examples tab for title renders six examples in both locales.

## Appendix A — Review Methodology

Findings were gathered by three parallel research passes (component source & tests; usage across 55+ consumer files, git history and dev app; documentation and review-format conventions), followed by a manual adversarial verification of every candidate against the source of `title.directive.ts`, `tooltip.component.ts` (+ template), `core/pop-up/pop-up-trigger.ts`, `core/title/title-text-ref.ts`, the Jest spec, the API guard report and the published docs. Severity calibration reuses the umbrella review's scale; two findings extend umbrella items (TTL-PERF-01 ← ARCH-14, TTL-ARCH-01 ← ARCH-04), and the accessibility grade accounts for tooltip-level A11Y-07/A11Y-20 being tracked separately.

Refuted during verification:
- **"Missing `ChangeDetectionStrategy.OnPush`"** — not applicable: `changeDetection` is a component-decorator option; directives have no change-detection strategy of their own. No action possible or needed.
- **"Double `FocusMonitor.monitor()` (base class + directive) leaks or double-fires"** — CDK `FocusMonitor` deduplicates monitors per element and refcounts subscriptions; the extra `stopMonitoring` in `ngOnDestroy` is a harmless no-op after the base teardown.
- **"`Node.TEXT_NODE` global breaks SSR"** — `hasOnlyText` is only reachable from hover/resize/mutation paths that never execute on the server; `getComputedStyle` is already routed through the injected `KBQ_WINDOW`.

Corrected on verification:
- **TTL-BUG-01** was initially drafted as "content never updates after init"; in fact `handleElementEnter()` refreshes content on every hover, so the impact was narrowed to *open-tooltip staleness and missed `disabled` re-evaluation* on programmatic input changes.
- **TTL-A11Y-01** was initially filed as "verify inherited tooltip ARIA"; source verification showed the title-specific defect (no `show()` on keyboard focus) is independent of — and more severe than — the inherited missing `role`/`aria-describedby`.
