# Koobiq `select` Component — Code Review & Improvement Plan

> Scope: `packages/components/select` + the shared `core` abstractions it composes (`core/option`, `core/select`) · Commit `3d86d38f` · 2026-06-29
> Generated by an automated multi-agent review (8 review dimensions + adversarial verification of every finding). 70 findings confirmed (2×P0, 8×P1, 24×P2, 36×P3); 3 refuted. Treat as a high-signal starting point; spot-check before acting.
> Findings tagged **(shared)** live in `core` and also affect `tree-select` / `autocomplete`. This document is a review + roadmap; no source is modified by it.

---

## 1. Executive Summary

- **Accessibility is the single biggest risk and the only release blocker.** The component implements essentially zero ARIA semantics: the host has no `role="combobox"`/`aria-expanded`/`aria-controls`/`aria-activedescendant`, the overlay has no `role="listbox"`, `kbq-option` has no `role="option"`/`aria-selected`, and the tag-remove control is not keyboard-operable. This directly violates the project's own "MUST pass AXE / WCAG AA" mandate (AGENTS.md). **2×P0 + several P1/P2** cluster here.
- **One confirmed production memory leak.** `localeService.changes` is subscribed in the constructor (`select.component.ts:858`) with **no teardown**, and is held by a `providedIn: 'root'` singleton — so every created-then-destroyed `KbqSelect` is retained for the app lifetime and keeps firing `markForCheck`.
- **One genuine RTL correctness bug with broad blast radius.** `triggerValues` (`select.component.ts:760`) calls `.reverse()` **in place** on CDK `SelectionModel.selected`'s memoized array during change detection — corrupting selection order non-deterministically and leaking into the emitted form value. It is the shared root cause behind several correctness / performance / template findings.
- **The component is a ~1947-line god class with mixed DI/input styles.** It owns 6+ responsibilities, ~12 legacy `@Input` accessors with stale migration TODOs, a 13-parameter constructor, and `@Output` EventEmitters — diverging from the already-migrated sibling `tree-select`. Not a runtime bug, but it concentrates change-detection churn and slows evolution.
- **Performance hotspots are real but bounded.** `ngDoCheck` forces a layout reflow every change-detection tick (`isVisible()` reads `offsetTop`/`offsetHeight`), and `calculateHiddenItems` does a double DOM-clone read/write thrash with up to ~2–3 synchronous `detectChanges()`. Both are fixable with observers + a single batched measurement pass.
- **What's strong.** The overlay/scroll lifecycle is mostly disciplined — `subscribeToScrolledToBottom()` and `resetOptions()` are correctly bounded (`takeUntil(closedStream)` / `takeUntil(options.changes)`) and are the reference pattern the leaky paths should copy. Token naming, BEM namespacing, and the existing `KbqAbstractSelect` base provide clean refactor seams.
- **Test coverage has structural false-positives.** The default value-sort tests pass vacuously (string fixtures make `a.value - b.value` a `NaN` no-op), and there is **no ARIA/AXE coverage** and no coverage of loading/error/empty panel states — so the highest-risk areas are also the least guarded.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

**SEL-A11Y-01 · No combobox semantics on host** — `select.component.ts:182` (host object).
Host exposes only `tabindex`/`disabled`/classes — no `role="combobox"`, `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-required`, `aria-invalid`, `aria-disabled`, `aria-labelledby`. A screen reader announces an unnamed focusable group (WCAG 4.1.2).
**Fix:** add host bindings (`[attr.role]="'combobox'"`, `[attr.aria-haspopup]="'listbox'"`, `[attr.aria-expanded]="panelOpen"`, `[attr.aria-controls]="panelOpen ? panelId : null"`, `aria-required/invalid/disabled`), wire `aria-labelledby` to the form-field label, generate a stable `panelId`. Couples with SEL-A11Y-04 for `aria-activedescendant`.

**SEL-A11Y-02 · Overlay panel has no `role="listbox"`** — `select.html:108` (`#panel`), `:123` (`#optionsContainer`).
No listbox role, no `aria-multiselectable`/`aria-labelledby`; nothing valid for the host's `aria-controls` to target.
**Fix:** put `role="listbox"` + a stable `id` (`panelId`) + `[attr.aria-multiselectable]="multiSelection"` + `aria-labelledby` on `#optionsContainer` **only** — keep the search input (`select.html:117`) and footer (`:136`) outside the listbox subtree.

> SEL-A11Y-01/02/03/04 are one logical unit — the combobox → listbox → option → activedescendant chain must land together to be coherent and pass AXE.

### P1 — High

**SEL-A11Y-03 · `kbq-option` has no `role="option"`/`aria-selected`/`aria-disabled`** **(shared)** — `core/option/option.ts:150` (host).
Selection is conveyed only visually (`kbq-selected` class + a non-semantic pseudo-checkbox). Shared with autocomplete.
**Fix:** add `[attr.role]="'option'"`, `[attr.aria-selected]="selected"`, `[attr.aria-disabled]="disabled"`; mark the pseudo-checkbox `aria-hidden` (`option.html:3`). Optionally `aria-setsize`/`aria-posinset` for virtual scroll.

**SEL-A11Y-04 · `aria-activedescendant` never wired despite `ActiveDescendantKeyManager`** — `select.component.ts:1735` (init), `:1851` (`scrollActiveOptionIntoView` forces `option.focus()`).
The key manager doesn't set `aria-activedescendant`; instead real DOM focus is moved into options and contested with the search input (`:1744`) — a non-standard combobox model.
**Fix:** keep focus on the combobox host (or the search input when present) and bind `[attr.aria-activedescendant]="keyManager.activeItem?.id"`; replace `option.focus()` with a scroll-into-view that does not steal focus. The `kbq-active` class stays as the visual indicator.

**SEL-A11Y-05 · Tag-remove icon not keyboard operable and unnamed** — `select.html:38`; `KbqTagRemove` hard-codes `tabindex:-1`, click-only.
In multiple mode a selected value can only be removed by mouse; the icon has no `role="button"`/`aria-label`, and the host tag is non-focusable (`[selectable]="false"`). WCAG 2.1.1 + 4.1.2.
**Fix:** use `kbq-icon-button` (sets `tabindex=0`) or override tabindex; add `role="button"`, a localized `[attr.aria-label]` (e.g. `Remove {{ option.viewValue }}`), `(keydown.enter)/(keydown.space)` → `onRemoveMatcherItem`; mark the glyph `aria-hidden`.

**SEL-LEAK-01 · `localeService.changes` subscription never torn down (root-singleton leak)** — `select.component.ts:858`.
Bare `this.localeService?.changes.subscribe(this.updateLocaleParams)`; `KbqLocaleService` is `providedIn:'root'` with an uncompleted `BehaviorSubject`, so every destroyed `KbqSelect` is retained for the app lifetime and keeps firing `markForCheck`.
**Fix:** `.pipe(takeUntilDestroyed(this.destroyRef))` — already imported and used throughout the file.

**SEL-BUG-01 · `triggerValues` mutates `SelectionModel.selected` via in-place `reverse()` in RTL** — `select.component.ts:760`. *(Merges correctness P1 + templates P1 + a perf note.)*
CDK `SelectionModel.selected` returns a memoized array by reference; `.reverse()` mutates it. The getter is read every CD pass from `@for` (`select.html:30,47`), so in RTL the order flip-flops per tick and corrupts the emitted value via `get selected()` → `propagateChanges()` (`:1824`). Count-only consumers (`calculateHiddenItems`) are unaffected.
**Fix:** copy before reversing — `const ordered = this.isRtl() ? [...selectedOptions].reverse() : selectedOptions;`. Prefer a memoized `computed()` keyed off selection/RTL/limit. Add a regression test: order stable across two CD passes + correct emitted `control.value` order in RTL.

**SEL-TEST-01 · Default value-sort tests are vacuous (NaN no-op)** — `select.component.spec.ts:4848`, `:4923` (+ RTL `:4870`, `:4940`); root cause SEL-BUG-04.
String fixture values make `a.value - b.value` → `NaN`, so `selectionModel.sort` is a no-op and the asserted order equals click/insert order. No test fails when the default comparator does nothing.
**Fix:** add a test selecting out of panel order and asserting **panel-order** output (`[Steak, Tacos]`, not click order); add a numeric fixture. These fail until SEL-BUG-04 is fixed.

### P2 — Should fix

- **SEL-BUG-02 · `clearValue` uses `selectionModel.clear(false)` → stale option `_selected`** — `select.component.ts:998`. Suppressing the `changed` emission skips the deselect subscription (`:932`), leaving cleared options visually checked in multiple mode (a confusing double-click to re-select). **Fix:** `selectionModel.clear()` (default emit) or explicitly `option.deselect()` before `propagateChanges()`.
- **SEL-BUG-03 · `onSelect` reads back `option.selected` to drive the model (two sources of truth)** — `select.component.ts:1783`. *(Merges BUG-89 + arch value-sync.)* Any path mutating `_selected` without the model drifts permanently. **Fix:** make `SelectionModel` the single source of truth (`toggle()` on user input; let the `changed` subscription drive `select()/deselect()`). Largely falls out of fixing SEL-BUG-02.
- **SEL-LEAK-02 · `onAttached()` re-subscribes `options.changes` per panel open without per-session teardown** — `select.component.ts:1245`. Scoped only by `takeUntilDestroyed`; N opens leave N parallel `setOverlayPosition` subscriptions until destroy. **Fix:** add `takeUntil(this.closedStream)`, mirroring `subscribeToScrolledToBottom()` (`:1486`).
- **SEL-PERF-01 · `ngDoCheck` forces a layout reflow every CD cycle** — `select.component.ts:919` → `isVisible()` `:1423` reads `offsetTop`/`offsetHeight`. **Fix:** replace the geometry probe with an `IntersectionObserver` (created once in `afterNextRender`, `runOutsideAngular`); keep only the ngControl-guarded `updateErrorState()` in `ngDoCheck`. `SharedResizeObserver` is already a dependency (`select-option.directive.ts:18`).
- **SEL-PERF-02 · `calculateHiddenItems` double-clones the trigger and thrashes layout + `detectChanges`** — `select.component.ts:1301`, `getTotalItemsWidthInMatcher` `:1517`, `getTotalVisibleItems` `:1888`, `buildTriggerClone` `:1918`. Two deep clones into the live DOM, O(N) interleaved `getComputedStyle`/offset reads, up to ~2–3 synchronous `detectChanges()`. **Fix:** single off-DOM clone appended once, all reads in one loop (no interleaved writes), `offsetWidth` over `getComputedStyle` where possible, one `markForCheck` at the end, hoist the gap constant; ideally drive from a `ResizeObserver` on the matcher list.
- **SEL-PERF-03 · Uncoalesced `setTimeout(0)` per option/visibility change** — `select.component.ts:905`. `distinctUntilChanged()` can't dedupe distinct `KbqOptionSelectionChange` objects, so Ctrl+A bursts schedule one macrotask each. **Fix:** `debounceTime(0)`/`auditTime(0, animationFrameScheduler)` inside the existing `takeUntilDestroyed` pipe; funnel both recompute triggers through one shared debounced stream.
- **SEL-PERF-04 · Template binds DOM-reading/allocating getters every CD cycle** — `colorForState` `:795` (reads `classList`), `getPanelClasses()` `:1258` (allocates + joins), `hiddenItemsTextFormatter` `:983`. **Fix:** convert to `computed()` signals driven by inputs/state.
- **SEL-A11Y-06 · Cleaner control has no `role="button"`/accessible name** — `select.html:73` + projected `kbq-cleaner`. Keyboard works (focusable inner button + bubbling handlers), but the control is announced unnamed (WCAG 4.1.2). **Fix:** give `KbqCleaner` `role="button"` + a localized `aria-label` (e.g. "Clear selection"); mark the icon `aria-hidden`.
- **SEL-A11Y-07 · Optgroup not exposed as `role="group"`; bare `<label>` with no control** **(shared)** — `core/option/optgroup.ts:15`, `optgroup.html:1`. The generated `labelId` is never consumed; a `<label>` with no labelable control is semantically wrong. **Fix:** add `[attr.role]="'group'"` + `aria-labelledby`; change `<label>` → `<span id="labelId">`.
- **SEL-A11Y-08 · Pseudo-checkbox conveys multi-select state only visually** **(shared)** — `core/option/option.html:3`. Once `aria-selected` lands (A11Y-03), hide the box from AT to avoid a duplicate/empty announcement. **Fix:** `aria-hidden="true"`. Bundle with SEL-A11Y-03.
- **SEL-API-01 · `KbqSelect`/`KbqSelectChange` untyped (`any` across public surface)** — `select.component.ts:116`, `:638`, `:468`, `:1144`, `:1645`; `KbqOption.value` `option.ts:171`. **Fix:** introduce `KbqSelect<T = any>`/`KbqSelectChange<T = any>` (default `any` keeps source compatibility); thread `T` through `KbqOption<T>`/`KbqVirtualOption<T>`. API-snapshot change → `approve-api`; land in a tracked SemVer window.
- **SEL-API-02 · Dead public export `selectEvents`** **(shared)** — `core/select/events.ts:1` (surfaces in `core.api.md`). A string constant whose value equals its name, with zero consumers. **Fix:** remove the const + the empty `events.ts` + its `export *`; run `approve-api`. Breaking → schedule with a major.
- **SEL-API-03 · `searchMinOptionsThreshold` accessor types asymmetric** — `select.component.ts:396` (setter `'auto'|number|undefined`, getter `number|undefined`). `'auto'` is a write-only sentinel. **Fix:** document both accessors, or migrate to `input<'auto'|number|undefined>()` + a `computed()` resolved value.
- **SEL-API-04 · `hiddenItemsTextFormatter` is a method decorated `@Input()`** — `select.component.ts:983`; `hiddenItemsText` (`:342`) is both an `@Input` and internally overwritten by locale (`:1417`) — two sources of truth. **Fix:** convert to `readonly hiddenItemsTextFormatter = input<(text, count) => string>(...)`; keep an `input()` for `hiddenItemsText` plus a separate `computed()`/signal for the locale-merged effective text so the component never writes its own input.
- **SEL-TPL-01 · Duplicated global `kbq-select__*` theme selectors drift vs tree-select** **(shared)** — `_select-theme.scss:29,44,48` vs `_tree-select-theme.scss`; the invalid-state color token diverges. Under `ViewEncapsulation.None` both emit globally. **Fix:** extract shared placeholder/search/no-options theme rules into one core `%`-placeholder/mixin; reconcile the invalid-state token to `--kbq-foreground-error`.
- **SEL-TEST-02 · No ARIA/role/AXE coverage** — `select.component.spec.ts:1999` (`describe('accessibility')` is tabindex/keyboard only). Note: `jest-axe` **is** a workspace devDependency (`package.json:121`, with `@types/jest-axe` at `:90`) and is already used by five sibling suites, so there is no tooling cost. **Fix:** add an a11y suite asserting combobox/listbox/option roles + `aria-*` (failing until A11Y-01..04 land), and include an `axe()` assertion.
- **SEL-TEST-03 · Loading/error/empty/search-empty states untested** — `select-common.ts`; `delayBeforeDisplayingResultWithoutOptions=101` (`:159`, used `:1053`). **Fix:** add `describe('loading / empty / error states')` projecting each component and advancing timers; cover the `paging` host-class branch.
- **SEL-TEST-04 · BUG-02 teardown test misses accumulation** — `select.component.spec.ts:6655`. Only covers the destroy-race crash, not per-session subscription accumulation (LEAK-02). **Fix:** open/close several times, emit one `options.changes`, assert `setOverlayPosition` called exactly once.
- **SEL-TEST-05 · `hiddenItems` jest test monkeypatches 4 layout primitives** — `select.component.spec.ts:5253`. The stubs encode the exact measurement strategy; SEL-PERF-02 silently invalidates it. A robust e2e equivalent already exists. **Fix:** treat the e2e test as the source of truth; reduce the jest test to a thin contract check.
- **SEL-TEST-06 · e2e visual coverage misses disabled/error/loading/empty/virtual-scroll panels** — `e2e.playwright-spec.ts:53` (only 4 open-panel fixtures × light/dark). **Fix:** add demo routes + `toHaveScreenshot` for disabled, error, loading, no-options/search-empty, and a virtual-scroll open panel in both themes.

## 4. Recommended Remediation Phases

**Phase 1 — Accessibility blockers (must land together).**
IDs: SEL-A11Y-01..08 + SEL-A11Y-09 + SEL-TEST-02 (regression guards) + SEL-TEST-06 (visual states).
The combobox → listbox → option → activedescendant chain (01/02/03/04) ships as one coherent change; 05/06/07/08/09 parallelize. Write the AXE/a11y specs **first** (fail → make pass). This unblocks the release.

**Phase 2 — Lifecycle & leaks.**
IDs: SEL-LEAK-01 (do first), SEL-LEAK-02, SEL-LIFE-01..05 + SEL-TEST-04. Mechanical, low-risk; copy the `subscribeToScrolledToBottom()` pattern.

**Phase 3 — Correctness.**
IDs: SEL-BUG-01 (RTL reverse), SEL-BUG-02 (clear desync), SEL-BUG-03 (single source of truth — falls out of BUG-02), SEL-BUG-04 (default sort), SEL-BUG-05/06/07 + SEL-TEST-01/07. Order: BUG-02 before/with BUG-03; BUG-04 before TEST-01. BUG-01 can move to Phase 2 (also a perf/template win).

**Phase 4 — Performance.**
IDs: SEL-PERF-01 (IntersectionObserver), -02 (single-pass measurement), -03 (coalesce), -04 + SEL-TPL-02 (computed getters). Order: PERF-02 before the SEL-TEST-05 rewrite; depends on BUG-01 (don't reintroduce in-place `reverse()` in the new `computed`).

**Phase 5 — Modern-Angular migration, API & styles hardening (SemVer-gated).**
IDs: SEL-ARCH-01..07, SEL-API-01..07, SEL-TPL-01/03/04/05/06/07/08 + SEL-TEST-03/05/08/09 + the adjacent cleanup.
Batch the API-changing items (generics SEL-API-01, dead-export SEL-API-02, input migration SEL-ARCH-02) and run `approve-api` once; schedule breaking pieces for a major. SEL-ARCH-01 (decomposition) precedes/accompanies ARCH-02 so extracted code is migrated once. Mirror shared fixes into tree-select.

## 5. Verification Strategy

**General gates (per phase):**
- `npx jest packages/components/select/select.component.spec.ts`
- `npx jest packages/components/core/option/option.spec.ts` (option role/aria — shared)
- `yarn run eslint && yarn run stylelint && yarn run prettier`
- `yarn run check-api` (and `yarn run approve-api` only when the public API intentionally changes — Phase 5)

**Phase 1 (a11y):** new jest a11y specs — host `role="combobox"` + `aria-haspopup/expanded/controls`; `#optionsContainer` `role="listbox"` + `aria-multiselectable`; each `kbq-option` `role="option"` + `aria-selected/disabled`; `aria-activedescendant` tracks the active option; optgroup `role="group"`; tag-remove + cleaner focusable + named. If jest-axe is adopted: `expect(await axe(...)).toHaveNoViolations()` in closed and open states. Manual NVDA/VoiceOver pass. Playwright (SEL-TEST-06): `npx playwright test packages/components/select/e2e.playwright-spec.ts` with new state screenshots; verify the focus ring (WCAG 2.4.7) and 3:1 indicators across light/dark.

**Phase 2 (lifecycle):** SEL-TEST-04 — open/close panel N times, fire one `options.changes`, assert `setOverlayPosition` spy called once. SEL-LEAK-01 — create/destroy many selects; assert `localeService.changes` observer count does not grow.

**Phase 3 (correctness):** BUG-01 RTL — assert tag order and `control.value` order stable across **two** `detectChanges()` passes and that `selectionModel.selected` is not mutated. BUG-02/03 — select A+B, click cleaner, reopen, assert no option carries `kbq-selected`/`aria-selected`; single-click re-select.
