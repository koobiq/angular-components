# Koobiq `dl` Component — Code Review & Improvement Plan

> Scope: `packages/components/dl` (three components, tokens, theme, SCSS, Jest spec, e2e fixture + Playwright spec, user guides, examples stubs, API guard report) plus the docs examples and the docs navigation · Commit `b665e503` · 2026-08-28
> Generated by a multi-dimension review (architecture, correctness, RxJS/lifecycle, accessibility, performance, public API/types, styles, tests, docs) with manual verification of every finding against the source, the design tokens, the consumers and `tools/public_api_guard`. 10 findings confirmed (P0×0, P1×1, P2×6, P3×3); 6 candidate findings refuted during verification (see Appendix A). This document is a review + roadmap; no source is modified by it.

---

## 1. Executive Summary

`KbqDlComponent` is one of the better-built packages in the library: fully signal-based, `OnPush`, RTL-aware, SSR-guarded (`platform.isBrowser` on every geometry read), with a localized separator name from `kbqInjectA11yLocaleConfiguration()`, 28 Jest cases and a Playwright suite that drives real drags. The comments explain *why*, not *what*. The findings below are consequently narrow — but the top one is structural.

- **A description list with no description-list semantics.** `kbq-dl`, `kbq-dt` and `kbq-dd` are unknown elements rendering `<ng-content />` with a single class each (`dl.component.ts:31-49, 90-102`); the only ARIA in the entire package sits on the resize separator. Nothing marks a term, nothing marks its description, nothing associates the two, so the pairing that the component exists to express is available visually and not otherwise (WCAG 1.3.1). Native `<dl>`/`<dt>`/`<dd>` would have given it for free (DL-A11Y-01).
- **The "measured term width" is the term *column* width, not the term.** `measureDtWidth()` reads `getBoundingClientRect().width` off the `kbq-dt` element (`:227-232`), which is a grid item with `width: auto` and no `justify-self`, so it stretches to its track — 25% of the host in the default layout, 50% in `wide`. Both `dtMinWidth` and `ddMinWidth` document that value as "the rendered term width" (`:124, :127, :162`). The value also changes meaning with `horizontalAlign`: `center`/`end` shrink-wrap the item, `start` does not (DL-BUG-01, DL-CSS-01).
- **The default `horizontalAlign: 'start'` emits no CSS at all.** `dl.scss:19-25` styles only the `center` and `end` modifiers, so the documented default resolves to grid's own `stretch` — which is what makes the measurement above ambiguous, and what makes `start` and `stretch` indistinguishable in the API (DL-CSS-01).
- **The first layout decision is delayed by 100 ms.** `startWith(null)` is piped *before* `debounceTime(100)` (`:220-223`), so the initial emission is debounced too: a list narrower than `verticalBreakpoint` paints in the horizontal layout and flips to vertical a tenth of a second later — a visible layout shift on every mount below the breakpoint (DL-LIFE-01).
- **Geometry is read from template-bound getters.** `maxDtWidth` and `currentDtWidth` (`:174-187`) call `clientWidth` and `getComputedStyle` and are bound three times in the template (`:62-63, 75, 77`), so every change-detection pass over the parent view forces a synchronous style and layout recalculation (DL-PERF-01).

Genuine strengths worth preserving: the resize separator is the most complete ARIA implementation in the packages reviewed so far — `role="separator"`, `aria-orientation`, a localized `aria-label` with a consumer override, live `aria-valuemin`/`valuenow`/`valuemax`, `tabindex="0"`, arrow/Home/End keyboard resizing, and an RTL-aware direction vector — and it is covered by both Jest and Playwright. The cursor logic that advertises the remaining travel direction (`:315-334`) is a genuinely thoughtful touch, and `handleResizeStart`'s focus-origin demotion (`:244-248`) fixes a class of focus-ring bug that most libraries ship with. SSR is handled deliberately rather than accidentally (`e702d5549`, DS-5266).

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

None.

### P1 — High

**DL-A11Y-01 · The list exposes no description-list semantics; only the resize separator has ARIA** — `dl.component.ts:31-39, 41-49, 90-102`; the package's complete ARIA surface is `dl.component.ts:69-77`.
`KbqDtComponent` and `KbqDdComponent` are two-line components whose host blocks add exactly one class each (`:36`, `:46`), and `KbqDlComponent`'s host block adds classes and two custom properties (`:90-102`). No `role`, no `aria-*`, on any of the three. A `<kbq-dl>` is therefore an unknown element containing more unknown elements: assistive technology sees a flat run of text where the author expressed term/description pairs, and the association between "Status" and "Active" — the entire point of the component — exists only in the visual grid (WCAG 1.3.1, Info and Relationships). The native platform solves this with `<dl>`/`<dt>`/`<dd>`, which this component deliberately does not use; ARIA's equivalents, `role="term"` and `role="definition"`, are supported in ARIA 1.2 and are exactly what the native elements map to. Note this is a WCAG judgement, not an automated failure — axe-core does not flag a custom element that carries no role, which is why 28 Jest cases and a full Playwright suite have never noticed. The contrast inside the package is what makes it a finding rather than an omission: the separator right next to it has `role`, `aria-orientation`, a localized `aria-label`, and all three `aria-value*` attributes.
**Fix:** add `role: 'term'` to `KbqDtComponent`'s host block and `role: 'definition'` to `KbqDdComponent`'s, and give `KbqDlComponent` an optional `ariaLabel` input surfaced as `aria-label` so a list can be named. Do not add `role="list"` on the container — `listitem` children are then required and neither leaf is one; leave the container generic (the future-correct `role="associationlist"` has no AT support yet, and should be revisited when it does). Verify with a `jest-axe` pass plus an explicit assertion per role, and add one manual screen-reader check to the phase's acceptance criteria — this is the kind of fix that passes automation while still announcing badly.

### P2 — Should fix

**DL-BUG-01 · The "measured term width" measures the stretched grid item, so the default minimum is a fraction of the host, not the term** — `dl.component.ts:162-169, 227-232`; documented otherwise at `:124, :127, :162`; `dl.scss:9, 19-25, 27-29`.
`measureDtWidth()` takes the first `kbq-dt` element and stores `Math.round(term.getBoundingClientRect().width)` (`:229-231`). That element is a grid item with `width: auto` and no `justify-self`, inside a container that sets `justify-items` only for the `center` and `end` modifiers (`dl.scss:19-25`) — so in the default configuration it is stretched to its track and the measurement returns the *column* width: one quarter of the host under `repeat(4, 1fr)` (`dl.scss:9`), one half under `wide` (`dl.scss:124`). That value then becomes the default for both `resolvedDtMinWidth` and `resolvedDdMinWidth` (`:166-169`), i.e. the minimum drag width and the maximum drag width both derive from an arbitrary fraction of whatever the host happened to be when the component first rendered. Three consequences: the JSDoc on `dtMinWidth`/`ddMinWidth` and the comment on `measuredDtWidth` are wrong about what the fallback is; the fallback silently changes meaning when `horizontalAlign` is `center` or `end`, where the item shrink-wraps and the measurement really is the text width; and a wide host produces a large minimum that a later narrow host cannot go below, because the measurement never re-runs (DL-BUG-02).
**Fix:** measure the content, not the box — wrap the term's text in a measuring pass that reads `scrollWidth` on a shrink-wrapped clone, or simply set `justify-items: start` for the default alignment (DL-CSS-01) so the item's own box *is* the content box and the current call becomes correct. Then fix the JSDoc to describe whichever is chosen. The regression test must distinguish the two: render a short term in a wide host and assert `aria-valuemin` is close to the text width and far below 25% of the host — the current e2e case cannot fail (DL-TEST-01).

**DL-BUG-02 · The term measurement runs once and never again, so async or changing content leaves the minimum stale** — `dl.component.ts:203, 217-224, 227-232`.
`terms` is a `contentChildren` signal (`:203`), but `measureDtWidth()` reads it imperatively inside `afterNextRender` (`:218`) rather than from a reactive context, and nothing calls it again — `updateLayout()` (`:284-303`) recomputes the layout and the cursor but not the measurement. Three real cases follow. A list whose terms arrive later (behind `@if`/`@for` over async data, the normal case for a details panel) measures `this.terms()[0]` as `undefined`, leaves `measuredDtWidth` at `0`, and therefore ships a minimum column width of zero — the separator can be dragged until the term column vanishes. A list whose terms change (locale switch, a longer label) keeps the old minimum. And a web font that loads after first render shifts every term without updating the value. The guard at `:231` (`if (term)`) makes the failure silent rather than throwing.
**Fix:** drive the measurement from the query instead of from a single render pass — an `effect()` over `terms()` that re-measures (guarded by `afterNextRender` for the first run), or extend the existing `SharedResizeObserver` subscription to observe the first term element as well as the host. Add a Jest case that renders the list with no terms, adds one, and asserts `aria-valuemin` changes from `0`; it fails today.

**DL-CSS-01 · `horizontalAlign: 'start'`, the documented default, emits no CSS and resolves to `stretch`** — `dl.component.ts:136-137, 98-99`; `dl.scss:19-25`.
The input is typed `KbqDlAlign = 'start' | 'center' | 'end'` and defaults to `'start'` (`:29, 137`), but the host binds classes only for the two other values (`:98-99`), and the stylesheet defines rules only for those two (`dl.scss:19-25`). Nothing ever writes `justify-items: start`, so the default renders as grid's initial `normal`, which for a blockified grid item with `width: auto` is `stretch`. For plain text the difference is invisible, which is why it has survived — but it is not invisible everywhere: a `kbq-dt` carrying a background, a border or a nested component stretches the full column instead of hugging its content, `text-align` inherits differently, and, most consequentially, it is what makes the default minimum-width measurement measure the wrong box (DL-BUG-01). The same asymmetry exists for `verticalAlign`, where `'start'` also emits nothing — but there grid's `normal` for a stretched item genuinely coincides with `start` for text, so only the horizontal axis misbehaves.
**Fix:** emit the `start` case explicitly — either add `.kbq-dl_horizontal-align-start { justify-items: start }` and bind it like its siblings, or set `justify-items: start` as the base rule on `.kbq-dl` and let the modifiers override. Prefer the second: it makes the default the one the API documents and fixes DL-BUG-01's measurement without any TypeScript change. Requires a Playwright baseline refresh (the terms stop stretching), which is the visible proof the fix landed.

**DL-LIFE-01 · `startWith(null)` before `debounceTime(100)` delays the first layout decision by 100 ms** — `dl.component.ts:189, 217-224`.
The resize subscription is `observe(host).pipe(startWith(null), debounceTime(this.resizeDebounceInterval), takeUntilDestroyed(...))` (`:220-223`). `debounceTime` delays *every* emission, including the synthetic one `startWith` injects, so `updateLayout()` — which is what decides between the horizontal and vertical layouts (`:284-293`) — first runs 100 ms after render. A list mounted below `verticalBreakpoint` (default 400 px, `:106`) therefore paints its terms and descriptions side by side, then reflows into stacked rows a tenth of a second later. On a page with several such lists (a details panel, the usual habitat) that is a visible cascade of layout shift, and it is worse on slow devices where the debounce competes with hydration. The intent is clearly the opposite — `startWith(null)` exists precisely to get an immediate first evaluation.
**Fix:** swap the order — `observe(host).pipe(debounceTime(interval), startWith(null), takeUntilDestroyed(...))` — so the synthetic emission bypasses the debounce and only genuine resize bursts are throttled. Guard it with a `fakeAsync` case that creates a narrow fixture, runs zero timers, and asserts `kbq-dl_vertical` is already present; today it only appears after `tick(100)`.

**DL-PERF-01 · Three template bindings read live layout through getters, forcing style and layout recalculation on every change-detection pass** — `dl.component.ts:62-63, 75, 77, 174-187, 299-302`.
`maxDtWidth` (`:174-181`) reads `nativeElement.clientWidth` *and* `window.getComputedStyle(...).columnGap`; `currentDtWidth` (`:183-187`) reads `resizeTrack().nativeElement.clientWidth`. Both are plain getters, and the template binds them four times: `[style.max-width.px]` (`:62`), `[attr.aria-valuemax]` (`:75`), `[attr.aria-valuenow]` (`:77`), plus `maxDtWidth` again inside `setDtWidth`/`updateResizeCursor` on every drag frame (`:308, 320`). Angular re-evaluates template expressions on every check of the containing view, so each pass over a page holding these lists triggers a forced synchronous style resolution (`getComputedStyle`) and two layout reads — the classic layout-thrash pattern, and the reason `updateLayout()` needs the explicit `markForCheck()` whose comment (`:299-302`) accurately describes the design but not its cost. During a pointer drag this runs per `sizeChange` event.
**Fix:** cache the two geometry values in signals updated from the places that already know geometry changed — the `SharedResizeObserver` callback and the drag handlers — and bind the signals instead of the getters. `columnGap` in particular changes only with the theme, so read it once per resize rather than per check. Verify with a performance trace over `dev:dl` during a drag: forced reflows per second should drop to the observer's rate, and the `markForCheck()` at `:302` should become unnecessary.

**DL-TEST-01 · Every geometry assertion runs against jsdom's zeros, and the one e2e case that verifies the measurement compares it with itself** — `dl.component.spec.ts:485-494`; `e2e.playwright-spec.ts:153-167`.
The Jest suite is substantial — 28 cases covering inputs, classes, the deprecated alias, keyboard resizing, the localized `aria-label` and RTL — but jsdom performs no layout, so `getBoundingClientRect()` and `clientWidth` are `0` throughout. That is visible in the assertions themselves: the negative-minimum case asserts `aria-valuemin` is `'0'` (`:493`), which is equally true of a correctly clamped `-50` and of a measurement that never happened. The suite compensates with `Object.defineProperty` mocks for `getClientRects` (`:500-502`), but only for the vertical-layout decision — the width path is unmocked. On the Playwright side, the case named *"should default the dt and dd minimums to the measured term width when they are not set"* (`e2e.playwright-spec.ts:153-167`) reads `termWidth` from `getFirstTerm(block).boundingBox().width` and asserts `aria-valuemin` is close to it — but `aria-valuemin` was itself computed from `getBoundingClientRect()` on that same stretched element, so the assertion restates the implementation and holds no matter which box is measured. It is exactly the case that should have caught DL-BUG-01.
**Fix:** mock `clientWidth`/`getBoundingClientRect` in the Jest width cases so the clamping maths is exercised against non-zero geometry, and rewrite the e2e case to assert against something independent of the implementation: a short term in a wide host must yield `aria-valuemin` far below the column width (e.g. under 30% of it). Mutation check: replacing `measureDtWidth`'s body with a constant `0` must fail at least one test — today it fails none in Jest and none in Playwright.

### P3 — Nice to have / hygiene

**DL-API-01 · The two leaf components miss `OnPush`, the module imports two CDK modules nothing uses, and 12 `protected` members are published** — `dl.component.ts:31-39, 41-49`; `dl.module.ts:1-13`; `tools/public_api_guard/components/dl.api.md:13-19, 28, 32-35, 37, 39, 42, 44-48`.
Three surface issues. (1) `KbqDtComponent` and `KbqDdComponent` are declared without `changeDetection: ChangeDetectionStrategy.OnPush` (`:31-38, 41-48`) while their parent has it (`:88`) — AGENTS.md states the strategy on every `@Component`, and here it means every `kbq-dt`/`kbq-dd` in a list is checked by the default strategy on every application tick. (2) `dl.module.ts:8-9` imports `A11yModule` and `PlatformModule`; the component imports `CdkMonitorFocus` directly in its own `imports` array (`:53`) and `Platform` is `providedIn: 'root'`, so neither module import does anything — the same legacy scaffolding `badge.module.ts:8-9` carries. (3) The API report publishes 12 `protected` members — `currentDtWidth`, `maxDtWidth`, the four `handle*` methods, `isVertical`, `normalizedDtMinWidth`, `resizeCursor`, `resizeDirection`, `resizerVisible`, `resolvedResizerAriaLabel` — because API Extractor treats `protected` as part of the subclass contract; `@docs-private` hides them from the docs site but not from the report, and both leaf classes plus `KbqDlComponent` are `(undocumented)` at class level despite the thorough member JSDoc.
**Fix:** add `changeDetection: ChangeDetectionStrategy.OnPush` to both leaf components (no behaviour change — neither has state); delete the two module imports; add class-level JSDoc to all three. Consider making the geometry getters `private` once DL-PERF-01 replaces them with signals, which removes most of the protected surface. All of this changes `dl.api.md`, so run `yarn run build:components` then `yarn run approve-api` — build first, the guard reads `dist/*.d.ts`.

**DL-CSS-02 · The default track is `1fr`, not `minmax(0, 1fr)`, so a long unbreakable term expands its column** — `dl.scss:9, 38-40, 44-46, 124, 127, 131`.
`grid-template-columns: repeat(4, 1fr)` (`:9`) expands to `minmax(auto, 1fr)`, and `auto` as a minimum is the item's min-content size — so a term containing an unbreakable string (a path, a UUID, a long identifier, all normal in the details panels this component is built for) pushes its column past the intended quarter and squeezes the description. The resizable branches already avoid this: `:38-40` and `:44-46` use `minmax(0, 1fr)` for the description columns, and `:127`/`:131` do the same in `wide` — so the author knew the pattern and applied it only where the resizer forced the issue. The non-resizable default, which is what every shipped example uses, still carries `1fr`.
**Fix:** change `:9` to `grid-template-columns: repeat(4, minmax(0, 1fr))` and `:124` to `repeat(2, minmax(0, 1fr))`, and add `min-width: 0` to `.kbq-dt`/`.kbq-dd` so the items themselves can shrink. Add an e2e row with a 60-character unbroken term to the states fixture; its baseline is the regression guard.

**DL-DOC-01 · Six of eleven inputs are undocumented, and the examples stubs are dead** — `dl.en.md:1-25`, `dl.ru.md`, `examples.dl.en.md:1-5`, `examples.dl.ru.md:1-5`, `apps/docs/src/app/structure.ts:517-529`.
The guide is 25 lines: one sentence and five example embeds, with a two-sentence note on `resizable`, `dtMinWidth`, `ddMinWidth` and `[(dtWidth)]` (`:21-23`). Nothing documents `vertical`, `verticalBreakpoint`, `wide`, `verticalAlign`, `horizontalAlign` or `resizerAriaLabel` — including the fact that `verticalBreakpoint` is what makes the "adaptive" behaviour in the first two examples work, and that `vertical` accepts `null` to hand the decision back to the breakpoint. The deprecated `minWidth` (`dl.component.ts:108-113`) is documented only in the source; it also lacks the `numberAttribute` transform its replacement has (`:106` vs `:113`), so `verticalBreakpoint="300"` type-checks as a static attribute under `strictTemplates` while `minWidth="300"` does not — an inconsistency between an input and its own alias. Separately, `examples.dl.en.md`/`.ru.md` are the standard "🚧 Documentation in progress 🚧" stubs and `structure.ts:528` sets `hasExamples: false`, so the Examples tab never renders and both files are unreachable.
**Fix:** add a properties table to both guides covering all eleven inputs, the `dtWidthChange` output and the deprecation, and state the adaptive rule explicitly (`vertical` overrides; otherwise the host width is compared against `verticalBreakpoint` on every resize). Add `numberAttribute` to `minWidth` so the alias behaves like its replacement, and plan an `ng-update` migration rewriting `minWidth` to `verticalBreakpoint` for the release that removes it (see `project_breaking_changes_need_migration_schematics`). Delete the two example stubs, or populate them and flip `hasExamples: true`.

## 4. Recommended Remediation Phases

**Phase 1 — Give the list semantics.**
IDs: DL-A11Y-01. Add `role="term"`/`role="definition"` to the leaf components and an optional accessible name to the container. Independent of everything else, and the only finding here that changes what a non-visual user experiences.

**Phase 2 — Fix what the default alignment and the measurement mean.**
IDs: DL-CSS-01, DL-BUG-01, DL-BUG-02. Emit `justify-items: start` as the base rule, then re-derive the measurement (which the CSS change alone may make correct), then make it re-run when the terms change. Sequenced this way because the CSS fix changes what the measurement returns, so doing it first avoids fixing the same number twice. Needs refreshed Playwright baselines.

**Phase 3 — Timing and geometry cost.**
IDs: DL-LIFE-01, DL-PERF-01. Swap `startWith`/`debounceTime`, and move the two geometry getters behind signals updated from the observer and the drag handlers. Both are contained to the constructor and the two getters, and both become verifiable once Phase 2's tests exist.

**Phase 4 — Coverage, surface and documentation.**
IDs: DL-TEST-01, DL-API-01, DL-CSS-02, DL-DOC-01. Mock geometry in the Jest width cases and rewrite the tautological e2e case, add `OnPush` to the leaves, drop the unused module imports, switch the default tracks to `minmax(0, 1fr)`, and write the properties tables in one `approve-api` cycle.

## 5. Verification Strategy

General gates, run sequentially (never in parallel — see `project_no_parallel_heavy_builds`):
- `npx jest packages/components/dl`, plus `packages/components/resizer` — `KbqResizer`/`KbqResizable` are consumed directly (`dl.component.ts:25`) and any change to the drag contract lands here.
- `yarn run eslint`, `yarn run stylelint`, `yarn run prettier` on touched files.
- `yarn run build:components`, then `yarn run check-api`; `approve-api` only in Phase 4.
- `yarn run e2e:docker` for anything visual; baselines only via `yarn run e2e:docker:update-snapshots`.
- Manual smoke: `yarn run dev:dl`, plus the `dl-resizable` docs example for the two-way `[(dtWidth)]` path.

Per-phase assertions:
- **Phase 1:** `getComputedRole` reports `term` on every `kbq-dt` and `definition` on every `kbq-dd`; `jest-axe` reports no new violations; a screen reader announces term and description as a pair on the `dl-overview` example.
- **Phase 2:** in a 1000 px host with a 40 px term, `aria-valuemin` is close to 40, not to 250. Rendering the list with terms behind an `@if` that flips after mount raises `aria-valuemin` from `0`. A term with a background hugs its text instead of spanning the column (screenshot).
- **Phase 3:** a fixture narrower than `verticalBreakpoint` carries `kbq-dl_vertical` on its first rendered frame with no timer advanced. A Chrome performance trace of a drag shows forced reflows at the observer's rate rather than per change-detection pass, and removing the `markForCheck()` at `:302` no longer stales the `aria-value*` attributes.
- **Phase 4:** `npx jest packages/components/dl` stays green and a `measureDtWidth` stubbed to `0` fails at least one Jest case and one Playwright case. A 60-character unbroken term no longer widens its column. `dl.api.md` diff contains only the JSDoc and `OnPush` transitions.

## Appendix A — Review Methodology

Findings were gathered by reading the whole package (`dl.component.ts` in full, the stylesheet, tokens, theme, the 629-line Jest spec, the 154-line e2e fixture and the 169-line Playwright spec, both guides and both example stubs), then cross-checking each candidate against the API guard report, the docs navigation, the design tokens, the five docs examples plus the `breadcrumbs-size` example that consumes `KbqDlModule`, and the package's eight-commit history — of which `f42396102` (DS-4609, column resizing) introduced everything the resizer findings touch and `e702d5549` (DS-5266) is the SSR guard that the geometry getters still honour. Two findings came from reading the CSS and the TypeScript against each other rather than either alone: the default alignment emits no rule (DL-CSS-01), which is what makes the measurement measure a track instead of a word (DL-BUG-01).

Refuted during verification:
- **"`SharedResizeObserver` is imported from `@angular/cdk/observers/private`, an unstable entry point"** — refuted as a dl-specific defect. The same import appears in `actions-panel/actions-panel.ts:3`, `clamped-text/clamped-text.ts:1`, `code-block/code-block.spec.ts:1` and their specs; it is an established library-wide convention, and a change would be a cross-cutting decision, not a fix to this package.
- **"`--kbq-description-list-dt-width` is undeclared, so the `kbq-dl_resized` grid template resolves to nothing"** — refuted. The custom property is written by the host style binding at `:100`, and the class it is used with (`:95`) is bound to the same `dtWidth() !== null` condition, so the property is always present exactly when the rule that consumes it applies.
- **"`aria-orientation` on `role="separator"` is invalid and will fail `aria-allowed-attr`"** — refuted. `aria-orientation` is invalid on `role="group"` but explicitly allowed on `role="separator"`; and a separator with `tabindex="0"` and `aria-value*` is the correct focusable-splitter pattern, which is what this is.
- **"Writing the `dtWidth` model from `updateLayout()` causes `ExpressionChangedAfterItHasBeenChecked`"** — refuted. `updateLayout` runs from a debounced RxJS subscription (`:220-223`), i.e. outside the change-detection pass, not from a lifecycle hook or a template expression.
- **"The deprecated `minWidth` input is dead weight"** — refuted. It is honoured at `:290`, where it takes precedence over `verticalBreakpoint`, exactly as its JSDoc promises (`:110-111`). Its only real problem is the missing `numberAttribute`, folded into DL-DOC-01.
- **"The package is missing structure files"** — refuted. `dl-tokens.scss`, `_dl-theme.scss`, `dl.module.ts`, `e2e.ts`, `e2e.playwright-spec.ts` and both guides are all present; this is one of the more completely scaffolded packages in the library.

Corrected on verification:
- **DL-A11Y-01** was first drafted as an AXE failure and therefore a candidate P0 under the AGENTS.md mandate. axe-core does not flag unknown elements that carry no role, so the claim was narrowed to a WCAG 1.3.1 judgement and filed as P1 — the same treatment the equivalent finding received in `divider`.
- **DL-BUG-01** was first drafted as "`measuredDtWidth` is always `0`", which is what the Jest spec shows (`:493`). That is a jsdom artefact; in a browser the value is non-zero but measures the column rather than the term, which is a subtler and more interesting defect, and it reframed the e2e case as evidence rather than coverage.
- **DL-CSS-01** was first drafted as "`horizontalAlign` has no effect". `center` and `end` do work (`dl.scss:19-25`); only the default `start` is unimplemented, which is both narrower and more consequential than the original claim.
