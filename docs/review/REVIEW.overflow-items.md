# Koobiq `overflow-items` Component — Code Review & Improvement Plan

> Scope: `packages/components/overflow-items` (three directives in one 377-line file, Jest spec, e2e fixture + Playwright spec, both user guides, examples page, API guard report, docs-structure entry, dev app) plus every in-repo consumer · Commit `b665e503` · 2026-08-28
> Generated by a multi-dimension review (architecture, RxJS/lifecycle, correctness, accessibility, performance, public API/types, styles, tests, docs) with manual verification of every finding against the source, the 20 in-repo call sites, the API guard report and git history. 13 findings confirmed (P0×0, P1×3, P2×4, P3×6); 7 candidate findings refuted during verification (see Appendix A). This document is a review + roadmap; no source is modified by it.

## 1. Executive Summary

`KbqOverflowItems` is the library's responsive-collapse engine: a container directive that measures its own box against the sum of its items and hides the ones that do not fit, plus two satellite directives (`KbqOverflowItem`, `KbqOverflowItemsResult`) sharing a `ElementVisibilityManager` base. It is load-bearing — `breadcrumbs` ships it in production markup (`breadcrumbs.html:12`), `top-bar` styles it from the outside, and there are **20 `kbqOverflowItems` host call sites across 19 files** in three component packages and sixteen docs examples. There are no release blockers, but three separate contracts the package publishes are not the ones it honours.

- **The one input that exists to bound the cost of the measurement is the one input that never takes effect.** `setupObservers()` builds the pipe from the constructor (`overflow-items.ts:249`) and reads `this.debounceTime()` while doing so (`:272`). Angular applies inputs *after* the directive instance is constructed — for property bindings and for static attributes alike — so that read always returns the default `0`, and `[debounceTime]="700"` is silently discarded. Both guides devote a section to the feature ("Enabling this option positively affects performance when there are many elements or when the container size changes frequently", `overflow-items.en.md:36-43`, `.ru.md:36-43`), and its default was deliberately tuned in `c684019b2` (DS-3788). Neither the Jest case nor the Playwright case can tell 0 from 700 (OVF-LIFE-01).
- **The overflow arithmetic cannot see `gap`.** `hasOverflown()` sums each item's border box plus its own margins (`overflow-items.ts:217-225, 359`) and compares that to the container's content box; the container's `gap`/`column-gap` never enters the sum. A `gap`-spaced container therefore under-counts by `(visible − 1) × gap`, leaves items clipped behind the forced `overflow: hidden`, and reports a "and N more" count that is too low. The evidence that this is real is that **not one of the 20 call sites uses `gap`** — every one of them spaces items with per-item margins instead, and `top-bar` goes as far as writing `gap: unset` on its own container (`top-bar.scss:49`) and re-implementing the spacing as `margin-right` on another package's classes (`top-bar.scss:4-21`) (OVF-BUG-01, and the mirror image of TB-ARCH-01).
- **Focus that is inside an item when it overflows is destroyed with no recovery.** `hide()` sets `visibility: hidden` (`:60`), which correctly removes the subtree from the tab order and the accessibility tree — but nothing checks whether `document.activeElement` is inside the element first, and nothing moves focus anywhere. Consumers put real interactive controls inside items: breadcrumb links (`breadcrumbs.html:13-16, 41-46`), top-bar action buttons (`top-bar/e2e.ts:60-72`), actions-panel buttons (`actions-panel/e2e.ts:18-32`). The documented trigger is exactly the responsive case — the guide names sidebar collapse (`overflow-items.en.md:45-48`) — so a keyboard user tabbed onto the third breadcrumb loses focus to `<body>` when the sidebar opens (OVF-A11Y-01).
- **The package ships no stylesheet at all, so every layout decision is an inline style and other packages have to style it from outside.** `setStyles()` writes `position`, `overflow`, `display`, `flex-grow`, `flex-direction` and `flex-wrap` through `Renderer2` (`:328-345`); inline declarations outrank any author stylesheet, so a consumer cannot change them without `!important`. Two packages already pad around the forced `overflow: hidden` to stop it clipping focus rings — `breadcrumbs.scss:17-20` (`padding: 1px`, with the comment "add space not to cut focus outline") and `top-bar.scss:5`, which then needs negative margins at `:52-53` to undo the height that padding adds (OVF-ARCH-01).

Genuine strengths, and they are substantial. This is one of the most modern files in the library: signal inputs and outputs throughout, signal content queries, `inject()`, no `@HostBinding`, no decorators-as-bindings, a single `takeUntilDestroyed()` chain, and `KBQ_WINDOW` rather than a bare `getComputedStyle`. Resize observation goes through the shared `SharedResizeObserver` rather than a per-instance listener — the exact scale problem the `title` review had to file — and the `switchMap` teardown of dynamic resize targets is proven by three dedicated specs (`overflow-items.spec.ts:214-290`). SSR is guarded deliberately (`:253`, added by `e702d5549`/DS-5266) and `debounceTime(0)` is load-bearing rather than decorative: it moves the style writes out of the `ResizeObserver` callback that produced the event. And the Playwright suite is the best behavioural coverage of any measurement-driven component in this library — **38 assertion-based tests with no screenshot baselines at all**, so the real layout engine decides every expectation and there is no Docker snapshot gate to fight.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

None.

### P1 — High

**OVF-LIFE-01 · The `debounceTime` input is read in the constructor, before Angular applies inputs, so every value other than the default is discarded** — `overflow-items.ts:162-167, 247-250, 252, 272`; docs `overflow-items.en.md:36-43`, `overflow-items.ru.md:36-43`; tests `overflow-items.spec.ts:294-318`, `e2e.playwright-spec.ts:312-323`.
The constructor calls `this.setupObservers()` (`:249`), which terminates in `.pipe(debounceTime(this.debounceTime()), takeUntilDestroyed())` (`:272`). `this.debounceTime()` is read there as a plain synchronous call, not inside any reactive context, and the class field that holds it (`:167`) is initialized before the constructor body runs. Angular constructs the directive instance first and only then writes inputs — `instantiateAllDirectives` calls `setInputsFromAttrs` *after* the instance is returned, so this is true for the static-attribute form `debounceTime="100"` exactly as it is for `[debounceTime]="700"`. The pipe is therefore always built with `0`, and the public input has no effect whatsoever; even if the initial read were correct, nothing re-pipes when the input later changes, unlike `orientation`, `reverseOverflowOrder` and `additionalResizeObserverTargets`, all three of which are consumed reactively through `toObservable` (`:257, 267-269`). This is not a latent input nobody uses: both guides sell it as the performance escape hatch for "many elements or frequent container size changes", the author shipped a dedicated fix to tune its default (`c684019b2`, DS-3788, which lowered `100` → `0`), and it is the only mitigation the library offers for OVF-PERF-01. Neither existing test can detect the defect. The Jest case asserts `directive.debounceTime()` is `100` (`overflow-items.spec.ts:312`) — which is true, the *signal* holds 100; it then does `hostResize$.next(); tick(100)` and expects one call (`:314-317`), which is satisfied identically at debounce 0 and at debounce 100. The Playwright case (`e2e.playwright-spec.ts:312-323`) resizes a fixture configured with `debounceTime: 700` (`e2e.ts:160`) and waits on a web-first assertion whose default timeout is longer than either value.
**Fix:** make the debounce reactive instead of captured: replace `debounceTime(this.debounceTime())` with `debounce(() => timer(this.debounceTime()))`, which re-reads the signal per emission, or pipe the whole trigger stream through `toObservable(this.debounceTime).pipe(switchMap((ms) => trigger$.pipe(debounceTime(ms)))) `. Make the Jest case discriminating — `hostResize$.next(); tick(50); expect(spy).not.toHaveBeenCalled(); tick(50); expect(spy).toHaveBeenCalledTimes(1)` — because as written it passes against a component that ignores the input entirely, and a coverage assertion that survives the bug it names is worth nothing. Then audit the file for the same shape: `setStyles()` (`:248`) is safe only because both signals it reads are read inside `toObservable` subscriptions rather than eagerly.

**OVF-BUG-01 · The overflow measurement counts item margins but never the container's `gap`, so `gap`-spaced containers clip silently** — `overflow-items.ts:217-225, 233-241, 347-363`; consumers `top-bar.scss:4-21, 49`, six docs examples, `actions-panel/e2e.ts:29`.
In the default `nowrap` path, `hasOverflown()` compares `containerSize − paddingStart − paddingEnd` (`:357-358`) against `itemsSize + resultSize`, where each item contributes `getBoundingClientRect().width + marginLeft + marginRight` (`:217-225`). Flexbox `gap` is neither a margin nor a padding: it is distributed between items by the layout algorithm and appears in none of the three quantities the directive reads. A container with `gap: 8px` and twenty 50px items therefore measures 1000px of content where the browser lays out 1152px, so the loop stops hiding roughly three items too early; the surplus is clipped by the `overflow: hidden` the directive writes on itself (`:330`), and the "and N more" count the result element renders is wrong by the same margin. Nothing warns — no console message, no visible error, just quietly truncated content in the component whose entire purpose is to not truncate content. The consumer evidence is unanimous: across all 20 in-repo host call sites there is not a single `gap` declaration on a `.kbq-overflow-items` element (verified by grep), and every one of them expresses item spacing as a per-item margin instead — `layout-margin-right-xs` in five `overflow-items` examples, `layout-margin-bottom-xs` in the vertical one, `layout-margin-left-xxs` in `actions-panel/e2e.ts:29`, and `top-bar` going furthest of all: `gap: unset` on its container when it `:has(.kbq-overflow-items)` (`top-bar.scss:48-49`) plus a `_overflow-items-margins` mixin (`:4-21`) that reconstructs the spacing as `margin-right` written onto *another package's* item class. Note the `wrap` path is immune, because `isCrossAxisExceeded` (`:226, 242`) reads `scrollHeight`/`clientHeight` — a real layout measurement that already includes gaps.
**Fix:** add the gap to the sum. Read `columnGap`/`rowGap` from the container's computed style (already fetched at `:356`), resolve `normal` to `0`, and add `gap × (visibleCount − 1)` — counting the result element when it is visible — inside `hasOverflown`. Extend `orientationConfig` with a `gap: ({ columnGap }) => parseFloat(columnGap) || 0` member per orientation so the two axes stay symmetric with the existing `paddingStart`/`paddingEnd` pattern. Then prove it by deletion: an e2e row with `gap: 10px` and no item margins must hide exactly as many items as the existing `overflowItems_marginRight` row (`e2e.ts:140`, 14 hidden), and the acceptance criterion for the fix is removing the `layout-margin-*` classes from the six docs examples and deleting `top-bar`'s `_overflow-items-margins` mixin in favour of a `gap` — which is also what TB-ARCH-01 asks for from the other side of the boundary.

**OVF-A11Y-01 · Focus inside an item that overflows is destroyed, with no detection and no recovery** — `overflow-items.ts:59-63, 117-121, 301-323`; consumers `breadcrumbs.html:13-16, 17-28, 41-46`, `top-bar/e2e.ts:60-72`, `actions-panel/e2e.ts:18-32`.
`getHiddenItems()` hides items by calling `ElementVisibilityManager.hide()`, which sets `visibility: hidden` and `position: absolute` (`:60-61`). The hiding primitive itself is correct — per HTML's "being rendered" definition such content is neither focusable nor exposed to assistive technology, so hidden items genuinely leave the tab order — but that is exactly what makes the omission dangerous. Nothing anywhere in the package asks whether the element about to be hidden contains `document.activeElement`, and nothing calls `focus()` afterwards, so when a resize hides the item the user is standing on, the browser blurs it and focus falls back to `<body>`: the next Tab restarts from the top of the document, and a screen-reader user's reading position is lost with no announcement. This is not hypothetical for this component's actual consumers, all of which put focusable controls inside items — `breadcrumbs.html:41-46` wraps a `kbq-button` link per breadcrumb, `top-bar/e2e.ts:60-72` and `actions-panel/e2e.ts:18-32` wrap action buttons — and the guide advertises precisely the scenario that triggers it, recommending `additionalResizeObserverTargets` for containers that resize when *another* element does, naming sidebar collapse (`overflow-items.en.md:45-48`, `.ru.md:45-48`). `reverseOverflowOrder`, which `breadcrumbs.html:12` uses in production, makes it more likely still, because it hides from the start of the list where the user is more likely to be. AGENTS.md states focus management as part of the WCAG AA mandate; this is a WCAG 2.4.3 judgement rather than an automated axe failure, since axe cannot observe a focus transition. The package also provides no ARIA text of its own at all, so `kbqInjectA11yLocaleConfiguration()` never comes into play — every consumer labels the result element itself (`breadcrumbs.html:23`, `actions-panel/e2e.ts:40`).
**Fix:** in `getHiddenItems()`, before each `itemToHide.hide()`, test `itemToHide.element.contains(this.document.activeElement)`; when true, remember it and after the loop move focus to the result element if it is visible, otherwise to the last still-visible item, using `FocusMonitor.focusVia(target, 'program')` so the focus ring is restored the way the rest of the library does it (see `project_kbq_focus_ring_mechanism`). The result element is the right target because in every real consumer it *is* the affordance that now contains the hidden item — breadcrumbs' expand button opens a dropdown listing exactly the hidden entries (`breadcrumbs.html:31-39`). Guard the whole thing behind `platform.isBrowser`, and cover it with a Playwright case: focus `Item3` in `overflowItems_default`, narrow the container to 200px, assert `document.activeElement` is the result element and not `body`. Document the behaviour in the guide's (currently absent) accessibility section — see OVF-DOC-01.

### P2 — Should fix

**OVF-PERF-01 · Every recalculation is a show-everything / hide-one / remeasure-everything loop, and the default observes `document.body`** — `overflow-items.ts:169-174, 255-264, 301-323, 347-363`.
`getHiddenItems()` starts by calling `show()` on every item (`:309`), which issues two `removeStyle` calls per item regardless of whether anything changed, then enters `while (this.hasOverflown(...))` (`:311`), hiding exactly one item per iteration (`:318`) and re-measuring the entire set on the next check. `hasOverflown()` performs one `getComputedStyle(container)` plus one `getBoundingClientRect(container)`, then for every still-visible item one `getComputedStyle` and one `getBoundingClientRect` (`:217-225`). For the package's own default fixture — 20 items of 50px, container 500px, result 100px, 12 hidden (`e2e.playwright-spec.ts:22-29`) — that is 13 iterations over a shrinking set of 20…8 items: roughly 200 `getBoundingClientRect` calls and 200 `getComputedStyle` reads, each iteration separated from the last by a style write, which means about a dozen *forced synchronous layouts* per recalculation. The cost is then multiplied by the trigger set: `additionalResizeObserverTargets` defaults to `this.document.body` (`:174`), so every layout change anywhere on the page — a dropdown that lengthens the document, a list that loads — re-runs the full pass for every `KbqOverflowItems` instance mounted, and the only documented way to bound that is the input OVF-LIFE-01 shows is dead. A secondary hazard: because the pass *shows everything first*, an instance inside a shrink-to-fit parent momentarily grows its own box, which the host `ResizeObserver` at `:256` will report; the inline `flex-grow: 1` (`:332`) is what keeps this from oscillating in the layouts used in-repo, which is a fragile thing to be relying on.
**Fix:** measure once per pass, decide arithmetically, write once. With all items shown, collect `[size]` for every item and for the result in a single read phase; compute the largest prefix (or suffix, under `reverseOverflowOrder`) that fits, honouring `alwaysVisible`; then apply the hides in one write phase. That reduces the pass to two forced layouts instead of N and to 2N CSSOM reads instead of N². Keep one verification re-measure at the end for the case where items are allowed to shrink (items are not required to set `flex-shrink: 0`, see OVF-DOC-01), and bail out of the write phase entirely when the computed hidden set equals the previous one — which is also the fix for OVF-API-01. Land OVF-LIFE-01 first so the debounce actually bounds the remaining cost, and consider narrowing the `additionalResizeObserverTargets` default from `document.body` to nothing, documenting the change as breaking.

**OVF-BUG-02 · `wrap` — and per-item `order` / `alwaysVisible` — never trigger a recalculation** — `overflow-items.ts:195-200, 266-271, 342-344, 353`; test `overflow-items.spec.ts:458-471`.
The trigger stream merges exactly four sources: the item query, `reverseOverflowOrder`, `orientation`, and the resize observers (`:266-271`). `wrap` is absent. Changing it does re-write `flex-wrap` on the host (`:342-344`), and `hasOverflown` does read the current value when it next runs (`:353`) — but nothing schedules that run. Whether the component recovers is therefore left to chance: it recovers only if the wrap change happens to alter the *host's own border box*, which is exactly what does not happen in the case the feature exists for, a container with a fixed `max-height` (`overflow-items-as-clamped-list-example.ts:20` sets `max-height: 48px`). Toggling `[wrap]` at runtime on such a container leaves the previous hidden set in place until an unrelated resize arrives. The same gap applies to the two per-item inputs: `toObservable(this.items)` (`:267`) emits when the *set* of items changes, not when an existing item's `order` (`:107`) or `alwaysVisible` (`:112`) is rebound, so `[alwaysVisible]="isPinned()"` toggling to `true` does not un-hide the item. The lone `wrap` spec asserts only that the style landed (`overflow-items.spec.ts:459-470`), never that a recalculation followed — the same shape of non-assertion as the `debounceTime` case.
**Fix:** add `toObservable(this.wrap).pipe(skip(1))` to the merge at `:266-271`, mirroring the two inputs already handled that way. For the per-item inputs, derive a stream from the items themselves — `toObservable(computed(() => this.items().map((item) => [item.order(), item.alwaysVisible()])))` reads every item's inputs inside a reactive context, so any rebinding emits. Then extend the Jest wrap case to assert `getHiddenItems` was called after the toggle (the spy pattern at `:424` and `:445` already exists for `orientation` and `reverseOverflowOrder`, and copying it keeps the three cases uniform), and add a Playwright row that toggles `wrap` on a fixed-`max-height` container.

**OVF-API-01 · `changes` fires on every recalculation, not when the hidden set changes; its JSDoc says otherwise and the spec pins the wrong behaviour** — `overflow-items.ts:176-186, 273-284`; `overflow-items.spec.ts:352-376, 518-529`.
The output is documented as "Emits when the set of hidden items changes" (`:177-178`). The subscriber emits unconditionally at the end of every pass (`:283`), with a freshly-constructed `Set` (`:281`), so a resize that changes nothing still produces an emission carrying a new object identity. The Jest suite does not merely miss this — it codifies it: `expect(updated.size).toBe(0); expect(updated).not.toBe(initial)` (`:374-375`) asserts that an empty hidden set is re-emitted as a *different* empty set after a resize. Because `hiddenItemIDs` is `toSignal(outputToObservable(this.changes))` (`:184-186`), that identity churn propagates to every template reading it, and the 20 call sites read it constantly: `kbqOverflowItems.hiddenItemIDs().size` in six docs examples and both e2e fixtures, `hiddenItemIDs().has(...)` in `breadcrumbs.html:33`, `top-bar/e2e.ts:85`, `actions-panel/e2e.ts:50`, and `@for (item of kbqOverflowItems.hiddenItemIDs().values(); …)` in `overflow-items-as-clamped-list-example.ts:36`. The round trip through the public output is itself a design smell: the directive has no internal source of truth for its hidden set, so a consumer calling `directive.changes.emit(new Set(['x']))` desynchronizes `hiddenItemIDs` from the DOM — and `overflow-items.spec.ts:518-529` asserts exactly that as expected behaviour.
**Fix:** hold the hidden set in a private `signal<ReadonlySet<unknown>>`, expose `hiddenItemIDs` as `this.hiddenSet.asReadonly()`, and write it plus `changes.emit()` only when the newly computed set differs from the previous one (compare `size` then membership; a two-line helper). That makes the JSDoc true, removes the per-frame identity churn from 20 templates, and removes the ability for a consumer to forge the state. Rewrite `overflow-items.spec.ts:352-376` to assert the opposite of what it asserts today — a no-op resize must produce *no* emission — and delete or re-scope `:518-529`, which is a test of the leak rather than of the component.

**OVF-ARCH-01 · The package ships no stylesheet, so six layout declarations are inline and unoverridable, and two other packages style its internals from outside** — `overflow-items.ts:328-345`; history `c08da92b8` (DS-3834); consumers `top-bar.scss:4-21, 48-54, 70-73`, `breadcrumbs.scss:17-20`.
There is no `.scss` file in the package at all. `setStyles()` writes `position: relative`, `overflow: hidden`, `display: flex`, `flex-grow: 1` (`:329-332`) plus `flex-direction` (`:339`) and `flex-wrap` (`:344`) through `Renderer2` — which is to say, into the element's `style` attribute. Inline declarations outrank every author stylesheet, so none of the six can be changed by a consumer without `!important`; `flex-grow: 1` in particular was added as a deliberate fix (`da410ef11`, DS-3809, "does not stretch to maximum width") and now cannot be opted out of. The forced `overflow: hidden` is load-bearing for the `wrap` path (it is what makes `scrollHeight > clientHeight` meaningful at `:226, 242`), but it also clips anything an item paints outside its box — and two packages have independently paid for that: `breadcrumbs.scss:17-20` adds `padding: 1px` under the comment "add space not to cut focus outline", and `top-bar.scss:5` adds `padding: var(--kbq-size-border-width)` and then has to undo the height it costs with `margin-top`/`margin-bottom: calc(-1 * var(--kbq-size-border-width))` at `:52-53`. The same vacuum drives the cross-package coupling that TB-ARCH-01 files from the other side: with no gap token and no spacing story of its own (see OVF-BUG-01), `top-bar` reaches into `.kbq-overflow-item`, `.kbq-overflow-item_always-visible` and `.kbq-overflow-items-result` — all host classes owned by *this* package — and renaming any of them silently breaks it, because nothing in either package's tests covers the pair. The stylesheet that used to exist was deleted in `c08da92b8` (DS-3834) as "unused", which it was: it still targeted `:host` and `kbq-overflow-items__item*` from the pre-directive design. Deleting it was right; not replacing it is what left the hole.
**Fix:** reintroduce `overflow-items.scss` with a `.kbq-overflow-items` block carrying the five static declarations (`position`, `overflow`, `display`, `flex-grow`, and the hidden-state rule) so specificity, not inline precedence, decides — leaving only the two genuinely dynamic ones (`flex-direction`, `flex-wrap`) in `setStyles()`, or better, driving those from the `orientation`/`wrap` host classes too. Add `--kbq-overflow-items-gap` (consumed once OVF-BUG-01 makes gap measurable) and `--kbq-overflow-items-padding` (defaulting to the border width, so the focus-outline clearance ships once instead of twice). The acceptance criterion is the deletion of `top-bar`'s `_overflow-items-margins` mixin and `breadcrumbs.scss:17-20`, with both packages' Playwright suites unchanged. No `_overflow-items-theme.scss` is needed — see Appendix A.

### P3 — Nice to have / hygiene

**OVF-A11Y-02 · `aria-hidden="false"` is written on every visible item and on the result** — `overflow-items.ts:33-36`; asserted at `overflow-items.spec.ts:487-500`.
The host binding is `'[attr.aria-hidden]': 'hidden()'`. Angular removes an `attr.` binding only for `null`/`undefined`; `false` is stringified, so a visible item carries `aria-hidden="false"` permanently rather than carrying no attribute — the spec asserts this outcome directly (`:499`). It is a valid ARIA value and axe will not flag it, but WAI-ARIA and MDN both discourage it: it cannot un-hide content nested inside an `aria-hidden="true"` ancestor, so it reads as a guarantee it does not provide, and it lands on every breadcrumb, every top-bar action and every badge in the docs examples. The `kbq-overflow-item-hidden` class binding beside it has the same shape but is harmless, since `[class.x]` genuinely removes the class on `false`.
**Fix:** bind `'[attr.aria-hidden]': 'hidden() || null'` so the attribute is absent when the element is visible; update the spec's `show()` case (`:499`) to expect `null`. Consider `inert` on the hidden host as a defence in depth for descendants that force `visibility: visible` back on.

**OVF-ARCH-02 · The two content queries use opposite `descendants` defaults, so items must be direct children while the result may be anywhere** — `overflow-items.ts:140-148`.
`items = contentChildren(KbqOverflowItem)` (`:143`) and `result = contentChild(KbqOverflowItemsResult)` (`:148`) are written identically, but Angular's defaults are not: `contentChildren` defaults `descendants` to `false` and `contentChild` defaults it to `true` (both stated in Angular's own source comments, `@angular/core/fesm2022/core.mjs:398, 427`). The result element can therefore sit at any depth, while an item wrapped in so much as a `<span>` for spacing simply vanishes from the query — and the failure mode is the worst kind: no error, no warning, just a container that never hides anything. Every in-repo call site happens to keep items at depth one, which is why this has never been hit; note that `@for`/`@if` blocks are *not* the problem, as the 38 Playwright tests all render items inside `@for` (`e2e.ts:106-118`) and pass. Nothing in either guide states the constraint.
**Fix:** decide explicitly rather than by default. Either pass `{ descendants: true }` to match `contentChild` and support nested items, or keep the current behaviour and state it in the class JSDoc and both guides ("`kbqOverflowItem` must be a direct child of `kbqOverflowItems`"). Add a Jest case with one item nested inside a wrapper `<div>` asserting the chosen semantics, so the default can never flip silently under an Angular upgrade.

**OVF-API-02 · The visibility contract is shipped publicly and documented nowhere, and item ids are typed `unknown`** — `overflow-items.ts:27-31, 45, 52, 102`; `tools/public_api_guard/components/overflow-items.api.md:11-21, 27, 41`; `tools/api-gen/manifest/helpers.ts:46-48`, `tools/api-gen/extraction/helpers.ts:22-34`; `apps/docs/src/app/structure.ts:786-787`.
Two related surface problems. **(1)** `ElementVisibilityManager` is marked `@docs-private` (`:30`) but is exported through `index.ts` and appears in the guard as `// @public` with `element`, `hidden`, `hide()` and `show()` all public (`overflow-items.api.md:11-21`) — `@docs-private` is not an API-Extractor tag and strips nothing (the same trap as `@internal`, which also needs `stripInternal: true`). Meanwhile the docs generator *does* honour it: `isPublic()` filters entries carrying the tag (`manifest/helpers.ts:46-48`) and `extendedDoc` is only linked when the base class is public (`extraction/helpers.ts:22-34`), so the API tab that `structure.ts:786-787` enables for this component renders `KbqOverflowItem` and `KbqOverflowItemsResult` *without* `hidden`, `hide()`, `show()` or `element` — the four members that are the entire point of those directives, and the ones consumers must use to read the hidden state. The class is also the only export in the package without the `Kbq` prefix. **(2)** `id = input.required({ alias: 'kbqOverflowItem' })` (`:102`) has no type argument, so it infers `InputSignal<unknown>` (`overflow-items.api.md:27`) and `hiddenItemIDs` is `ReadonlySet<unknown>` (`:41`), which makes `has()` accept anything and removes any compile-time check on the lookup. That is not theoretical either: in-repo ids are already a mix of `number` (`breadcrumbs.html:13, 42, 47`, `actions-panel/e2e.ts:26`) and `string`, including `top-bar/e2e.ts:216`, where the static attribute form `kbqOverflowItem="0"` yields the string `'0'` and is matched by `hiddenItemIDs().has('0')` at `:252` — a property binding of the same conceptual id would produce `0` and silently never match.
**Fix:** rename to `KbqElementVisibilityManager` and either drop `@docs-private` (so the inherited members reach the API tab through `extendedDoc`) or lift `hidden`/`hide()`/`show()`/`element` onto the two concrete directives with their own JSDoc. Narrow the id to `input.required<string | number>({ alias: 'kbqOverflowItem' })` and propagate through `changes`/`hiddenItemIDs` as `ReadonlySet<string | number>`. While in there, `hidden = computed(() => this.hiddenState())` (`:52`) is a pure alias — `this.hiddenState.asReadonly()` says the same thing without a second reactive node. All three are API-report changes: run `yarn run build:components` then `yarn run approve-api` (build first, the guard reads `dist/*.d.ts`), and note the JSDoc/`(undocumented)` interaction — adding docs to a public member changes the report on its own.

**OVF-TEST-01 · The Jest suite runs where the component cannot do anything, and three of its cases assert nothing discriminating** — `overflow-items.spec.ts` (530 lines, 20 cases); corroborated by `breadcrumbs.spec.ts:269`.
jsdom returns an all-zero `DOMRect` from `getBoundingClientRect` and an empty string for computed margins, so `containerSizeWithoutPaddings` and `itemsSize` are both `0`, `0 > 0` is `false`, and **no item is ever hidden in any Jest run**. The `breadcrumbs` suite documents this in a comment against this very component — "flush `KbqOverflowItems` `debounceTime(0)` — shows all items in jsdom" (`breadcrumbs.spec.ts:269`). That is not a defect in itself, because the behavioural coverage genuinely exists in Playwright (38 real-browser cases, all assertion-based, no screenshot baselines to maintain — a better arrangement than most measurement components in this repo have). The defect is that three Jest cases look like coverage and are not: `:294-318` cannot distinguish the debounce values it names (OVF-LIFE-01), `:352-376` asserts the identity churn that OVF-API-01 says is a bug, and `:459-470` asserts a style landed rather than a recalculation ran (OVF-BUG-02). Separately, five call sites reach private methods through `(directive as any)` (`:307, :398, :410, :424, :445`), which means renaming `getHiddenItems` or `sortItemsByOrder` breaks the suite at runtime rather than at compile time.
**Fix:** repair the three cases as described in their own findings, and keep the Jest suite honestly scoped to what jsdom can decide — wiring, teardown, input plumbing, host bindings — with a one-line comment at the top of the describe saying so, so the next author does not add a measurement assertion that passes vacuously. Replace the `as any` casts with a typed local interface (`type Internals = { getHiddenItems: (...) => …; sortItemsByOrder: (...) => … }`) so a rename is a compile error. Add the Playwright rows named in OVF-BUG-01 (a `gap` row), OVF-BUG-02 (a `wrap` toggle) and OVF-A11Y-01 (a focus row).

**OVF-DOC-01 · `wrap` is documented nowhere, there is no accessibility section, and the item sizing contract every fixture obeys is unstated** — `overflow-items.en.md:1-52`, `overflow-items.ru.md:1-52`, `examples.overflow-items.en.md:1-6`, `examples.overflow-items.ru.md:1-6`.
The guides cover seven topics — `reverseOverflowOrder`, `order`, `alwaysVisible`, `justify-content`, `orientation`, `debounceTime`, `additionalResizeObserverTargets` — and omit `wrap` entirely, in both languages. `wrap` is a public input shipped in `1ddf45fd2` (DS-3381) that changes the measurement algorithm outright (`:353` switches to a cross-axis check); the only place it surfaces is the Examples page, which describes the *behaviour* ("Items wrap across multiple lines and are hidden once they exceed the container height", `examples.overflow-items.en.md:3-4`) without ever naming the input that enables it, so a reader who wants the effect has no way to reach it. Second, there is no accessibility section at all — for a component whose whole function is removing content from view, and whose result element every consumer has to label by hand (`breadcrumbs.html:23`, `actions-panel/e2e.ts:40`, `top-bar/e2e.ts:73`), the guides say nothing about what happens to screen readers, to focus (OVF-A11Y-01), or about labelling the result. Third, an undocumented sizing requirement: every fixture in the package sets `flex-shrink: 0` on items and on the result (`overflow-items.spec.ts:46, 53, 113, 132, 134`; `e2e.ts:102, 112, 179, 183, 242, 252, 313, 319, 378, 382`), because a flex item that shrinks to fit can never be measured as overflowing. Not one docs example does, and the guides never mention it — the examples survive only because flex's `min-width: auto` floors text content at its intrinsic size, which a consumer's `min-width: 0` reset would remove.
**Fix:** add a "Wrapping" section to both guides embedding `overflow-items-as-clamped-list` and naming `[wrap]="'wrap'"` explicitly; add an "Accessibility" section stating that hidden items leave the tab order and the accessibility tree, that the result element must be labelled by the consumer, and (after OVF-A11Y-01) where focus goes; add a sentence to the intro stating that items must not shrink (`flex-shrink: 0`, or an intrinsic floor) and must be direct children (OVF-ARCH-02). The Examples page is a real rendered surface here — `structure.ts:788` sets `hasExamples: true` and the file is populated, not a stub — so it is worth keeping in sync rather than treating as dead.

**OVF-STYLE-01 · Hidden-state class breaks the repo's BEM separators, plus three smaller hygiene items** — `overflow-items.ts:35, 94, 202-245, 272, 365-376`; `tsconfig.json:6-11`.
Four small things. **(1)** `kbq-overflow-item-hidden` (`:35`) is a modifier of `kbq-overflow-item` written with neither of the repo's two separators — `__` marks elements and a single `_` marks modifiers, a convention this very directive follows correctly one line away in `kbq-overflow-item_always-visible` (`:94`), and which the deleted stylesheet also followed (`kbq-overflow-items__item_hidden`, `c08da92b8`). It is also a de-facto public selector with no documented status: three other packages' tests query it (`actions-panel/e2e.playwright-spec.ts:41`, `breadcrumbs/e2e.playwright-spec.ts:10`, plus this package's own suite), so renaming it is breaking and needs to be scheduled as such. **(2)** The RxJS operator `debounceTime` and the input `debounceTime` collide at `:272` (`debounceTime(this.debounceTime())`) — legal, but it is the exact line OVF-LIFE-01 is about, and the shadowing is part of why it reads as correct. **(3)** `orientationConfig` (`:202-245`) carries a trailing `as const` on a field that already has an explicit type annotation, where it does nothing, and is rebuilt with twelve closures for every directive instance; a module-level constant taking the window as a parameter would be shared. **(4)** The `findLast` polyfill's TODO says "Should be removed when `Array.prototype.findLast` is supported" (`:366`) — browsers have supported it since 2022, so the real blocker is `tsconfig.json:8-11`, which sets `lib: ["ES2022", "DOM"]` while `findLast` is ES2023. The TODO is actionable today by bumping `lib` to `ES2023`, and it should say so.
**Fix:** rename the class to `kbq-overflow-item_hidden` behind a transitional period that emits both, update the three consumer test selectors, and document the class as public in the guide; alias the RxJS import (`import { debounceTime as debounceTimeOperator }`) or, better, resolve it while implementing OVF-LIFE-01; drop the dead `as const` and hoist `orientationConfig` to module scope; either bump `lib` to `ES2023` and delete `findLast`, or rewrite the TODO to name the real blocker.

## 4. Recommended Remediation Phases

**Phase 1 — Make the documented knobs real.**
IDs: OVF-LIFE-01, OVF-BUG-02. Re-pipe the debounce so the input is read per emission, and add `wrap` plus the per-item `order`/`alwaysVisible` reactivity to the trigger set. Neither changes the public API, both are contained in `setupObservers()`, and both ship with tests that fail against today's code — which the current tests do not. This is first because OVF-PERF-01's mitigation does not exist until the debounce works.

**Phase 2 — Fix the measurement model.**
IDs: OVF-BUG-01, OVF-PERF-01, OVF-API-01. Count `gap` in `hasOverflown`, restructure the pass into read-once / decide / write-once, and emit `changes` only on an actual change. These three touch the same two methods and should land together; the shared acceptance criterion is that `top-bar`'s `_overflow-items-margins` mixin and the `layout-margin-*` classes in the six docs examples can be deleted in favour of a `gap` with no change to any Playwright expectation.

**Phase 3 — Own the styling and the focus contract.**
IDs: OVF-ARCH-01, OVF-A11Y-01, OVF-A11Y-02, OVF-STYLE-01. Reintroduce `overflow-items.scss` with the static declarations and two tokens (`--kbq-overflow-items-gap`, `--kbq-overflow-items-padding`), move focus off an item before hiding it, stop writing `aria-hidden="false"`, rename the hidden modifier class. This is the phase that closes TB-ARCH-01 from this side; the class rename is breaking and needs an alias period plus updates to three other packages' test selectors, so schedule it with a minor.

**Phase 4 — API surface, contract docs and test honesty.**
IDs: OVF-API-02, OVF-ARCH-02, OVF-DOC-01, OVF-TEST-01. Rename and re-expose `ElementVisibilityManager`, narrow the id type, settle the `descendants` question explicitly, write the missing `wrap`/accessibility/sizing documentation, and repair the three vacuous Jest cases. One `yarn run build:components && yarn run approve-api` cycle covers the API changes; the id narrowing is a breaking type change and belongs with the same minor as Phase 3.

## Appendix A — Review Methodology

Every file in the package was read in full (`overflow-items.ts` 377 lines, `overflow-items.spec.ts` 530, `e2e.ts` 404, `e2e.playwright-spec.ts` 395, both guides, both examples pages, `module.ts`, `index.ts`, `ng-package.json` — 1,706 lines of TypeScript plus docs). Each candidate was then checked against five independent sources: the API guard report and its `api-extractor` registration (`tools/api-extractor/config.json:37`), the docs generator's own handling of `@docs-private` (`tools/api-gen/manifest/helpers.ts:46-48`, `tools/api-gen/extraction/helpers.ts:22-34`), every in-repo consumer found by grep across `packages/` and `apps/` (20 `kbqOverflowItems` host call sites in 19 files, plus every stylesheet that names a `kbq-overflow-*` class), Angular's own runtime source for the query and input semantics this component depends on (`@angular/core/fesm2022/core.mjs:398, 427`), and the package's 15-commit git history. Consumer evidence is what upgraded OVF-BUG-01 and OVF-ARCH-01 from style opinions to confirmed defects: in both cases the workaround already exists in the tree, written independently by different authors, and in `top-bar`'s case it is already filed from the other direction as TB-ARCH-01, whose recommended fix (`--kbq-overflow-items-gap` owned by this package) is the same fix Phase 3 proposes here. Design tokens were not verified because the package consumes none — see below.

Refuted during verification:
- **"The missing `overflow-items-tokens.scss` and `_overflow-items-theme.scss` are defects"** — refuted, and checked first. The package declares no colour, no typography and no CSS custom property: a grep for `--kbq-` across the whole package returns hits only inside the e2e fixture's own host styles (`e2e.ts:127, 128, 193, 194, 264, 265, 330, 331`). Theme mixins in this repo are not aggregated — each component `@include`s its own from its own SCSS — so a theme partial here would have nothing to express, and a token file would declare nothing. The stylesheet that did exist was deleted deliberately in `c08da92b8` (DS-3834) because it still targeted `:host` and `kbq-overflow-items__item*` from the pre-directive design. The defect is not the missing files; it is that nothing replaced the two host declarations that *were* worth keeping as CSS — filed as OVF-ARCH-01.
- **"Hidden items stay in the tab order and are still announced"** — refuted. `hide()` sets `visibility: hidden` (`:60`), and per HTML's "being rendered" definition such content is neither focusable nor exposed to assistive technology; the `aria-hidden="true"` alongside it is belt-and-braces rather than the only barrier. The genuine defect is what happens to focus that is *already* inside the element when it is hidden — filed as OVF-A11Y-01 — and the noise the same binding leaves on visible items, filed as OVF-A11Y-02.
- **"Importing `SharedResizeObserver` from `@angular/cdk/observers/private` is an unstable-dependency defect"** — refuted as a finding against this package. Eleven other packages import the same private entry point (`title`, `clamped-text`, `code-block`, `dl`, `inline-edit`, `navbar`, `select`, `timezone`, `toast`, `actions-panel`, `core/overflow-shadow`). That is repo-wide convention worth one umbrella decision, not a per-package finding.
- **"`debounceTime(0)` is a pointless operator and should be dropped"** — refuted; it is load-bearing. The subscriber writes styles and reads layout, and `debounceTime(0)` schedules on the async scheduler, moving that work out of the `ResizeObserver` callback that produced the event and avoiding the "ResizeObserver loop completed with undelivered notifications" error that a synchronous write-back would raise. The default value is correct; the input meant to raise it is what is broken (OVF-LIFE-01).
- **"The `while` loop at `:311` can spin forever"** — refuted. Each iteration either flips one item's `hidden()` to `true` (`:318`) or hits the `break` at `:316`, and the candidate search (`:312-314`) excludes already-hidden and `alwaysVisible` items, so the loop is bounded by the item count. The `break` path is exercised by two e2e rows where even the `alwaysVisible` item does not fit (`e2e.playwright-spec.ts:274-281, 355-365`).
- **"The component crashes or misbehaves under SSR"** — refuted. `setupObservers()` returns early when `!platform.isBrowser` (`:253`, added by `e702d5549`/DS-5266) so no geometry is read on the server, and `setStyles()` only goes through `Renderer2`, which is server-safe. The server renders every item visible and the browser's first `ResizeObserver` emission corrects it — a hydration flash in the worst case, not an error. `getComputedStyle` is correctly routed through the injected `KBQ_WINDOW` (`:218, 234, 356`) rather than the banned global.
- **"A `display: none` ancestor leaves the component permanently in a wrong state"** — refuted by construction. Inside a non-rendered subtree every `getBoundingClientRect` is zero, so `containerSizeWithoutPaddings` and `itemsSize` are both `0`, `hasOverflown` returns `false` and nothing is hidden; when the subtree becomes displayed the host `ResizeObserver` (`:256`) reports the box change and the pass re-runs. This was verified against the observation set-up rather than measured in a browser, and is worth an e2e row regardless (see OVF-TEST-01).

Corrected on verification:
- **OVF-LIFE-01** was drafted as a P3, "the `debounceTime` input is not reactive — changing it at runtime does not re-pipe". Reading the construction order showed the much stronger claim: `setupObservers()` runs from the constructor (`:249`), before Angular writes any input, so the value is never read at all and the default `0` is baked in even for the static-attribute form. Severity moved P3 → P1, and the two tests that appear to cover it were found to be satisfied identically by the broken and the fixed behaviour.
- **OVF-A11Y-02** was drafted as an axe `aria-hidden-focus` failure ("hidden items contain focusable controls"). Refuted as an automated failure — `visibility: hidden` removes those descendants from the focusable set, so axe has nothing to flag — and the finding was narrowed to the `aria-hidden="false"` written on *visible* items, dropping from P2 to P3.
- **OVF-TEST-01** was drafted as a P2, "no meaningful test coverage for a measurement-driven component", by analogy with the equivalent finding in the `title` review. The Playwright suite turned out to be 38 assertion-based real-browser cases with no screenshot baselines — genuinely strong behavioural coverage, and better than most siblings — so the finding was narrowed to the three Jest cases that assert nothing discriminating plus the private-method casts, and dropped to P3.
