## 1. Executive Summary

- **One crash-class correctness bug is the top blocker.** Any notification whose `date` string the configured `DateAdapter` cannot parse (with Luxon that includes the library's own display format `dd.MM.yyyy` — only ISO/RFC2822/SQL survive `parse(value, '')`) makes `makeGroup` call `format(null)`, which **throws inside the `groupedItems` map, errors the observable, and permanently blanks the panel** — reopening resubscribes to the same dead pipe (NC-BUG-01). The neighbouring `compareByDateDesc` guards exactly this case, so the invariant was known but not applied.
- **Keyboard accessibility is release-blocking.** The panel computes `isTrapFocus` but never applies a focus trap (prior A11Y-24 — still open; Tab escapes the overlay and host-scoped Escape then goes dead), and the per-item / per-group delete buttons are `display: none` until `:hover`/`:focus-within` — but they are the only focusable element in their container, so keyboard focus can never reveal them: **a keyboard user cannot delete anything** (NC-A11Y-01/02). Icon-only header buttons (close, remove-all) have no accessible name and not even a tooltip (NC-A11Y-03).
- **The reopen-leak class from the prior review is structurally fixed.** The panel component is created per open and destroyed per close (ComponentPortal dispose), and all its subscriptions are `takeUntilDestroyed`-bounded — prior BUG-10/BUG-33 are gone. What remains is one **destroy-while-open** path: the nested `closingActions()` subscription is only torn down on `visibleChange(false)`, which trigger destruction never emits, leaving a permanent subscription that throws a `TypeError` on every subsequent scroll anywhere in the app (NC-LEAK-01, same pattern in app-switcher).
- **The inner-scroll "prevent close" protocol taints the whole app.** The handler mutates the shared `CdkScrollable` instances emitted by the root `ScrollDispatcher` (`kbqPopoverPreventHide`/`type` are written and never reset) with no containment check — after the center has been open once, close-on-scroll silently stops working for *other* overlays (popover `closeOnScroll`) on any scrollable that was scrolled meanwhile (NC-BUG-02).
- **DI topology undermines the repo's own standalone-first mandate.** The scroll-strategy token has no default factory and its provider (plus the focus-trap overrides) lives only in the legacy `KbqNotificationCenterModule`, so a pure-standalone import crashes with `NullInjectorError` — the NgModule is load-bearing, and all 6 docs examples are forced through it (NC-ARCH-01). The service is simultaneously `providedIn: 'root'` **and** re-provided by that module, creating a documented two-instance trap the package's own spec has to work around (NC-ARCH-02).
- **Performance has one headline fix.** `@for (… track group)` tracks freshly-minted group objects by identity, so every push/remove/page-append tears down and rebuilds the *entire* list DOM (plausibly 200–500 ms per push at infinite-scroll scale); keeping the already-computed `yyyyMMdd` key on the group and tracking by it converts that to an incremental update (NC-PERF-01). Adjacent: dates are re-parsed O(n log n) per emission, and the `unreadItemsCounter` getter allocates a new Observable per read, resubscribing the async pipe every CD cycle (NC-PERF-02/03).
- **The date grouping only works on Luxon.** The group key is built by *display formatting* with `'yyyyMMdd'`; on the Moment adapter `dd` is the min weekday name, so 2026-07-04 and 2026-07-11 share key `202607Sa` and merge into one group (NC-BUG-03). Grouping must key on `getYear/getMonth/getDate` instead.
- **What's strong.** The infinite-scroll stream design is genuinely well-architected (audited, deduplicated, triple-gated, short-page re-check via `pairwise`, focus retention on retry) and its unit-test block is exemplary — every guard has a dedicated negative test asserted from the DOM. Conventions are near-perfect (standalone, OnPush, native control flow, host objects, `inject()`, no ngClass/ngStyle), theming is 100% token-based, and templates are cleanly namespaced. Test *quality* is above repo average; test *breadth* (keyboard/focus, trigger inputs/outputs, e2e states) is the gap.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

**NC-BUG-01 · Unparsable `date` crashes `groupedItems` — the panel goes permanently blank** — `notification-center.service.ts:241-242`, also `notification-item.ts:67`.
`makeGroup` does `adapter.parse(item.date, '')` → with the Luxon adapter an empty format falls back to ISO/RFC2822/SQL parsing and returns **`null`** for anything else (including `dd.MM.yyyy`); `adapter.format(null, 'yyyyMMdd')` then throws (`DateTime: Cannot format invalid date.`; the Moment adapter throws equivalently on invalid moments). The throw happens inside the `map` of `groupedItems`, which **errors the observable**: the `| async` subscription in `notification-center.html:63` dies, the list renders nothing, and reopening resubscribes to the same erroring pipe. The same unguarded parse-then-format crashes per-item time rendering (`notification-item.ts:67`). `compareByDateDesc` (`:260-262`) guards null parses — the invariant was known.
**Fix:** validate the parse result in `makeGroup` and the item `data` setter (skip or bucket into an "unknown date" group; fall back to raw string for time); add `catchError` (or per-item try) so one bad item cannot kill the stream; document the accepted `date` format (see NC-API-08); add regression tests with garbage and `dd.MM.yyyy` dates.

**NC-A11Y-01 · Focus trap computed but never applied — Tab escapes the open panel (prior A11Y-24, still open)** — `notification-center.ts:151`, `:282-284`, `:498`.
`isTrapFocus` is set `true` on every open (`trigger` is `'click, keydown'`), but nothing consumes it: no `cdkTrapFocus` in `notification-center.html` (the only repo consumer of the pattern is `popover.component.html:5`), and `notification-center.module.ts:18-19` even ships `ConfigurableFocusTrapFactory`/`EmptyFocusTrapStrategy` providers for a trap that is never created. The overlay sits at the end of `<body>`, so tabbing past the last control leaves the panel while it stays open; Escape is bound on the panel host only (`:111`) and stops working once focus is outside.
**Fix:** replicate popover — wrap panel content with `[cdkTrapFocus]="isTrapFocus"` (consider `focusFirstTabbableElement()`); add jest coverage for trap + Escape.

**NC-A11Y-02 · Item and group delete buttons are keyboard-unreachable (`display: none` chicken-and-egg)** — `notification-item.scss:16-25`, `:116-123`; `notification-center.scss:72-84`.
Both buttons are `display: none`, revealed on `:hover`/`:focus-within` of their container — but `display: none` removes them from the tab order and they are the **only** focusable element in their container (sub-header always; item unless the consumer projects focusable `actions`), so `:focus-within` can never become true via keyboard. A keyboard user cannot delete a notification, a group, or reach the buttons at all (WCAG 2.1.1). They are also icon-only with tooltip-only labels (see NC-A11Y-03/09).
**Fix:** keep the buttons focusable (visually de-emphasize via `opacity`/clip instead of `display: none`) and reveal on `:focus-visible` of the button itself; pair the theme's `:hover` backdrop with a focus twin (`notification-item.scss:141-143`); add `aria-label`s.

### P1 — High

**NC-A11Y-03 · Icon-only header buttons have no accessible name (AXE `button-name` failure)** — `notification-center.html:4-20` (silent-mode toggle), `:24-33` (remove-all), `:38-47` (close).
All three contain only `<i kbq-icon>` glyphs; remove-all and close have no `aria-label` **and no tooltip**. The very first element focused on open (`switcher().focus()`, `notification-center.ts:198`) is announced as an unnamed button. The locale configuration has no keys for "close"/"remove all", so strings must be added (`core/locales/*.ts`, `notificationCenter` section).
**Fix:** add `[attr.aria-label]` from `localeData` to all three (plus the group/item remove buttons); extend the locale config with the missing keys.

**NC-A11Y-04 · Panel has no role, no accessible name, no announcement** — `notification-center.ts:108-112`; `notification-center.html:1-3`.
The host has only a class binding and `keydown.escape`; there is no `role="dialog"` (or `complementary`), no `aria-labelledby` pointing at the "Notifications" title (which has no `id`), no `aria-modal`. Focus is teleported into the overlay on open with zero context for screen-reader users.
**Fix:** `role="dialog"` + `aria-labelledby` on the host; `id` on the title; pair with NC-A11Y-01 so the dialog pattern is complete.

**NC-LEAK-01 · Destroy-while-open leaks the nested `closingActions` subscription — then throws on every scroll app-wide** — `notification-center.ts:470-479`.
The nested subscription (`// eslint-disable-next-line rxjs-x/no-nested-subscribe`) is torn down only in the `visibleChange(false)` branch. Destroying the trigger while the panel is open (route change) never emits `false` (`KbqPopUpTrigger.ngOnDestroy` only disposes the overlay, `pop-up-trigger.ts:276-282`); overlay disposal completes `outsidePointerEvents`/`backdropClick`, but `scrollDispatcher.scrolled()` is a root-singleton stream that never completes — the merge subscription lives forever, pins the document scroll listener, and on the next scroll of any registered scrollable dereferences `this.instance.setStickPosition()` with `instance === null` → recurring `TypeError` outside the zone. `app-switcher.ts:541-549` has the identical pattern.
**Fix:** `this.visibleChange.pipe(switchMap((visible) => visible ? this.closingActions() : EMPTY), takeUntilDestroyed(this.destroyRef)).subscribe(...)` (removes the eslint-disable too) + `this.instance?.setStickPosition()`. Mirror in app-switcher.

**NC-BUG-02 · Inner-scroll handler permanently taints shared `CdkScrollable`s — breaks close-on-scroll for other overlays** — `notification-center.ts:470-477`.
`scrollDispatcher.scrolled()` emits the *same live `CdkScrollable` instance* to every subscriber; the handler writes `event['kbqPopoverPreventHide'] = true; event['type'] = 'click'` onto it and never resets. The `event['scrollDispatcher']` guard matches **every** CdkScrollable (no containment check), so: (1) scrolling any unrelated scrollable while the panel is open is treated as "inner scroll" and won't close the panel; (2) once flagged, a long-lived scrollable permanently satisfies the base hide-gate (`pop-up-trigger.ts:655`), silently disabling close-on-scroll for *other* pop-up-family overlays (e.g. popover `closeOnScroll`, `popover.component.ts:545`) even after the center is closed.
**Fix:** don't mutate the payload — filter by containment (compare the emitted scrollable's element against the panel element) inside this trigger's own subscription; if the flag protocol must stay, reset flags on close and give `KbqPopUpTrigger` an explicit `shouldPreventHide(event)` hook **(shared)**.

**NC-PERF-01 · `track group` by object identity rebuilds the entire list DOM on every emission** — `notification-center.html:63`, `:86`; root cause `notification-center.service.ts:92-106`.
`groupedItems` builds fresh group objects per `originalItems` emission (every `push`/`remove`/`removeGroup`/`removeAll`/`items=`), so `track group` destroys and recreates every group's embedded view — taking the nested `@for (item …; track item)` and every `<kbq-notification-item>` (tooltip triggers, icon components, read-state subscriptions, date re-parse in the `data` setter) down with it, even though item references are stable across `push`. One push while open = full-list teardown+rebuild: tens of ms at ~100 items, plausibly 200–500 ms at the 1000-item infinite-scroll scale — every page-append rebuilds everything already loaded. Hover/tooltip state is lost each time.
**Fix (headline):** keep the already-computed day key on the group object (it is currently thrown away via `Object.values`) and `track group.id`; keep `track item` or move to `track item.id` **after** NC-BUG-06 (today's colliding ids would produce NG0955 duplicate-key errors). Long term: `cdk-virtual-scroll` if lists grow unbounded (complicated by sticky day headers).

**NC-ARCH-01 · Pure-standalone import crashes: the NgModule is load-bearing** — `notification-center.ts:69-71`, `:315`; `notification-center.module.ts:16-21`.
`KBQ_NOTIFICATION_CENTER_SCROLL_STRATEGY` has no default factory, and its provider lives only in `KbqNotificationCenterModule` — a consumer following the repo's own standalone-first mandate (`imports: [KbqNotificationCenterTrigger]`) gets `NullInjectorError` at directive construction. The module also carries the focus-trap overrides (`FocusTrapFactory`/`FOCUS_TRAP_INERT_STRATEGY`), so the two import paths behave differently. All 6 docs examples are forced to import the module. Tooltip/popover share this repo-wide pattern — fix consistently.
**Fix:** give the token a `factory:` default (`new InjectionToken(..., { factory: () => inject(Overlay).scrollStrategies.reposition({ scrollThrottle: 20 }) })`) or provide on the trigger's `providers`; move the focus-trap providers to a `provideKbqNotificationCenter()` function or the component `providers` so standalone === module behavior.

**NC-ARCH-02 · Service double-provided: `providedIn: 'root'` + module `providers` — two-instance trap** — `notification-center.service.ts:42` vs `notification-center.module.ts:20`.
A standalone component importing the NgModule gets the module's providers in its own standalone injector — its own service instance — while root-level code (the documented `push()`-from-a-service pattern) talks to the root instance: pushed notifications never reach the visible center, counters diverge. The package's own spec documents the workaround (`notification-center.spec.ts:78-79`: "The rendered center resolves the service from the module provider … so drive that exact instance").
**Fix:** delete `KbqNotificationCenterService` from the module `providers`; keep `providedIn: 'root'`. Changelog note (behavioral fix).

**NC-BUG-03 · Group key `'yyyyMMdd'` is Luxon-specific — the Moment adapter groups by weekday** — `notification-center.service.ts:242`.
The key is built by *display formatting*. Moment's `format()` receives the string verbatim (`moment-date-adapter` `format()` → `newDate.format(displayFormat)`), where `dd` is the **min weekday name**, not day-of-month — so 2026-07-04 (Sat) and 2026-07-11 (Sat) both key as `202607Sa` and merge into one group under the first item's date title. Works only by coincidence on Luxon.
**Fix:** never build keys via display formats — use `adapter.getYear/getMonth/getDate(parsedDate)` (adapter-agnostic), e.g. `${year}-${month}-${date}`. Add a Moment-adapter grouping test.

**NC-BUG-04 · Infinite scroll never starts when the first page doesn't fill the viewport** — `notification-center.ts:231-252`.
`onNextPage` is driven only by scroll events and `loadingMore` true→false transitions. If page 1 is loaded before opening (or via `loadingMode`, which never touches `loadingMore`) and is shorter than the panel, the container isn't scrollable — no scroll event, no transition — pagination stalls at page 1 despite `hasMore === true`.
**Fix:** run one `isScrolledToBottom()` check through the same `requestNextPage()` guard after first render (`afterNextRender`) and on `originalItems` emissions.

**NC-API-01 · Configuration token and everything downstream is untyped** — `notification-center.ts:66`, `:128`, `:142-144`.
`new InjectionToken('KbqNotificationCenterConfiguration')` has no generic (api.md: `InjectionToken<unknown>`); `configuration` has no annotation (api.md: `configuration: any`, `localeData: any`). A consumer providing the token gets zero shape validation — a partial object silently renders `undefined` strings in the panel. The shape is fully known (`core/locales/ru-RU.ts`, `notificationCenter`: 8 keys). The team types the scroll-strategy token right next door — this is an oversight, not a pattern.
**Fix:** `export interface KbqNotificationCenterLocaleConfiguration {…}`; type the token, the field, and `KBQ_NOTIFICATION_CENTER_DEFAULT_CONFIGURATION`. Compile-time only; `build:components` + `approve-api`.

**NC-TEST-01 · `'default trigger is click'` never dispatches a click** — `notification-center.spec.ts:63`.
The body calls `trigger().show()` programmatically; if `trigger` regressed to `'hover'` the test still passes. What it verifies is "show() renders the panel".
**Fix:** rename accordingly and add a real test clicking the trigger element (open + second-click close), plus a keydown-open test (`dispatchKeyboardEvent` from `core/testing` is available and unused).

### P2 — Should fix

- **NC-BUG-05 · `popoverMode` setter hijacks `placement` even when set to `false`, irreversibly** — `notification-center.ts:371-376`. The setter body ignores `value`: any `[popoverMode]` binding (including `false`) overwrites `placement` (default `Right`) and the constructor's priority list, with no path back; whether an explicit `kbqNotificationCenterPlacement` survives depends on attribute order. **Fix:** apply Bottom placement/priority only when `value === true`; restore the saved placement/priority on `false` (or derive placement at `show()` time).
- **NC-BUG-06 · `setIds` mints colliding ids (prior BUG-49 — still present, now the norm for batches)** — `notification-center.service.ts:267-271`. `item.id = item.id ?? new Date().getTime().toString()` inside a synchronous `forEach`: every id-less item in one `items = […]` assignment shares one timestamp. The `toastService.read` matcher (`:150`, `find` by id) then marks the *first* collided item read while the one actually read stays unread. Also blocks the natural `track item.id` fix (NG0955). **Fix:** `${Date.now()}-${counter++}` or `crypto.randomUUID()`; add the same-ms regression test (it fails today).
- **NC-BUG-07 · Service mutates consumer-owned objects in place** — `notification-center.service.ts:268`, `:274`, `:195`, `:208`, `:153`; `notification-item.ts:85`. `items=`/`push()` write `id`/`read`/`toastId` onto the caller's objects and keep the caller's array reference. Consequences: NgRx dev-mode frozen stores throw `TypeError` on assignment; OnPush consumers rendering the same objects never see `read` changes (no `originalItems` emission on read-marking — only `onRead` fires); external mutation silently desyncs. **Fix:** shallow-copy on ingestion (`values.map((item) => ({ ...item }))`) or document ownership transfer explicitly; route the item component's `data.read = true` through a service method.
- **NC-ARCH-03 · `EventEmitter` used inside an `Injectable`** — `notification-center.service.ts:77-83`. `onReload`/`onNextPage`/`onDelete` are `EventEmitter`s — an Angular anti-pattern outside `@Output()`. **Fix:** `Subject<…>` (subscribe-compatible; batch with the signals migration).
- **NC-ARCH-04 · Hand-rolled reactivity bridge instead of signals** — `notification-center.service.ts:52-118`, `:161-188`; `notification-center.ts:194-196`. Seven `BehaviorSubject`s + seven one-line `setX()` wrappers + a `changes` merge whose only consumer calls `markForCheck()`, while the template reads raw `.value`. This is what `signal()`/`computed()` replaces (AGENTS.md mandate). **Fix:** modes → `signal(false)`; `groupedItems`/`unreadItemsCounter` → `computed()`; delete `changes` + the markForCheck subscription.
- **NC-ARCH-05 · Base trigger declares `instance: any` — visibility and existence checks are off (shared)** — `core/pop-up/pop-up-trigger.ts:229`; symptoms at `notification-center.ts:486-503`. Because `instance` is `any`, `updateData()` compiles while writing the component's `protected popoverMode`/`scrolledToBottomOffset` and a `footer` property that exists on **neither** `KbqNotificationCenterComponent` nor `KbqPopUp` (popover copy-paste — dead data flow). **Fix:** type the base as `instance: T | null`; give the component explicit `updateX()` setters (the `updateTrapFocus` pattern); drop the dead `header`/`footer`/`arrow` copies.
- **NC-ARCH-06 · Input migration debt is overstated by the TODOs — and new code added legacy inputs** — `notification-center.ts:361`, `:348`, `:353`, `:358`. `scrolledToBottomOffset` (added in af6e64fe) is a legacy `@Input` with no inheritance blocker; `backdropClass`/`panelClass`/`offset` carry auto-generated "referenced in the signature of another class" skip-reasons but are only read locally — migratable now. Genuinely blocked (verified against the base): `placement`, `disabled`, `stickToWindow`, `container`, and both `@Output`s (base declares abstract `EventEmitter` members). **Fix:** migrate the four now; leave the rest until `KbqPopUpTrigger` is signal-ready.
- **NC-ARCH-07 · `popoverHeight` duplicated on component and trigger with a wrong propagation guard** — `notification-center.ts:158-168` vs `:383-396`. The trigger setter propagates only `if (this.instance?.popoverHeight)` — i.e. only when the instance already has a truthy height: first set while open no-ops until reopen; clearing (`''`) never propagates. Component setter writes `style.height` directly instead of a host binding. **Fix:** guard on `if (this.instance)`; single owner + `[style.height]` host binding.
- **NC-API-02 · `KbqNotificationsGroup` is unexported but sits in two public signatures** — `notification-center.service.ts:30`; `removeGroup(group: KbqNotificationsGroup)` (`:221`) and `groupedItems` (`:92`). The api.md has the `ae-forgotten-export` warning baked in (`notification-center.api.md:118`) — consumers cannot name the type. **Fix:** export it (SemVer-minor; `build:components` + `approve-api` per repo rule).
- **NC-API-03 · `KbqNotificationItem extends Omit<KbqToastData, 'closeButton'>` is 100% redundant coupling** — `notification-center.service.ts:8-26`. All eight inherited members are re-declared locally; the `extends` contributes zero members and only drags the toast *class* into this package's public .d.ts — future `KbqToastData` widening silently changes this surface. **Fix:** standalone interface (shape-identical; heritage-clause change → `approve-api`).
- **NC-API-04 · `onRead` is a BehaviorSubject event bus with an unsafe cast and a lying doc tag** — `notification-center.service.ts:74`, `:155`. New subscribers synchronously get `null` or a stale last-read item; `onRead.next(toastData as KbqNotificationItem)` emits a `KbqToastData` that lacks the required `date`/`read` fields while the correctly-typed `item` is in scope two lines up (one-line fix); tagged `@docs-private` yet fully public and *required* API (`notification-item.ts:87` calls it). Family convention (toast does the same) — fix in a coordinated pass; the cast fix is immediate.
- **NC-API-05 · Dual mutation paths on every mode flag** — `notification-center.service.ts:52-72` vs `:160-188`. Public mutable `BehaviorSubject`s *and* `setX()` wrappers — consumers can bypass the setters, so the setters can never gain logic (e.g. the error-cleanup in `retryLoadMore` is skippable via `loadingMore.next(true)`). **Fix:** expose `Observable` views + make setters the single write path (major; falls out of NC-ARCH-04).
- **NC-API-06 · Dead public `header`/`footer` on the trigger** — `notification-center.ts:331-333`; api.md:161/:164. Not base-class requirements (unlike `arrow`/`content`/`customClass`, which are abstract members) — gratuitous public fields, permanently `undefined`, copied into the instance in `updateData()`. **Fix:** delete both + the `updateData` lines (`approve-api`; realistically no consumer impact).
- **NC-API-07 · Input alias inconsistency; `placementChange` is `EventEmitter<any>`** — `notification-center.ts:343-441`. Two inputs are namespaced (`kbqNotificationCenterPlacement`/`…PanelClass`), eight bind bare (`offset`, `container`, `disabled`, …) — collision-prone on an attribute-directive host. `@Output('kbqPlacementChange')` is untyped where the base abstract says `EventEmitter<string>` (one-line fix). Renames are breaking — align repo-wide or not at all.
- **NC-API-08 · `date: string` contract is undocumented** — `notification-center.service.ts:24`. The model's one required field has no JSDoc and is parsed with an empty format — "whatever the adapter's ISO/RFC/SQL fallback accepts" (adapter-dependent). **Fix:** document ("any value parseable by your `DateAdapter`, e.g. ISO 8601"); couples with NC-BUG-01.
- **NC-A11Y-05 · Focus is destroyed (falls to `<body>`) after remove-all / remove-group / remove-item** — `notification-center.html:30`, `:80`; `notification-item.html:108`. All three delete paths unmount the button that holds focus (remove-all also unmounts itself via `@if (!service.isEmpty)`); Escape then stops working. The component already solves this for retry (`retryLoadMore` → `focusScrollContainer()`, `notification-center.ts:212-222`) — the pattern just isn't applied. **Fix:** move focus to a surviving control/container in the three delete handlers.
- **NC-A11Y-06 · Trigger exposes no popup state; unread/silent conveyed by color alone** — `notification-center.ts:302-308`. No `aria-expanded`/`aria-haspopup="dialog"`/`aria-controls`; in the reference usage the badge is bare text and silent mode is badge color only (WCAG 1.4.1). **Fix:** host `attr.aria-*` bindings on the trigger; document an `aria-label` recipe with the count for the badge.
- **NC-A11Y-07 · Focus ring lost on keyboard open/close (program-origin focus) (shared)** — `core/pop-up/pop-up-trigger.ts:544-546`; `notification-center.ts:198`, `:480`. Both the initial focus (via plain `KbqButton.focus()`, reached after two `setTimeout`s) and the restore-to-trigger use native `.focus()` — FocusMonitor classifies them `program`, so no `.cdk-keyboard-focused` ring (WCAG 2.4.7). The repo already fixed this class of bug via `focusVia` (commit `17317fb3`, filter-bar); `KbqButton.focusViaKeyboard()` exists and is unused. **Fix:** thread a focus origin through show/hide (use `focusVia`).
- **NC-A11Y-08 · Read/unread is mouse-only and visual-only** — `core/common-behaviors/read-state.ts:4-30` (hostDirective at `notification-item.ts:34`); `notification-item.html:57-60`. Read is triggered by hover-dwell (>500 ms) or click; items are not focusable — no keyboard path to mark read (WCAG 2.1.1 parity). The unread indicator is a color dot with no text alternative. **Fix:** make items focusable (`tabindex="-1"` + roving or list semantics) and mark read on focus-dwell too; add visually-hidden "unread" text or `aria-label` on the item.
- **NC-A11Y-09 · Tooltips are not exposed to AT at all (shared)** — `kbqTooltip` never wires `aria-describedby` (verified across `packages/components/tooltip`), so the tooltip-only labels on the silent-mode toggle and remove buttons contribute nothing for screen readers. **Fix (shared):** add `aria-describedby` wiring in the tooltip trigger; until then, `aria-label` everywhere tooltips are the only label.
- **NC-A11Y-10 · Silent-mode dropdown has no menu semantics; selection is a dot icon (shared)** — `notification-center.html:147-164`; `packages/components/dropdown` has zero `role`/`aria-*` (grep). - **NC-A11Y-11 · No live region for list changes** — pushes while open, deletions, and the transition to the empty state update the DOM silently (only the load-more rows are live). A SR user gets no confirmation that "remove all" worked. **Fix:** one visually-hidden `aria-live="polite"` region announcing push/delete/empty transitions.
- **NC-PERF-02 · `unreadItemsCounter` getter allocates a new Observable per read — async pipe resubscribes every CD cycle** — `notification-center.service.ts:130-141`; trigger delegate `notification-center.ts:336-338`. Bound as `trigger.unreadItemsCounter | async` in a long-lived navbar view (the documented pattern in all 6 examples), and `AsyncPipe` compares by identity — every CD cycle disposes and rebuilds the chain (O(n) filter + allocations, app lifetime). **Fix subtlety (load-bearing):** the churn is accidentally what keeps the count fresh, because `item.read` is mutated without re-emitting `originalItems`. - **NC-PERF-03 · `groupedItems` re-parses every date O(n·log n) per emission** — `notification-center.service.ts:92-106`, `:240-265`. `makeGroup` does 3 date ops per item and `compareByDateDesc` re-parses **both** operands per comparison in both sorts — ≈13 000 adapter parses per emission at 1000 items (30–80 ms), on the same trigger as the NC-PERF-01 rebuild. At ≤100 items it is 1–5 ms (honest caveat). **Fix:** parse once per item (cache a timestamp at ingestion), group and sort on the cached number.
- **NC-PERF-04 · Every list scroll re-enters the zone and ticks the app** — `notification-center.html:59`. OverlayScrollbars initializes outside the zone, but observing the `onScroll` output wraps every scroll callback in `ngZone.run()` (`scrollbar.component.ts:159-169`); `auditTime(100)` limits only the bottom-check, not the zone re-entry — ~60 app ticks/s during a flick. **Fix:** feed `scroll$` outside the zone (scrollbar `[events]` input or a native listener via `runOutsideAngular`), re-enter only in the audited subscriber.
