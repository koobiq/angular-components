> Scope: `packages/components/search-expandable/**` (+ `packages/components-dev/search-expandable`, `packages/docs-examples/components/search-expandable`, v20 migration schematic cross-check) · Commit `af6e64fe` · 2026-07-04

## 1. Executive Summary

`KbqSearchExpandable` is a young, compact component (296-line class, 40-line template) that collapses a search field into an icon button. Its baseline hygiene is good: standalone + `OnPush`, `inject()` DI, `host` object instead of decorators, `@if/@else` control flow, `takeUntilDestroyed()` on every subscription, `FocusMonitor.focusVia()` for focus restoration (the correct keyboard-focus-ring pattern in this repo), and locale-aware strings via `KBQ_LOCALE_SERVICE` with an override token. E2E screenshots cover both states in light/dark themes.

The main risk is the **value-emission pipeline**, which was damaged when the old `KbqFilterSearch` was folded into this component during the Angular 20 upgrade (`17bc91dd`). The old component had `(keydown.enter)="onEnter()"` on the input; the merge kept the `isEmitValueByEnterEnabled` flag and the `filter()` that suppresses debounced emission, but the Enter handler itself was never carried over — enabling the documented flag silences the control entirely (SE-BUG-01). Around the same pipeline: `emitValueTimeout` is read once in the constructor before inputs are set, so it can never take effect (SE-BUG-02); closing the field inside the debounce window leaves the stale query in the bound `FormControl` (SE-BUG-03); and the CVA echoes programmatic writes back through `onChange`, marking the control dirty and double-emitting `valueChanges` (SE-BUG-04).

The second risk is **accessibility on the default path**. The collapsed state renders an icon-only button with no accessible name (axe `button-name` failure, WCAG 4.1.2) — a release blocker under this repo's "MUST pass all AXE checks" rule (SE-A11Y-01). The expanded state's close control is a focusable `<i kbq-icon-button>` with no `role`, no name, and Enter-but-not-Space activation (SE-A11Y-02); part of that gap is inherited from `KbqIconButton` itself **(shared)**.

Everything else is modernization debt in a known shape: migration TODOs left behind (`@Input` accessors, `@ViewChildren` next to `viewChild()`, `isOpened` written internally instead of `model()`), a public mutable `BehaviorSubject`, and `any`/`unknown` leaking into the published API surface. Tests are decent in volume (25 specs) but miss exactly the paths where all four P1 bugs live.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

**SE-A11Y-01 · Collapsed search button has no accessible name** — `packages/components/search-expandable/search-expandable.html:2-15`.
The default render is `<button kbq-button>` containing only `<i kbq-icon="kbq-magnifying-glass_16">`. There is no `aria-label`, no visually-hidden text, and the tooltip (`[kbqTooltip]="tooltipText"`, `:6`) provides at best a description on hover/focus, not a name. Screen readers announce an unnamed button; axe fails the `button-name` rule on the component's default state (WCAG 4.1.2). The repo's AGENTS.md makes AXE-clean a hard requirement, so this blocks release. The fix is nearly free because a localized string already exists.
**Fix:** bind `[attr.aria-label]="tooltipText"` on the button (localized via `KBQ_LOCALE_SERVICE`/configuration token, same source the tooltip uses). Add an axe/`button-name` regression spec (couples with SE-TEST-01).

### P1 — High

**SE-BUG-01 · `isEmitValueByEnterEnabled` never emits — the Enter handler was lost in the v20 merge** — `packages/components/search-expandable/search-expandable.ts:185`, template `search-expandable.html:20-30`.
The constructor pipeline suppresses debounced emission when the flag is on (`filter(() => !this.isEmitValueByEnterEnabled())`), but the template's only key handlers are `(keyup.escape)` on the input and `(keyup.enter)` on the *close icon*. Nothing emits the value on Enter. Git archaeology confirms the regression: the pre-v20 `KbqFilterSearch` (`git show 17bc91dd~1:packages/components/filter-bar/filter-search.ts`) had `(keydown.enter)="onEnter()"` → `onSearch.emit(searchControl.value)`; the flag and the `filter()` survived the merge into `KbqSearchExpandable`, the handler did not. A repo-wide grep finds no external Enter wiring, and the spec has zero tests for this input. Net effect: enabling a documented API silences the control entirely (except the clear-on-close), and consumers migrated off `KbqFilterSearch` cannot restore their previous behavior.
**Fix:** add `(keydown.enter)="onEnterKey()"` to the input, where `onEnterKey()` calls `emitValue(this.value.getValue(), true)` when `isEmitValueByEnterEnabled()` is set. Write the failing spec first (SE-TEST-01).

**SE-BUG-02 · `emitValueTimeout` input has no effect — signal read once in the constructor** — `packages/components/search-expandable/search-expandable.ts:186`.
`debounceTime(this.emitValueTimeout())` evaluates the input signal while the pipeline is built in the constructor, i.e. before Angular sets any inputs; the operator captures the default `200` forever. Any consumer-provided `[emitValueTimeout]` is silently ignored. The old `KbqFilterSearch` built the same pipeline in `ngOnInit` (after inputs), which is why it used to work.
**Fix:** make the debounce reactive — `debounce(() => timer(this.emitValueTimeout()))` — or move pipeline construction to `ngOnInit`. Add a spec asserting a non-default timeout is honored.

**SE-BUG-03 · Closing within the debounce window leaves the stale query in the bound control** — `packages/components/search-expandable/search-expandable.ts:259-265` + `:282-287`.
`toggle()` "clears" only the internal subject (`this.value.next(defaultValue)`); the bound control is cleared indirectly, when the debounced pipeline echoes `''` through `onChange`. The `lastEmittedValue` guard breaks that chain: type `abc` and close before the 200 ms tick — `debounceTime` swallows `abc` and delivers only `''`, and `emitValue('')` compares `'' !== lastEmittedValue ('')` → false → skipped. With `[formControl]`, the control (already holding `abc` via the inner binding, see SE-BUG-04) keeps the stale query forever while the UI shows a collapsed, "empty" search; reopening reveals the ghost text and any consumer filtering stays active.
**Fix:** clear the control explicitly in `toggle()` — call `emitValue(defaultValue, true)` unconditionally (not only under `isEmitValueByEnterEnabled()`, `:262-264`), or reset `ngControl.control` directly. Spec: type → close within the debounce window → assert control value is `''`.

**SE-BUG-04 · CVA echo: programmatic writes re-enter `onChange`; with `[formControl]` the debounce is bypassed and `valueChanges` double-fires** — `packages/components/search-expandable/search-expandable.ts:174`, `:182-189`, `:245-247`; template `search-expandable.html:27`.
Two design decisions collide. (1) The inner `<input>` binds *the same control instance* the consumer bound to the host (`[formControl]="$any(ngControl?.control)"`), so every keystroke updates the consumer's control immediately — the 200 ms debounce never applies to reactive-forms consumers. (2) The pipeline `ngControl.valueChanges → value → debounceTime → onChange` then re-delivers the same value: `FormControlDirective`'s `onChange` path calls `markAsDirty()` + `setValue()`, which fires a second `valueChanges` for each settled keystroke and — worse — turns programmatic `setValue()`/`writeValue()` into a "user" edit (control becomes dirty ~200 ms after a programmatic write). This violates the CVA contract (`writeValue` must not round-trip into `onChange`). For `ngModel` consumers the debounce does work, so behavior differs by binding style.
**Fix:** decouple the view control from the consumer control — use an internal `FormControl` for the input, feed the pipeline from it, and let CVA be the only bridge (`writeValue` → internal control with `emitEvent: false`; debounced internal changes → `onChange`). This also removes the `$any()` cast (SE-ARCH-01) and makes the debounce real for both binding styles.

**SE-A11Y-02 · Close control is a focusable `<i>` without button semantics; Enter works, Space doesn't** — `packages/components/search-expandable/search-expandable.html:32-38`; **(shared)** `packages/components/icon/icon-button.component.ts:24-32`.
`KbqIconButton` makes the element focusable (`tabindex=0`) but adds no `role="button"`, no accessible name, and no keyboard activation — the template compensates with `(keyup.enter)` only. A keyboard user tabbing to the close icon cannot activate it with Space (native button behavior), and a screen reader announces an unnamed, role-less focusable element (WCAG 2.1.1, 4.1.2). Initially this handler looked like accidental duplication of Escape; verification shows it is intentional-but-incomplete keyboard support.
**Fix:** locally — add `role="button"`, a localized `aria-label` (e.g. new `clear`/`close` key in the `searchExpandable` locale section), and `(keydown.space)` handling (prevent scroll default); or replace the suffix with a real `<button kbq-button>`. File the missing button semantics of `KbqIconButton` as a shared issue (see Adjacent flags).

### P2 — Should fix

**SE-ARCH-01 · Template reaches into `ngControl.control` through `$any()`** — `search-expandable.html:27`, `search-expandable.ts:62`. The inner input binding both defeats template type-checking and creates the dual-writer topology behind SE-BUG-04. Resolved by the internal-control refactor (SE-BUG-04 fix); until then a typed getter (`get control(): FormControl`) would at least remove `$any()`.

**SE-ARCH-02 · `isOpened` is a plain `@Input` the component itself mutates** — `search-expandable.ts:88-90`, `:257`. The migration TODO ("application code writes to the input") marks exactly the case Angular's `model()` exists for. `model<boolean>(false)` + `isOpenedChange` semantics come for free (`kbq-search-expandable [(isOpened)]`), and the host-class binding becomes signal-driven.

**SE-ARCH-03 · Mixed view-query APIs: `@ViewChildren`+`QueryList` for single conditional children next to `viewChild()`** — `search-expandable.ts:76-78`, `:195-221`. The `QueryList.changes` subscriptions exist only to detect the `@if` swap and focus the new element. Signal queries express this directly: `viewChild(KbqInput)` / `viewChild(KbqButton)` + an `effect()`. Keep the queries optional and guard reads (repo pitfall: over-tightened `.required` view queries throw NG0951 in prod).

**SE-ARCH-04 · `value: BehaviorSubject` as public mutable state** — `search-expandable.ts:83`. Prior repo-wide finding `ARCH-16` (still open, see ledger). It is public API (`search-expandable.api.md:81`), the spec writes to it directly, and it duplicates the control's state. Should become an internal signal/private subject with a readonly accessor; coordinate with the SE-BUG-04 refactor since the pipeline feeds off it.

**SE-API-01 · `any`/`unknown` leak into the published API** — `search-expandable.ts:80` (`configuration;` — implicit any), `:161-163`; published as `configuration: any`, `localeData: any` (`tools/public_api_guard/components/search-expandable.api.md:39`, `:53`) and `InjectionToken<unknown>` (`:26`). Define `interface KbqSearchExpandableConfiguration { tooltip: string; placeholder: string }`, type the token `InjectionToken<KbqSearchExpandableConfiguration>`, and type `configuration`/`localeData`. Requires `yarn run build:components` + `approve-api`.

**SE-TEST-01 · The four P1 bugs live precisely in untested paths** — `search-expandable.spec.ts` (372 lines, 25 specs). No spec touches `isEmitValueByEnterEnabled`, `emitValueTimeout`, close-during-debounce, dirty-state after programmatic `setValue`, focus restoration after toggle, or the external configuration token; no spec types into the DOM input (tests poke `component.value.next()` internals instead, `:97`). Add behavioral specs (dispatch real `input`/`keydown` events) for each P0/P1 finding — they double as the regression gate for Phase 1.

**SE-DOC-01 · Documentation does not mention half of the public API** — `search-expandable.en.md`/`.ru.md` (8 lines each), `examples.search-expandable.en.md`/`.ru.md` (empty). `isEmitValueByEnterEnabled`, `emitValueTimeout`, `isOpenedChange`, `tooltipText`, `KBQ_SEARCH_EXPANDABLE_CONFIGURATION`, and the mandatory form-binding constraint (constructor throws without `formControl`/`ngModel`, `search-expandable.ts:168-170`) are all undocumented. Add an API/usage section and an example exercising the Enter mode once SE-BUG-01 is fixed.

### P3 — Nice to have / hygiene

- **SE-BUG-05 · Duplicate FocusMonitor subscriptions** — `search-expandable.ts:131-139`, `:192-193`, `:289-291`. Angular ≥14 always calls `setDisabledState(false)` at init, so `runFocusMonitor()` runs from the `disabled` setter *and* `ngAfterViewInit`, and again on every disabled→enabled flip, stacking subscriptions on the same monitored element (harmless today — they only assign `lastFocusOrigin` — but fragile). **Fix:** subscribe once, gate on a flag, or make enable/disable idempotent.
- **SE-BUG-06 · `onChange` is declared but not initialized** — `search-expandable.ts:229`. A pipeline emission before `registerOnChange` would throw `TypeError`; debounce makes it unlikely, not impossible. **Fix:** initialize to a no-op like `onTouch` (`:232`).
- **SE-A11Y-03 · Input's accessible name rests on `placeholder` alone** — `search-expandable.html:26`. Passes axe today, but placeholder-as-name is fragile (disappears while typing, low-contrast). **Fix:** add `[attr.aria-label]="placeholder"`.
- **SE-A11Y-04 · No search semantics on the input** — `search-expandable.html:20-30`. Consider `type="search"`/`inputmode` trade-offs (`type="search"` adds a native clear button that fights the custom suffix — if adopted, hide it via CSS) or a `role="search"` landmark on the expanded wrapper.
- **SE-STYLE-01 · No `search-expandable-tokens.scss` / `_search-expandable-theme.scss`** — package root vs `button`/`icon-button` convention. Visual theming is intentionally delegated to `kbq-button`/`kbq-form-field`, so this is hygiene, not a defect; but the suffix-size overrides in `search-expandable.scss:11-21` would live better behind component tokens.
- **SE-STYLE-02 · Icon names hardcoded twice** — `search-expandable.html:14`, `:18`, `:34` (`kbq-magnifying-glass_16`, `kbq-circle-xmark_16`). Consider extending the configuration token if icon customization is ever needed; at minimum deduplicate the magnifying-glass literal.
- **SE-TEST-02 · E2E is screenshots-only** — `e2e.playwright-spec.ts` (one test, light/dark of both states). No interaction flow (toggle → type → Escape/close → focus restored) and no axe scan. Add one interaction test after Phase 2.
- **SE-ARCH-05 · Hardcoded `name="value"` on the input** — `search-expandable.html:22`. Leaks a generic control name into the parent form/autofill heuristics; drop it or derive from an input.

## 4. Recommended Remediation Phases

**Phase 1 — Value-pipeline correctness (regression specs first).**
IDs: SE-BUG-01, SE-BUG-02, SE-BUG-03, SE-BUG-04 + SE-TEST-01 (write failing specs before fixes). One coherent change: internal `FormControl` for the input, pipeline rebuilt off it with reactive debounce, explicit forced clear in `toggle()`, Enter handler restored. Fixing SE-BUG-04's topology makes 01/02/03 fixes small; landing them separately would churn the same 40 lines four times.

**Phase 2 — Accessibility blockers.**
IDs: SE-A11Y-01 (P0), SE-A11Y-02, optionally SE-A11Y-03/04; plus the axe regression spec. Independent of Phase 1; can land first if release pressure demands (SE-A11Y-01 is the only P0). New locale key for the close-control label touches `packages/components/core/locales/*` (all 5 locales).

**Phase 3 — API & architecture modernization.**
IDs: SE-ARCH-01..05, SE-API-01. `model()` for `isOpened`, signal view-queries + `effect()` for focus handoff, typed configuration interface/token, `value` de-publicized. Public API changes: run `yarn run build:components` then `yarn run approve-api` (sequentially); breaking-change review for `value`'s visibility. Do after Phase 1 — same files, and the internal-control refactor lands there.

**Phase 4 — Tests & docs completion.**
IDs: SE-TEST-02, SE-DOC-01. Playwright interaction flow (toggle → type → close → focus restored) + docs for the full input/output/token surface with an Enter-mode example (`yarn build:docs-examples-module` after adding examples).

**Phase 5 — Style hygiene.** Optional.
IDs: SE-STYLE-01, SE-STYLE-02. Tokens/theme scaffolding and icon-name deduplication; no user-visible change expected (guarded by existing screenshots).

## 5. Verification Strategy

General gates (sequential, never parallel):
- `npx jest packages/components/search-expandable/search-expandable.spec.ts` — unit suite green; new behavioral specs use real DOM events, not `component.value.next()`.
- `npx playwright test packages/components/search-expandable/e2e.playwright-spec.ts` — screenshots unchanged for Phases 1–4 (no visual delta expected); update only in Phase 5 if tokens shift rendering.
- `yarn run build:components` then `yarn run check-api` — API guard; `approve-api` only for Phase 3's intentional surface changes.
- `yarn run eslint` / `yarn run stylelint` on touched files.

Per-phase assertions:
- **Phase 1:** with `isEmitValueByEnterEnabled`, typing emits nothing until Enter, then exactly once; `[emitValueTimeout]="500"` delays emission ~500 ms (`fakeAsync` + `tick`); type-then-close within the window leaves control value `''`; programmatic `setValue()` leaves the control pristine and fires `valueChanges` exactly once; `ngModel` and `formControl` behave identically.
- **Phase 2:** axe scan of collapsed and expanded states reports zero violations; close control activates via Enter **and** Space; SR name present for button, input, close control.
- **Phase 3:** `[(isOpened)]` two-way binding works; `tools/public_api_guard/components/search-expandable.api.md` shows typed `configuration`/token and no `any`; no NG0951 from view-query reads (queries stay optional).
- **Phase 4:** docs build renders new example (`yarn run docs:build`); Playwright interaction test passes in light/dark.
