# Koobiq `button-toggle` Component Family — Code Review & Improvement Plan

> Scope: `packages/components/button-toggle` (`KbqButtonToggleGroup`, `KbqButtonToggle`, `KbqButtonToggleChange`, `ToggleType`, `KBQ_BUTTON_TOGGLE_GROUP_VALUE_ACCESSOR`, `KbqButtonToggleModule`) + the shared abstractions it composes (`KbqButton`/`KbqButtonCssStyler`, `KbqTitleDirective`, `KbqIcon`, CDK `FocusMonitor`/`SelectionModel`, `getNodesWithoutComments`) · Commit `18ea72fe` · 2026-06-30
> Generated by an automated multi-agent review (8 review dimensions + adversarial verification of every finding). 57 raw findings confirmed across dimensions → deduplicated to 6×P1, ~20×P2, ~25×P3 (0×P0); 4 refuted. Treat as a high-signal starting point; spot-check before acting.
> Findings tagged **(shared)** live in `core`/`button` and also affect siblings. This document is a review + roadmap; no source is modified by it.

## 1. Executive Summary

- **No release blockers (0×P0), but accessibility is broken in substance (grade D).** The control *behaves* like a radio group (single mode) / multi-select (multiple mode) — it even computes `type: 'radio' | 'checkbox'` in `ngOnInit` — yet **nothing is exposed to assistive tech**: the inner `<button>` has no `role`, no `aria-checked`/`aria-pressed`; the group host has no `role="radiogroup"`/`"group"` and no accessible-name hook; the computed `type` is **dead code, never bound**. Selection is communicated by a CSS class (`.kbq-selected`) only. This is a real WCAG 4.1.2 (Name/Role/Value) + 1.3.1 failure on a stateful control.
- **`focus()` is silently broken (P1).** `focus()` calls `.focus()` on the host `<kbq-button-toggle>`, which is not focusable (tabindex lives on the inner `<button>`). The correctly-queried focus target `mcButton = viewChild.required(KbqButton)` exists but is **never used** — dead.
- **A real theming bug hides in one wrong class name (P1).** `_button-toggle-theme.scss` colors `& > .kbq-button, & > .kbq-icon-button`, but `KbqButton` emits `.kbq-button-icon` for icon-only buttons (and drops `.kbq-button` — they are mutually exclusive). So **icon-only toggles receive no themed background/text/icon color in any state** and fall back to the plain button transparent theme. The broken rendering is frozen into the `02-light.png` Playwright baseline rather than caught.
- **Icon-only toggles are nameless buttons (P1).** No `aria-label` input, no safeguard; `KbqIcon` glyphs are `aria-hidden`. Shipped in the docs `overview`/`alignment` examples → live AXE `button-name` violations.
- **Public types lie (P1/P2).** `buttonToggleGroup = inject(KbqButtonToggleGroup, { optional: true })!` is typed non-null but is `null` for a standalone toggle (the class guards it everywhere); the public API snapshot freezes the lie. The `disabled` getter is typed `boolean` but returns `null` standalone. `value`/`selected`/`change`/`valueChange`/`buttonToggles` are pervasively `any`.
- **Stale Angular-Material heritage throughout.** Cyrillic homoglyph in public JSDoc (`MсButtonToggle`, Cyrillic `с`); test variables named `nativeCheckboxLabel`/`buttonToggleLabelElements` typed `HTMLLabelElement` that actually query `<button>`; comments referencing "native radio/checkbox" and "Jasmine" that do not apply; a dead `expect(groupInstance.value);` with no matcher.
- **Reactivity is pre-signals (architecture C / lifecycle C+).** Six public inputs are legacy `@Input` getter/setter pairs (with stale "Skipped for migration" TODOs) using the deprecated `coerceBooleanProperty`; state lives in plain fields forcing manual `markForCheck()` fan-out; `iconType`/`type` are mutable public derived fields. The sibling `toggle.component.ts` already uses `input()` + `booleanAttribute`.
- **Tests cover core selection well but skip a11y, focus, and icon detection (C+).** No AXE/aria assertions anywhere; `FocusMonitor`/`focus()`/`tabIndex`/`iconType` untested; Playwright fakes hover/active/focus via CSS classes and covers dark theme in only 1 of 3 screenshots.
- **What is solid:** OnPush; the `SelectionModel` selection logic (single/multiple, falsy values, repeated/swapped toggles); two-way binding + forms integration; `FocusMonitor` monitor/stopMonitoring **is** correctly paired (no leak); per-CD cost is genuinely small (performance B+); RTL is mostly safe (gap/logical spacing). `prefers-reduced-motion` is a non-issue — there are no transitions, and the only animation (`.kbq-progress`) is never applied here and is already gated in core.

## 3. Prioritized Findings (deduplicated, verified)

### P1 — High

**BTOG-A11Y-01 · No ARIA role/state — selection is invisible to assistive tech** — `button-toggle.component.ts:308-321` (inner button), `:57-60` (group host), `:364`/`:397` (dead `type`).
The group behaves like a radio-button group (single mode) or a multi-select (multiple mode), and each toggle computes `type = 'radio' | 'checkbox'` in `ngOnInit`. But nothing is exposed: the inner `<button>` has no `role`, `aria-checked`, or `aria-pressed`; the group host (`kbq-button-toggle-group`) has no `role="radiogroup"`/`"group"` and no `aria-label`/`aria-labelledby`; the composed `KbqButton` adds only `aria-disabled`. The `type` value is never bound to the DOM (a grep shows it is read nowhere) — it is dead code. A screen-reader user hears a plain, unlabeled button with no selected/pressed state and no group relationship in both modes. WCAG 2.1 SC 4.1.2 (Name/Role/Value) + 1.3.1.
**Fix:** single mode → `role="radio"` + `[attr.aria-checked]="checked"` on the inner button and `role="radiogroup"` on the group host; multiple/standalone → `[attr.aria-pressed]="checked"` (toggle-button pattern) or `role="checkbox"` + `aria-checked`, plus `role="group"` on the host. Switch the attribute on the already-computed `type` and drive state from the existing `checked` getter. Add an accessible-name hook (`aria-label`/`aria-labelledby`) on the group. Pair with BTOG-A11Y-03 (roving tabindex) so `role="radio"` matches expected keyboard behavior.

**BTOG-A11Y-02 · Icon-only toggle renders as a nameless button (AXE `button-name`)** — `button-toggle.component.ts:307-321`; SVG `aria-hidden` at `icon/icon-registry.ts:287,312`; live cases at `docs-examples/.../button-toggle-overview-example.html:26-38`, `button-toggle-alignment-overview-example.html:25-31`, `components-dev/button-toggle/template.html`.
A toggle whose projected content is only an icon renders an inner `<button>` with no text. `KbqIcon`'s SVG is `aria-hidden="true"` and the `<i kbq-icon>` carries no text, so the button has no accessible name — an AXE `button-name` / WCAG 4.1.2 failure. There is no `aria-label` input on `KbqButtonToggle` and no dev-mode warning. The frozen API (`button-toggle.api.md:48-53`) confirms no name input exists. Not hypothetical: the canonical docs examples ship icon-only groups. (Mirrors `button` BTN-A11Y-03.)
**Fix:** add an `aria-label`/`aria-labelledby` input forwarded to the inner button, and in dev mode `console.warn` when a toggle resolves to icon-only content with no accessible name (hook at the existing icon detection in `ngAfterContentInit`). Add labels to the shipped docs examples.

**BTOG-API-01 · `buttonToggleGroup` typed non-null but injected `{ optional: true }!` (null at runtime)** — `button-toggle.component.ts:335`; `tools/public_api_guard/components/button-toggle.api.md:24`.
`buttonToggleGroup = inject(KbqButtonToggleGroup, { optional: true })!` — the `!` strips `null` from the static type, but the injection is optional and is `null` for a standalone toggle (tested at `button-toggle.component.spec.ts:691`). The class guards it everywhere it dereferences (`:347,356,381,396,399,427,448`), proving the author expects `null`. The non-null assertion disables TypeScript's ability to flag a future un-guarded access (which would NPE on a standalone toggle), and the lie is frozen into the public API snapshot (`api.md:24` declares non-null).
**Fix:** drop the `!`, type the field `KbqButtonToggleGroup | null` and make it `protected` (only consumed internally + template); keep the existing truthiness guards.

**BTOG-BUG-01 · `focus()` focuses the non-focusable host, not the inner button** — `button-toggle.component.ts:433-435`.
`focus()` calls `this.element.nativeElement.focus()` on the host `<kbq-button-toggle>`, which has no tabindex (the `[tabIndex]` binding is on the inner `<button>` at `:315`). Calling `.focus()` on a non-focusable custom element is a no-op — focus never moves. Meanwhile `mcButton = viewChild.required(KbqButton)` (`:367`) is the correct focus target but is referenced nowhere — dead code. The public `focus()` API silently does nothing.
**Fix:** delegate to the inner button: `this.mcButton().focus()` (`KbqButton.focus()` already guards `disabled` and focuses the native element). Optionally expose `focusViaKeyboard()` too.

**BTOG-STYLE-01 · Theme mixin targets non-existent `.kbq-icon-button`; icon-only toggles get no themed colors** — `_button-toggle-theme.scss:5`.
The state mixin applies background/text/icon color via `& > .kbq-button, & > .kbq-icon-button`. `KbqButton` never emits `.kbq-icon-button` — it emits `.kbq-button-icon` for icon-only buttons and drops `.kbq-button` (`button.component.ts:67-68`, the two classes are mutually exclusive). The structural SCSS uses `.kbq-button-icon` correctly (`button-toggle.scss:35-36`), so layout works and hides the gap, but the theme mixin's `.kbq-icon-button` branch matches nothing. Result: icon-only toggles receive **no** themed background/text/icon color for any state (default/hover/active/selected/selected-active/disabled/selected-disabled) and fall back to `KbqButton`'s transparent theme. The Playwright "with icon" test (`e2e.playwright-spec.ts:19-27`) renders exactly this case, so the broken render is frozen into `02-light.png` rather than caught.
**Fix:** replace `& > .kbq-icon-button` with `& > .kbq-button-icon` at `_button-toggle-theme.scss:5`, then re-record the "with icon" Playwright baselines.

**BTOG-TEST-01 · `FocusMonitor` monitor/stopMonitoring lifecycle is untested** — `button-toggle.component.ts:417` (monitor), `:423` (stopMonitoring); `button-toggle.component.spec.ts` (no coverage).
`ngAfterViewInit` calls `focusMonitor.monitor(el, true)` and `ngOnDestroy` calls `focusMonitor.stopMonitoring(el)`. Neither is exercised: no test asserts that the focus origin drives `.cdk-keyboard-focused` (the only thing producing the visible focus ring, `button-toggle.scss:30-33`) or that `stopMonitoring` runs on destroy (a teardown/leak path). The wiring looks correct, so this is a coverage gap on an a11y-relevant path rather than a proven bug.
**Fix:** spy `FocusMonitor.monitor`/`stopMonitoring` (or drive a real keyboard focus origin) — assert the keyboard-focus class applies and that `stopMonitoring` is called on destroy.

### P2 — Should fix

**Accessibility**
- **BTOG-A11Y-03 · No roving-tabindex / arrow-key navigation for a radio-style group** — `button-toggle.component.ts:315`. Every inner button gets `[tabIndex]="tabIndex() || 0"`, so all toggles are tab stops; a grep for `keydown`/`Arrow*`/`FocusKeyManager`/roving across the package returns nothing. This is acceptable for a toggle-button group but wrong for the radio semantics implied by `type='radio'` (WAI-ARIA expects one tab stop into the group, with Arrow keys moving + selecting). **Fix:** for single-selection groups implement the radiogroup keyboard pattern via CDK `FocusKeyManager` (selected toggle `tabIndex=0`, others `-1`; Arrow keys move focus + selection); keep per-toggle tab stops for multiple mode. Must land together with BTOG-A11Y-01's `role="radio"`.
- **BTOG-A11Y-04 · Group host exposes no `role` and no accessible-name mechanism** — `button-toggle.component.ts:57-60`. The host sets only `class`/`[class.kbq-button-toggle_vertical]`; no `role` and no `aria-label`/`aria-labelledby` binding, so the set of toggles is not announced as a group and cannot be named. (Overlaps BTOG-A11Y-01 for the radiogroup case; scoped here to the grouping wrapper + naming hook for multiple mode.) **Fix:** add `role="group"` (or `role="radiogroup"` in single mode) and support `aria-label`/`aria-labelledby`; document in `button-toggle.en.md`/`.ru.md`.

**Correctness**
- **BTOG-BUG-02 · `onToggleClick` emits the per-toggle `change` unconditionally; the comment claims single-selector-only** — `button-toggle.component.ts:443-455` (comment `:454`, emit `:455`). On a no-op re-click of an already-selected radio (`isSingleSelector=true`, `newChecked=true===_checked`), the `if (newChecked !== this._checked)` guard is false so `syncButtonToggle`/`onTouched`/`valueChange`/CVA do **not** fire — yet `this.change.emit(...)` outside the guard still fires with the unchanged value, while the group emits nothing. The always-emit behavior is locked in by `button-toggle.component.spec.ts:287-305`, but the comment is wrong. **Fix:** correct the comment to state it always emits; if emit-on-real-change is intended, move the emit inside the guard (confirm intent — it changes documented test behavior).
- **BTOG-TYPE-01 · `disabled` getter typed `boolean` returns `null` for a standalone toggle** — `button-toggle.component.ts:380-382` (+ `:335`). `return this._disabled || (this.buttonToggleGroup && this.buttonToggleGroup.disabled)` — for a standalone toggle (`buttonToggleGroup === null`) with `_disabled=false` this evaluates `false || null` → `null`, violating the declared `boolean` return type. The `!` on `:335` hides it from strict typing. Renders fine (null is falsy) but violates the public getter contract. **Fix:** `return this._disabled || (this.buttonToggleGroup?.disabled ?? false);`.

**Public API & Types**
- **BTOG-API-02 · Pervasive `any` on the public value surface** — `button-toggle.component.ts:37,49,82,92,98,144,165,168,183,189,372` / `api.md:19,51,62-64,71,83,88,92-94,97`. `KBQ_BUTTON_TOGGLE_GROUP_VALUE_ACCESSOR`, `KbqButtonToggleChange.value`, group `value`/`selected`/`writeValue`/`valueChange`, toggle `value`, and the CVA fns are all `any`; the group has no generic type parameter, so consumers get zero type safety on bound/emitted values. **Fix:** type the provider const as `Provider`; switch the trivial `any`→`unknown`; longer-term make `KbqButtonToggleGroup<T>` / `KbqButtonToggleChange<T>` / `KbqButtonToggle<T>` (SemVer-significant → defer to a breaking batch).
- **BTOG-API-03 · `buttonToggles` Signal element type erased to `any[]` by `forwardRef`** — `button-toggle.component.ts:117` / `api.md:69`. `contentChildren(forwardRef(() => KbqButtonToggle))` resolves to `Signal<readonly any[]>` because the `forwardRef` loses the element type (contrast the correctly-typed `icons` at `api.md:33`). **Fix:** `contentChildren<KbqButtonToggle>(forwardRef(() => KbqButtonToggle))` — yields `Signal<readonly KbqButtonToggle[]>` with no runtime change.
- **BTOG-API-04 · `tabIndex` typed `number | null` but the default is `undefined`** — `button-toggle.component.ts:375` / `api.md:48`. `input<number | null>(undefined!)` — the declared type excludes the actual default value (`tabIndex()` returns `undefined` before any binding). No functional bug (the template guard `tabIndex() || 0` treats them all as falsy), but the public type is dishonest. **Fix:** `input<number | null>(null)` (use `null` as the unset sentinel) or include `undefined` in the type.
- **BTOG-API-05 · Cyrillic homoglyph + stale "Mc" naming in public JSDoc** — `button-toggle.component.ts:43,46,48` (also stale "radio-button group" wording at `:53`). The three JSDoc comments on `KbqButtonToggleChange` read `MсButtonToggle`, where the second character is Cyrillic Small Letter Es (U+0441), not Latin `c` (verified by byte inspection). The name is also stale — the actual class is `KbqButtonToggle`. These are user-visible docs on a `@public` class, violating the English/ASCII-comment policy and acting as a copy/search trap. **Fix:** replace all three with ASCII `KbqButtonToggle`; update the directive description to mention both single (radio-like) and multiple (checkbox-like) modes.

**Architecture & conventions**
- **BTOG-ARCH-01 · All six public inputs are legacy `@Input` getter/setter pairs (signal migration skipped); uses deprecated `coerceBooleanProperty`** — group `vertical/value/multiple/disabled` and toggle `checked/value/disabled` (`:69-137,345-386`), each carrying the auto-migration "Skipped for migration" TODO. The sibling `toggle.component.ts` already uses `input()` + `booleanAttribute`/`numberAttribute`. **Fix:** migrate pure-coercion inputs to `input(false, { transform: booleanAttribute })` first (`vertical`, `multiple`); plan `disabled`/`checked`/`value` as `model()`/`computed()` + a selection signal (coordinated with BTOG-RX-* / BTOG-PERF-*). At minimum replace `coerceBooleanProperty` with `booleanAttribute`.
- **BTOG-ARCH-02 · Conflicting host class bindings: static `class: 'kbq-button-toggle'` + `[class]: '"kbq-button-toggle" + iconType'`** — `button-toggle.component.ts:326-331`. The `[class]` string binding re-emits the base class (making the static one redundant) and glues `iconType` into non-BEM tokens (`kbq-button-toggle-icon`/`-icon-text`), and mixes a whole-string `[class]` with the discrete `[class.kbq-disabled]`/`[class.kbq-selected]`. It works (Angular merges them) but is brittle and non-idiomatic, and the glued classes are unused (see BTOG-STYLE-02). **Fix:** drop the concat; express the modifier as discrete bindings `[class.kbq-button-toggle_icon]` / `[class.kbq-button-toggle_icon-text]` (matching the existing `kbq-button-toggle_vertical` BEM modifier), keeping the static base class.
- **BTOG-ARCH-03 · `iconType`/`type` are public mutable imperative derived fields** — `button-toggle.component.ts:364-365` (decl), `:397` (`type`), `:412` (`iconType`) / `api.md:35,50`. Both are derived state assigned imperatively and leak into the public API as writable fields; `type` is never read anywhere (dead public state), `iconType` is template-only. **Fix:** make `type` a `computed`/`protected readonly`; derive `iconType` reactively and mark it `protected`, removing two unintended public writable fields.

**RxJS & Lifecycle**
- **BTOG-RX-01 · Uncancelled microtask in `ngOnDestroy` runs `syncButtonToggle` after the group is torn down** — `button-toggle.component.ts:420-430`. `if (group && group.isSelected(this)) Promise.resolve().then(() => group.syncButtonToggle(this, false))` has no liveness guard, and `KbqButtonToggleGroup` implements **no `OnDestroy`**. When the whole `<kbq-button-toggle-group>` is removed, each selected child still queues this microtask, which runs after teardown: it mutates the now-stale `SelectionModel` via `deselect()` and calls `valueChange.emit(this.value)` on a destroyed `output()`. Both are inert today (no crash), but it is wasted work and a latent teardown-emission hazard; the whole-group-destroy path is untested (the existing test removes a single child while the group stays alive). **Fix:** give `KbqButtonToggleGroup` an `ngOnDestroy`/destroyed flag and early-return in `syncButtonToggle`, or schedule via injector-scoped `afterNextRender`/`takeUntilDestroyed` so the deferred call auto-cancels.
- **BTOG-RX-02 · Dead guard: null-check on a `contentChildren()` signal that can never be null** — `button-toggle.component.ts:130-136`. In the `disabled` setter, `const buttonToggles = this.buttonToggles(); if (!buttonToggles) { return; }` — a plural `contentChildren()` signal always returns a `ReadonlyArray` (`[]` before/outside `ngAfterContentInit`), never `null`. The guard is unreachable dead code, a QueryList-era leftover. **Fix:** remove the guard (or eliminate the imperative loop entirely via signal-derived child state — see the RX/ARCH cluster).

**Tests**
- **BTOG-TEST-02 · No accessibility assertions anywhere (zero AXE, zero `aria`/`role`)** — `button-toggle.component.spec.ts` (whole file), `e2e.playwright-spec.ts` (whole file). The Jest suite asserts only `.checked`/`.value`/classes/form-state/change events; the Playwright suite is screenshot-only. ARIA regressions and the BTOG-A11Y-* gaps would pass silently. (Mirrors the repo-wide gap in `button` BTN-TEST-04.) **Fix:** once the ARIA from BTOG-A11Y-01..02 lands, assert rendered `role`/`aria-checked`/`aria-pressed` per mode, the icon-only name path, and tabindex management; add an `axe-playwright` `analyze()` pass over the e2e page in light + dark as part of library-wide a11y tooling.
- **BTOG-TEST-03 · `iconType` (`-icon` vs `-icon-text`) detection is untested** — `button-toggle.component.ts:404-414`. None of the test fixtures includes an `<i kbq-icon>` child, so `icons.length` is always 0 and both icon branches are dead in tests. **Fix:** add (a) icon-only and (b) icon+text fixtures and assert the resulting host class.
- **BTOG-TEST-04 · `focus()` method and `tabIndex` input are untested** — `button-toggle.component.ts:375,432-435,315`. Both are frozen public API with no coverage. **Fix:** assert `focus()` moves focus to the inner button and that `[tabIndex]` propagates (default `0`, custom value reflected).
- **BTOG-TEST-05 · Playwright fakes hover/active/focus via CSS classes; no real pseudo-states** — `e2e.ts:52-56`, `e2e.playwright-spec.ts`. States are toggled via `[class.kbq-hover]`/`[class.kbq-active]`/`[class.cdk-keyboard-focused]`/`[class.kbq-progress]`; the theme aliases these to the real `:hover`/`:active`/focus styles, so the screenshots only verify the class-fallback branch and never exercise real pseudo-states or `FocusMonitor`. The spec drives no `page.hover()`/`.focus()`/Tab. **Fix:** drive at least one state via real Playwright interaction (`page.hover()`, keyboard Tab).
- **BTOG-TEST-06 · Dead assertion: `expect(groupInstance.value);` with no matcher** — `button-toggle.component.spec.ts:275`. Asserts nothing; the test's intent (group value updated to `'test1'`) is silently unverified. **Fix:** `expect(groupInstance.value).toBe('test1');` — or delete the test, which duplicates `:233`/`:251` (see BTOG-TEST-09).
- **BTOG-TEST-07 · Material-heritage misnaming/mistyping of element locals** — `button-toggle.component.spec.ts:179,401,527` (`HTMLLabelElement` for elements queried via `By.css('button')`), `:435,459` (`nativeCheckboxLabel`/`nativeCheckboxButton`). There are no `<label>` or native checkbox/radio elements in this component. The wrong typings can mask real type errors and the names mislead. **Fix:** rename to `…ButtonElements`/`innerButton` and type `HTMLButtonElement` (match the correctly-named `innerButtons` at `:76/89`).
- **BTOG-TEST-08 · Name/body mismatch: "should have the correct FormControl state…" tests an NgModel** — `button-toggle.component.spec.ts:124-144`. The test asserts `valid`/`pristine`/`touched` on `groupNgModel` (an `NgModel`), lives in the ngModel describe block, and a separate `using FormControl` block already exists at `:22`. **Fix:** rename to reference NgModel control state.

### P3 — Nice to have / hygiene

**Accessibility**
- **BTOG-A11Y-05 (shared) · 1px zero-offset keyboard focus ring that recolors the border** — `button-toggle.scss:30-33`, `_button-toggle-theme.scss:50-52`, `button-toggle-tokens.scss:35`. `outline: 1px solid var(--kbq-states-line-focus-theme)` with no `outline-offset`, plus a same-token `border-color`. **Public API & types**

**Architecture**
- **BTOG-ARCH-04 · Imperative cross-component selection plumbing instead of signal-derived state** — `button-toggle.component.ts:130-136` (disabled fan-out), `:219-240` (public `syncButtonToggle`), `:284,294` (group writes `toggle.checked`), `:463-467` (public `markForCheck`). The pre-signals Material pattern; functionally correct, but it is the reason the component needs manual `markForCheck` under OnPush. **Fix:** as part of the signal migration, expose group state as signals and derive child `checked`/`disabled` via `computed()`, removing the manual fan-out and the public `markForCheck` escape hatch.
- **BTOG-ARCH-05 · Legacy `KbqButtonToggleModule` retained; first-party code imports the module rather than the standalone components** — `button-toggle.module.ts`, `public-api.ts:2`; `e2e.ts`, all spec wrappers, and all docs-examples import `KbqButtonToggleModule`. Acceptable (documented legacy support) but it doubles the public surface. **Fix:** keep the module for back-compat but dogfood standalone imports in first-party examples/dev/e2e/spec.

**Correctness**
- **BTOG-BUG-03 (shared) · Icon detection depends on `preserveWhitespaces:false`, and its output class is unused** — `button-toggle.component.ts:404-414`, shared `core/utils/utils.ts:28-32`. `getNodesWithoutComments` strips only comment nodes, not whitespace text nodes, so a consumer compiling with `preserveWhitespaces:true` misclassifies an icon-only toggle as `-icon-text`. Mitigated here because the resulting classes are unused (the work is dead). Same class of defect as `button` BTN-BUG-03. **Fix:** filter whitespace-only text nodes when counting; or remove the whole detection if the classes stay unused.

**Templates & styles**
- **BTOG-STYLE-02 · `iconType` host classes (`kbq-button-toggle-icon`/`-icon-text`) are computed but styled by nothing** — `button-toggle.component.ts:328,365,412`. A repo-wide grep finds zero references; it is dead computed state plus a per-init DOM query for no rendered effect. **Fix:** remove the computation + dynamic host class, or — if intended as a public hook — document it and add the selectors.
- **BTOG-STYLE-03 · Duplicate focus `border-color` (structural raw token shadowed by the theme token)** — `button-toggle.scss:32` sets `border-color: var(--kbq-states-line-focus-theme)`; `_button-toggle-theme.scss:51` sets `border-color: var(--kbq-button-toggle-item-states-focused-outline)` at equal specificity, included last, so the theme wins. Both resolve identically today, so a consumer overriding only the component token works by luck of source order. **Fix:** drop the structural `border-color`, let the theme own it via the dedicated token; reference the component token for `outline` too.
- **BTOG-STYLE-04 · Redundant `border-radius` re-declared in the vertical block** — `button-toggle.scss:96` duplicates the identical value already applied at `:39`; the vertical block only needs `width: 100%`. **Fix:** delete the redundant declaration.

**Performance** (all bounded, none on a hot path)
- **BTOG-PERF-01 · `[class]` host binding allocates a new string every change-detection cycle** — `button-toggle.component.ts:328`. `"kbq-button-toggle" + iconType` is rebuilt each dirty-check even though `iconType` is effectively constant after init; when `iconType === ''` it also duplicates the static class. Resolves with BTOG-ARCH-02.
- **BTOG-PERF-02 · `value` getter `.map`s `selectionModel.selected` to a new array on every read** — `button-toggle.component.ts:82-90`. Read 2–3× per click (emit + `valueChange`), and each emitted value is a fresh array reference that can defeat consumer reference-equality memoization. Not a template/host binding (off the CD path). **Fix:** compute the value once per change and reuse; longer term back selection with a signal/`computed`.
- **BTOG-PERF-03 · `disabled` setter fans out `markForCheck` to every child on each write; redundant init self-write** — `button-toggle.component.ts:127-137` (+ `:176`). No `oldValue !== newValue` guard, so a parent CD re-feeding the same value re-marks N children; `ngAfterContentInit` does `this.disabled = this._disabled` purely to trigger the fan-out. Bounded (disabled writes only), not hot. **Fix:** guard on value change; signal-derived child `disabled` removes the fan-out entirely.
- **BTOG-PERF-04 · `checked` is a getter delegating to `group.isSelected` on every dirty-check (×2 bindings)** — `button-toggle.component.ts:346-348` (consumed at `:313,330`). An O(1) Set lookup, negligible, but it is the canonical example of getter-based reactivity that OnPush cannot memoize. **Fix:** back with a signal/`computed` during the migration.

**RxJS & lifecycle**
- **BTOG-RX-03 · State held in plain fields forces manual `markForCheck()` instead of signal-driven CD** — `button-toggle.component.ts:136,176,185,360,463-467`. The legacy push pattern; root cause of BTOG-RX-02 and BTOG-PERF-03. **Fix:** migrate `checked`/`disabled`/`vertical`/`multiple` to signals; derive child state via `computed()`; then delete the manual fan-out and the public `markForCheck()`.
- **BTOG-RX-04 · `iconType` derived imperatively in `ngAfterContentInit` instead of reactively** — `button-toggle.component.ts:404-414`. A one-shot DOM read; projected icon content that changes after init (via `@if`) leaves the host class stale. **Fix:** recompute via an `effect()` keyed on `icons()` (a pure `computed` cannot re-read live `childNodes`), or document the fixed-at-init behavior.

**Tests**
- **BTOG-TEST-09 · Duplicate test re-asserts single-selection group-update** — `button-toggle.component.spec.ts:270-276`. Its only real assertion is subsumed by `:233-240` and `:251-268`; combined with the dead assertion (BTOG-TEST-06) it adds no coverage, and the title references a "native radio button" that does not exist. **Fix:** delete, or repurpose into a genuinely missing assertion (keyboard/focus).
- **BTOG-TEST-10 · Stale Jasmine reference in a Jest comment** — `button-toggle.component.spec.ts:382-383` ("…when Jasmine attempts to stringify them."). The suite runs on Jest. **Fix:** retarget or drop the runner-specific note.
- **BTOG-TEST-11 · "checkboxes" terminology in a single-selection test** — `button-toggle.component.spec.ts:345` ("should deselect all of the checkboxes…") lives in the exclusive (radio-semantic) describe block. **Fix:** rename to "toggles".
- **BTOG-TEST-12 · `disabled`-getter-falsy + standalone-disabled path untested** — `button-toggle.component.ts:380-382`; the spec only covers group-disabled cases. (Note: a `typeof toggle.disabled === 'boolean'` assertion would currently fail on the standalone path, exposing BTOG-TYPE-01.) **Fix:** add a standalone `[disabled]` test once the getter is coerced.
- **BTOG-TEST-13 · Dark theme covered for only 1 of 3 Playwright scenarios** — `e2e.playwright-spec.ts:12-39`. Only "with title, prefix and suffix" captures a dark screenshot; the (common) title-only and icon-only layouts have no dark-mode coverage. **Fix:** add `-dark.png` for "with title" and "with icon" (or a light+dark helper applied to all three).
- **BTOG-TEST-14 · No explicit keyboard-interaction test** — `button-toggle.component.spec.ts` (all interactions use `.click()`). Soft: the inner native `<button>` already maps Enter/Space → click, so existing tests cover activation; the genuinely missing capability (arrow-key navigation) is unimplemented (BTOG-A11Y-03). **Fix:** add Enter/Space defense-in-depth; add arrow-key tests only after roving-tabindex is implemented.

### Refuted on verification (excluded)

- *"Standalone re-click is a no-op that still emits (untested)"* — refuted. A standalone toggle is never a single-selector (`isSingleSelector` requires a non-multiple group), so a standalone re-click always toggles state. The radio no-op-but-still-emit contract **is** already tested at `button-toggle.component.spec.ts:287-305`.
- *"`prefers-reduced-motion` is never covered"* — refuted. `button-toggle` has no `transition`/`animation`/`@keyframes`; the only motion (`.kbq-progress`) is never applied here and is already gated behind `@media (prefers-reduced-motion: reduce)` in core. A reduced-motion screenshot would be pixel-identical.
- *Two performance "confirmations"* (the one-time `ngAfterContentInit` DOM walk; the conditional `ngOnDestroy` microtask) — verified as correct and off the hot path: no performance defect. (The lifecycle hazard of the microtask is captured separately as BTOG-RX-01.)
- *"File named `.component.ts` diverges from the reference component"* — the reference `button/` uses the **same** `.component.ts` suffix (`button.component.ts`), so `button-toggle` is consistent with it, not divergent. Excluded.

## Appendix A — Review Methodology

Produced by 8 parallel review agents (architecture, RxJS/lifecycle, correctness, accessibility, public API/types, tests, templates/styles, performance), each reading the source directly. Every raw finding was then adversarially verified by an independent agent against the actual code (line numbers re-checked, severities re-rated, proposed fixes validated). Of the raw findings, 57 were confirmed across dimensions (deduplicated here to 6×P1, ~20×P2, ~25×P3) and 4 refuted (several down-rated where the proposed fix was unsound or the impact purely cosmetic). The reviewer additionally hand-verified the two highest-impact findings against `button`'s styler: that `KbqButtonCssStyler` emits `.kbq-button-icon` (not `.kbq-icon-button`) and drops `.kbq-button` for icon-only buttons (BTOG-STYLE-01), and that the `iconType` host classes are referenced nowhere in the repo (BTOG-STYLE-02). The companion `button` review (`docs/REVIEW/REVIEW.button.md`) independently flags the same class of missing ARIA (BTN-A11Y-01/02/03), the same `@Input`/legacy-accessor migration debt, the same whitespace-fragile icon detection (BTN-BUG-03), and the same shared focus-ring concern (BTN-STYLE-06).
