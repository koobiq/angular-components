# Koobiq `empty-state` Component — Code Review & Improvement Plan

> Scope: `packages/components/empty-state` (component + 4 slot directives, SCSS/tokens/theme, Jest spec, e2e fixture + Playwright spec, en/ru guides, 11 docs examples, dev app, API guard report) · Commit `b665e503` · 2026-08-28
> Generated by a multi-dimension review (source, styles, consumers, docs, tests, API guard, git history) with manual verification of every finding against the source. 12 findings confirmed (P0×0, P1×1, P2×5, P3×6); 7 candidate findings refuted during verification (see Appendix A). This document is a review + roadmap; no source is modified by it.

---

## 1. Executive Summary

`kbq-empty-state` is a small, purely presentational package: one component (`KbqEmptyState`, [empty-state.component.ts](../../packages/components/empty-state/empty-state.component.ts), 94 lines) plus four marker directives (`KbqEmptyStateIcon`, `KbqEmptyStateTitle`, `KbqEmptyStateText`, `KbqEmptyStateActions`) that do nothing but stamp a class onto the projected slot. All layout comes from `empty-state.scss` (109 lines) driven by 28 CSS custom properties. A repo-wide sweep finds 15 files outside the package referencing it: one library component (`file-upload`, 3 files), the docs application's icons viewer, 8 example templates belonging to `notification-center`, `list`, `select` and `file-upload`, its own dev app and its `ng-update` schematic. `file-upload` consumes it in an unusual way that exposes the package's main structural weakness.

- **The most serious defect is a packaging one.** `empty-state.scss` reads 24 `--kbq-empty-state-size-*` custom properties but never `@use`s the file that defines them; the token layer is attached only through `KbqEmptyState`'s `styleUrls` array (`empty-state.component.ts:60`). `file-upload` re-uses the stylesheet by relative path across the package boundary (`dropzone.ts:397`) and — inevitably — takes only half of it. The result is that every `max-width` and `actions-margin-top` rule in the file-upload empty state resolves to an undefined `var()`, so the 320 px caption cap silently becomes `none` (EST-CSS-01).
- **The `errorColor` input is only half reactive.** The title/text colours flip through host classes and work correctly, but the icon is tinted once, imperatively, in `ngAfterContentInit` (`empty-state.component.ts:89-93`). Toggling `[errorColor]` back to `false` never removes the tint, toggling it to `true` after init never applies it, and it only works at all when `kbq-empty-state-icon` sits *directly* on the `kbq-icon-item` element — which is not the markup shape 2 of the package's own 11 examples use (EST-BUG-01).
- **The title is styled as a heading but is never exposed as one.** `_empty-state-theme.scss:42-44, 52-54` applies the `subheading` and `headline` typography levels to `.kbq-empty-state-title`, yet all 23 in-repo usages write `<div kbq-empty-state-title>`; a repo-wide grep for an `<h1>`–`<h6>` host returns zero. Not an AXE failure — a WCAG 1.3.1 judgement — but the library offers neither an affordance nor a line of guidance (EST-A11Y-01).
- **Verification is thin for a component whose entire contract is visual.** One Jest case (`empty-state.component.spec.ts:28-45`) asserts the default classes and nothing else: `size`, `alignTop`, `errorColor` and `setErrorColor()` have zero unit coverage. The Playwright suite is a single screenshot pair over a 17-cell matrix, which is the only thing standing between the token system and a silent regression (EST-TEST-01).
- **The published API reference is empty.** `structure.ts:562-563` sets `hasApi: true`, so the docs site renders an API page generated from JSDoc, and there is not a single JSDoc comment in the package — all 8 public members carry `// (undocumented)` in `tools/public_api_guard/components/empty-state.api.md` (EST-DOC-01).

Genuine strengths: the component is honest about its job — no RxJS, no listeners, no measurement, no timers, so there is no teardown surface and no performance story to get wrong. It is `OnPush`, it uses the `host` object rather than `@HostBinding`, the three-tier size system is expressed entirely as overridable custom properties (which is exactly why `file-upload` can retheme it from the outside without a single `!important`), the e2e fixture covers a well-chosen 17-cell matrix including a long-text overflow case, every `var()` the package emits resolves against the live design-token set, and the one breaking change in its history (`big` → `size`) shipped with a registered `ng-update` schematic (`packages/schematics/src/migrations/empty-state-size-attr/index.ts:10-25`, `collection.json:27-31`) — the repo rule is being followed here.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

None.

### P1 — High

**EST-CSS-01 · `empty-state.scss` is not self-contained; its token layer is reachable only through the component's `styleUrls`** — `empty-state.scss:1-3, 13-14, 21, 50, 62`, `empty-state-tokens.scss:1-31`, `empty-state.component.ts:60`, `file-upload/dropzone.ts:397`.
`empty-state.scss` `@use`s exactly two things — `../core/styles/common/tokens` and `./empty-state-theme` (`:1-3`) — and then consumes 24 `--kbq-empty-state-size-*` custom properties that are declared nowhere in its own dependency graph. They live in `empty-state-tokens.scss`, which is attached as a *second entry* in `styleUrls: ['./empty-state.scss', 'empty-state-tokens.scss']` (`empty-state.component.ts:60`). Because both files are `ViewEncapsulation.None`, the token block `:where(.kbq-empty-state) { … }` (`empty-state-tokens.scss:1`) only reaches the document when `KbqEmptyState` itself is instantiated. `file-upload` re-uses the layout stylesheet without the component — `styleUrls: ['./dropzone.scss', '../empty-state/empty-state.scss']` (`dropzone.ts:397`) — and consequently ships the rules without the variables.
The residue is measurable. `file-upload` re-declares 9 padding tokens (`dropzone.scss:40-50`, only under `.kbq-local-dropzone`), 2 margin tokens (`dropzone.scss:55-56`) and 4 more (`multiple-file-upload.component.scss:183-186`), but never `--kbq-empty-state-size-{compact,normal,big}-max-width` or `-actions-margin-top`. `KbqFileUploadEmptyState` inherits the `kbq-empty-state_normal` host class, so `.kbq-empty-state_normal .kbq-empty-state-text { max-width: var(--kbq-empty-state-size-normal-max-width); }` (`empty-state.scss:49-51`) matches its caption `div` (`dropzone.ts:388`) with an unresolved `var()` — invalid at computed-value time, so `max-width` falls back to its initial `none` and the documented 320 px cap disappears; the caption stretches the full dropzone width. Secondary cost: when both components are on a page the entire `empty-state.scss` ruleset, including both `@include`s at `:108-109`, is injected into the document twice. The consumer's 12 token re-declarations, spread over three files, are themselves the workaround evidence that the package gives no supported way to reuse its layout.
**Fix:** move the custom-property block into the stylesheet that reads it — either `@use './empty-state-tokens';` from `empty-state.scss` (and drop the second `styleUrls` entry), or, better, wrap both in a `@mixin kbq-empty-state-styles()` in a `_empty-state.scss` partial that emits tokens *and* rules, leaving `empty-state.scss` as a one-line `@include`. Then rewrite `dropzone.ts:397` to `@include` that mixin from `dropzone.scss` instead of listing a cross-package `styleUrls` path. Guard it with a Playwright case in `file-upload/e2e.playwright-spec.ts` that renders a multiple-file-upload with a caption longer than 320 px and asserts the caption box width, and add a `stylelint`/CI grep forbidding `styleUrls` entries that escape the component's own package directory.

### P2 — Should fix

**EST-BUG-01 · `errorColor` tints the icon once, irreversibly, and only for one of two supported markup shapes** — `empty-state.component.ts:21-31, 74, 89-93`, `_empty-state-theme.scss:14-22`.
`ngAfterContentInit()` reads the `errorColor` signal exactly once and, if truthy, calls `icon.setErrorColor()` (`:89-93`), which assigns `this.icon.color = 'error'` on the injected `KbqIconItem` (`:24-30`). Three defects follow. (1) **Irreversible:** `KbqColorDirective`'s setter swaps the `kbq-*` class on the element (`core/common-behaviors/color.ts:52-66`); nothing ever restores the original colour, so `[errorColor]` going `true → false` at runtime leaves a red icon above now-normal text, and `false → true` never tints at all — while the title/text colours *do* flip, because they ride on the reactive host classes `kbq-empty-state_error-color` / `_normal-color` (`empty-state.component.ts:68-69` → `_empty-state-theme.scss:4-22`). (2) **Shape-dependent:** `KbqEmptyStateIcon` resolves the icon via `inject(KbqIconItem, { optional: true })` (`:22`), so the tint only happens when `kbq-empty-state-icon` is on the *same element* as `kbq-icon-item`. Two of the package's own examples wrap instead — `<div kbq-empty-state-icon><i kbq-icon-item …></i></div>` (`empty-state-icon-example.ts:16-18`, `empty-state-content-example.ts:20-28`) — and for those the call is a silent no-op. (3) **Silently overwritable:** the tint is applied after the template's own `[color]` binding, so a consumer whose `[color]` expression later changes value (the error example binds `[color]="'contrast'"`, `empty-state-error-example.ts:22`) has the error tint reverted with no way to notice.
**Fix:** drop the imperative path entirely and express it in CSS, matching how the title and text already work: add `.kbq-empty-state_error-color .kbq-empty-state-icon, .kbq-empty-state_error-color .kbq-empty-state-icon .kbq-icon-item { color: var(--kbq-empty-state-error-color); }` to the error block in `_empty-state-theme.scss:14-22`. That makes the behaviour reactive, reversible and shape-independent in one change, and lets `KbqEmptyStateIcon.setErrorColor()`, the `KbqIconItem` injection and `ngAfterContentInit` all be deleted (see EST-API-01). Add specs that (a) set `[errorColor]` true→false and assert the icon's colour class, and (b) run the wrapper-`div` markup shape.

**EST-A11Y-01 · The title is given heading typography but is never a heading, and there is no announcement affordance** — `_empty-state-theme.scss:26-59`, `empty-state.component.ts:41-47`, `dropzone.ts:385`.
`.kbq-empty-state-title` is rendered at the `subheading` level for `size="normal"` (`_empty-state-theme.scss:42-44`) and at `headline` for `size="big"` (`:52-54`) — i.e. it is visually a heading by design. `KbqEmptyStateTitle` is a bare attribute directive that adds only a class (`empty-state.component.ts:41-47`), so the host element is whatever the consumer writes, and every in-repo usage writes a generic `div`: 9 elements across the package's own docs examples, 6 in the dev app (`components-dev/empty-state/template.html:10, 24, 38, 52, 66, 80`), the e2e fixture (`e2e.ts:56`), the Jest fixture (`empty-state.component.spec.ts:54`), the `file-upload` component (`dropzone.ts:385`) and 5 more in other packages' examples (4 × notification-center, `file-upload-primitive-example.ts:50`) — 23 elements, and `grep -rEn "<(h[1-6])[^>]*kbq-empty-state-title"` over `packages/` returns 0. No automated AXE rule fires for this (axe does not infer headings from font size), so this is a WCAG 1.3.1 (Info and Relationships, Level A) judgement, not a failing check: screen-reader users cannot reach or enumerate the placeholder's heading, and `kbq-empty-state` has no accessible name of any kind. Separately, an empty state is almost always inserted dynamically — the `select` example renders one inside `@if (error())` in an open select panel with no title at all, only text (`select-loading-error-custom-example.ts:35-48`), and the docs app swaps one in when an icon search returns nothing (`icons-viewer.template.html:48-54`) — and the package offers nothing to announce it. The `alert` package already establishes the repo's pattern for exactly this: a JSDoc note telling consumers to add `role="alert"`/`aria-live` on the host (`alert.component.ts:78-79`).
**Fix:** the attribute selector already accepts any element, so this is a documentation-and-defaults fix, not an API change. (1) Switch every example, the dev app and the e2e fixture to `<h2 kbq-empty-state-title>` (`empty-state.scss` sets no `margin` on the title beyond the token, so the browser default `h2` margin must be zeroed in `_empty-state-theme.scss` alongside the typography include). (2) Add an `### Accessibility` section to `empty-state.en.md` / `empty-state.ru.md` stating that the title element should be a heading of the right level for its page, and that a dynamically inserted empty state needs `role="status"` (or `role="alert"` for the error variant) on `<kbq-empty-state>`. (3) Mirror the `alert.component.ts:78-79` JSDoc note onto `KbqEmptyState` and `KbqEmptyStateTitle`. Guard with a `jest-axe` case rendering the fixture inside a document with an `h1`.

**EST-ARCH-01 · `KbqEmptyState` is subclassed across a package boundary and inherits a content query it can never satisfy** — `file-upload/dropzone.ts:369-416, 425-429`, `empty-state.component.ts:70, 80`, `multiple-file-upload.component.scss:185`.
`KbqFileUploadEmptyState extends KbqEmptyState` (`dropzone.ts:404`) but declares its own `@Component`, so Angular's inheritance feature merges host attributes, host bindings, inputs and queries from the base definition while the `template` and `styles` are *not* inherited — which is exactly why the subclass has to re-list the base stylesheet manually (`dropzone.ts:397`, see EST-CSS-01) and why it replaces the four `<ng-content>` slots with a fixed template (`dropzone.ts:379-395`). The inherited `@ContentChild(KbqEmptyStateIcon) icon` (`empty-state.component.ts:80`) then becomes permanently unsatisfiable: the subclass's `<i kbq-empty-state-icon>` lives in its *view*, not in projected content, and both call sites render `<kbq-file-upload-empty-state … />` with no children (`dropzone.ts:425-429`, `multiple-file-upload.component.html:15`). So `[class.kbq-empty-state_has-icon]='!!icon'` (`empty-state.component.ts:70`) is never true there, the optical-compensation offset at `empty-state.scss:65-67` never applies, and the consumer's `--kbq-empty-state-size-normal-image-addon-height: 4px` override (`multiple-file-upload.component.scss:185`) is dead code. A second symptom of the same coupling: `this.size = 'big'` in the subclass constructor (`dropzone.ts:412`) is dead because both call sites bind `[size]` — and that constructor write is the reason `size` is still a decorator `@Input` with a stale auto-migration TODO on the base class (`empty-state.component.ts:76-78`, see EST-STYLE-01).
**Fix:** stop subclassing. Turn `KbqFileUploadEmptyState` into a composition — a thin wrapper whose template is `<kbq-empty-state [size]="size()" > <i kbq-empty-state-icon …> … </kbq-empty-state>` — which restores the content query, drops the cross-package `styleUrls`, removes the constructor input write and unblocks migrating `size` to `input()`. If `KbqEmptyState` is genuinely meant to be extensible, say so explicitly: expose the slot classes through a SCSS mixin (EST-CSS-01) and replace the content query with a `contentChild()` signal plus an explicit `hasIcon` input so a subclass can declare the fact. Guard with a `file-upload` spec asserting `kbq-empty-state_has-icon` on the dropzone empty state.

**EST-TEST-01 · One Jest case, covering none of the three inputs** — `empty-state.component.spec.ts:28-45`, `e2e.playwright-spec.ts:9-17`.
The entire Jest suite is a single `it('should init and set classes')` that renders one fixture in its default state and asserts six `classList` memberships (`:39-44`). Nothing exercises `size` (3 values, and the sole carrier of every padding, `max-width` and margin rule), `alignTop` (which flips `justify-content` between `center` and `flex-start`, `empty-state.scss:99-105`), `errorColor` (whose title/text branch and icon branch behave differently, EST-BUG-01), the `kbq-empty-state_has-icon` class, or `KbqEmptyStateIcon.setErrorColor()`. The Playwright side is one `test('states')` producing a light/dark screenshot pair over the 17-cell matrix in `e2e.ts:116-188` — good coverage of *rendered* output, but a single `threshold: 0` baseline is a blunt instrument, and it is currently the only thing that would catch an EST-CSS-01-class token regression. The git history corroborates that this area is unguarded rather than stable: of 38 commits touching the package, none is a `fix(empty-state)` — the last behavioural change was `4f6c86ae0 feat(empty-state)!: update empty-state sizes (#DS-3507)`, and everything since is Angular/palette/e2e infrastructure.
**Fix:** extend `empty-state.component.spec.ts` with a host exposing all three inputs as signals and add cases for: each `size` → `kbq-empty-state_<size>`; `alignTop` true/false → `_align-top` / `_align-center`; `errorColor` true/false → `_error-color` / `_normal-color` *and* the icon's colour class in both directions; icon present/absent → `_has-icon`; and the wrapper-`div` icon shape. Add a computed-style assertion for `--kbq-empty-state-size-normal-max-width` resolving to `320px` so EST-CSS-01 cannot regress silently.

**EST-DOC-01 · Zero JSDoc in the package, but the docs site publishes a generated API page** — `empty-state.component.ts:1-94`, `tools/public_api_guard/components/empty-state.api.md:13-74`, `apps/docs/src/app/structure.ts:562-563`, `empty-state.en.md:11-27`.
`structure.ts` sets `hasApi: true, apiId: 'empty-state'` (`:562-563`), and the component viewer loads `docs-content/api-docs/components-empty-state.html` (`component-viewer.component.ts:210`), which `tools/api-gen` renders from JSDoc `description` / `jsdocTags` (`tools/api-gen/rendering/entities.ts:62-64`). The package contains exactly one comment that is not the stale migration TODO — `@docs-private` on a protected getter (`empty-state.component.ts:82-84`) — so the API report marks all six exported symbols and all eight public members `// (undocumented)` (`empty-state.api.md:13-74`) and the published API tab lists `size`, `errorColor`, `alignTop`, `icon` and `setErrorColor()` with blank descriptions. The prose guides do not compensate: `size` is named (`empty-state.en.md:13`) but `alignTop` and `errorColor` are only described in effect — "Content can be aligned to the center or to the top" (`:19`), "the text turns red" (`:25`) — so a reader cannot discover either input name from the documentation at all.
**Fix:** add JSDoc to `KbqEmptyState` (class-level: what it is for, plus the `alert`-style a11y note from EST-A11Y-01), to each of `size` / `errorColor` / `alignTop` (naming the accepted values and the default), and to the four slot directives explaining which slot each fills. Name `[alignTop]` and `[errorColor]` explicitly in `empty-state.en.md:17-27` and `empty-state.ru.md:17-27`, as `size` already is. Note the ordering constraint: adding JSDoc removes `// (undocumented)` markers and therefore changes `empty-state.api.md`, so this must land with `yarn run build:components && yarn run approve-api` or the `api` CI job goes red.

### P3 — Nice to have / hygiene

**EST-API-01 · Internal machinery is `@public`, and `icon`'s declared type is wrong** — `empty-state.component.ts:21-31, 80`, `empty-state.api.md:21, 41-48`.
`KbqEmptyStateIcon.setErrorColor()` exists solely so that `KbqEmptyState.ngAfterContentInit` can reach into it, but it is exported `@public` with no documentation (`empty-state.api.md:43`); any consumer can call it and freeze the implementation. The `icon` content-query result is likewise public (`empty-state.api.md:21`) and typed `KbqEmptyStateIcon | null` (`empty-state.component.ts:80`) — Angular assigns `undefined`, not `null`, when a single-result query finds nothing, and `strictPropertyInitialization` is not enabled in `tsconfig.json` (only `strictNullChecks` / `strictFunctionTypes` at `:21-22`), so the wrong type compiles and misleads. The component also declares no `exportAs`, so a template reference variable on `<kbq-empty-state #ref>` yields the element rather than the instance.
**Fix:** if EST-BUG-01 is fixed in CSS, delete `setErrorColor()`, the `KbqIconItem` injection and `ngAfterContentInit` outright. Otherwise mark `setErrorColor()` `@docs-private` and make it `protected`. Make `icon` `protected` (only the host binding at `:70` reads it) or, if it stays public, type it `KbqEmptyStateIcon | undefined`. Add `exportAs: 'kbqEmptyState'`. All three change the API report — schedule with EST-DOC-01's `approve-api` run.

**EST-STYLE-01 · Stale auto-migration TODO, and `size` is the odd input out** — `empty-state.component.ts:74-78, 82-87`.
`errorColor` and `alignTop` are `input()` signals (`:74-75`); `size` is a decorator `@Input()` carrying a verbatim Angular migration artefact — `// TODO: Skipped for migration because: Your application code writes to the input. This prevents migration.` (`:76-78`). The writer is `file-upload/dropzone.ts:412` (`this.size = 'big'` in the subclass constructor), which EST-ARCH-01 shows to be dead code, so the blocker no longer exists. Consequently `emptyStateSizeClass` is a plain getter recomputing a template string on every host-binding evaluation (`:85-87`) instead of a `computed()`, and `size` is the one input that cannot participate in signal-based derivations. AGENTS.md asks for `input()` over decorators; the file is half-migrated.
**Fix:** after EST-ARCH-01 removes the constructor write, change to `readonly size = input<KbqDefaultSizes>('normal')`, convert `emptyStateSizeClass` to `protected readonly emptyStateSizeClass = computed(() => \`kbq-empty-state_${this.size()}\`)` and update the host binding to `emptyStateSizeClass()`. Migrate `@ContentChild(KbqEmptyStateIcon)` to `contentChild(KbqEmptyStateIcon)` in the same pass — use the *optional* form with a guard, not `.required`. Delete the TODO comment.

**EST-ARCH-02 · `KbqEmptyStateModule` imports two modules nothing in the package uses** — `empty-state.module.ts:1-3, 14-16`, `empty-state.api.md:57`.
`A11yModule` and `PlatformModule` are imported (`:1-3`, `:14-16`) although the package contains no CDK a11y directive (`cdkTrapFocus`, `cdkMonitorFocus`, …) and no `Platform` usage — the entire source is 94 lines with two Angular imports. They are not re-exported, so consumers are not affected functionally, but they appear in the generated module declaration in the public API report (`empty-state.api.md:57`) and pull two CDK entry points into the module graph for nothing.
**Fix:** delete both imports from `empty-state.module.ts`; run `yarn run build:components && yarn run approve-api` (the `ɵmod` signature at `empty-state.api.md:57` changes).

**EST-CSS-02 · Two theme tokens break the package's own naming shape, and the consumer has already copied the mistake** — `empty-state-tokens.scss:26-30`, `multiple-file-upload.component.scss:17-18, 64-65, 106-107`.
The 24 layout tokens follow `--kbq-empty-state-size-<size>-<part>-<property>`; the four theme tokens do not. `--kbq-empty-state-title` (`:27`) is a *colour* whose name reads as a size or content token, and its sibling `--kbq-empty-state-color` (`:28`) is specifically the **text** colour, not the component's colour — the pair is only decipherable by reading `_empty-state-theme.scss:4-12`. The error pair (`:29-30`) at least says `error`, but reproduces the same shape. This is not cosmetic: `file-upload` retints the empty state through these two names in three separate places (`multiple-file-upload.component.scss:17-18, 64-65, 106-107`), so the ambiguity is already load-bearing in a second package.
**Fix:** rename to `--kbq-empty-state-title-color`, `--kbq-empty-state-text-color`, `--kbq-empty-state-error-title-color`, `--kbq-empty-state-error-text-color`, keeping the old names as aliases (`--kbq-empty-state-title: var(--kbq-empty-state-title-color)`) for one minor release, and update the three `file-upload` call sites. Custom-property names are a published contract for theming, so announce the deprecation in the changelog.

**EST-CSS-03 · Unconditional `flex: 1` with no intrinsic height; every example compensates by hand** — `empty-state.scss:5-11, 99-105`.
The host is `display: flex; flex-direction: column; align-items: center; flex: 1` (`:5-10`). `flex: 1` expands to `flex: 1 1 0%`, so as a flex item the component takes a zero basis and grows — but in a plain block container it has no height of its own, and `justify-content: center` (`:100`) then centres content inside a box exactly as tall as its content, making `alignTop` visually indistinguishable from the default. Every consumer works around this by hand, and each one differently: all 11 of the package's docs example files add `style="min-height: 216px"` to all 13 `<kbq-empty-state>` elements, two of them additionally add `class="flex"` (`empty-state-align-example.ts:19, 30`, `empty-state-content-example.ts:19, 39`); the e2e fixture sets `min-height: 100px; min-width: 200px` in a `:host` override (`e2e.ts:86-91`); the list example hard-codes `style="margin-top: 132px"` (`list-intermediate-state-example.html:48`); the select example reaches for spacing utilities, `class="layout-margin-top-l layout-margin-bottom-3xl"` (`select-loading-error-custom-example.ts:36`); and the docs app wraps it in a div carrying `margin: var(--kbq-size-3xl) auto` (`icons-viewer.template.html:49-53` → `icons-viewer.scss:57-59`). Five different vertical-positioning workarounds across four packages is a missing default, not a coincidence.
**Fix:** either give the host a token-driven `min-height` per size tier (`--kbq-empty-state-size-<size>-min-height`), so `alignTop` and `align-center` mean something without consumer help, or — if the sizing really must come from the parent — document that requirement in `empty-state.en.md` / `.ru.md` under `### Align` and drop the now-redundant inline styles from the examples. Do not change `flex: 1` without a Docker screenshot run: it is baked into both `__screenshots__` baselines.

**EST-DOC-02 · `examples.empty-state.*.md` are dead placeholder files** — `examples.empty-state.en.md:1-5`, `examples.empty-state.ru.md:1-5`, `apps/docs/src/app/structure.ts:564`.
Both files carry the "🚧 Documentation in progress 🚧" stub. Because `hasExamples: false` (`structure.ts:564`), the Examples tab never renders for this component, so nothing is broken for users — the files are simply dead weight that reads like an unfinished surface, while 11 working examples already exist under `packages/docs-examples/components/empty-state/` and are all embedded inline in the main guides (`empty-state.en.md:3-59`).
**Fix:** delete both stubs (the guides already carry every example), or flip `hasExamples` to `true` and populate them with the 11 `<!-- example(…) -->` embeds. Deleting is the smaller, more honest change; pick one and do not leave the third state.

## 4. Recommended Remediation Phases

**Phase 1 — Make the package self-contained.**

**Phase 3 — API and documentation contract.**

**Phase 4 — Tests and remaining hygiene.**

## Appendix A — Review Methodology

Every file in `packages/components/empty-state` was read in full (`cat -n`), then traced outward: a repo-wide sweep for `kbq-empty-state` found 15 referencing files outside the package, all of which were read — the `file-upload` component (four files), the docs application's icons viewer, examples for `notification-center`, `list`, `select` and `file-upload`, and the `ng-update` migration schematic. Also covered: the 11 own docs examples, the dev app, the e2e fixture and Playwright spec, the API guard report, the api-extractor and docs-navigation configuration, and 38 commits of git history. Every custom property emitted by the package was resolved against `node_modules/@koobiq/design-tokens/web/new/index.bundled.css`, and every typography level against `packages/components/core/styles/typography/_typography.scss`. No builds or test suites were run; findings rest on source reading and token resolution only. Severity follows the repo review scale: P1 requires real user impact or an untrue published contract.

Refuted during verification:
- **"The component emits undefined `var()`s."** All 10 `--kbq-size-*` tokens (`xxs`=4px … `6xl`=56px) and all 3 `--kbq-foreground-*` tokens resolve in the live token set; every typography level used by `_empty-state-theme.scss` (`text-compact`, `text-normal`, `text-big`, `subheading`, `headline`) exists in `_typography.scss:11-28`. The token layer itself is sound — the defect in EST-CSS-01 is *reachability*, not correctness.
- **"The `'[class]': 'emptyStateSizeClass'` host binding fights the static `class: 'kbq-empty-state'` and the four `[class.…]` bindings."** Angular merges host static classes with map bindings per class name; the identical pattern ships in `icon.component.ts:28-32` (`class: 'kbq kbq-icon'` + `'[class]': 'svgIcon ? null : iconName'`) and renders all three classes. The Jest spec asserts both `kbq-empty-state` and `kbq-empty-state_normal` on the same element (`empty-state.component.spec.ts:39-40`). No defect.
- **"`errorColor` / `alignTop` need `booleanAttribute` transforms."** `strictTemplates` is on (`tsconfig.json:117`), so the classic `alignTop="false"` and bare-`alignTop` traps are hard compile errors, not silent truthiness bugs. The inputs are correct as declared.
- **"Writing `icon.color = 'error'` from a lifecycle hook needs `markForCheck()`."** `KbqColorDirective`'s setter manipulates `classList` directly (`core/common-behaviors/color.ts:52-66`), so the class swap needs no change-detection pass. The reversibility and shape problems are real and are filed as EST-BUG-01; the change-detection concern is not.
- **"`empty-state.en.md:1` — 'the border is not part of the component' — is a stale sentence, no example shows a border."** The docs live-example viewer draws it: `border: 1px solid var(--kbq-background-contrast-fade)` (`apps/docs/src/app/components/live-example-viewer/docs-live-example-viewer.scss:49`). The sentence is accurate in context.
- **"`[class.kbq-empty-state_has-icon]='!!icon'` risks `ExpressionChangedAfterItHasBeenChecked`."** Content-query results are assigned before content hooks, and host bindings are processed after both within the same `refreshView`; the ordering is safe. (The query being permanently *empty* in the `file-upload` subclass is a different problem — EST-ARCH-01.)
- **"Missing AGENTS.md structure files."** All six are present — `empty-state-tokens.scss`, `_empty-state-theme.scss`, `empty-state.module.ts`, `public-api.ts`, `e2e.ts` and `e2e.playwright-spec.ts` — and the package is listed in `tools/api-extractor/config.json:23` and in `apps/docs/src/app/structure.ts:554-565`. Nothing is missing structurally.

Reading `dropzone.scss:40-50` and `multiple-file-upload.component.scss:183-186` showed the consumer explicitly zeroes those paddings anyway, so the padding symptom is invisible; the finding was re-aimed at the packaging defect and at the properties the consumer does *not* redeclare (`max-width`, `actions-margin-top`), where the damage is real and observable.
