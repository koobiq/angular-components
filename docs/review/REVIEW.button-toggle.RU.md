# Семейство компонентов `button-toggle` Koobiq — код-ревью и план улучшений

> Охват: `packages/components/button-toggle` (`KbqButtonToggleGroup`, `KbqButtonToggle`, `KbqButtonToggleChange`, `ToggleType`, `KBQ_BUTTON_TOGGLE_GROUP_VALUE_ACCESSOR`, `KbqButtonToggleModule`) + общие абстракции, которые он использует (`KbqButton`/`KbqButtonCssStyler`, `KbqTitleDirective`, `KbqIcon`, CDK `FocusMonitor`/`SelectionModel`, `getNodesWithoutComments`) · Коммит `18ea72fe` · 2026-06-30
> Подготовлено автоматическим многоагентным ревью (8 измерений + состязательная проверка каждой находки). Подтверждено 57 находок по измерениям → дедуплицировано до 6×P1, ~20×P2, ~25×P3 (0×P0); 4 отклонено. Используйте как высокосигнальную отправную точку; перепроверяйте перед действиями.
> Находки с пометкой **(shared)** лежат в `core`/`button` и затрагивают также соседей. Документ — это ревью и дорожная карта; исходный код им не меняется.

## 1. Краткое резюме

- **Блокеров релиза нет (0×P0), но доступность сломана по сути (оценка D).** Контрол *ведёт себя* как radio-группа (одиночный режим) / мультивыбор (режим `multiple`) — он даже вычисляет `type: 'radio' | 'checkbox'` в `ngOnInit` — но **ничего не сообщается ассистивным технологиям**: у внутренней `<button>` нет `role`, нет `aria-checked`/`aria-pressed`; у host группы нет `role="radiogroup"`/`"group"` и нет точки задания доступного имени; вычисленный `type` — **мёртвый код, никуда не привязан**. Выбор передаётся только CSS-классом (`.kbq-selected`). Это реальное нарушение WCAG 4.1.2 (Name/Role/Value) + 1.3.1 на контроле с состоянием.
- **`focus()` молча сломан (P1).** `focus()` вызывает `.focus()` на host `<kbq-button-toggle>`, который не фокусируем (tabindex живёт на внутренней `<button>`). Корректно запрошенная цель фокуса `mcButton = viewChild.required(KbqButton)` существует, но **не используется** — мёртвый код.
- **Реальный баг темизации спрятан в одном неверном имени класса (P1).** `_button-toggle-theme.scss` красит `& > .kbq-button, & > .kbq-icon-button`, но `KbqButton` для icon-only кнопок выдаёт `.kbq-button-icon` (и снимает `.kbq-button` — классы взаимоисключающие). Поэтому **icon-only toggle не получает темизированный фон/текст/иконку ни в одном состоянии** и откатывается на обычную transparent-тему кнопки. Сломанный рендер заморожен в эталоне Playwright `02-light.png`, а не пойман.
- **Icon-only toggle — кнопки без имени (P1).** Нет input'а `aria-label`, нет защиты; глифы `KbqIcon` помечены `aria-hidden`. Поставляются в docs-примерах `overview`/`alignment` → живые AXE-нарушения `button-name`.
- **Публичные типы лгут (P1/P2).** `buttonToggleGroup = inject(KbqButtonToggleGroup, { optional: true })!` типизирован как non-null, но равен `null` для standalone-toggle (класс везде его проверяет); снимок публичного API замораживает эту ложь. Геттер `disabled` типизирован `boolean`, но возвращает `null` в standalone. `value`/`selected`/`change`/`valueChange`/`buttonToggles` — повсеместно `any`.
- **Повсеместное наследие Angular Material.** Кириллический гомоглиф в публичном JSDoc (`MсButtonToggle`, кириллическая `с`); переменные тестов `nativeCheckboxLabel`/`buttonToggleLabelElements` типизированы `HTMLLabelElement`, хотя на деле опрашивают `<button>`; комментарии о «native radio/checkbox» и «Jasmine», которые здесь неприменимы; мёртвый `expect(groupInstance.value);` без матчера.
- **Реактивность до-сигнальная (архитектура C / жизненный цикл C+).** Шесть публичных input'ов — легаси `@Input` getter/setter (с устаревшими TODO «Skipped for migration»), используют устаревший `coerceBooleanProperty`; состояние лежит в простых полях, вынуждая ручной fan-out `markForCheck()`; `iconType`/`type` — мутабельные публичные производные поля. Соседний `toggle.component.ts` уже использует `input()` + `booleanAttribute`.
- **Тесты хорошо покрывают ядро выбора, но пропускают a11y, фокус и определение иконок (C+).** Нигде нет AXE/aria-ассертов; `FocusMonitor`/`focus()`/`tabIndex`/`iconType` не покрыты; Playwright подделывает hover/active/focus через CSS-классы и покрывает тёмную тему лишь в 1 из 3 снимков.
- **Что сделано хорошо:** OnPush; логика выбора `SelectionModel` (single/multiple, falsy-значения, повторяющиеся/подменяемые toggle); двусторонняя привязка + интеграция с формами; `FocusMonitor` monitor/stopMonitoring **парны корректно** (без утечки); стоимость на CD действительно мала (производительность B+); RTL в основном безопасен (gap/логические отступы). `prefers-reduced-motion` — не проблема: переходов нет, единственная анимация (`.kbq-progress`) здесь не применяется и уже закрыта в ядре.

## 3. Приоритизированные находки (дедуплицированы, проверены)

### P1 — Высокий

**BTOG-A11Y-01 · Нет ARIA role/state — выбор невидим для ассистивных технологий** — `button-toggle.component.ts:308-321` (внутренняя кнопка), `:57-60` (host группы), `:364`/`:397` (мёртвый `type`).
Группа ведёт себя как radio-группа (single) или мультивыбор (multiple), и каждый toggle вычисляет `type = 'radio' | 'checkbox'` в `ngOnInit`. Но ничего не выставляется: у внутренней `<button>` нет `role`, `aria-checked` или `aria-pressed`; у host группы (`kbq-button-toggle-group`) нет `role="radiogroup"`/`"group"` и нет `aria-label`/`aria-labelledby`; составной `KbqButton` добавляет лишь `aria-disabled`. Значение `type` никуда не привязано (grep показывает, что оно нигде не читается) — это мёртвый код. Скринридер слышит обычную безымянную кнопку без состояния выбранности и без принадлежности группе в обоих режимах. WCAG 2.1 SC 4.1.2 (Name/Role/Value) + 1.3.1.
**Исправление:** single-режим → `role="radio"` + `[attr.aria-checked]="checked"` на внутренней кнопке и `role="radiogroup"` на host группы; multiple/standalone → `[attr.aria-pressed]="checked"` (паттерн toggle-button) либо `role="checkbox"` + `aria-checked`, плюс `role="group"` на host. Переключать атрибут по уже вычисленному `type`, состояние брать из существующего геттера `checked`. Добавить точку задания доступного имени (`aria-label`/`aria-labelledby`) на группу. Делать вместе с BTOG-A11Y-03 (roving-tabindex), чтобы `role="radio"` соответствовал ожидаемому поведению клавиатуры.

**BTOG-A11Y-02 · Icon-only toggle рендерится как кнопка без имени (AXE `button-name`)** — `button-toggle.component.ts:307-321`; SVG `aria-hidden` в `icon/icon-registry.ts:287,312`; живые случаи в `docs-examples/.../button-toggle-overview-example.html:26-38`, `button-toggle-alignment-overview-example.html:25-31`, `components-dev/button-toggle/template.html`.
Toggle, чьё проецируемое содержимое — только иконка, рендерит внутреннюю `<button>` без текста. SVG `KbqIcon` помечен `aria-hidden="true"`, а `<i kbq-icon>` не несёт текста, поэтому у кнопки нет доступного имени — нарушение AXE `button-name` / WCAG 4.1.2. У `KbqButtonToggle` нет input'а `aria-label` и нет предупреждения в dev-режиме. Замороженный API (`button-toggle.api.md:48-53`) подтверждает отсутствие input'а имени. Это не гипотеза: канонические docs-примеры поставляют icon-only группы. (Зеркалит `button` BTN-A11Y-03.)
**Исправление:** добавить input `aria-label`/`aria-labelledby`, пробрасываемый на внутреннюю кнопку, и в dev-режиме `console.warn`, когда toggle разрешается в icon-only без доступного имени (зацепка — существующее определение иконок в `ngAfterContentInit`). Добавить подписи в поставляемые docs-примеры.

**BTOG-API-01 · `buttonToggleGroup` типизирован non-null, но инъектирован `{ optional: true }!` (null в рантайме)** — `button-toggle.component.ts:335`; `tools/public_api_guard/components/button-toggle.api.md:24`.
`buttonToggleGroup = inject(KbqButtonToggleGroup, { optional: true })!` — `!` снимает `null` со статического типа, но инъекция опциональна и равна `null` для standalone-toggle (тест в `button-toggle.component.spec.ts:691`). Класс везде его проверяет при разыменовании (`:347,356,381,396,399,427,448`), доказывая, что автор ожидает `null`. Non-null-ассерт лишает TypeScript возможности предупредить о будущем незащищённом доступе (который даст NPE на standalone-toggle), и ложь заморожена в снимке публичного API (`api.md:24` объявляет non-null).
**Исправление:** убрать `!`, типизировать поле `KbqButtonToggleGroup | null` и сделать `protected` (используется только внутри + в шаблоне); сохранить существующие проверки на истинность.

**BTOG-BUG-01 · `focus()` фокусирует нефокусируемый host, а не внутреннюю кнопку** — `button-toggle.component.ts:433-435`.
`focus()` вызывает `this.element.nativeElement.focus()` на host `<kbq-button-toggle>`, у которого нет tabindex (биндинг `[tabIndex]` стоит на внутренней `<button>` в `:315`). Вызов `.focus()` на нефокусируемом кастомном элементе — no-op, фокус не перемещается. При этом `mcButton = viewChild.required(KbqButton)` (`:367`) — корректная цель фокуса, но нигде не используется (мёртвый код). Публичный `focus()` молча ничего не делает.
**Исправление:** делегировать на внутреннюю кнопку: `this.mcButton().focus()` (`KbqButton.focus()` уже проверяет `disabled` и фокусирует нативный элемент). Опционально выставить `focusViaKeyboard()`.

**BTOG-STYLE-01 · Theme-миксин таргетит несуществующий `.kbq-icon-button`; icon-only toggle без темизированных цветов** — `_button-toggle-theme.scss:5`.
State-миксин задаёт фон/текст/цвет иконки через `& > .kbq-button, & > .kbq-icon-button`. `KbqButton` никогда не выдаёт `.kbq-icon-button` — для icon-only кнопок он выдаёт `.kbq-button-icon` и снимает `.kbq-button` (`button.component.ts:67-68`, классы взаимоисключающие). Структурный SCSS использует `.kbq-button-icon` корректно (`button-toggle.scss:35-36`), поэтому раскладка работает и скрывает пробел, но ветка `.kbq-icon-button` theme-миксина не матчит ничего. Итог: icon-only toggle не получает **никакого** темизированного фона/текста/иконки ни в одном состоянии (default/hover/active/selected/selected-active/disabled/selected-disabled) и откатывается на transparent-тему `KbqButton`. Playwright-тест «with icon» (`e2e.playwright-spec.ts:19-27`) рендерит ровно этот случай, поэтому сломанный рендер заморожен в `02-light.png`, а не пойман.
**Исправление:** заменить `& > .kbq-icon-button` на `& > .kbq-button-icon` в `_button-toggle-theme.scss:5`, затем перезаписать эталоны Playwright для «with icon».

**BTOG-TEST-01 · Жизненный цикл `FocusMonitor` monitor/stopMonitoring не покрыт** — `button-toggle.component.ts:417` (monitor), `:423` (stopMonitoring); `button-toggle.component.spec.ts` (нет покрытия).
`ngAfterViewInit` вызывает `focusMonitor.monitor(el, true)`, `ngOnDestroy` — `focusMonitor.stopMonitoring(el)`. Ни то, ни другое не проверяется: ни один тест не утверждает, что origin фокуса задаёт `.cdk-keyboard-focused` (единственное, что даёт видимое focus-кольцо, `button-toggle.scss:30-33`) или что `stopMonitoring` вызывается при destroy (путь teardown/утечки). Проводка выглядит корректно, поэтому это пробел покрытия на a11y-значимом пути, а не доказанный баг.
**Исправление:** spy на `FocusMonitor.monitor`/`stopMonitoring` (или прогон реального keyboard-origin) — проверить, что класс keyboard-фокуса применяется и что `stopMonitoring` вызывается при destroy.

### P2 — Следует исправить

**Доступность**
- **BTOG-A11Y-03 · Нет roving-tabindex / навигации стрелками для radio-группы** — `button-toggle.component.ts:315`. Каждая внутренняя кнопка получает `[tabIndex]="tabIndex() || 0"`, поэтому все toggle — табстопы; grep по `keydown`/`Arrow*`/`FocusKeyManager`/roving по пакету ничего не даёт. Это приемлемо для группы toggle-button, но неверно для radio-семантики, подразумеваемой `type='radio'` (WAI-ARIA ожидает один табстоп в группу, стрелки перемещают + выбирают). **Исправление:** для одиночного выбора реализовать клавиатурный паттерн radiogroup через CDK `FocusKeyManager` (выбранный toggle `tabIndex=0`, остальные `-1`; стрелки двигают фокус + выбор); для multiple оставить по-токенный табстоп. Делать вместе с `role="radio"` из BTOG-A11Y-01.
- **BTOG-A11Y-04 · У host группы нет `role` и механизма доступного имени** — `button-toggle.component.ts:57-60`. Host задаёт только `class`/`[class.kbq-button-toggle_vertical]`; нет `role` и нет биндинга `aria-label`/`aria-labelledby`, поэтому набор toggle не объявляется как группа и не может быть назван. (Пересекается с BTOG-A11Y-01 для случая radiogroup; здесь ограничено обёрткой-группой + точкой именования для multiple.) **Исправление:** добавить `role="group"` (или `role="radiogroup"` в single-режиме) и поддержку `aria-label`/`aria-labelledby`; задокументировать в `button-toggle.en.md`/`.ru.md`.

**Корректность**
- **BTOG-BUG-02 · `onToggleClick` безусловно эмитит per-toggle `change`; комментарий утверждает «только single-selector»** — `button-toggle.component.ts:443-455` (комментарий `:454`, emit `:455`). При no-op повторном клике уже выбранного radio (`isSingleSelector=true`, `newChecked=true===_checked`) условие `if (newChecked !== this._checked)` ложно, поэтому `syncButtonToggle`/`onTouched`/`valueChange`/CVA **не** срабатывают — но `this.change.emit(...)` вне условия всё равно эмитит с неизменным значением, тогда как группа не эмитит ничего. Поведение «всегда эмитить» зафиксировано тестом `button-toggle.component.spec.ts:287-305`, но комментарий неверен. **Исправление:** исправить комментарий на «эмитит всегда»; если задумана эмиссия только при реальном изменении — перенести emit внутрь условия (подтвердить намерение — это меняет задокументированное поведение теста).
- **BTOG-TYPE-01 · Геттер `disabled` типизирован `boolean`, но возвращает `null` для standalone-toggle** — `button-toggle.component.ts:380-382` (+ `:335`). `return this._disabled || (this.buttonToggleGroup && this.buttonToggleGroup.disabled)` — для standalone-toggle (`buttonToggleGroup === null`) при `_disabled=false` это даёт `false || null` → `null`, нарушая объявленный тип `boolean`. `!` в `:335` скрывает это от строгой типизации. Рендерится нормально (null — falsy), но нарушает контракт публичного геттера. **Исправление:** `return this._disabled || (this.buttonToggleGroup?.disabled ?? false);`.

**Публичный API и типы**
- **BTOG-API-02 · Повсеместный `any` на публичной поверхности значений** — `button-toggle.component.ts:37,49,82,92,98,144,165,168,183,189,372` / `api.md:19,51,62-64,71,83,88,92-94,97`. `KBQ_BUTTON_TOGGLE_GROUP_VALUE_ACCESSOR`, `KbqButtonToggleChange.value`, групповые `value`/`selected`/`writeValue`/`valueChange`, toggle `value` и CVA-функции — все `any`; у группы нет дженерик-параметра, поэтому потребитель не получает типобезопасности на привязываемых/эмитируемых значениях. **Исправление:** типизировать провайдер-константу как `Provider`; тривиальные `any`→`unknown`; в перспективе сделать `KbqButtonToggleGroup<T>` / `KbqButtonToggleChange<T>` / `KbqButtonToggle<T>` (значимо по SemVer → отложить в ломающий батч).
- **BTOG-API-03 · Тип элемента сигнала `buttonToggles` стёрт в `any[]` из-за `forwardRef`** — `button-toggle.component.ts:117` / `api.md:69`. `contentChildren(forwardRef(() => KbqButtonToggle))` разрешается в `Signal<readonly any[]>`, потому что `forwardRef` теряет тип элемента (сравните корректно типизированный `icons` в `api.md:33`). **Исправление:** `contentChildren<KbqButtonToggle>(forwardRef(() => KbqButtonToggle))` — даёт `Signal<readonly KbqButtonToggle[]>` без изменений в рантайме.
- **BTOG-API-04 · `tabIndex` типизирован `number | null`, но дефолт — `undefined`** — `button-toggle.component.ts:375` / `api.md:48`. `input<number | null>(undefined!)` — объявленный тип исключает фактический дефолт (`tabIndex()` возвращает `undefined` до любой привязки). Функционально не баг (шаблонный guard `tabIndex() || 0` трактует всё это как falsy), но публичный тип нечестен. **Исправление:** `input<number | null>(null)` (использовать `null` как sentinel «не задано») или включить `undefined` в тип.
- **BTOG-API-05 · Кириллический гомоглиф + устаревшее «Mc» в публичном JSDoc** — `button-toggle.component.ts:43,46,48` (а также устаревшая формулировка «radio-button group» в `:53`). Три JSDoc-комментария на `KbqButtonToggleChange` читаются как `MсButtonToggle`, где второй символ — кириллическая «с» (U+0441), а не латинская `c` (подтверждено побайтово). Имя к тому же устаревшее — реальный класс `KbqButtonToggle`. Контракт radio «no-op, но всё равно эмитит» **уже** покрыт в `button-toggle.component.spec.ts:287-305`.
- *«`prefers-reduced-motion` нигде не покрыт»* — отклонено. У `button-toggle` нет `transition`/`animation`/`@keyframes`; единственная анимация (`.kbq-progress`) здесь не применяется и уже закрыта `@media (prefers-reduced-motion: reduce)` в ядре. Снимок reduced-motion был бы попиксельно идентичен.
- *Два «подтверждения» производительности* (однократный обход DOM в `ngAfterContentInit`; условный микротаск в `ngOnDestroy`) — проверены как корректные и вне горячего пути: дефекта производительности нет. (Риск жизненного цикла у микротаска зафиксирован отдельно как BTOG-RX-01.)
- *«Файл назван `.component.ts` и расходится с эталонным компонентом»* — эталонный `button/` использует **тот же** суффикс `.component.ts` (`button.component.ts`), поэтому `button-toggle` согласован с ним, а не расходится. Исключено.

## 5. Стратегия проверки

**Общие гейты (на каждую фазу):**
- `npx jest packages/components/button-toggle/button-toggle.component.spec.ts`
- `yarn run eslint && yarn run stylelint && yarn run prettier`
- `yarn run check-api` (и `yarn run approve-api` только когда публичный API меняется намеренно — Фаза 5) — сначала собрать `build:components` (guard читает `dist/*.d.ts`).

**Фаза 1 (a11y):** новые спеки — single-режим выставляет `role="radio"` + `aria-checked`, отслеживающий `checked`, а группа — `role="radiogroup"`; multiple-режим выставляет `aria-pressed`/`role="group"`; icon-only toggle без имени даёт dev-предупреждение; группа принимает доступное имя. При внедрении `axe-playwright`: `analyze()` по e2e-странице в светлой + тёмной теме.

**Фаза 2 (корректность/стили):** `focus()` переносит фокус на внутреннюю `<button>`; standalone `toggle.disabled` — реальный `boolean`; разрушение целой выбранной группы не эмитит после teardown; `yarn run styles:build-all`, затем перезаписать эталон Playwright «with icon» и убедиться, что icon-only toggle теперь получают темизированные цвета.

**Фаза 3 (тесты/гигиена):** хотя бы одно состояние Playwright прогоняется через реальный `page.hover()`/Tab; `-dark.png` для сценариев только-заголовок и только-иконка; переименованные/ретипизированные локали компилируются; не осталось `expect()` без матчера.

**Фаза 4 (миграция):** `[vertical]`/`[multiple]`/`[disabled]`/`[checked]` ведут себя идентично после миграции на `input()`/`model()`; CD детей обновляется без ручного `markForCheck`; полный `yarn run unit:components`.

**Фаза 5 (API):** после изменений типов → `yarn run check-api`, просмотреть `button-toggle.api.md`, затем `approve-api`. Проверить типами, что `toggle.buttonToggleGroup` — `KbqButtonToggleGroup | null`, `disabled` round-trip в `boolean`, а `buttonToggles()` — `readonly KbqButtonToggle[]`. Полная регрессия: `yarn run unit:components` + `yarn run e2e:components` перед мержем.
