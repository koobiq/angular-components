# Компонент Koobiq `app-switcher` — Code Review и план улучшений

> Область: `packages/components/app-switcher` (8 исходных файлов + тесты/стили/документация) и общие абстракции `core`, которые он расширяет (`core/pop-up` → `KbqPopUp`/`KbqPopUpTrigger`, `dropdown` → `KbqDropdownItem`) · Коммит `18ea72fe` · 2026-06-29
> Подготовлено автоматическим мультиагентным ревью (9 измерений + состязательная верификация каждого замечания). Из 79 исходных замечаний 67 подтверждено/оставлено (после дедупликации ~61 уникальное: 3×P0, 5×P1, ~24×P2, ~28×P3) и 12 опровергнуто/пересмотрено. Воспринимайте как высокосигнальную отправную точку; перепроверяйте перед действиями.

## 1. Краткое резюме

- **Безопасность — главный риск и блокер релиза.** Компонент рендерит публичную строку `KbqAppSwitcherApp.icon` как сырой HTML через `DomSanitizer.bypassSecurityTrustHtml(...)`, привязанный к `[innerHtml]`, в **двух** местах (`kbq-app-switcher-list-item.ts:81`, `app-switcher-dropdown-app.ts:61`). Это намеренно отключает санитайзер Angular, поэтому любая разметка иконки с обработчиком события (`<img onerror>`, `<svg><script>`) выполняется. `icon` — часть документированного контракта данных, а в документации передаётся сырой SVG — если хоть один потребитель наполняет данные приложений с бэкенда или из удалённой конфигурации, это stored/reflected XSS. Нет санитизации, нет предупреждения в документации, нет регрессионного теста на XSS. **Кластер 2×P0** (две точки). Независимо подтверждает `SEC-04`/`SEC-05` из монорепо-ревью.
- **Доступность — второй блокирующий риск.** Компонент функционально является клавиатурным меню ссылок на приложения, но почти не предоставляет необходимой семантики, нарушая мандат `AGENTS.md` «MUST pass AXE / WCAG AA». Самое жёсткое нарушение (P0): **тоггл сворачивания/разворачивания группы — это нефокусируемый `<div>`, шеврон которого `display:none` до `:hover`**, без `role="button"`, без `aria-expanded` и без активации Enter/Space — пользователи клавиатуры и тача не могут им управлять (WCAG 2.1.1, уровень A). Вдобавок **вся вложенная навигация площадка→приложение работает только по наведению** (`(mouseenter)` управляет `activeSite`/`activeApp`), поэтому даже клавиатурное открытие подменю показывает устаревший/пустой контент. Плюс: нет роли menu/list на панелях, `<img alt="{{app.type}}">` отдаёт внутренний код категории вместо имени приложения, у поля поиска только placeholder (нет метки), а у кнопки очистки нет имени.
- **Корректность — в основном краевые падения в сеттерах входов.** `selectedSite` разыменовывает результат `originalSites.find(...)` без проверки совпадения — выбор устаревшего/удалённого id площадки бросает `TypeError` (`app-switcher.ts:451`). `currentApps` читает `selectedSite.apps` в режиме нескольких площадок даже когда площадка не выбрана, ломая рендер (`:342`). Сеттер `sites` оставляет `_parsedSites` устаревшим при переключении multi→single (`:375`). Поиск фильтрует только `app.name`, игнорируя видимый `caption`. Ни одно не срабатывает на «счастливом пути», который покрывают тесты, — именно поэтому они и выживают.
- **Отчёты об «утечке по скроллу» сводятся к багу мёртвого кода, а не к утечке.** `private closeOnScroll: null;` объявлено без инициализатора, поэтому в рантайме значение `undefined`, а не `null` — из-за чего `if (this.closeOnScroll === null)` в `ngAfterContentInit` **всегда false**. Блок авто-скрытия по вложенному скроллу, который он охраняет (включая подписку `scrollDispatcher.scrolled()` на `:526`, которую двое ревьюеров пометили как утечку в root-синглтон), **никогда не выполняется**. Так что «утечка» неактуальна (именно поэтому `BUG-34` из монорепо был спорным), но реальная фича молча отключена. Единственный настоящий пробел в teardown — подписка `closingActions()` на `:541`, которая течёт в root `ScrollDispatcher` только если директиву уничтожают, пока попап открыт.
- **Архитектура — на середине миграции с реальной слабостью типизации.** `KbqAppSwitcherTrigger` — god-class на ~325 строк, смешивающий парсинг входов, алгоритм группировки, позиционирование оверлея и локаль. У поля `configuration` нет аннотации типа (неявный `any`), и этот `any` протекает через `localeData` в каждую строку локали в шаблоне; оба `InjectionToken` нетипизированы. Двусторонняя привязка (`selectedApp`, `selectedSite`, `collapsed` у list-item) всё ещё `@Input`+`@Output`, где подошёл бы `model()`, а провайдеры focus-trap живут только в legacy `NgModule`, поэтому standalone-потребители их молча теряют.
- **Производительность: ограниченный, но реальный churn на OnPush.** `@for` отслеживает по **идентичности объекта** коллекции, которые `makeGroupsForApps`/`filterSites` пересоздают как новые ссылки, поэтому каждое нажатие в поиске разрушает и пересоздаёт весь DOM строк; `filterSites` глубоко клонирует все площадки через `structuredClone` на каждое нажатие без debounce; а `[innerHtml]="getIcon(app.icon)"` выделяет новый `SafeHtml` на каждый проход change-detection, переразбирая каждый SVG.
- **Тесты широки по геттерам, но мимо рисковой поверхности.** Нет теста на XSS/санитизацию, нет AXE/a11y-теста, нет теста клавиатуры/focus-trap, нет теста на отрисованную группировку (сворачивание/разворачивание) или вложенный dropdown, нет теста `selectedSite` при отсутствующем id — именно там, где живут проблемы P0/P1. Асинхронная обвязка cargo-culted (`TestScheduler` создаётся в каждом `beforeEach`, но `.run()` никогда не вызывается), есть мёртвая экспортируемая фикстура, а Playwright — два статичных скриншота без взаимодействия.
- **Что хорошо.** Базовый жизненный цикл `KbqPopUpTrigger`/`KbqPopUp` дисциплинирован, и почти весь teardown там корректен (`takeUntilDestroyed` на `scrollable.elementScrolled`, `positionChanges`, `detachments`); редьюсер группировки `defaultGroupBy` покрыт юнит-тестом изолированно; SCSS использует дизайн-токены и `kbq-list-item-base()` для большинства состояний; именование BEM единообразно. Швы для рефакторинга (типизированный интерфейс конфигурации, `model()`, сервис группировки) чистые.

## 3. Приоритизированные замечания (дедуплицировано, верифицировано)

### P0 — Блокеры релиза

**AS-SEC-01/02 · DOM-XSS: `app.icon` рендерится через `bypassSecurityTrustHtml` + `[innerHtml]` (две точки)** — `kbq-app-switcher-list-item.ts:81-83` (привязка `:26`) и `app-switcher-dropdown-app.ts:61-63` (привязка `:16`). *(Подтверждает монорепо `SEC-04`/`SEC-05`.)*
`getIcon()` возвращает `this.sanitizer.bypassSecurityTrustHtml(icon || '')` над публичной строкой `KbqAppSwitcherApp.icon`, привязанной через `[innerHtml]`. Это полностью отключает HTML-санитайзер Angular, поэтому `app.icon = '<img src=x onerror=alert(document.cookie)>'` (или встроенный `<svg><script>`) выполняется в контексте пользователя. `icon` — документированные публичные данные (`app-switcher.ts:64`), а примеры передают сырой SVG, поэтому любой источник с сервера/удалённой конфигурации/частично контролируемый атакующим делает это stored/reflected XSS. Две точки рендерят одни и те же данные на двух путях (список single-site + dropdown в режиме площадок); починка одной оставляет вторую эксплуатируемой.
**Исправление:** не доверять сырой разметке вслепую. Предпочтительно — сменить контракт на ссылку по **имени** `KbqIcon` и рендерить через `<i kbq-icon>`. Если встроенный SVG нужен, прогонять обе точки через **один** общий хелпер санитизации со строгим allowlist для SVG (например, DOMPurify `USE_PROFILES:{svg:true,svgFilters:true}`, с вырезанием обработчиков/скриптов) перед `bypassSecurityTrustHtml`. Как минимум — явно задокументировать, что `icon` ДОЛЖЕН быть доверенной разметкой, контролируемой разработчиком. Добавить регрессионный тест на XSS (AS-SEC-05/AS-TEST-03).

**AS-A11Y-01 · Тоггл сворачивания/разворачивания группы — нефокусируемый `<div>`, скрытый до hover, без `aria-expanded`** — `app-switcher.html:45-50`, `kbq-app-switcher-list-item.ts:72`, `kbq-app-switcher-list-item.scss:62-65,118-129`.
Когда у приложения есть `aliases`, заголовок группы рендерится как `<div kbq-app-switcher-list-item [toggle]="true">`; шеврон тоггла (`.kbq-app-switcher-list-item__toggle`) — `display:none` и становится видимым только на `:hover`/`.kbq-hover`/`.kbq-focused`. Сворачивание/разворачивание управляется `(click)`-обработчиком `clickHandler` на `<div>` — не `<button>`, без `role="button"`, без `aria-expanded`, без активации Enter/Space. Скринридер озвучивает статичный элемент без состояния, а аффорданс невидим без указателя. Нарушает WCAG 2.1.1 (Keyboard, уровень A) и 4.1.2; проваливает AXE → нарушает мандат `AGENTS.md`.
**Исправление:** рендерить заголовок группы как настоящий `<button type="button">` (или задать host `role="button"`, `tabindex=0`, активацию `(keydown.enter)`/`(keydown.space)`) и привязать `[attr.aria-expanded]="!collapsed"`. Сделать шеврон воспринимаемым без hover (видимым или по `:focus-visible`).

> AS-SEC-01/02 и AS-A11Y-01 — два жёстких блокера релиза. Кластер P1 по доступности ниже (AS-A11Y-02/04/05/06 + навигация только по hover AS-A11Y-NAV) должен приземлиться вместе с AS-A11Y-01, чтобы открытый попап реально прошёл AXE.

### P1 — Высокий

**AS-A11Y-NAV · Нет клавиатурного/тач-пути для вложенной навигации площадка→приложение (контент управляется hover)** *(объединяет AS-A11Y-09, AS-TPL-03, AS-TPL-09.)* — `app-switcher.html:2,21,85,102`, `kbq-app-switcher-list-item.scss:62-65,118-129`.
Флайаут «другие площадки» и подменю сгруппированных приложений наполняются из `activeSite`/`activeApp`, которые устанавливаются **только** через `(mouseenter)` (`:85`, `:102`); `(mouseenter)="otherSites()?.close()"` (`:2`,`:21`) тоже только по указателю. `KbqDropdownTrigger` поддерживает открытие с клавиатуры, но раз `activeSite`/`activeApp` не устанавливаются по фокусу, связанные панели `dropdownWithSelectedSite`/`dropdownWithGroupedApps` рендерят устаревший/пустой контент для клавиатурных пользователей — то есть клавиатурный пользователь свитчера на несколько площадок не может добраться до приложений других площадок. На тач-устройствах (нет hover) — то же, и тоггл группы (AS-A11Y-01) тоже недостижим. WCAG 2.1.1 (уровень A).
**Исправление:** дублировать каждый драйвер `(mouseenter)` активацией по `focus`/клавиатуре — устанавливать `activeSite`/`activeApp`, когда соответствующий триггер получает фокус или открывается с клавиатуры; закрывать флайаут площадок по focus-out, а не только по `mouseenter`. Держать тоггл в потоке (`visibility`/opacity или `@media (hover:none)` всегда видимый), а не `display:none`.

**AS-A11Y-02 · Панели оверлея/меню не имеют роли (нет `menu`/`list`/`listbox`)** **(shared)** — `app-switcher.html:33-66`; `kbq-app-switcher-list-item.ts:55` снимает `kbq-dropdown-item` через `[class.kbq-dropdown-item]="false"` без замены роли; общая панель dropdown задаёт только `tabindex="-1"`.
Попап — список ссылок на приложения, но ни контейнер, ни строки не несут landmark/widget-роли, поэтому AT озвучивает плоскую группу ссылок без семантики «меню»/«список» и без числа элементов. WCAG 1.3.1 / 4.1.2.
**Исправление:** дать прокручиваемому списку `role="menu"` (или `role="list"`), а строкам-ссылкам `role="menuitem"`/`listitem` (или обернуть в `<ul>`/`<li>`). Согласовать роли контейнера/элементов с общей панелью dropdown.

**AS-A11Y-04 · `alt` изображения использует `app.type` (код группировки), давая пустой или неверный alt** — `kbq-app-switcher-list-item.ts:29`, `app-switcher-dropdown-app.ts:19`.
У `<img>` иконки `alt="{{ app.type }}"`. `type` — необязательный дискриминатор группировки (`app-switcher.ts:62`), часто `undefined`/`''` (см. `e2e.ts`, у многих приложений `type:''`), поэтому `alt` пустой или, хуже, отдаёт внутренний код вроде `NAD`/`SIEM` вместо имени приложения. WCAG 1.1.1.
**Исправление:** использовать `alt="{{ app.name }}"` или пометить изображение декоративным (`alt=""` + `aria-hidden` на span с встроенным SVG), так как соседний `.__name` уже именует приложение. Никогда не отдавать `app.type`.

**AS-A11Y-05 · У поля поиска нет программной метки (только placeholder)** — `app-switcher.html:5-11`.
У `<input kbqInput>` есть только `placeholder`; нет `<label>`, `aria-label` или `aria-labelledby`. Placeholder — ненадёжное доступное имя. WCAG 1.3.1 / 3.3.2 / 4.1.2.
**Исправление:** добавить `[attr.aria-label]="localeData.searchPlaceholder"` (или отдельную строку локали `searchAriaLabel`), либо визуально скрытый `<label>`, связанный с id инпута.

**AS-A11Y-06 · У кнопки очистки (clear-search) нет доступного имени** **(shared)** — `app-switcher.html:12`.
`<kbq-cleaner />` расширяет `KbqIconButton` (фокусируемый, `tabindex=0`), но ему не задан `aria-label`, поэтому клавиатурный/AT-пользователь слышит безымянную кнопку. WCAG 4.1.2.
**Исправление:** `<kbq-cleaner [attr.aria-label]="localeData.clearSearch" />` (добавить локализованную строку `clearSearch`) либо задать `aria-label` по умолчанию внутри `KbqCleaner` (shared).

### P2 — Желательно исправить

- **AS-BUG-02 · Сеттер `selectedSite` разыменовывает результат `originalSites.find()` без проверки совпадения** — `app-switcher.ts:451-458`. `const originValue = this.originalSites.find(s => value.id === s.id)`, затем `{ ...originValue, apps: [] }` + `makeGroupsForApps(originValue.apps, …)`. Устаревший/удалённый id (или `selectedSite` до `sites`) делает `originValue` undefined → `originValue.apps` бросает. **Исправление:** `if (!originValue) { this._parsedSelectedSite = value; return; }`; гарантировать инициализацию `originalSites` первой.
- **AS-BUG-06 · `currentApps` читает `selectedSite.apps` в sitesMode, когда `selectedSite` может быть не задан** — `app-switcher.ts:342-344`. Шаблон итерирует `trigger.currentApps` при открытии, поэтому свитчер на несколько площадок, открытый без `selectedSite`, ломает рендер. **Исправление:** `return this.sitesMode ? (this.selectedSite?.apps ?? []) : this._parsedApps;` или дефолт `selectedSite` = `originalSites[0]`.
- **AS-BUG-05 · Сеттер `sites` оставляет `_parsedSites` устаревшим при переключении multi→single** — `app-switcher.ts:375-394`. Single-ветка задаёт `_parsedApps`, но не сбрасывает `_parsedSites`, поэтому `get sites()` отдаёт устаревшие данные после переключения multi→single. **Исправление:** в single-ветке задать `this._parsedSites = []` (или пересобрать).
- **AS-BUG-08 · Поиск совпадает только с `app.name`, игнорируя видимый `app.caption`** — `app-switcher.ts:265`. List-item рендерит `caption` второй строкой, но искать по нему нельзя. (Замечание про alias/группы — *не* баг: поиск идёт по плоскому `originalSites`, так что сгруппированные приложения достижимы.) **Исправление:** `app.name…includes(q) || (app.caption?.toLowerCase().includes(q) ?? false)`.
- **AS-ARCH-04 · Мёртвый guard `closeOnScroll === null` отключает авто-скрытие по вложенному скроллу и делает «утечку» неактуальной** — `app-switcher.ts:322,525`. `private closeOnScroll: null;` никогда не присваивается → рантайм `undefined` → `=== null` всегда false → блок в `ngAfterContentInit` (`:526-535`, проверка `kbq-hide-nested-popup`) **никогда не выполняется**. Это молча отключает фичу *и* объясняет, почему утечка `scrollDispatcher.scrolled()` на `:526` (монорепо `BUG-34`) неактуальна. **Исправление:** определить намерение — если авто-скрытие нужно, объявить `closeOnScroll: boolean | null = null` (и добавить `takeUntilDestroyed` к теперь живой подписке); если нет — удалить поле и мёртвый блок.
