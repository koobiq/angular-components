## 1. Резюме

- **Доступность — главный риск и единственный блокер релиза.** Компонент не реализует буквально ни одной ARIA-семантики: ни одного `role` или `aria-*` атрибута нет ни в `tree-select.html`, ни в host-биндингах компонента (проверено исчерпывающим grep). Нет `role="combobox"`, нет `aria-expanded`, нет роли у панели, а хост никогда не рендерит `id`, поэтому `[attr.for]="control().id"` у лейбла form-field (`form-field.html:2`) висит в воздухе. Это нарушает собственный мандат проекта «MUST pass AXE / WCAG AA» (AGENTS.md). Здесь сосредоточены **2×P0 + 2×P1** — поверх собственного «нулевого ARIA» субстрата дерева (`REVIEW.tree.md` A1–A14).
- **Спорная утечка из монорепозиторного ревью закрыта.** `REVIEW.md` BUG-03 (голые подписки `selectionModel.changed` / `valueChanges` поиска, сначала «disputed», затем подтверждённые как реальные в его Appendix F) исправлена коммитом `f14a571c` (2026-07-02): все три подписки теперь идут через `takeUntilDestroyed` (`tree-select.component.ts:745`, `:753-755`, `:1483-1486`). Подписка на локаль тоже защищена (`:678`) — в отличие от всё ещё открытого SEL-LEAK-01 у select. Это закрывает follow-up #3 монорепозиторного ревью.
- **Контракт встраивания дерева — главная структурная слабость.** tree-select подменяет `SelectionModel` встроенного дерева (`:743`), а затем вручную повторно вызывает `tree.ngAfterContentInit()` (`:758`) — тело content-init дерева выполняется дважды, оставляя дублирующиеся подписки `unorderedOptions.changes` / `renderedOptions.changes` / `tabOut` живыми на всё время жизни компонента (каждое изменение опций выполняет работу по синхронизации рендера несколько раз — а это горячий путь фильтрации поиском). Вдобавок он monkey-patch'ит `tree.onKeyDown` (`:1417-1419`) и содержит мёртвый провайдер `{ provide: KbqTree, useExisting: KbqTreeSelect }` — структурную ложь о типе (`:156`).
- **Публичный API нетипизирован и протекает внутренностями.** `value`/`selected`/`writeValue`/`KbqTreeSelectChange.value` — `any`; output `valueChange` объявлен и задокументирован как «two-way binding for the value input» — но input `value` не существует, а output ни разу не эмитится; `selectionModel`, `overlayDir`, `triggerRect`, `changeDetectorRef`, `panelDoneAnimatingStream` и прочие — публичные. Импорт standalone `KbqTreeSelect` без `KbqTreeSelectModule` падает на DI (`KBQ_SELECT_SCROLL_STRATEGY` не имеет провайдера по умолчанию).
- **Горячие точки производительности унаследованы от select.** `calculateHiddenItems` делает тот же двойной DOM-клон с чередующимися чтениями/записями layout и синхронным `detectChanges()` (`:1133`, `:1308`, `:1324`), а шаблон каждый цикл CD вызывает геттеры, читающие DOM и создающие объекты (`colorForState` `:643`, `getPanelClasses()` `:1088`).
- **Что сильно.** RxJS-гигиена только что приведена в порядок (5 фиксов за последний месяц — компонент активно сопровождается); `panelWidth`/`panelMinWidth`/`multiline`/`selectAllToggle` уже signal-инпуты (тот самый «мигрировавший сосед», которого хвалит `REVIEW.select.md`); токен цвета invalid-состояния уже использует `--kbq-foreground-error` (`_tree-select-theme.scss:12`) — целевое состояние, к которому SEL-TPL-01 просит привести select; свежая миграция Karma→Jest (147 тестов) плюс действительно сильный Playwright-набор (позиционирование, включая RTL-переполнение, скролл, клавиатура) дают прочную регрессионную сетку — кроме a11y, где покрытие нулевое.

## 3. Приоритизированные находки (дедуплицированы, верифицированы)

### P0 — блокеры релиза

**TS-A11Y-01 · Нет combobox-семантики и нет `id` на хосте** — `tree-select.component.ts:161-173` (host-объект).
Хост выставляет только `tabindex`/`disabled`/классы — нет `role="combobox"`, `aria-haspopup="tree"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-required`, `aria-invalid`, `aria-disabled`, `aria-labelledby`. Хуже, чем в select: хост к тому же не биндит `[attr.id]`, хотя аксессор `id` (`:464-474`) поддерживает uid, на который целится лейбл form-field через `[attr.for]="control().id"` (`form-field.html:2`) — ассоциация висит в воздухе (а `for` в любом случае не может указывать на non-labelable кастомный элемент). Скринридер объявляет безымянную фокусируемую группу (WCAG 4.1.2, 1.3.1).
**Исправление:** добавить host-биндинги `[attr.id]="id"`, `[attr.role]="'combobox'"`, `[attr.aria-haspopup]="'tree'"`, `[attr.aria-expanded]="panelOpen"`, `[attr.aria-controls]="panelOpen ? panelId : null"`, `aria-required/invalid/disabled`; дать лейблу form-field `id` и связать `aria-labelledby` с ним. Зеркало SEL-A11Y-01 — выпускать одним общим изменением.

**TS-A11Y-02 · Панель оверлея и встроенное дерево не дают семантики для combobox-цепочки** — `tree-select.html:106-134` (`#panel`, `#optionsContainer`); субстрат: host `tree-selection.component.ts:123-131`.
У div панели и контейнера опций нет `role`/`id`; у спроецированного `kbq-tree-selection` нет `role="tree"`, а у его опций — `role="treeitem"` (этот субстрат — `REVIEW.tree.md` A1–A14, здесь не перефайливается). Нет ничего, на что мог бы указывать `aria-controls` хоста, а состояние выбора (`aria-selected`, `aria-multiselectable`) передаётся только визуально (псевдочекбоксами).
**Исправление:** дать контейнеру дерева стабильный `panelId`; сначала (или одновременно) выпустить tree A1–A14 (`role="tree"`/`treeitem`/`aria-selected`/`aria-expanded` на опциях), затем связать здесь цепочку combobox → tree. Держать поле поиска и футер вне accessibility-поддерева дерева.

> TS-A11Y-01/02/03 — одна логическая единица: цепочка combobox → tree → treeitem → activedescendant должна выйти вместе, чтобы быть связной и проходить AXE.

### P1 — высокий приоритет

**TS-A11Y-03 · Модель фокуса: реальный DOM-фокус спорят опции и поиск; нет `aria-activedescendant`; Tab проглатывается** — `tree-select.component.ts:1474-1476` (`scrollActiveOptionIntoView` принудительно вызывает `activeItem.focus()`), `:1271-1273`, `:713-718` и `:790-794` (автофокус поиска), `:1209-1213` (Tab → `preventDefault` + close).
Клавиатурная навигация переносит реальный фокус в опции дерева, а поле поиска отбирает его обратно после каждого выбора (`:790-794` даже не проверяет `shouldShowSearch()`, в отличие от `:1275-1279`); `aria-activedescendant` не рендерится никогда. Tab внутри открытой панели гасится `preventDefault`, что расходится с ARIA-паттерном combobox (Tab должен закрывать панель и передавать фокус дальше).
**Исправление:** держать DOM-фокус на combobox-хосте (или на поле поиска, когда оно есть) и биндить `[attr.aria-activedescendant]="keyManager.activeItem?.id"`; заменить `activeItem.focus()` на прокрутку в зону видимости без кражи фокуса; обернуть вызов фокуса в `:790-794` проверкой `shouldShowSearch()`; позволить Tab закрывать панель без `preventDefault`. Зеркало SEL-A11Y-04.

**TS-A11Y-04 · Иконка удаления тега не управляется с клавиатуры и не имеет имени** **(shared)** — `tree-select.html:37-43`; `KbqTagRemove` жёстко задаёт `tabindex: -1`, только клик.
В multiple-режиме выбранное значение можно удалить только мышью; у иконки нет `role="button"`/`aria-label`, а сам тег нефокусируемый (`[selectable]="false"`). WCAG 2.1.1 + 4.1.2. Идентично SEL-A11Y-05 — одно общее исправление в tags/select/tree-select.
**Исправление:** сделать контрол удаления фокусируемым, добавить `role="button"` + локализованный `aria-label` (например, `Remove {{ option.viewValue }}`), обрабатывать Enter/Space → `onRemoveSelectedOption`; пометить глиф `aria-hidden`.

**TS-BUG-01 · Ручной повторный вызов `tree.ngAfterContentInit()` дважды инициализирует встроенное дерево** — `tree-select.component.ts:757-758`; тело: `tree-selection.component.ts:286-334`.
Angular вызывает `KbqTreeSelection.ngAfterContentInit()` естественным образом; tree-select затем подменяет `selectionModel` дерева (`:743`) и повторно запускает хук вручную (с eslint-disable). Последствия, живущие до destroy: `unorderedOptions.changes` подписан дважды (`tree-selection.component.ts:287` — `updateRenderedOptions` выполняется дважды на каждое изменение опций), `renderedOptions.changes` дважды (`:312` — с двумя вызовами `notifyOnChanges()` цикл select/deselect + `resetOptions` выполняется до 4× на одно изменение), `keyManager.tabOut` дважды (`:304`), а подписки первого запуска на `keyManager`/`selectionModel.changed` осиротели на выброшенных объектах (`:289`, `:306`). Фильтрация поиском и раскрытие lazy-load — пути, мутирующие опции, — платят умноженную цену. Monkey-patch `this.originalOnKeyDown = tree.onKeyDown; tree.onKeyDown = () => {}` (`:1417-1419`) — часть того же хрупкого контракта.
**Исправление:** дать `KbqTreeSelection` явный идемпотентный API встраивания — например, метод `initialize(selectionModel)` (или инжектируемую конфигурацию `KBQ_TREE_EMBEDDING`), который сносит и пересоздаёт свои подписки, плюс публичный хук делегирования клавиатуры вместо monkey-patching свойства экземпляра. Краткосрочно: сделать `ngAfterContentInit` реентерабельным (снимать прежние подписки перед повторной подпиской). Добавить регрессионный тест: `updateRenderedOptions` выполняется ровно один раз на изменение `unorderedOptions`.

### P2 — стоит исправить

- **TS-A11Y-05 · Контрол очистки без имени** **(shared)** — `tree-select.html:72-81` + спроецированный `kbq-cleaner`. Клавиатура работает (фокусируемая внутренняя кнопка + всплывающие обработчики `keydown.enter/space`), но контрол объявляется без имени (WCAG 4.1.2). То же, что SEL-A11Y-06 — исправить один раз в `KbqCleaner` (`role="button"` + локализованный `aria-label`, иконка `aria-hidden`).
- **TS-LEAK-01 · `closeSubscription` накапливает по подписке на каждое открытие панели** — `tree-select.component.ts:1079`. `onAttached()` переприсваивает `closeSubscription = this.closingActions().subscribe(...)` без отписки от предыдущей; `backdropClick`/`outsidePointerEvents`/`detachments` персистентного `overlayRef` никогда не комплитятся, так что N открытий оставляют N живых подписок, каждая из которых вызывает `close()` (идемпотентно, поэтому незаметно — но утечка реальна). **Исправление:** `this.closeSubscription.unsubscribe()` перед переприсваиванием либо отписка в `close()`. Зеркало SEL-LIFE-01/SEL-LEAK-02.
- **TS-BUG-02 · Сервис локали затирает input `hiddenItemsText`; `hiddenItemsTextFormatter` — метод с декоратором `@Input()`** — `tree-select.component.ts:1292-1296`, `:295-297`, `:840-843`. `updateLocaleParams` безусловно перезаписывает пользовательский `@Input() hiddenItemsText` при каждой смене локали (два источника истины — TODO «Your application code writes to the input» на `:295` документирует запах вместо исправления), а `hiddenItemsTextFormatter` — метод, украшенный input-декоратором. **Исправление:** оставить `input()` для `hiddenItemsText` плюс `computed()` для эффективного текста, слитого с локалью; форматтер превратить в `readonly hiddenItemsTextFormatter = input<(text, count) => string>(...)`. Идентичный близнец: SEL-API-04.
- **TS-PERF-01 · `calculateHiddenItems` дважды клонирует триггер и молотит layout + `detectChanges`** — `tree-select.component.ts:1133-1182`, `getTotalItemsWidthInMatcher` `:1308-1322`, `getTotalVisibleItems` `:1324-1348`, `buildTriggerClone` `:1363-1372`. Два глубоких клона, добавляемых в живой триггер, чередующиеся чтения `getComputedStyle`/offset на каждый тег (`getItemWidth` `:1374-1382`), до 2 синхронных `detectChanges()` за проход; `refreshTriggerValues` тоже вызывает `detectChanges()` при каждом изменении выбора (`:1391`). **Исправление:** один клон вне DOM, все чтения одним циклом, один `markForCheck` в конце; предпочтительно `ResizeObserver` на списке matcher'а. Зеркало SEL-PERF-02 — выделить один общий измерительный helper для обоих компонентов (см. TS-ARCH-05).
- **TS-PERF-02 · Шаблон каждый цикл CD вызывает DOM-читающие/аллоцирующие члены** — `colorForState` `:643-651` (читает `classList` — дважды за цикл: цвет тега + цвет стрелки), `getPanelClasses()` `:1088-1101` (аллоцирует + join, пока панель открыта), вызов метода `hiddenItemsTextFormatter(...)` (`tree-select.html:65`). **Исправление:** перевести на `computed()`-сигналы, управляемые `errorState`/инпутами. Зеркало SEL-PERF-04/SEL-TPL-02.
- **TS-API-01 · Нетипизированный `any` по всей публичной поверхности** — геттеры `value`/`selected`/`selectedValues` (`:458`, `:995-1003`), `writeValue(value: any)` (`:952`), `new SelectionModel<any>` (`:743`), `KbqTreeSelectChange.value: any` (`:132-139`), нетипизированные параметры `clearValue($event)` и `onRemoveSelectedOption(selectedOption: any, $event)` (`:845`, `:1116`), `panelKeydownHandler` возвращает `any` (`:1203`, через ветку `return this.originalOnKeyDown.call(...)`), `any`-индексная сигнатура `panelClass` (`:331-338` — зеркало SEL-API-05). **Исправление:** ввести `KbqTreeSelect<T>`/`KbqTreeSelectChange<T>` (дефолт `any` сохраняет source-совместимость), типизировать обработчики, сделать возврат `panelKeydownHandler` `void`. Изменение снапшота API → `approve-api`.
- **TS-API-02 · Мёртвый output `valueChange` и фантомный input `value`** — `tree-select.component.ts:323-328`. JSDoc output'а говорит, что он существует «to facilitate the two-way binding for the `value` input», но input `value` не существует (только геттер `:458`), а `valueChange` ни разу не эмитится (ноль `valueChange.emit` в файле). `(valueChange)` компилируется и молча никогда не срабатывает; `[(value)]` не компилируется. **Исправление:** либо реализовать `value` как `model()` (с эмиссией при каждом изменении), либо удалить output + доку; breaking → окно SemVer.
- **TS-API-03 · Standalone-импорт падает на DI: у `KBQ_SELECT_SCROLL_STRATEGY` нет провайдера по умолчанию** **(shared)** — `tree-select.component.ts:197`; токен: `core/select/constants.ts:17`; провайдер только в NgModule (`tree-select.module.ts:36`, `select.module.ts:43`). `imports: [KbqTreeSelect]` без `KbqTreeSelectModule` бросает `NullInjectorError` при конструировании — вразрез со standalone-first политикой репозитория (все 14 docs-примеров вынуждены идти через модуль). **Исправление:** дать токену дефолтную фабрику `providedIn: 'root'` (или fallback на уровне компонента, как делает `tabs/tab.component.ts:38`); провайдер в модуле оставить для переопределений.
- **TS-ARCH-02 · Мёртвый провайдер `KbqTree` — структурная ложь о типе** — `tree-select.component.ts:156`. `{ provide: KbqTree, useExisting: KbqTreeSelect }`, хотя `KbqTreeSelect` не наследует `KbqTreeBase` (`tree/tree.ts:21`); ни один код в репозитории не инжектит `KbqTree`, так что сегодня провайдер лишь вводит в заблуждение — но любой будущий потребитель получит сломанный экземпляр. Ссылка: `REVIEW.tree.md` AR8. **Исправление:** удалить провайдер (или предоставлять реальный встроенный `KbqTreeSelection`, когда появится настоящий потребитель); прогнать `approve-api`.
- **TS-ARCH-03 · `multiline` незаметно превращает single-select в multi-семантику** — `tree-select.component.ts:585-587` (`multiSelection = multiple || multiline()`), `:743` (multi-флаг модели выбора), `:999-1003` (значение становится массивом).
