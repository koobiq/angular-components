## 1. Executive Summary

- **The docs app is modern in its bootstrap and shallow in its safety nets.** It is standalone-first, server-rendered with prerendering and hydration + event replay, injects `KBQ_WINDOW` behind an SSR-safe mock, and uses `takeUntilDestroyed()` in most components. But it carries almost no automated verification and a cluster of lifecycle/correctness defects that a single unit or e2e test would have caught. The finding set is dominated by **lifecycle leaks, convention drift from the repo's own AGENTS.md mandates, and missing test/SEO plumbing** — not by structural rot.
- **Top risk #1 — a growing memory leak in a root singleton.** `DocsDocStates` (a `providedIn:'root'` service) subscribes to `scroll` in `registerHeaderScrollContainer`/`registerNavbarScrollContainer` and never tears the subscriptions down; `component-viewer`, `icons-viewer` and `welcome` re-register on **every navigation**, so scroll listeners accumulate for the life of the tab. The same service dereferences `currentHeaderScrollContainer` in `scrollUp()` and `currentHeader` in `checkHeaderOverflow()` without a guard, both typed non-optional but assigned only inside `register*` (DOCS-BUG-01).
- **Top risk #2 — the whole page graph ships in the initial bundle.** `routes.ts` uses `component:` for all 12 page/tab components with **zero** `loadComponent`/`loadChildren`; the icons viewer, both design-token viewers and their data tables are eagerly bundled into the main chunk of an SSR site (DOCS-PERF-01).
- **Top risk #3 — effectively no tests.** The entire ~50-file application has **one** spec (`docsearch.directive.spec.ts`, 2 shallow smoke cases) and **zero** Playwright coverage, while all 57 repo-wide Playwright specs target component packages. Routing, locale switching, the document loader, `doc-states`, the 1,184-line structure registry and the StackBlitz writer are untested (DOCS-TEST-01).
- **A cluster of real P2 correctness bugs.** Navigating to an unknown component id calls `router.navigate(['/404'])` **without returning** and then dereferences the null `docItem`, throwing a `TypeError` on the same emission (DOCS-BUG-02). The StackBlitz writer caches the *promise* of a project build, so one failed file fetch poisons the cache and that example's "Open in StackBlitz" button stays broken until a full reload (DOCS-BUG-03). DocSearch is re-instantiated on every locale change into the same container, duplicating the widget on the long-lived navbar (DOCS-BUG-05). The icons viewer leaks a `Location.subscribe` and has an unguarded `queryParamMap` deref race (DOCS-BUG-04).
- **Convention drift from AGENTS.md is systemic but low-severity.** 12 of 25 production components — including the root `DocsAppComponent` — omit `ChangeDetectionStrategy.OnPush`; legacy `@Input`/`@Output`/string-selector `@ViewChild` decorators, `any`, `ngClass` and `*ngTemplateOutlet` recursion persist in the example/anchors/tokens components; and `structure.ts` is a 1,184-line hand-maintained registry whose `isNew` badges are gated by 20 hardcoded `expiresAt` dates, **19 of which have already silently expired** (DOCS-ARCH-01/02/04).
- **Accessibility has concrete, cheap-to-fix gaps.** The copy button binds `(click)` to a non-focusable `<i>` rather than the pseudo-link, so copying is **mouse-only** (DOCS-A11Y-01); the source-view toggle and icon-grid cells are non-semantic elements missing `role`/`aria-expanded`/Space activation (DOCS-A11Y-02); and the Angular template a11y ESLint rules are explicitly disabled with no AXE in any test, removing the guardrail.
- **What's strong.** The bootstrap is exemplary: `bootstrapApplication`, `provideClientHydration(withEventReplay())`, `provideHttpClient(withFetch())`, a locale-prefixed router with a `canMatch` guard, and a genuinely careful `KBQ_WINDOW` SSR mock in `config.server.ts`. `DocsLocaleState` is a clean RxJS→signal bridge reused by 10+ components. Styles are almost entirely token-driven. The content pipeline (marked + custom renderer → `dist/docs-content`), generated `sitemap.xml`, `prerender-routes.txt` and `llms.txt`, and the Algolia DocSearch integration are all solid foundations — the SEO gap is that this plumbing is not wired to per-page metadata.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

None. Calibration note: consistent with the other component reviews in this folder, P0 is reserved for a live XSS with untrusted input, a fully screen-reader-inoperable core widget, or outright-broken tooling. Nothing in the docs app breaks the mainline (valid-URL) user path, and the one HTML-injection surface is non-exploitable (Appendix A).

### P1 — High

**DOCS-BUG-01 · `DocsDocStates` leaks scroll subscriptions on every navigation and NPE-derefs unguarded container fields** — `app/services/doc-states.ts:43-44, 54-56, 61-64, 69`.
`DocsDocStates` is `@Injectable({ providedIn: 'root' })` (`:10`). Both `registerHeaderScrollContainer` (`:54-56`) and `registerNavbarScrollContainer` (`:69`) do `fromEvent(el,'scroll').pipe(debounceTime(10)).subscribe(this.check…)` and **discard the returned subscription** — there is no `takeUntilDestroyed`, `Subscription` field, or teardown. `DocsComponentViewerComponent` (`component-viewer.component.ts:93`), `DocsIconsViewerComponent` (`icons-viewer.component.ts:101`) and `DocsWelcomeComponent` (`welcome.component.ts:53`) each call `registerHeaderScrollContainer` from their constructor/`ngOnInit`, so **every client-side navigation adds another live scroll subscription to the singleton** that is never released. Each call also overwrites the shared `currentHeaderScrollContainer`/`navbarScrollContainer` field, so the orphaned subscriptions keep firing `checkHeaderOverflow`/`checkNavbarOverflow` against the newest element — unbounded listener accumulation plus redundant work per scroll frame. Separately, the fields `currentHeader`, `currentHeaderScrollContainer`, `navbarScrollContainer` are declared non-optional `HTMLElement` (`:15-17`) but assigned only inside `register*`, so `scrollUp()` (`:43-44`, `this.currentHeaderScrollContainer.scroll(0,0)`) and `checkHeaderOverflow` (`:62`, `this.currentHeader.offsetHeight`) throw `Cannot read properties of undefined` if invoked before registration or after the element is gone.
**Fix:** scope each registration to the caller's `DestroyRef` (pass it in, or expose a returned `Subscription`/`unregister()` the component tears down), or collapse to a single `switchMap`ped stream that unsubscribes the previous container on each new registration. Make the three element fields `HTMLElement | undefined` (or signals) and guard `scrollUp`/`checkHeaderOverflow`. Add a `doc-states.spec.ts` asserting the subscription count stays flat across repeated `register*` calls.

**DOCS-PERF-01 · Zero route-level lazy loading — the entire page-component graph is eagerly bundled** — `app/routes.ts` (imports `:3-16`, `component:` refs throughout; `app/config.ts:15`).
Every page and tab component is statically imported and wired via `component:` — `DocsWelcomeComponent`, `DocsComponentViewerComponent` and its three tab children (`DocsComponentOverview/Api/ExamplesComponent`), `DocsDesignTokensViewer`, `DocsTokensOverview`, `DocsTypographyTable`, `DocsIconsViewerComponent`, `DocsPopoverExample`, `DocsSelectExample`, `DocsPageNotFoundComponent` (12 distinct classes). A repo-wide grep confirms **no `loadComponent`/`loadChildren`** in the docs app (the only `loadComponent*` hits are a private `loadComponents` portal helper in the example viewers). Because SSR + hydration are enabled (`config.ts:16-17`), the whole component graph — including the heavy icons viewer and both token-table viewers with their generated data — ships in the initial client chunk instead of being fetched on demand.
**Fix:** convert route `component:` entries to `loadComponent: () => import('…').then(m => m.X)` for at least the leaf/heavy pages (icons viewer, design-tokens viewers, examples tab, welcome). Re-run `ng build` and compare the initial-bundle stats; confirm `prerender-routes.txt`/`sitemap.xml` generation and hydration still pass.

**DOCS-TEST-01 · The application has effectively no test coverage** — `apps/docs/**` (only `app/components/docsearch/docsearch.directive.spec.ts`; `package.json:279`).
A glob of `apps/docs/**/*.spec.ts` returns exactly one file — the DocSearch directive spec — with two shallow cases (`should render docsearch button`, `should open docsearch modal`). `apps/docs/**/*.playwright-spec.ts` returns nothing; all 57 Playwright specs in the repo target `packages/components/**`. `unit:koobiq-docs` (`ng test koobiq-docs`) therefore exercises 2 tests. Everything load-bearing is uncovered: `routes.ts` (guard, redirects), `locale.ts`, `document-loader.ts`, `doc-states.ts`, the 1,184-line `structure.ts` (id/route integrity, stale-badge detection), `stackblitz-writer.ts`, `icon-items.ts`, and every viewer. Several bugs in this review (BUG-01, BUG-02, BUG-03) are exactly what a first unit/e2e pass would surface.
**Fix:** stand up a test foundation (Jest, per repo policy — no Karma): unit specs for the four services + `structure` integrity (every `id` resolves to a route, unique ids, no already-expired `isNew` without a build warning) + the StackBlitz writer's cache/error behavior; then a small Playwright smoke (home → component page → API/Examples tabs → locale switch → expand a live example). Wire it into CI alongside the component-package specs.

### P2 — Should fix

**DOCS-BUG-02 · Unknown component id navigates to `/404` without returning, then dereferences the null doc item** — `app/components/component-viewer/component-viewer.component.ts:85-91`.
In the `activatedRoute.url` subscription, `docsGetItemById(...)` returns `null` for an unmatched `:id`; the code does `if (!docItem) { this.router.navigate(['/404']); }` with **no `return`**, then immediately runs `this.structureItem = docItem!;` and `this.structureCategoryId = docsGetCategoryById(this.structureItem.categoryId!)!.id;`. For any invalid/stale/mistyped component URL this throws `TypeError: Cannot read properties of undefined (reading 'categoryId')` on the same emission (`docsGetCategoryById(undefined)` returns `undefined`, then `.id` throws). The redirect was already scheduled so the user usually still lands on `/404`, but an uncaught error is logged and the component's change-detection pass for that emission is broken.
**Fix:** `return` immediately after scheduling the redirect (`if (!docItem) { this.router.navigate(['/404']); return; }`). Add a spec navigating to a bogus id and asserting a clean redirect with no thrown error.

**DOCS-BUG-03 · StackBlitz writer caches the build *promise*, so one failed fetch permanently breaks that example's button** — `app/components/stackblitz/stackblitz-writer.ts:70-91`.
`createStackBlitzForExample` does `this.cache.set(exampleId, this.buildInMemoryProject(data, exampleId).then(…))`. `buildInMemoryProject` awaits `Promise.all` of `loadFile` HTTP requests; if any file 404s or the network drops, the **rejected** promise is stored in the `Map` and every subsequent click on that example returns the same rejected promise. Unlike an RxJS `shareReplay` stream (which self-heals — see Appendix A), a cached rejected promise never retries, so the "Open in StackBlitz" button for that example stays dead until a full page reload.
**Fix:** only cache on success — `.catch(err => { this.cache.delete(exampleId); throw err; })` on the stored promise, or cache the resolved value rather than the in-flight promise. Add a spec that rejects the first `loadFile` and asserts the second call re-fetches.

**DOCS-BUG-04 · Icons viewer subscription cluster: a real `Location` leak plus inconsistent teardown and an unguarded `queryParamMap` deref** — `app/components/icons-viewer/icons-viewer.component.ts:81, 94, 134, 176, 186`.
Four issues of graded severity: (a) `this.location.subscribe(() => this.modalService.closeAll())` (`:94`) discards the subscription — `Location` is a root/app-scoped service, so this `popstate` handler **outlives the component**: a genuine leak. (b) `this.http.get(…).subscribe(…)` in the constructor (`:81`) is one-shot but has no `takeUntilDestroyed`, so its callback (`markForCheck`, `init`, `refreshTitle`) can run after destroy — inconsistent with the guarded subscription at `:96`. (c) `this.activeRoute.queryParams.subscribe(…)` in `init()` (`:134`) lacks `takeUntilDestroyed` too; `ActivatedRoute` streams complete on route teardown so this is an inconsistency more than a hard leak. (d) `syncSearchQuery` reads `this.queryParamMap.s` (`:186`) where `queryParamMap` (`:76`, no initializer) is populated by the `:96` subscription — the field can be `undefined` when `syncSearchQuery` runs from `valueChanges`, a latent `TypeError` (safe today only because of ordering + the 300 ms `auditTime`).
**Fix:** pipe `takeUntilDestroyed(this.destroyRef)` on the `Location`, constructor-`http` and `queryParams` subscriptions; initialize `queryParamMap` to `{}` (or guard the deref). Consider migrating the icon list to a signal + `httpResource`/`toSignal`.

**DOCS-BUG-05 · DocSearch is re-instantiated on every locale change, duplicating the widget on the long-lived navbar** — `app/components/docsearch/docsearch.directive.ts:48-63`.
`initDocsearch()` subscribes to `docsLocaleService.changes` and calls `docsearch({ container: 'docs-docsearch', … })` on **every** emission. The `takeUntilDestroyed` guards component teardown, but the directive sits on the navbar (mounted once at the app shell, effectively permanent), so each ru↔en switch mounts a **fresh** DocSearch button/modal into the same fixed container without unmounting the previous one — accumulating duplicate widgets and orphaned listeners across a session.
**Fix:** instantiate DocSearch once, and on locale change update its parameters instead of re-calling `docsearch()` (or tear the previous instance down first). Since `facetFilters`/`translations` depend on locale, prefer a single init that reads locale reactively, or dispose+recreate explicitly.

**DOCS-A11Y-01 · The copy button's action is mouse-only — `(click)` is on a non-focusable `<i>`, not the pseudo-link** — `app/components/copy-button/copy-button.ts:20-22`.
In the idle branch the template is `<span kbq-link pseudo><i class="kbq kbq-square-multiple-o_16" (click)="copyContent()"></i></span>`. The click handler is on the `<i>` glyph, which is not focusable and has no keyboard handler; the focusable `kbq-link` wrapper has none. A keyboard-only user cannot trigger the copy, violating WCAG 2.1.1 (Keyboard) — the exact "MUST pass AXE / WCAG AA" mandate in AGENTS.md.
**Fix:** move the action onto the focusable control — put `(click)`/`(keydown.enter)`/`(keydown.space)` on the `<span kbq-link pseudo>` (or better, use a real `<button>`/`kbq-button` with an `aria-label`), and keep the `<i>` decorative. Fold the shared copy behavior into the extracted clipboard directive (DOCS-DUP-01).

**DOCS-A11Y-02 · Non-semantic interactive controls and disabled a11y linting** — `app/components/live-example-viewer/docs-live-example-viewer.html:15`, `app/components/icons-viewer/icons-viewer.template.html:21-33`, `eslint.config.js:299-303`.
The source-view toggle is `<span kbq-link pseudo (click)="toggleSourceView()" (keydown.enter)="toggleSourceView()">` — it *is* keyboard-focusable (the `KbqLink` directive host-binds `tabindex=0`, `link.component.ts:47`) and Enter-activatable, but it has **no `role="button"`** (announced as a link, not a toggle), **no `aria-expanded`** (the collapsed/expanded state of the code panel is never conveyed), and **Space does not activate it** (only Enter). Icon-grid cells are `<div … tabindex="0" (click)="setActiveIcon(icon)" (keyup.enter)="setActiveIcon(icon)">` — focusable and Enter-operable, but non-semantic `<div>`s missing native button semantics and Space activation. Compounding this, the Angular template a11y ESLint rules (`click-events-have-key-events`, `interactive-supports-focus`, `label-has-associated-control`, `no-autofocus`, `elements-content`) are all set to `0` (`eslint.config.js:299-303`), and no test uses AXE/`jest-axe` — so nothing catches these automatically.
**Fix:** give the toggle `role="button"` + `[attr.aria-expanded]` + a `keydown.space` handler (or make it a real button); make icon cells `<button type="button">` (or add `role="button"` + Space). Re-enable the template a11y rules for `apps/docs` and add an AXE smoke to the Playwright suite from DOCS-TEST-01. (Note: the anchors list uses real `<a [routerLink]>` elements — not an a11y defect — but does use `[ngClass]`, tracked under DOCS-ARCH-04.)

**DOCS-SEO-01 · No `Meta`/description/OG/canonical, no `TitleStrategy`, and inconsistent + stale tab titles** — `app/index.html:5`, `app/components/icons-viewer/icons-viewer.component.ts:197-199`, `app/components/component-viewer/component-viewer.component.ts:138-149`.
For a public, server-rendered documentation site the SEO surface is thin: `index.html` has a single static `<title>Koobiq</title>` and no meta description; **no component sets `Meta` tags, Open Graph/Twitter cards, or a canonical URL**, and there is **no `TitleStrategy`**. Titles are set ad-hoc in two components: `component-viewer` builds `` `${Name} · Koobiq` `` (`:138-149`) while `icons-viewer.refreshTitle` builds `` `${name} · Icon · Mosaic` `` (`:198`) — the legacy **"Mosaic"** product name (Koobiq's predecessor) instead of "Koobiq", and it is never reset when leaving the icons page (it only gets overwritten if the next route happens to set a title). So prerendered pages are near-indistinguishable to search engines and social embeds despite the excellent `sitemap.xml`/`prerender-routes.txt`/`llms.txt` generation already in place.
**Fix:** add a `TitleStrategy` (or per-route `title` + resolvers) that sets a unique title and meta description per page from the `structure` registry, plus OG/Twitter/canonical tags under SSR; fix the `icons-viewer` title to "Koobiq". This is the highest-leverage, lowest-cost SEO win.

**DOCS-ARCH-01 · The OnPush mandate is violated by 12 of 25 components, including the root** — `app/app.component.ts:12-57` and 11 others.
AGENTS.md requires `ChangeDetectionStrategy.OnPush` on every component. 12 production components omit it: `DocsAppComponent` (`app.component.ts:12`, which also defaults to `Default` CD while driving two `@angular/animations` triggers and has a non-`readonly` `isExamplesPage` field), `DocsAnchorsComponent`, `DocsExampleViewerComponent`, `DocsTypographyTable`, `DocsComponentViewerWrapperComponent`, `DocsLiveExampleComponent`, `DocsTokensTable`, `DocsTokensOverview`, `DocsWelcomeComponent`, `DocsLiveExampleViewerComponent`, `DocsNavbarComponent`, `DocsStackblitzButtonComponent`. (The other 13 correctly set OnPush, so the pattern is understood — this is drift, not ignorance.)
**Fix:** add OnPush to all 12 (and `readonly` to `isExamplesPage`); where a component relies on default CD for imperative updates, migrate that state to signals so OnPush is safe. Consider `@angular/animations` → CSS transitions on the app shell to drop the animations dependency.

**DOCS-ARCH-02 · `structure.ts` is a 1,184-line hand-maintained registry with 19/20 stale `isNew` dates** — `app/structure.ts`.
The single flat file hardcodes all 77 items and categories with inline `name: Record<DocsLocale, string>` i18n literals (88 `ru:` occurrences), and drives `isNew` badges through 20 `expiresAt('YYYY-MM-DD')` calls. As of 2026-07-07, **19 of the 20 dates are already in the past** (earliest `2025-05-04`, only `2025-07-15` still future), so those badges have silently flipped off with no build-time signal — and `isNew` is evaluated once at module load, so a badge that expires mid-session only updates on reload. `expiresAt` also **throws on an invalid ISO date at import time**, which would crash the whole structure module. Lookups (`docsGetItemById`, `docsGetCategoryById`, `:1179/:1183`) are O(n) `Array.find()`. The raw URL segments are cast to the id enums with unchecked `<DocsStructureItemId>id` / `<DocsStructureCategoryId>categoryId` — in the caller `component-viewer.component.ts:77,115`, not here.
**Fix:** add a build/test check that fails when an `expiresAt` date is already past (turn silent expiry into a CI signal); index items/categories by `Map` for O(1) lookups; validate the id casts (return `null` and redirect on a bad segment, which also hardens DOCS-BUG-02); optionally split the registry per category. Externalizing the inline i18n ties into DOCS-I18N-01.

**DOCS-I18N-01 · No central translation dictionary — bilingual strings are scattered as ad-hoc literals and ternaries** — `app/services/locale.ts:74-79` and ~8 components.
`DocsLocaleService`/`DocsLocaleState` expose only the locale *code* (`isRuLocale`, `locale`) — there is no string catalog. UI strings are inlined per component in two shapes: `{ru,en}` object literals (`tokens-overview.ts:126-139`, `typography-overview.ts:61-82`, `design-tokens-viewer.ts:53-77`, `navbar.component.ts:50-75`, `structure.ts`, `sidenav.ts`) and `isRuLocale() ? '…' : '…'` ternaries (`footer.component.html`, `page-not-found.component.ts:13,16`, the error/loading HTML in `example-viewer.ts:130-132` and `docs-live-example.ts:158-160`). Adding a string means touching a component; there is no single place to audit coverage. (The per-locale **prebuilt content HTML** loaded via `documentUrl` is the correct approach and is *not* a finding.)
**Fix:** introduce a small typed dictionary keyed by a token id with `{ru,en}` values, exposed through `DocsLocaleState` (e.g. `t('copy.success')`), and migrate the scattered literals to it. This also removes the duplicated `'Скопировано'/'Copied'` toast strings (DOCS-DUP-01).

**DOCS-DUP-01 · Copy-to-clipboard is implemented three times** — `app/components/copy-button/copy-button.ts:40-51`, `app/components/code-snippet/code-snippet.ts:18-27`, `app/components/icons-viewer/icon-preview-modal/icon-preview-modal.component.ts:83-92`.
All three inject `Clipboard` from `@angular/cdk/clipboard` independently and hand-roll their own success feedback: `copy-button` uses a 1 s `setTimeout` label toggle (DOCS-ARCH-03), while `code-snippet` and `icon-preview-modal` duplicate a byte-identical success toast `{ style: 'success', title: this.isRuLocale() ? 'Скопировано' : 'Copied' }`. Three implementations of one behavior means three places to fix the copy-button a11y bug (DOCS-A11Y-01) and the locale strings (DOCS-I18N-01).
**Fix:** extract a single `DocsCopyToClipboard` directive/service that copies, emits a shared success toast (via the dictionary), and is keyboard-operable by construction; adopt it in all three call sites.

### P3 — Nice to have / hygiene

**DOCS-BUG-06 · Unhandled HTTP error paths in two constructors + no error handling in the document loader** — `app/components/version-picker/version-picker.directive.ts:27-47`, `app/services/document-loader.ts:17-23`.
`DocsVersionPickerDirective` fires `httpClient.get('https://next.koobiq.io/assets/versions.json').subscribe(next)` in its constructor with a single-argument `subscribe` — a failed fetch is entirely unhandled (`:52` then mutates `window.location`). `DocsDocumentLoader.get` has no `catchError` and never evicts a `Map` entry; it is saved from being a hard bug only because rxjs 7's `shareReplay(1)` resets on error (Appendix A), so it self-heals on the next subscribe.
**Fix:** add `catchError` with a user-visible fallback to the version fetch; add `catchError` + `Map`-eviction-on-error to the document loader for defense-in-depth and clarity.

**DOCS-BUG-07 · Brittle DOM coupling in the example and anchor components** — `app/components/live-example/docs-live-example.ts:182, 187, 199, 209`, `app/components/anchors/anchors.component.ts:65, 217-224`.
`docs-live-example` does raw `element.innerHTML = ''` (`:187, :209`) and hardcodes the `'kbq-markdown__pre'` class literal (`:182, :199`) to find and rewrite generated markup. `anchors` uses a non-null-asserted `this.document.querySelector('docs-component-viewer')!` (`:65`) and derives heading level by string-prefix matching a hardcoded `['kbq-markdown__h3','h4','h5']` array against `classList` (`:217-224`). All of this silently breaks if the markdown renderer's class names change.
**Fix:** centralize the markdown class names in a shared constant (shared with `tools/markdown-to-html`), replace `innerHTML=''` with `replaceChildren()`, and guard the `querySelector`.

**DOCS-BUG-08 · `sidenav` seeds the selected node once and desyncs after navigation** — `app/components/sidenav/sidenav.ts:107-112`.
`selectedNodeId = model(this.location.path().replace(\`/${this.locale()}/\`, ''))` is computed once in the field initializer. `DocsSidenav` is rendered once at the app shell (not re-created per route), so after client-side navigations the highlighted tree node can drift from the actual route; the code compensates with a `setTimeout` re-highlight (DOCS-ARCH-03).
**Fix:** derive the selected node reactively from router events (or `toSignal(router.events…)`) instead of a one-time field initializer.

**DOCS-BUG-09 · `DocsLocaleService.setLocale` navigates with a malformed command array** — `app/services/locale.ts:52-57`.
`const path = this.router.url.split('/'); path[1] = locale; this.router.navigate(path)` — for `/ru/icons` this passes `['', 'en', 'icons']`, whose leading `''` relies on the Router coalescing empty segments; and because `router.url` is not stripped first, any query string/fragment rides along inside the last segment.
**Fix:** build the commands from the parsed URL tree (`router.parseUrl`) or drop the empty leading segment and preserve `queryParams`/`fragment` explicitly.

**DOCS-ARCH-03 · `setTimeout`-driven UI timing in four components** — `app/components/sidenav/sidenav.ts:137`, `app/components/copy-button/copy-button.ts:47`, `app/components/design-tokens-viewers/tokens-overview.ts:262`, `app/components/anchors/anchors.component.ts:153`.
`sidenav` (`setTimeout(() => tree().highlightSelectedOption())` in `ngAfterViewInit`), `tokens-overview` (`setTimeout(() => wrapper().scrollToSelectedContentSection())`) and `copy-button` (1 s label reset + manual `markForCheck`, non-signal state) use bare, untracked timers to sidestep change-detection/layout timing. (`anchors.component.ts:153` is the defensible one — its handle is stored, cleared in `ngOnDestroy` and on re-entry.)
**Fix:** replace the untracked timers with `afterNextRender`/`afterRenderEffect` (or signals) so the work is tied to a render pass and the CD update is implicit; make `copy-button.isLabelSuccessVisible` a signal to drop `markForCheck`.

**DOCS-ARCH-04 · Legacy decorator/API cluster contradicting the repo's modern conventions** — example/live-example viewers, `navbar`, `anchors`, `tokens-overview`, `stackblitz-button`.
Persisting against AGENTS.md's `input()`/`output()`/signal-query/no-`any`/no-`ngClass` mandates: `@Input` setters + `@Output() EventEmitter` in `example-viewer.ts:56-67` and `docs-live-example.ts:71-82`; string-selector `@ViewChild('codeSnippet'|'exampleElement')` in `docs-live-example.ts:69` and `docs-live-example-viewer.ts:99`; `componentClass: any`/`ComponentPortal<any>`/`Type<any>` in both viewers (`example-viewer.ts:142`, `docs-live-example.ts:168,171`, `docs-live-example-viewer.ts:70`); `@Input() set exampleId` in `stackblitz-button.ts:24`; `navbar.component.ts` implements `OnDestroy` with manual `matchMedia` add/remove + a Safari `addListener` try/catch fallback (`:103-124`), an implicit-`any` `setAutoTheme = (e) =>` handler (`:137`), and a manual `this.themeService.ngOnDestroy()` on a shared root singleton behind an `eslint-disable no-lifecycle-call` (`:117-118`) — which tears down app-wide theme state when the navbar is destroyed; `anchors` imports and uses `[ngClass]` (`:2,33` / template `:4`); `tokens-overview` uses `*ngTemplateOutlet` self-recursion (`:174,188-190`) instead of native control flow.

**DOCS-ARCH-05 · Dead code** — `app/environments/environment.ts` + `environment.prod.ts`, `app/components/select-example/select-example.component.ts:111-112`, `app/components/live-example/docs-live-example.ts:174`.
The `environment.*.ts` objects are never imported anywhere (only referenced by `angular.json` file replacement) — the `production` flag is never read. `DocsSelectExample.popoverContent` (`:111-112`) is a char-for-char copy-paste of `DocsPopoverExample.popoverContent`, unused in the select template. `docs-live-example.ts:174` carries a Russian `// todo проверить…` comment, violating the English-comments convention.
**Fix:** delete the unused `environment` files (or actually consume the flag), remove the dead `popoverContent` field, translate/remove the Russian comment.

**DOCS-DUP-02 · Duplicated fragment-URL regex, portal-attachment, error HTML and hardcoded issue URL** — `example-viewer.ts` vs `docs-live-example.ts`.
The `href="#…"` → absolute-fragment regex is byte-identical in `example-viewer.ts:104-108` and `docs-live-example.ts:129-133` (with identical comment blocks); the `new DomPortalOutlet(...)` + `ComponentPortal` attach pattern is duplicated across both viewers (and again inside `docs-live-example`'s `initCodeBlocks`/`initCodeSnippets`); the error HTML and the hardcoded `https://github.com/koobiq/angular-components/issues/new` link are duplicated in both `showError` methods.
**Fix:** extract a shared `DocsMarkdownContentRenderer` helper for the fragment rewrite + portal bootstrap + error rendering, and a single `GITHUB_ISSUE_URL` constant.

**DOCS-PERF-02 · `tokens-overview` reads every token via `getPropertyValue` in nested loops on each recompute** — `app/components/design-tokens-viewers/tokens-overview.ts:270-293, 250-259`.
`getComputedStyle(document.body)` is correctly hoisted once (`:270`), but `styles.getPropertyValue(token)` is then called per token across every section and sub-section (`:278, :289`), and `calculateViewData()` re-runs on each theme change (`:250-252`) and once via `afterNextRender` (`:254-258`) — each pass can force style recalculation across the full token set.
**Fix:** batch the reads or memoize per (theme, token); recompute only the sections whose tokens changed. Low priority — one page, off the hot path.

**DOCS-STYLE-01 · Hardcoded color/padding in the anchors theme and an unconditional `var()` with no fallback** — `app/components/anchors/_anchors-theme.scss:33, 24, 28`, `app/components/live-example-viewer/docs-live-example-viewer.scss:9`.
`_anchors-theme.scss:33` hardcodes `#363949` in a `box-shadow` (should be a token) and uses raw px paddings (`:24, :28`) plus `-webkit-/-moz-/-o-` vendor prefixes (`:16-18, :39-42`). Separately, `docs-live-example-viewer.scss:9` reads `var(--docs-live-example-example-background)` with **no fallback**, while that variable is assigned in `styles/_examples.scss:6` only under four modifier classes — so the base example background resolves to nothing outside those modifiers.
**Fix:** replace `#363949` with the appropriate `--kbq-*` token and px with size tokens; give the `var()` a fallback (`var(--…, var(--kbq-background-bg-secondary))`) or assign the variable on the base class.

**DOCS-SEO-02 · Yandex.Metrika is embedded as an inline script in `index.html`** — `app/index.html:16-49`.
The analytics counter (`ym(106476768, 'init', { …webvisor: true })`) is an inline IIFE plus a `<noscript>` pixel. Inline scripts are hostile to a strict CSP and the tracker is unmanaged/unconditional (no consent gating, always loads `webvisor`).
**Fix:** move the counter behind a small provider/service (load conditionally, honor a consent flag), or at minimum extract it so a `script-src 'self'` CSP with a nonce/hash is feasible.

**DOCS-SSR-01 · The server `KBQ_WINDOW` stub omits members real code paths may call** — `app/config.server.ts:6-48`.
The SSR factory returns only `matchMedia`/`localStorage`/`location`/`removeEventListener` cast with `satisfies Partial<Window>`, so TypeScript does not flag the missing members. Any `KBQ_WINDOW` consumer that reads `window.getComputedStyle`, `window.setTimeout` or `window.addEventListener` during server render would hit `undefined` and crash SSR. The app currently prerenders because no reachable server path uses them — a latent hazard, not a live bug.
**Fix:** either broaden the stub to cover the members used behind `KBQ_WINDOW` (no-op `addEventListener`, a passthrough `getComputedStyle`/`setTimeout`) or add an SSR smoke that renders each route to catch a future regression.

**DOCS-SEC-01 · Defense-in-depth: request URL and status text are interpolated into `bypassSecurityTrustHtml` in the error branch** — `app/components/example-viewer/example-viewer.ts:128-134`, `app/components/live-example/docs-live-example.ts:158-162`.
`showError` builds `` `Failed to load document: ${url}. Error: ${error.statusText}. <a …>` `` and passes it through `bypassSecurityTrustHtml` into `[innerHTML]`. This is **not currently exploitable** (verified: `url` is constructed only from allowlisted `structure` ids + locale, never from a raw route string, and `error.statusText` is same-origin server/browser text — Appendix A), so it is filed as hardening only. The happy-path `bypassSecurityTrustHtml(rawDocument)` on build-generated same-origin HTML is an accepted, standard docs pattern. `example-viewer.ts:90-93` also uses the deprecated `subscribe(next, error)` positional overload (the twin `docs-live-example.ts` already uses the observer-object form).
**Fix:** bind `url`/`statusText` as text (interpolation/`textContent`) rather than concatenating into a bypassed HTML string, so a future refactor that makes `url` dynamic cannot reintroduce an XSS sink; switch the deprecated `subscribe` to the observer-object form.

## 4. Recommended Remediation Phases

Each phase lands with its own specs (repo convention). Run gates sequentially, never in parallel (heavy builds are serial per repo memory).

**Phase 1 — Service-layer & correctness bugs.** IDs: DOCS-BUG-01, DOCS-BUG-02, DOCS-BUG-03, DOCS-BUG-04, DOCS-BUG-05, DOCS-BUG-06. Scope the `DocsDocStates` registrations to a `DestroyRef`; `return` after the `/404` redirect; only cache successful StackBlitz builds; add `takeUntilDestroyed`/guards across the icons viewer; instantiate DocSearch once; add `catchError` to the version + document fetches. Each fix ships with a focused unit spec — these double as the seed of Phase 5. Highest user/maintainer impact, no public API surface.

**Phase 2 — Bundle & SEO.** IDs: DOCS-PERF-01, DOCS-SEO-01, DOCS-SEO-02. Convert routes to `loadComponent`; add a `TitleStrategy` + per-page meta/description/OG/canonical driven by `structure`, fixing the "Mosaic" title; move analytics behind a provider. Measured by initial-bundle delta and per-page `<title>`/`<meta>` in the prerendered `dist` HTML, with hydration clean.

**Phase 3 — Accessibility.** IDs: DOCS-A11Y-01, DOCS-A11Y-02. Make the copy action keyboard-operable, give the toggle/icon cells button semantics + `aria-expanded` + Space, re-enable the template a11y ESLint rules for `apps/docs`, and add an AXE smoke. Keyboard-only pass over home, a component page and the icons page.

**Phase 4 — Conventions, consolidation & structure hygiene (splittable).** IDs: DOCS-ARCH-01…05, DOCS-I18N-01, DOCS-DUP-01, DOCS-DUP-02, DOCS-PERF-02, DOCS-STYLE-01, DOCS-BUG-07, DOCS-BUG-08, DOCS-BUG-09, DOCS-SSR-01, DOCS-SEC-01. OnPush across the 12 components; migrate legacy decorators to signal APIs; extract the shared clipboard directive and markdown-content helper; introduce the i18n dictionary; add the `expiresAt`-stale build check and `Map` indexes to `structure`; token-ize the hardcoded styles; harden the SSR window stub and the error-HTML binding. Largest but lowest-risk phase.

**Phase 5 — Test foundation.** ID: DOCS-TEST-01. Jest suites for `doc-states`, `document-loader`, `locale`, `structure` integrity and the StackBlitz writer, plus a Playwright smoke (home → component page → tabs → locale switch → live-example expand → AXE). Placed last because Phases 1–4 already contribute targeted specs; this closes the remaining breadth and wires docs into CI.

## 5. Verification Strategy

General gates after every phase (sequentially — never run heavy builds in parallel):
- `yarn run unit:koobiq-docs` (`ng test koobiq-docs`, Jest — repo policy is no Karma).
- `npx eslint apps/docs` and scoped `npx stylelint "apps/docs/**/*.scss"`; `yarn run prettier` on touched files.
- `yarn run docs:build` (`ng build koobiq-docs`). Note the prerequisite chain: it consumes prebuilt content, so a full `docs` pipeline run (`build:components` → `styles:build-all` → `build:tokens:data` → `build:docs-content` → `build:package-docs-content` → `build:docs-examples-module` → `build:docs-examples`) is needed once per phase, not per commit.
- Dev smoke: `yarn run docs:start:dev`.

Per-phase assertions:
- **Phase 1:** a long navigation session (30+ route changes) shows a flat scroll-listener/subscription count in the DevTools memory profile; a bogus `/components/nope` URL redirects to `/404` with no console error; a forced `loadFile` failure leaves the StackBlitz button retryable; DevTools-offline on a doc page then online + re-navigate recovers without a full reload.
- **Phase 2:** `ng build` initial-bundle stats shrink versus baseline; `docs:generate-prerender-routes` + `docs:generate-sitemap` still succeed; grep prerendered `dist/**/index.html` for unique `<title>` + `<meta name="description">` per page and zero "Mosaic"; hydration console clean.
- **Phase 3:** keyboard-only Tab/Enter/Space operates copy, source-toggle and icon cells; AXE scan of home, a component page and the icons page is clean.
- **Phase 4:** `yarn run docs:build` green; grep confirms a single clipboard implementation, no `Record<DocsLocale` literals outside the dictionary, no `ngClass`, OnPush on all components; the `expiresAt`-stale check fails the build when a date is past.
- **Phase 5:** new Jest suites + Playwright smoke green in CI.

## Appendix A — Review Methodology & Verdicts

Findings were gathered by three parallel research passes (architecture/services; all ~25 components; tests/styles/i18n/SEO/tooling), then every candidate was adversarially verified against source at commit `c183a1bb` by a fan-out of per-cluster verification agents reporting current line numbers, plus a completeness critic that surfaced five additional confirmed findings (DOCS-BUG-02, DOCS-BUG-03, DOCS-BUG-05, DOCS-BUG-08, DOCS-BUG-09) and confirmed the copy-button a11y defect. Severity is calibrated against the sibling reviews in this folder.

**Corrected during verification:**
- **DOCS-BUG-02 (original: "`DocsDocumentLoader` caches failed HTTP loads forever")** — **refuted.** The installed rxjs is 7.8.2, where `shareReplay(1)` (bufferSize-number form) uses `resetOnError: true`; a transient error resets the connector and the next subscriber triggers a fresh HTTP request, so the loader self-heals. The `Map` never evicting is real but harmless; retained only as the defense-in-depth half of DOCS-BUG-06. The genuine "permanent failure caching" bug exists instead in the StackBlitz writer's **promise** cache (DOCS-BUG-03), which does not self-heal.
- **DOCS-SEO-01 (original: "static `<title>Koobiq` for all pages")** — **adjusted.** Component pages *do* get dynamic `… · Koobiq` titles via `component-viewer`; the real gaps are missing meta/OG/`TitleStrategy` and the stale "Mosaic" title on the icons page.
- **DOCS-A11Y-01 (original: "source-view toggle span may not be focusable → P1")** — **adjusted to P2.** The `KbqLink` directive host-binds `tabindex=0`, so the span *is* focusable and Enter-activatable; the residual gaps are `role`/`aria-expanded`/Space. The stronger, separately-filed a11y defect is the mouse-only copy button.
- **DOCS-PERF-02 (original: "`getComputedStyle` called repeatedly in a loop")** — **adjusted.** `getComputedStyle` is hoisted/cached once; the per-token cost is `getPropertyValue` in the nested loops.
- **DOCS-STYLE-01 (original: "`--docs-live-example-example-background` never defined")** — **adjusted.** It *is* assigned in `_examples.scss:6`, but only under four modifier classes; the real issue is the unconditional `var()` with no fallback on the base class.

**Refuted (not filed):**
- **`welcome.component.ts` scroll-subscription leak** — the pipe includes `takeUntilDestroyed()` (`:46-48`); properly torn down.
- **`footer.component.ts` index-based `setValue`** — uses `findIndex` by locale id with an `index >= 0` guard (`:73-79`) and both `changes` subscriptions pipe `distinctUntilKeyChanged` + `takeUntilDestroyed`.
- **`icon-preview-modal` `DOMParser`/canvas "breaks SSR"** — the modal is only instantiated after a user click (`icons-viewer.component.ts:167-175`); the browser-only APIs never run on the server.
- **`popover-example`/`select-example` missing OnPush** — both *do* set OnPush; only the dead `popoverContent` field in `select-example` is a real (P3) issue.

**Assessed and accepted:**
- **Happy-path `bypassSecurityTrustHtml(rawDocument)`** in both viewers renders build-generated, same-origin markdown→HTML — a deliberate, standard docs pattern (mirrors Angular Material's doc viewer). Not a live vulnerability; the error-branch interpolation is filed as defense-in-depth only (DOCS-SEC-01).
