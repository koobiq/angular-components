## 1. Executive Summary

- **Overall health: strong, mature, and well-governed.** This is a production-grade Angular 20 design system (62 stable components plus `core`) with exemplary engineering discipline. Every `AGENTS.md` mandate is fully met across the board: 100% standalone components, 100% `OnPush`, modern control flow everywhere, host-object bindings only, zero `ngClass`/`ngStyle`, and zero `@HostBinding`/`@HostListener` decorators. The finding set is dominated by accessibility gaps and subscription-lifecycle leaks rather than structural or design rot.
- **Test coverage is a genuine strength.** Unit-spec coverage sits at ~98% — only `table` lacks a unit spec (`TEST-18`) — and visual regression (Playwright) specs cover 55 of 62 components. This is well above typical for a library of this size.
- **Top risk #1 — Accessibility is the single largest liability.** With 6 P0 and 14 P1 a11y findings, the foundational interactive widgets are not screen-reader operable: `select` (`A11Y-01`, `A11Y-04`), `modal` (`A11Y-02`, `A11Y-16`), `tabs` (`A11Y-03`, `A11Y-06`), and `tree` (`A11Y-05`, `A11Y-09`) ship without required ARIA roles/semantics. Compounding this, accessibility ESLint template rules are globally disabled (`A11Y-15`) in a project that targets WCAG AA — removing the automated guardrail that would have caught these.
- **Top risk #2 — Unsanitized HTML injection (XSS).** Two components render untrusted input through `bypassSecurityTrustHtml` with no sanitization: `markdown` (`SEC-01`/`SEC-03`) and `app-switcher` icon markup (`SEC-04`/`SEC-05`). Neither path has a security regression test (`TEST-01`, `TEST-02`, `TEST-08`). A CI trigger also allows unauthenticated code execution via the `/approve-snapshots` comment (`SEC-02`).
- **Top risk #3 — Pervasive subscription-leak pattern in commonly-reopened overlays and pipes.** A recurring `.subscribe()`-without-`takeUntilDestroyed()` pattern leaks on every panel/overlay open across `select` (`BUG-02`), `notification-center` (`BUG-10`/`BUG-33`), `toast` (`BUG-08`), `tags` (`BUG-07`), and all four locale-aware number pipes (`BUG-21`/`BUG-22`/`BUG-23` + the duplicate root `BUG-16`). Several are confirmed; a cluster of similar reports are disputed and need triage.
- **Headline metrics.** Findings: P0=11, P1=57, P2=86, P3=63. Modern reactivity is broadly adopted but mid-migration: `input()` 291 vs `@Input` 393, `output()` 107 vs `@Output` 31, `inject()` 349 vs constructor 210; 41 `signal` / 28 `computed` / 23 `model` / 11 `effect`. Outstanding debt: 649 `: any`, 460 TODO/FIXME, 99 `new Subject`, 10 `ngDoCheck` hotspots, 87 `eslint-disable`, 6 `@ts-ignore`, 7 `@deprecated`, 12 remaining `*ngIf`.
- **What's excellent.** Convention adherence is near-perfect; the component file/structure pattern is uniform and predictable; test breadth is high; the `release`/`cli` and `schematics` tooling is comprehensive; and the architecture has almost no structural P0/P1 issues (architecture: 0 P0, 1 P1). The team has clearly invested in governance and it shows.
- **What needs attention.** (1) A focused accessibility remediation pass on the core interactive widgets plus re-enabling the a11y lint rules; (2) sanitizing the two `bypassSecurityTrustHtml` paths and adding XSS tests; (3) a systematic sweep to add `takeUntilDestroyed()` to the leaking subscriptions and complete long-lived subjects; (4) finishing the `input()`/`output()`/`inject()` migration and burning down the `: any` and TODO debt; and (5) hardening the `cli` release tooling, where several guards and config wirings are silently no-ops (`BUG-01`, `BUG-30`, `BUG-31`).

**Notable deep-dives**

- **BUG-01 (P0, Confirmed) — CLI release flow cannot reach a real remote.** `packages/cli/src/cli.ts` defines options for project-dir, dist-dir, changelog-scope, tag-name, repo-owner, repo-name and the two `--without-*` toggles, but no option and no env fallback for `repoUrl` or `repoToken`. Yet `IReleaseTaskConfig` requires both, and every task consumes them — `new GitClient(config.projectDir, config.repoUrl)` and `new Octokit({ token: config.repoToken })`. At runtime both are always `undefined`, so `GitClient.remoteGitUrl` is `undefined` and commands degrade to `git ls-remote undefined ...` / `pushTagToRemote` defaulting its remote to `undefined`, while Octokit makes unauthenticated GitHub API calls. The fix is to add `.option('--repo-url <string>', ..., process.env['REPO_URL'])` and `.option('--repo-token <string>', ..., process.env['REPO_TOKEN'] ?? process.env['GITHUB_TOKEN'])` so the config is actually populated. This compounds with BUG-31 (wrong Octokit key) and BUG-30 (commented-out guards) to make the publishing pipeline non-functional and unsafe as wired.

- **BUG-12 (P1, Confirmed) — `merge()` of an array silently no-ops the error-tooltip auto-hide.** In `inline-edit.ts` `onAttach()` calls `merge(formFieldRefList.map((ref) => ref.control().stateChanges)).pipe(...)`. Passing a single *array* of observables to RxJS `merge` makes it treat the array as one `ObservableInput`, so the inner `stateChanges` streams are never subscribed and the pipeline completes immediately. The consequence is that the logic which hides the validation-error tooltip once the control becomes valid never runs after the initial state. The fix is a one-character change — spread the mapped observables: `merge(...formFieldRefList.map((ref) => ref.control().stateChanges))`.

- **BUG-17 / BUG-64 (P1/P2, Confirmed) — timezone sort and offset parsing are both broken.** `timezonesSortComparator` returns `parseOffset(first.offset)` (the absolute parsed offset of the *first* element) when offsets differ, instead of the difference. This violates the `Array.sort` contract: `cmp(A,B)` and `cmp(B,A)` are both positive, so the comparator is not antisymmetric and zone ordering within each country group is engine-dependent. Separately, `parseOffset` derives the sign from `hours >= 0`, but `parseInt('-00', 10)` is `-0` and `-0 >= 0` is `true`, so a `-00:30` offset is parsed as `+30`. Both should derive intent from the source string: return `parseOffset(first.offset) - parseOffset(second.offset)` for the comparator, and read the sign from `offset.trim().startsWith('-')` rather than from the parsed hours. The existing specs pass only because they check a single comparison's sign and only test whole-hour offsets.

- **Disputed leak findings (BUG-03, 06, 09, 11, 15, 34).** A cluster of "missing `takeUntilDestroyed`" reports were adversarially downgraded. In several cases the captured stream is *component-owned* (a local `SelectionModel`, a component `EventEmitter`, or a `FormControl` that dies with the component), so no instance is retained past destruction; in others the subscription is to a `QueryList.changes` that RxJS-completes on view teardown. These remain convention inconsistencies worth standardizing (and are echoed as P3 hygiene items like BUG-86/BUG-96), but they are not true leaks and should not be treated as release blockers.

## 4.2 Architecture & Conventions

Architecture findings are overwhelmingly **incomplete migration to modern Angular conventions** rather than design defects. The dominant pattern is decorator-based `@Input()` accessor pairs (each carrying a "Skipped for migration" TODO) and `@Output() EventEmitter` fields living alongside already-migrated `input()`/`output()`/`model()` APIs in the *same files* — splitter, search-expandable, filter-bar, code-block, input/textarea, and the tree/list outputs. Two ARCH items (ARCH-24, ARCH-25) are confirmations that empty/dev packages are *intentionally* so and need no action.

**Adoption-gap context.** The codebase is *most of the way* through the modern-Angular migration, and the architecture findings essentially map the remaining frontier:

- **`@Input()` → `input()`/`model()`:** the largest residual gap. Splitter (ARCH-15), search-expandable (ARCH-16), code-block (ARCH-13), input/textarea (ARCH-09), and filter-bar (ARCH-17) all retain accessor-pair inputs with explicit "Skipped for migration" TODOs. The high-value subset is the writable two-way inputs (`softWrap`, `viewAll`, `activeFileIndex`, `hideTabs`, splitter sizing) where components write back to their own `@Input` fields — exactly the anti-pattern `model()` signals resolve, and which currently force manual `emit()` calls to keep OnPush in sync.
- **`@Output EventEmitter` → `output()`:** tree/list `selectionChange`/`onCopy` (ARCH-10) and filter-bar `onChangePipe` (ARCH-17) are plain outputs sitting next to already-migrated `output()` siblings in the same class — pure consistency wins.
- **`Subject`/`BehaviorSubject` → signal:** number pipes mirror `localeService.id` through a `changes` subscription (ARCH-05) that is the *root cause* of the leak cluster in 4.1 (BUG-16/21/22/23) — dropping it removes both the duplicated state and the leak. search-expandable's `value` BehaviorSubject and filter-bar's internal subjects are further signal candidates.
- **`constructor` → `inject()`:** `DateFormatter`/`KbqLocaleService`/number pipes (ARCH-18), `KbqFormElement` (ARCH-20), and the date-formatter examples (ARCH-26) still use constructor/`@Inject` parameter injection against the AGENTS.md mandate.
- **Token/theme & type consistency:** the Luxon options token carries the *moment* description string (ARCH-21), `localeChanges`/`setLocale`/`tabIndex`/`kbqBuildTree` leak `any` onto public surfaces (ARCH-22/23/12/30), and `.eslintrc.js` globally disables `no-explicit-any` (ARCH-08), removing the only guardrail across ~649 `any` occurrences. There is also a dead path-graph entry to a non-existent `vertical-navbar` package (ARCH-28).
- **Remaining legacy structural directives:** of the ~12 remaining legacy `*ng*` usages repo-wide, the architecture pass specifically flags `*ngTemplateOutlet` in breadcrumbs (ARCH-11) and dynamic-translation (ARCH-29), both mixed with the bracket form `[ngTemplateOutlet]` already used elsewhere in the same templates.

**Notable deep-dives**

- **ARCH-01 (P1, Confirmed) — modal's deprecated dynamic-component path.** `modal.component.ts` injects `private cfr: ComponentFactoryResolver` and `createDynamicComponent()` calls `this.cfr.resolveComponentFactory(component)` then `factory.create(childInjector)`. Both `ComponentFactoryResolver` and `resolveComponentFactory` are deprecated in Angular and slated for removal; with Ivy the supported path is `ViewContainerRef.createComponent(component, { injector })`. This is the only deprecated-API usage flagged for the unit and will break on a future major. Because the modal already holds a `ViewContainerRef` (the body container), the fix is mechanical: `viewContainerRef.createComponent(component, { injector: childInjector })` and remove the `ComponentFactoryResolver` injection.

- **ARCH-02 (P2, Confirmed) — tooltip reaches into a private CDK field.** `show()` gates focus-triggered tooltips with `if (this.triggerName === 'focus' && this.focusMonitor['_lastFocusOrigin'] !== 'keyboard') return;`. The bracket access reads CDK `FocusMonitor`'s undocumented private `_lastFocusOrigin`, which has been renamed/removed across `@angular/cdk` versions — so a CDK upgrade silently changes behavior (focus tooltips always suppressed, or shown on mouse focus) with **no compile error to catch it**. The component already calls `focusMonitor.monitor(...)` in `ngAfterViewInit`; the fix is to capture the emitted origin from that public observable into a field and read *that* instead of the private member.

- **ARCH-03 (P2, Confirmed) — dual `@Input @Output` on one field.** `@Input() @Output() readonly kbqOnOk: EventEmitter<T> | OnClickCallback<T> = new EventEmitter<T>();` (and `kbqOnCancel`) makes one field simultaneously an input (a callback assigned via service `Object.assign`) and an output (subscribable `EventEmitter`). When driven through the service, `changeProps()`'s `Object.assign` overwrites the `EventEmitter` with a plain function, silently breaking any template output binding to `kbqOnOk`. This conflates an imperative callback with an event stream on one ambiguous public type; the fix is to split into a distinct `@Output() EventEmitter` and a separate `@Input()` callback.

## 4.3 Accessibility (WCAG 2.1 AA)

**Notable deep-dives**

- **A11Y-01 / A11Y-04 (P0, Confirmed) — select is unusable with a screen reader.** The trigger host (`select.component.ts:182-194`) declares no ARIA: no `role="combobox"`, `aria-haspopup="listbox"`, `aria-expanded`, or `aria-controls`. The panel (`select.html`) has no `role="listbox"`, and the shared `KbqOption` host only sets CSS classes plus an `id` — no `role="option"`, `aria-selected`, or `aria-disabled`. Critically, the component uses `ActiveDescendantKeyManager`, which **keeps DOM focus on the trigger** and never moves it into the list, so `aria-activedescendant` is the *only* mechanism by which AT can learn which option is highlighted — and it is absent. The result is a focusable element with no announced role, no open/closed state, and no announcement of options, their count, or the current selection. Because `KbqOption` is shared, the same blocker propagates to `tree-select` and `autocomplete`. The fix is to add `role="combobox"` + `aria-haspopup` + `[attr.aria-expanded]` + `[attr.aria-controls]` on the trigger, `role="listbox"` (+ `aria-multiselectable` for multiple) on the panel, and `role="option"` + `[attr.aria-selected]` on `KbqOption`.

- **A11Y-15 (P1, Confirmed) — the a11y guardrails are switched off.** AGENTS.md states the library MUST pass AXE and meet WCAG AA, yet `.eslintrc.js` `templateRules` sets `click-events-have-key-events`, `interactive-supports-focus`, `label-has-associated-control`, `elements-content`, `no-autofocus`, and `button-has-type` all to `0` for every `*.html`. These are precisely the static rules that catch the click-without-keydown, non-focusable-interactive, and missing-label failures cataloged above, and there is no axe step in CI to compensate. This single config decision explains *how* the P0/P1 ARIA gaps accumulated unnoticed — re-enabling these rules (at least as warnings) and/or adding an automated axe check is the highest-leverage remediation because it prevents regression of every other finding in this section.

- **A11Y-19 (P1, Confirmed) — form-field errors and hints are silent.** `KbqFormField` collects `KbqHint`/`KbqError`/`KbqPasswordHint` as `ContentChildren` and renders them, but never builds an `aria-describedby` on the control, never sets `aria-invalid` when `control().errorState` is true, and `KbqError` has no id, no `role="alert"`, and no `aria-live` region (`KbqHint` even has an unused `id()`). The `<label for>` association is correct, so labels work — but validation feedback is entirely invisible to AT, failing WCAG 3.3.1 (Error Identification) in addition to 1.3.1/4.1.3. The fix is to compose `[attr.aria-describedby]` from the visible hint/error ids, bind `[attr.aria-invalid]` to the invalid state, and give `KbqError` an id with `role="alert"` (or wrap the region in an `aria-live` container) so errors are announced as they appear.

### Confirmed exploit paths

**SEC-01 / SEC-03 — Markdown XSS (P0, Confirmed).** Verified directly: `markdown.component.ts:99-100` is exactly

```ts
private getResultHTML(markdown: string): SafeHtml {
    return this.sanitizer.bypassSecurityTrustHtml(this.markdownService.parseToHtml(markdown, this.markedOptions));
}
```

The result binds to `[innerHtml]`. `KbqMarkdownService.parseToHtml` returns `marked.parse(markdown)` and its own JSDoc states it does not sanitize. `marked` (v17) passes raw inline/block HTML, `<script>`, `<img onerror=...>`, and `javascript:` hrefs through verbatim by design. Because Angular's sanitizer is deliberately bypassed, a `markdownText` of `<img src=x onerror=alert(document.cookie)>` executes in the app origin. `markdownText` is a public input that consumers will routinely feed user-generated content (comments, chat, descriptions) — this is a concrete stored/reflected XSS. There is no DOMPurify or allow-list anywhere in the package. **Fix:** run the `marked` output through `this.sanitizer.sanitize(SecurityContext.HTML, html)` (or DOMPurify) and only bypass the already-cleaned string; re-apply the class-aliasing transform after sanitization. If raw HTML must be supported, gate it behind an explicit, documented trusted-input opt-in.

**SEC-04 / SEC-05 — App-switcher icon XSS (P0/P1, Confirmed).** `getIcon()` is `return this.sanitizer.bypassSecurityTrustHtml(icon || '')`, bound via `[innerHtml]="getIcon(app.icon)"`; the identical sink exists in `app-switcher-dropdown-app.ts:63`. `app.icon` is a public input documented as "Inline SVG markup for the application icon." In the common multi-tenant app-switcher case the apps array is backend-populated, so an `icon` of `<svg><script>...</script></svg>` or `<img src=x onerror=...>` runs. Notably, the same repo's `KbqIconRegistry.addSvgIconLiteralInNamespace` (`icon-registry.ts:71`) calls `sanitizer.sanitize(SecurityContext.HTML, literal)` *before* bypassing — app-switcher omits that step entirely. A safe `iconSrc` alternative already exists, so the trusted-HTML path is avoidable. **Fix:** mirror the icon-registry pattern (`sanitize(SecurityContext.HTML, icon)` then bypass) or render through `KbqIcon`/the registry; apply to both list-item and dropdown-app.

**SEC-02 — Unauthenticated CI code execution (P0, Confirmed).** Verified in `e2e-approve-snapshots.yml`: the workflow triggers on `issue_comment: [created]` and gates only on `github.event.issue.pull_request && contains(github.event.comment.body, '/approve-snapshots')` (line 13) — there is no `author_association`/membership/collaborator check. It then resolves the PR head via `xt0rted/pull-request-comment-branch`, checks out `head_ref` (the fork's source branch for fork PRs, line 21), and runs `yarn run e2e:setup` and `yarn run e2e:components --update-snapshots` on that untrusted code, all under top-level `permissions: contents: write` plus a final `git-auto-commit-action` that pushes. Any user able to comment on any PR — including a malicious fork PR — executes arbitrary code (install scripts, modified test/build scripts) with a write-scoped `GITHUB_TOKEN`. **Fix:** gate on `comment.author_association` ∈ {OWNER, MEMBER, COLLABORATOR} (or an explicit allow-list / API permission check) before checkout, and separate trusted-token usage from the untrusted-code checkout.

### P1 supply-chain and navigation

**SEC-07 — False provenance (P1, Confirmed).** `publish.yml:13` declares `id-token: write # needed for provenance data generation`, but the publish path `npmPublish()` in `npm-client.ts` builds `['publish', '--access', 'public', '--tag', distTag]` with no `--provenance`, and no `.npmrc`/`publishConfig.provenance` exists. OIDC permission is granted but no attestation is ever produced, giving a false impression of supply-chain integrity. **Fix:** add `--provenance` to the publish command (or `provenance=true` in CI `.npmrc`/`publishConfig`) and ensure each package.json has the `repository` field provenance requires.

**SEC-06 — Reverse tabnabbing (P1, Confirmed).** `code-block.ts:588` sanitizes `file.link` via `SecurityContext.URL` (good, blocks `javascript:`) but then calls `this.window.open(safeURL.toString(), '_blank')` with no `noopener`. The opened external page (consumer-supplied "open external system" link) holds a live `window.opener` and can navigate the Koobiq tab to a phishing URL. **Fix:** `window.open(url, '_blank', 'noopener,noreferrer')` or null the opener post-open.

### Hardening notes (no active exploit — Disputed status)

These are explicitly classified as defense-in-depth, not live vulnerabilities:

- **SEC-08 (icon-registry fetch path):** `svgElementFromText` does `div.innerHTML = text` on raw HTTP responses for the URL and icon-set paths, while only the literal path sanitizes. Exploitable only with a compromised CDN / icon-endpoint open-redirect / `http` MITM. The spec's "XSS prevention" block exercises only `addSvgIconLiteral`, masking the gap. Recommend sanitizing fetched text for parity plus a URL-path spec.
- **SEC-13 (code-block line-numbers):** `highlight()` correctly sanitizes before the `innerHTML` writes in the vendored plugin; safety depends entirely on that ordering surviving future refactors. Recommend a comment/test pinning the order and a final sanitize for defense-in-depth.
- **SEC-09 (`shell:true` in `npmPublish`):** command array is fully static (no interpolation), so injection is not demonstrable; dropping `shell:true` removes needless surface.
- **SEC-10 / SEC-11 (CI least-privilege):** `e2e.yml` over-requests `contents: write` for a comment-only job; `pr-docs-preview.yml` shares the Firebase secret with the build step (same-repo gated). Both are least-privilege/secret-isolation improvements.
- **SEC-12 (moment):** `~2.29.2` resolves to the patched 2.29.4 — no active CVE; flagged purely as EOL/maintenance hygiene, with luxon as the supported path.

## 4.6 Bundle / SSR / Performance

This dimension is comparatively light: one **P2** performance finding was confirmed (well, Likely), and the broader bundle/SSR/zoneless audit areas produced no recorded findings in this batch. That absence is itself informative — see the implications below. The single recorded issue is a per-change-detection allocation + library re-subscription in the scrollbar wrapper, driven by a method call in a template binding.

| ID | Sev | Conf | Component | Location | Finding |
|----|-----|------|-----------|----------|---------|
| PERF-01 | P2 | Likely | scrollbar | `packages/components/scrollbar/scrollbar.component.ts:54` | Scrollbar re-registers all event listeners on every change-detection cycle |

### Deep-dive

**PERF-01 — Scrollbar re-binds listeners every CD (P2, Likely).** Verified: the template binds `[events]="mergeEvents()"`, and `mergeEvents()` (`scrollbar.component.ts:130-149`) constructs and returns a brand-new object literal on every invocation (`defaultListeners` is built fresh, then spread). Because it is a method call in the template, it runs every change-detection pass and yields a new reference each time. `KbqScrollbarDirective`'s `set events` reacts to the reference change by calling `this.scrollbarInstance.on(value, true)`, re-binding the overlayscrollbars listeners on every CD of any ancestor. For a scrollbar wrapped around a large scrollable region this is a steady per-CD allocation + library re-subscription cost. **Fix:** compute the merged events once — a `computed()` derived from the `events()` signal, or memoize on the `events` input — so the bound reference is stable until inputs actually change. Marked Likely (not Confirmed) because the practical cost depends on how often the host actually runs change detection.

### Audit areas with no recorded findings (and what that implies)

- **`sideEffects: false` audit / bundle treeshaking:** no finding recorded. This implies either the package metadata is correctly marked or the audit did not surface a concrete regression; it should not be read as a clean bill — a follow-up confirming `sideEffects` in each `package.json`/`ng-package.json` is warranted before relying on treeshaking guarantees.
- **`ngDoCheck` hotspots:** the brief references ~10 `ngDoCheck` hotspots, but only PERF-01 was filed as a discrete finding. The implication is that the remaining `ngDoCheck` uses were judged acceptable or unverified; they remain a watch-list for the same class of per-CD cost demonstrated by PERF-01.
- **Zoneless readiness (≈99 `Subject`s vs signals):** no finding filed. The heavy reliance on RxJS `Subject`s over signals is a migration-readiness concern rather than a correctness bug, so it surfaces as a strategic note: zoneless adoption will require auditing those subscriptions for manual change-detection assumptions.
- **SSR guards (`isPlatformBrowser` for `document`/`window`/`localStorage`) and overlay hydration risk:** no finding filed in this batch. Given that SEC-06 confirms `this.window.open` is reachable in `code-block` (i.e. `window` is accessed), the absence of a recorded SSR-guard finding should be treated as "not yet audited to closure" rather than "verified safe" — overlay/document access under SSR remains an open verification item.

### Structural semver hazards

**API-03 — Exact-pinned adapter peers (P1, Confirmed).** `packages/components/package.json:28` declares the `@koobiq/angular-moment-adapter` / `@koobiq/angular-luxon-adapter` peers as `{{VERSION}}`. The packager (`tools/builders/packager/build.ts:147`) substitutes `newPackageJson.version` verbatim, producing an exact pin like `"20.0.0"` with no caret — whereas `syncNgVersion` (line 166) correctly emits `^20.0.0` for the Angular peers. The consequence is concrete: a consumer bumping `@koobiq/components` to `20.0.1` is forced to exactly `@koobiq/angular-*-adapter@20.0.0`, producing peer-dependency conflicts on every patch release. **Fix:** emit a caret range (`^${newPackageJson.version}`) for the `{{VERSION}}` adapter peers, matching the existing `{{NG_VERSION}}` convention. This is the most consumer-visible semver defect in the set.

**API-01 — Test utilities in production surface (P1, Confirmed).** Verified at `core/public-api.ts:21`: `export * from './testing/index'` re-exports the entire `core/testing` folder (`dispatch-events.ts`, `event-objects.ts`, `type-in-element.ts`, `mock-ng-zone.ts`, `element-focus.ts`) into `@koobiq/components/core`, and these are baked into `core.api.md` (e.g. `createKeyboardEvent`, `createMouseEvent`, `dispatchEvent`). These framework-agnostic test helpers bloat the runtime bundle, pollute autocomplete, and — once published — become semver-guarded API that cannot be removed without a major bump. Angular CDK isolates the equivalents under `@angular/cdk/testing` for exactly this reason. **Fix:** drop the re-export and expose the helpers via a dedicated secondary entry point (`@koobiq/components/core/testing`) with its own `ng-package.json`/`public-api`, making them opt-in and excluded from the runtime surface.

**API-02 — 30+ `ae-forgotten-export` warnings baked into guards (P1, Confirmed).** Rather than being resolved, 30+ `Warning: (ae-forgotten-export) The symbol "X" needs to be exported` are committed into the `api.md` snapshots. Several land on genuinely public surface: `toggle.api.md:60-63` (`labelPosition: InputSignal<ToggleLabelPositionType>` — the type of a public input is unexported), `form-field.api.md:305-307` (`KbqStepper.connectTo(numberInput: KbqNumberInput)` and `get control(): KbqNumberInput` — a consumer cannot type the argument to a public method), plus `modal`'s `CssUnitPipe`, `sidebar`'s `KbqSidebarParams`, `notification-center`'s `KbqNotificationsGroup`, `time-range`'s `FormValue`/`RangeErrorStateMatcher`, and more. Consumers can hold these instances but cannot import or annotate them, breaking typed wrapper code. **Fix:** triage each warning — export the genuinely public types from the relevant `public-api.ts`; mark the rest `@docs-private`/`@internal` and refactor so they don't appear on public signatures. Don't ship `api.md` with unresolved extractor warnings.

### Type-hygiene debt (`: any` on public API — violates AGENTS.md)

AGENTS.md forbids `any` on public API types (prefer `unknown`), yet it recurs across the guarded surface:

- **API-07 (Confirmed):** verified at `autocomplete-trigger.directive.ts:342/348` — `registerOnChange(fn: (value: any) => {})` and `registerOnTouched(fn: () => {})`. `=> {}` is "function returning the empty-object type," not `=> void`; this is a typing mistake that leaks into `autocomplete.api.md:190-192` and is inconsistent with every other CVA in the library (checkbox/button-toggle use `=> void`). **Fix:** `(value: any) => void` and `() => void`.
- **API-04 (Confirmed):** `KbqLocaleService` exposes `readonly locales: any = {}`, implicit-`any` `current`, and an `any`-returning `getParams`; consumers (number/filesize pipes) index `locales[locale].formatters.number` with zero type-checking. A `KbqLocaleData`/`KbqLocale` interface (the repo already has `types.ts` locale configs) should type these. This same untyped-locale pattern is what API-11 surfaces on app-switcher/filter-bar (`configuration: any`, `get localeData(): any`).
- **API-05 (Confirmed):** `setActiveItem(item: any)`/`updateActiveItem(item: any)` implementation signatures on the public `ListKeyManager` (echoed in `FocusKeyManager`/`ActiveDescendantKeyManager`) defeat inference; the correct `number | T` union already exists in the overloads.
- **API-06 (Confirmed):** exported `offset(value)` has an implicit-`any` param surfacing as `offset(value: any): string` in `timezone.api.md:139`, and the body does `value.split(':')`/`charAt(0)` unguarded — non-string or missing-`:` input throws. **Fix:** annotate `value: string` (callers already pass `string`) or mark `@docs-private`.
- **API-09 / API-10 (Confirmed):** number-formatter `transform(value: any, ...)` and `KbqHighlightPipe.transform(value: any, args: any): any` are fully untyped despite knowable shapes; `strToNumber` already accepts `unknown`, so the public `any` is gratuitous.

### Naming / deprecation lifecycle

**API-08 (Confirmed):** `highlight.pipe.ts:23` declares `@Pipe({ name: 'mcHighlight' })` — surfaced in `core.api.md:2526`. A scan of all 63 `api.md` files shows this is the *only* public template token still using the pre-rebrand `mc` prefix; every other token is `kbq`. **Fix:** rename to `kbqHighlight`, keep `mcHighlight` as a `@deprecated` alias plus an ng-update migration for one major cycle, then remove. On deprecation lifecycle more broadly: the brief notes ~7 `@deprecated` symbols, but only this naming inconsistency was filed as a finding — the implication is that the remaining deprecations have a defined removal path and were not flagged as semver hazards in this batch, whereas `mcHighlight` lacks any deprecation alias at all and is the gap to close.

**Secondary entry-point hygiene:** the only structural entry-point issue filed is API-01 (test utilities leaking into `core` instead of living behind a `core/testing` subpath). No other secondary-entry-point violations were recorded, which implies the package's subpath layout is otherwise consistent — establishing the `core/testing` subpath is the single remaining hygiene fix in this area.

## 5. Notes by Package / Group

### Overlay / floating (select, tree-select, tooltip, autocomplete, popover)
This is the weakest cluster for accessibility: the select listbox overlay ships with no ARIA roles, `aria-activedescendant`, or `aria-expanded`/`aria-haspopup` (A11Y-01, Confirmed, P0), and the tooltip overlay has neither `role="tooltip"` nor a trigger `aria-describedby` association (A11Y-07, Confirmed; A11Y-21 popover dialog role, Likely). The dominant correctness theme is per-open subscription leakage: `select.onAttached` re-subscribes to `options.changes` on every panel open without teardown (BUG-02, Confirmed), autocomplete's `keyManager.change` subscription has no teardown (BUG-37, Likely), and popover-confirm re-subscribes `onConfirm` on every `updateData`, causing duplicate emissions (BUG-36, Confirmed). Two architecture smells: the tooltip reaches into `FocusMonitor`'s private `_lastFocusOrigin` (ARCH-02, Confirmed), and no overlay honors `prefers-reduced-motion` (A11Y-36, Likely). Lower-priority select logic bugs include numeric-subtraction value sorting that breaks non-numeric order (BUG-88, Likely) and `option.selected`-driven selection-model drift in multiple mode (BUG-89, Likely). The tree-select leak claim (BUG-03) is **Disputed**.

### Forms (field / input / date-time)
The form-field family is structurally accessible-incomplete and leak-prone. The calendar date grid is not keyboard-operable — no `role`, focus, or keydown handling (A11Y-08, Confirmed, P0-adjacent) — and the cleaner clickable wrapper lacks button/keyboard semantics (A11Y-22, Likely). A real data bug: `time-range-editor.mapTimeRange` copies `toTime` into `toDate`, emitting a wrong range (BUG-05, Confirmed). Subscription leaks recur across the group: `KbqFormField.stateChanges` (BUG-41), `KbqPasswordToggle.stateChanges` (BUG-40), `KbqTextarea`'s constructor subscription to `parent.animationDone` (BUG-42), and the datepicker-input `incorrectInput` tooltip (BUG-38) and `control.valueChanges` (BUG-39) — all Confirmed. The datepicker `setFormat` masks a possible null regex match with `@ts-ignore` (BUG-43, Confirmed), and timepicker increment/decrement is off-by-one at unit boundaries (BUG-44, Likely). `KbqInput`/`KbqTextarea` retain legacy `@Input` accessors where modern coercion inputs fit (ARCH-09, Confirmed). The datepicker null-deref on programmatic open (BUG-04) is **Disputed**.

### Selection & data (tree, list, tags, button-toggle)
Selection components have the broadest ARIA gaps after select: tree/list expose no `role="tree"`/`treeitem`/`listbox`/`option` and no `aria-selected`/`expanded`/`level` (A11Y-09, Confirmed), and button-toggle groups expose no `radiogroup`/`radio` or `aria-pressed`/`aria-checked` (A11Y-10, Confirmed). Confirmed correctness bugs: `tag-list.registerInput` never unsubscribes `ngControl.statusChanges` (BUG-07); tag-input's paste guard `data && data.length === 0` is dead code (BUG-46); and `list-selection.selectActiveOptions` throws on shift+arrow with no prior active item (BUG-45, Likely). Tag-input's blur `(... || true)` makes the autocomplete blur-veto a no-op (BUG-47, Likely). Lower-priority: `tagsSubscriptions$` is `next()`'d but never completed (BUG-90, Confirmed), tree still uses `@Output EventEmitter` where siblings migrated to `output()` (ARCH-10, Confirmed), and a roleless `aria-label` span is ignored by AT (A11Y-37, Likely). The tree `unorderedOptions.changes` leak (BUG-06) is **Disputed**.

### Modal / layered surfaces (modal, sidepanel, toast, notification-center)
The modal is the headline P0 here: no `role="dialog"`, `aria-modal`, or `aria-labelledby` on the dialog (A11Y-02, Confirmed; A11Y-16 restates the title-association gap, Confirmed). Architecturally the modal is dated — it creates dynamic content via deprecated `ComponentFactoryResolver` (ARCH-01, Confirmed) and declares `kbqOnOk`/`kbqOnCancel` as both `@Input` and `@Output` on one `EventEmitter` (ARCH-03, Confirmed). Overlay-reopen leaks dominate correctness: toast-container leaks `service.animation` on every dispose (BUG-08, Confirmed) and notification-center leaks `visibleChange`/`service.changes` per open (BUG-10, BUG-33, Confirmed). Other Likely items: modal animation `setTimeout`s aren't cancelled on destroy (BUG-50), multi-mask logic mutates the wrong instance's mask (BUG-51), sidepanel can leak its overlay on mid-open close (BUG-48), and notification-center computes `isTrapFocus` but never applies a focus trap (A11Y-24). Notification-center derives unique ids from millisecond timestamps, colliding for batched items (BUG-49, Confirmed). No reduced-motion handling spans these animations (A11Y-25, Likely), and `modal-control.service` uses `@ts-ignore` to hide null-typed singleton fields (TEST-09, Confirmed). The toast hovered/focus leak (BUG-09) is **Disputed**.

### Navigation (tabs, app-switcher, breadcrumbs, navbar, link)
`kbq-tab-group` exposes no tab semantics at all — no `role="tablist"`/`tab`, `aria-selected`, or `aria-controls`, and generated IDs are never cross-referenced (A11Y-03 / A11Y-06, Confirmed, P0). App-switcher renders untrusted `app.icon` markup via `bypassSecurityTrustHtml` (SEC-05, Confirmed; see also SEC-04). Confirmed/Likely correctness: the vertical tab-group resize handler never subscribes because `vertical()` is read in the constructor (BUG-53), `app-switcher.updatePosition` recreates the overlay via an untracked `setTimeout` (BUG-55), and `preventClosingByInnerScrollSubscription.unsubscribe()` can throw on first hide (BUG-52). Breadcrumbs sets `aria-label` but no `role="navigation"` landmark (A11Y-26, Likely) and its roving-focus relies on registration order that can diverge from DOM order (A11Y-27, Likely); the breadcrumbs template still uses legacy `*ngTemplateOutlet` (ARCH-11) and `focusFirst` gets an `HTMLElement` where `Document|ShadowRoot` is expected (BUG-92). `KbqFocusableComponent.tabIndex` is typed `: any` on a public input (ARCH-12, Confirmed). The app-switcher `visibleChange`/`searchControl` leak (BUG-11) is **Disputed**.

### Content & text (markdown, code-block, title, ellipsis-center, dl)
This group carries the most severe security finding: the markdown component renders unsanitized HTML via `bypassSecurityTrustHtml`, a stored/reflected XSS sink (SEC-01, Confirmed, P0; restated as SEC-03/SEC-06's `window.open(_blank)` reverse-tabnabbing in code-block, Confirmed). Critically, the entire `docs-examples` package ships with zero spec or visual tests (TEST-16, Confirmed). On the build side, `components-experimental` is a confirmed intentional empty barrel (ARCH-24) and `components-dev` apps are confirmed not published (ARCH-25), so neither leaks into the npm build.

### config / CI / build
The P0 here is a supply-chain exposure: `e2e-approve-snapshots.yml` allows unauthenticated code execution via a `/approve-snapshots` comment trigger (SEC-02, Confirmed). The publish workflow grants `id-token` for provenance but `npm publish` never sets `--provenance`, so the privilege buys nothing (SEC-07, Confirmed). Accessibility ESLint template rules are globally disabled in a self-declared WCAG-AA project (A11Y-15, Confirmed) — and `no-explicit-any` is disabled alongside them (ARCH-08, Confirmed). Lower-priority build hygiene: a stale `tsconfig.json` path mapping points to the non-existent `vertical-navbar` package (ARCH-28, Confirmed — verified: no such directory exists), and `tsconfig.eslint.json` pulls `dist`/build output globs into the lint type-check project (TEST-17, Likely). Two CI permission concerns are filed as hardening/**Disputed**: `e2e.yml` requesting `contents:write` while running untrusted PR code (SEC-10) and `pr-docs-preview.yml` deploying fork-PR build output with a Firebase service account (SEC-11).

### security & dependencies
Three of this group's findings are P0 and overlap the content cluster: unsanitized markdown HTML rendering (SEC-03, Confirmed) and the app-switcher raw-icon-HTML XSS (SEC-04, Confirmed). The markdown XSS branch and the class-alias transform have no security/regression coverage (TEST-02, Confirmed), and the markdown whitespace regex is broken because `\s*` is a literal `s*` inside a template literal (BUG-32, Confirmed). The app-switcher icon XSS path likewise has no sanitization test (TEST-08, Likely), and a `valueChanges` subscription in its `ngAfterViewInit` lacks teardown (BUG-85, Likely). ### tests & code-health (global)
The recurring global signal is subscription-leak hygiene across commonly-reopened overlays — notification-center on its root service (BUG-33, Confirmed) being the clearest — plus the datepicker `setFormat` null-deref masked by `@ts-ignore` and a broken character class (BUG-35, Confirmed). Two further leak claims are **Disputed**: the app-switcher `scrollDispatcher.scrolled()` subscription (BUG-34) and BUG-15 elsewhere. On test coverage: the `table` component has no unit spec (TEST-18, Confirmed), seven components lack Playwright visual specs (TEST-19, Confirmed), and an unmanaged `setTimeout` in ellipsis-center's `refresh()` can run on a destroyed view (BUG-87, Likely). `dynamic-translation` still uses legacy `*ngTemplateOutlet` (ARCH-29, Confirmed), and an `aria-label` on a roleless element is silently ignored by AT (A11Y-39, Likely). `modal-control.service`'s `@ts-ignore` hiding null-typed root state recurs here (TEST-20, Likely).

### public API & semver
The public API leaks test-only utilities into production: `createKeyboardEvent`, `dispatchEvent`, `MockNgZone`, and `typeInElement` are exported from the core public API (API-01, Confirmed). 30+ public symbols are referenced but not exported (`ae-forgotten-export`), so consumers cannot name public types (API-02, Confirmed) — a real DX/semver hazard. Adapter `peerDependencies` are pinned to an exact version (no caret) via `{{VERSION}}` substitution (API-03, Confirmed), which will cause needless peer-resolution friction. Several public surfaces are untyped: the timezone `offset()` export has an implicit-`any` param and unvalidated string parsing (API-06, Confirmed), autocomplete CVA `registerOnChange`/`registerOnTouched` are typed `=> {}` instead of `=> void` (API-07, Confirmed), `KbqHighlightPipe.transform` is fully untyped (API-10, Confirmed), `kbqBuildTree()` takes `value: any` (ARCH-30, Confirmed), and app-switcher exposes public `configuration: any`/`localeData: any` (API-11, Likely). `KbqHighlightPipe` also still uses the legacy `mcHighlight` template name — the last remaining `mc`-prefixed public token (API-08, Confirmed).

## 6. Cross-cutting & Tooling

**CI/CD (13 GitHub Actions workflows).** The repository runs 13 workflows (`api`, `commitlint`, `docs-next`, `docs-stable`, `e2e`, `e2e-approve-snapshots`, `license`, `linters`, `pr-docs-preview`, `pr-notify`, `publish`, `scorecard`, `units`). The most serious problem is a trust-boundary failure in the snapshot pipeline: `e2e-approve-snapshots.yml` is triggered by a `/approve-snapshots` issue comment with no authorization gate, allowing unauthenticated code execution (SEC-02, Confirmed, P0). Two further workflows run untrusted fork-PR code with elevated scope or secrets — `e2e.yml` requests `contents:write` (SEC-10) and `pr-docs-preview.yml` deploys fork-PR build output using a Firebase service account (SEC-11) — both filed as hardening/Disputed but worth tightening to `pull_request_target` discipline with explicit ref pinning. The presence of `scorecard.yml` shows supply-chain posture is on the team's radar, which makes the unauthenticated-trigger gap (SEC-02) especially out of place.

**Release / publish pipeline & provenance.** The publish path is broken on two axes. First, the CLI that drives staging and publishing is itself non-functional: `repoUrl`/`repoToken` are never wired to any option, so all git-remote and GitHub API calls run with `undefined` (BUG-01, P0), Octokit is constructed with the wrong option key (BUG-31), pre-release labelling silently no-ops (BUG-29), and the pre-flight clean-tree/upstream guards are commented out (BUG-30) — see the release-CLI subsection above for the full set. Second, the workflow layer undercuts its own security guarantees: `publish.yml` grants `id-token` write for npm provenance, but `npm publish` is never invoked with `--provenance`, so no provenance attestation is actually produced (SEC-07, Confirmed). Partial-publish runs are non-idempotent with no rollback or resume (BUG-82), so a mid-publish failure leaves the registry in an inconsistent state. Together these mean the documented release process cannot be trusted to run end-to-end without manual intervention.

**Build / tsconfig graph.** The root `tsconfig.json` is the single source of path mappings for ~60 component entry points plus the adapters and CLI, with `strict` null checks and Angular `strictTemplates`/`strictInjectionParameters`/`strictInputAccessModifiers` enabled — a solid strictness baseline. The graph has drifted, though: it still maps `@koobiq/components/vertical-navbar` to a package directory that no longer exists (ARCH-28, Confirmed — verified absent on disk), and `tsconfig.eslint.json` pulls `dist`/build-output globs into the lint type-check project, which both slows linting and risks type-checking stale emitted code (TEST-17, Likely). These are low-severity but indicate the build graph is not being pruned as packages are removed.

**Lint / format config.** This is the most consequential tooling finding for a WCAG-AA library. `.eslintrc.js` extends `@angular-eslint/template/all` and then explicitly disables the accessibility template rules that would have caught most of this review's P0/P1 ARIA gaps — `elements-content`, `click-events-have-key-events`, `interactive-supports-focus`, and `label-has-associated-control` are all set to `0` (A11Y-15, Confirmed). In other words, the linter is configured to be silent on exactly the class of defect (missing roles, non-keyboard-operable interactive elements, unlabeled controls) that dominates Section 5's selection, overlay, and navigation findings. Compounding the type-safety story, `@typescript-eslint/no-explicit-any` is globally disabled (ARCH-08, Confirmed), which is why so many `any`-typed public surfaces (API-04, API-05, API-06, API-09, API-10, API-11, ARCH-12, ARCH-30) survive review. The config also turns off the modern-Angular nudges `@angular-eslint/prefer-signals`, `prefer-inject`, and `prefer-output-emitter-ref`, directly enabling the legacy-`@Input`/`@Output`/constructor-injection debt catalogued across ARCH-09 through ARCH-26. Re-enabling the a11y rules (even at warn) and `no-explicit-any` on the public API would convert a large share of this report's findings into CI-enforced regressions.

**Schematics / migrations.** The migration suite is the team's contract for moving consumers across major versions, and it currently does not honor that contract. The flagship `v20-upgrade` migration registered for `ng update` never applies its fixes because the fix defaults aren't honored (BUG-27, P1), so consumers running the upgrade get a no-op. Several rules that do run are too broad — whole-file comma/brace normalization (BUG-75), unscoped divider `inset` removal that reaches into `.ts` files (BUG-76), and a global `mc-`→`kbq-` replacement that over-matches non-icon tokens (BUG-80) — meaning the migrations risk corrupting unrelated source. Utility-level bugs (`sortObjectByKeys` dropping keys on falsy values, BUG-78; `migrateTemplate` reading and writing different tree paths, BUG-79; the `deprecated-icons` warn/fix asymmetry, BUG-77; the `new-icons-pack` schema/code default mismatch, ARCH-06) reduce confidence further, and the inline-template path of the size-attr migrations is untested (TEST-06). The migrations should be treated as not-yet-trustworthy until BUG-27 is fixed and the over-matching rules are scoped and covered by fixture tests.
