# Koobiq `form-field` Component — Code Review & Improvement Plan

> Scope: `packages/components/form-field` + the shared `core` abstractions it composes (`core/form-field/form-field-ref`, `core/common-behaviors/color`) · Commit `96fee28c` · 2026-07-01
> Generated by an automated multi-agent review (8 review dimensions + adversarial verification of every finding + a completeness critic). 63 findings confirmed (3×P0, 5×P1, 22×P2, 33×P3); 9 additional critic-surfaced candidates; 2 refuted. Treat as a high-signal starting point; spot-check before acting. The Russian mirror is [`docs/REVIEW/REVIEW.form-field.RU.md`](./REVIEW.form-field.RU.md).
> Findings tagged **(shared)** live in `core` and affect other components; **(cross-package)** findings require changes in the control packages (`input` / `select` / `textarea`) that implement `KbqFormFieldControl`. This document is a review + roadmap; no source is modified by it.

---

## 1. Executive Summary

- **Accessibility is the single biggest risk and the only release blocker.** `KbqFormField` is the container every text control composes, yet it never establishes the programmatic relationships a screen reader needs: it collects hints/errors (each with a generated `id`) but **never writes `aria-describedby`** onto the control; `kbq-error` has **no `role`/`aria-live`** and is mounted/unmounted under `@if (invalid)`, so validation text is announced neither on focus nor on appearance; the cleaner and the password-toggle are **icon-only, non-semantic controls with no role and no accessible name**; and `KbqInput` never sets `aria-invalid`. This directly violates AGENTS.md's "MUST pass AXE / WCAG AA" mandate. **3×P0 + 1×P1** cluster here.
- **Independently confirmed.** A repo-wide search returns **zero `aria-describedby`** wiring in the form-field/input chain, and `KbqInput`'s host sets only `id`/`placeholder`/`disabled`/`required` — no `aria-invalid` (only `KbqTextarea` has it, inconsistently). The companion monorepo review (`docs/REVIEW/REVIEW.md`) independently flags the same gaps (`A11Y-19`, `A11Y-22`, `BUG-40`, `BUG-41`).
- **One real validator-corruption bug.** `KbqFormField` imperatively calls `control.setErrors({ passwordStrength: true })` from a `stateChanges` handler (`form-field.ts:351`). `setErrors` **replaces** the entire errors object, so a password field with `required`/`pattern`/async validators loses those errors the moment strength fails — messages vanish and form state becomes inconsistent.
- **Four unbounded subscription leaks, all the same shape.** `stateChanges` (and a `checkRule` Subject) are subscribed with no `takeUntilDestroyed` in `KbqPasswordHint` (×2), `KbqPasswordToggle`, and `KbqFormField` itself — the last is the *only* subscription in `form-field.ts` that omits the guard its siblings all use. Each retains a destroyed component and keeps firing CD on a dead view. All fix with one line.
- **The package is functionally solid but mid-migration and type-loose.** It correctly uses standalone + OnPush + host-object bindings throughout (no `@HostBinding`/`ngClass`/`ngStyle`), but mixes signal queries with legacy `@ContentChild`/`@Input` decorators, reaches into control subtypes via `as any` duck-typing (the `#DS-3893`/`#DS-2915` circular-dependency workarounds), types the shared `KBQ_FORM_FIELD_REF.control` and the public `rule`/`trim` surface as `any`, and ships a `_fiedset-theme.scss` filename typo plus foreign `styleUrls` that bundle input/timepicker/datepicker/textarea/tags CSS into every form-field consumer.
- **Two legacy engines carry the debt.** `KbqPasswordHint` (a `setTimeout`-wired rules engine, module-tagged "Legacy" but undeprecated and untested) and `KbqTrim` (a `registerOnChange` monkey-patch that silently trims values) concentrate most of the correctness, lifecycle, and test findings. `KbqReactivePasswordHint` is the intended replacement and is the reference pattern (`afterNextRender` + `takeUntilDestroyed`).
- **What's strong.** Convention adherence (standalone/OnPush/host bindings), the `KbqReactivePasswordHint` lifecycle pattern, `KbqStepper`'s `output()`/`inject()`/`takeUntilDestroyed` usage, and clean BEM token naming give solid refactor seams. Most findings are hygiene (33×P3); the actionable core is small and well-bounded.
- **Test coverage has real holes.** Whole public units are untested — the legacy `KbqPasswordHint` rules engine, the `KbqFieldset` trio, and `KbqTrim` — prefix/suffix/hint are snapshot-only, and there is **zero ARIA/AXE/keyboard coverage** in a package whose top risk is accessibility.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers (accessibility)

**FF-A11Y-02 · Hints and errors are never linked to the control via `aria-describedby`** **(cross-package)** — `form-field.ts:519` (`initializeHint`); `hint.ts:15` (`'[attr.id]': 'id()'`).
`KbqHint`/`KbqError`/`KbqPasswordHint` expose a generated host `id`, and the form-field collects them, but nothing ever writes `aria-describedby` onto the control's native element. A repo-wide search for `aria-describedby` in form-field/input returns nothing; `KbqInput`'s host sets only `id`/`placeholder`/`disabled`/`required`. So the generated ids are dead weight and the hint/error text is visually adjacent but not programmatically associated — SR users focusing the field never hear it. WCAG 1.3.1 / 3.3.2.
**Fix:** compute the describing-id set in `KbqFormField` (hints + reactive/password hints + errors when present) and apply it to the control via a `setDescribedByIds` contract added to `KbqFormFieldControl` and implemented on the `KbqInput`/`KbqSelect`/`KbqTextarea` host — mirror Angular Material's form-field. Couples with FF-A11Y-03.

**FF-A11Y-03 · `kbq-error` has no `role`/`aria-live`, and `@if (invalid)` prevents reliable announcement** *(merges the "no live region" and "@if teardown" findings)* — `error.ts:14` (host); `form-field.html:38` (`@if (invalid)`).
`KbqError` sets only `class: 'kbq-error'` and reuses `hint.html`; there is no `role="alert"` / `aria-live` anywhere in the package. Worse, the error is mounted/unmounted under `@if (invalid)`, so a live region added on the projected node would be inserted *with content already present* — which screen readers frequently do not announce. Combined with FF-A11Y-02, the error is invisible both on appearance and on focus. WCAG 4.1.3.
**Fix:** render a **persistent** live-region wrapper in the hint area (`aria-live="polite" aria-atomic="true"`, always in the DOM) and toggle only its inner content on `invalid`, rather than adding/removing the whole projected `kbq-error` node. Wire the control's `aria-describedby` to the error id as well (with FF-A11Y-02) so it is discoverable on focus.

**FF-A11Y-01 · Cleaner is a non-semantic `<div>` click target: no role, no accessible name, no Space** *(merges FF-STYLE-08)* — `form-field.html:22`.
The cleaner wrapper is `<div class="kbq-form-field__cleaner" (click)="clearValue($event)" (keydown.enter)="clearValue($event)">`; the projected `KbqCleaner` (extends `KbqIconButton`) renders a bare focusable `<i>` with **no `role` and no accessible name**, and the wrapper handles only Enter, not Space. So the clear control is announced as an unlabeled focusable graphic and, unlike a native button, does not activate on Space. WCAG 4.1.2 / 2.1.1. (Note: Enter already works via bubbling — the gaps are role, name, and Space, not total keyboard inoperability.)
**Fix:** put `role="button"` + a localized `aria-label` (see FF-I18N-01) on the focusable element (the `tabindex=0` cleaner), and add `(keydown.space)` with `preventDefault`. Preferably render the cleaner as a native `<button type="button">` so role/name/keyboard come for free.

> FF-A11Y-01/02/03 are one logical unit — the control → describedby → error-live-region chain must land together to be coherent and pass AXE.

### P1 — High

**FF-LOGIC-03 · `setErrors({ passwordStrength: true })` clobbers all other validators on the control** — `form-field.ts:351`.
In `ngAfterContentInit` the `stateChanges` handler does `this.control().ngControl?.control?.setErrors({ passwordStrength: true })` whenever a password hint has an error and the control is unfocused. `AbstractControl.setErrors` **replaces** the entire errors object. Any `required`/`pattern`/async error is wiped and replaced by only `{ passwordStrength: true }`; messages bound to `hasError('required')` vanish, and the other validators are not re-run until the value changes.
**Fix:** merge — `const c = this.control().ngControl?.control; c?.setErrors({ ...(c.errors ?? {}), passwordStrength: true });` — and remove only that key when strength passes. Better: expose a real validator function rather than mutating errors from the container.

**FF-RXJS-04 · `KbqFormField`'s password-strength `stateChanges` subscription lacks `takeUntilDestroyed`** — `form-field.ts:347`.
`this.control().stateChanges.pipe(startWith(), delay(0)).subscribe(...)` is the **only** subscription in the file missing the guard — `initializeControl` (`:506`), `initializePrefixAndSuffix` (`:515`), `initializeHint` (`:522`) and `runFocusMonitor` (`:465`) all use `takeUntilDestroyed(this.destroyRef)`. After destroy it keeps mutating a possibly still-live `FormControl`'s errors (see FF-LOGIC-03) and retains the dead component.
**Fix:** add `takeUntilDestroyed(this.destroyRef)` to the pipe (`destroyRef` is already injected at `:132`).

**FF-RXJS-01 · `KbqPasswordHint` subscribes to `stateChanges` and a `checkRule` Subject with no teardown** — `password-hint.ts:149`.
Inside a `setTimeout`, `control.stateChanges.subscribe(this.checkValue)` and `(...).checkRule.subscribe(...)` are created with no `takeUntilDestroyed`, no stored subscription, and no `ngOnDestroy`. Both target control-owned streams that outlive the hint, so every created-then-destroyed hint stays subscribed and keeps firing `markForCheck` against a dead view.
**Fix:** capture `destroyRef` as a field and pipe both through `takeUntilDestroyed(this.destroyRef)`.

**FF-RXJS-03 · `KbqPasswordToggle` subscribes to `stateChanges` with no teardown** — `password-toggle.ts:137`.
`this.formField?.control()?.stateChanges.subscribe(this.updateState)` has no guard; the existing `ngOnDestroy` (`:152`) only calls `focusMonitor.stopMonitoring(...)`. The `updateState` closure (which calls `markForCheck`) stays subscribed to the long-lived stream after destroy.
**Fix:** `takeUntilDestroyed(this.destroyRef)`, or store the `Subscription` and unsubscribe in the existing `ngOnDestroy`.

**FF-A11Y-04 · Password toggle is an icon-only `<i>` with no role, no accessible name, no toggle state** — `password-toggle.ts:43`.
The toggle renders `<i [kbq-icon-button]="iconClass">` inside `<ng-content>`; the focusable `<i>` has no `role`, no accessible name, and no `aria-pressed`/`aria-expanded` reflecting shown/hidden. The hover tooltip is not an accessible name. SR users hear an unlabeled focusable graphic and never learn the shown/hidden state. WCAG 4.1.2.
**Fix:** on the focusable element (prefer restructuring to a native `<button type="button">` that owns the keyboard handlers), add `role="button"`, a localized `aria-label` derived from `hidden` (see FF-I18N-01), and `[attr.aria-pressed]="!hidden"`.

### P2 — Should fix

**Accessibility**
- **FF-A11Y-05 · `aria-invalid` missing on the control** **(cross-package)** — invalid state is class-only (`ng-invalid`, `kbq-form-field_invalid`). `KbqInput` (`input.ts:34-44`) and `KbqSelect` set no `aria-invalid`; only `KbqTextarea` does (`textarea.component.ts:43`). **Fix:** add `[attr.aria-invalid]="errorState"` to `KbqInput`/`KbqSelect` hosts; add `aria-required` for non-native controls.
- **FF-A11Y-06 · Fieldset labels via `legend.innerText`, not `aria-labelledby`; native `<legend>` misused** *(merges the "invalid legend" critic)* — `fieldset.ts:55,68`. `ariaLabel = computed(() => this.legend()?.nativeElement?.innerText)` is empty before layout, not reactive to i18n, and duplicates visible text; a native `<legend>` outside a `<fieldset>` (`e2e.ts:66`) has no a11y semantics. **Fix:** give `[kbqLegend]` a generated id and set `[attr.aria-labelledby]` on the host; drop the innerText-derived label.
- **FF-I18N-01 · Icon-only controls have no localizable accessible names; package never uses `KbqLocaleService`** *(critic)* — `password-toggle.ts:45`, cleaner, stepper. Every a11y-name fix (FF-A11Y-01/04/07) will hardcode English/Russian unless sourced from the koobiq localization service other components use. Treat as the localization dependency of the Phase-1 a11y work.
- **FF-A11Y-10 · `KbqTrim` silently trims values, corrupting whitespace-significant input** *(critic)* — `form-field.ts:559`. Applied to all `[kbqInput]`/`[kbqTextarea]` by default; a trailing space in a password/code is stripped without indication, and the model diverges from the visible value until re-render. **Fix:** make trimming opt-in (or exclude password inputs) and keep the visible value in sync.

**Correctness**
- **FF-LOGIC-01/02 · `PasswordRules.Length` guard is dead → NaN length checks always fail** — `password-hint.ts:129,175`. `min`/`max` are `input<number>(undefined!)`, so `(this.min() || this.max()) === null` is never true and the "need min/max" guard never throws; `checkLengthRule` then compares `value.length >= undefined` (`NaN`, always false), so a valid-length password is reported failing and can push a `passwordStrength` error onto the whole control. **Fix:** guard with `== null` on both bounds; coalesce in the check (`min ?? 0`, `max ?? Infinity`).

**Public API & Types**
- **FF-API-01 / FF-ARCH-03 · `KBQ_FORM_FIELD_REF.control` typed `any`** **(shared)** — `core/form-field/form-field-ref.ts:10`. The shared ref (the `#DS-2915` TODO) defeats type-checking at every injection site (`KbqPasswordHint`/`KbqReactivePasswordHint`/`KbqStepper`/`KbqPasswordToggle`/`core/select/common.ts`) and enables the `as any` casts elsewhere. **Fix:** type as `Signal<KbqFormFieldControl<unknown>>`; keep narrow casts only for subtype members. `approve-api` after.
- **FF-API-02/03 · `regExpPasswordValidator` numeric-enum-keyed + `rule: input<PasswordRules | any>`** — `password-hint.ts:29,70`. `| any` collapses the public `rule` input to `any` (snapshot `InputSignal<any>`); the exported validator's inferred type is `{1;2;3;4:RegExp}` keyed by enum *values*, brittle to reordering and missing `Length`/`Custom`. **Fix:** `input<PasswordRules>()` and `Partial<Record<PasswordRules, RegExp>>`. `approve-api`.
- **FF-API-04 · `KbqNumberInput` `ae-forgotten-export`** — `stepper.ts:11`. `connectTo(numberInput: KbqNumberInput)` and `get control(): KbqNumberInput` surface an unexported type (`form-field.api.md:306` warning). **Fix:** export a real `KbqNumberInputControl` interface (resolves `#DS-3893`) or mark the members `@docs-private`.
- **FF-API-05 · Missing `exportAs` on `KbqSuffix`/`KbqFieldsetItem` (and `KbqLegend`)** — `suffix.ts:4`, `fieldset.ts:22,13`. Siblings `KbqPrefix`/`KbqLabel` have it. **Fix:** add `exportAs` for template-ref parity. Non-breaking; `approve-api`.
- **FF-API-06 · `KbqTrim.trim(value: any): any` on the public surface** — `form-field.ts:551`. Violates the no-`any` rule; the body only meaningfully handles `string`. **Fix:** `trim(value: unknown): unknown`, or `@docs-private`.

**Performance**
- **FF-PERF-01 · Unconditional `detectChanges()` in `ngAfterViewInit`** — `form-field.ts:373`. `runFocusMonitor` mutates no bound value synchronously, so the comment is stale and every form field forces a full extra CD pass at init (costly on form-heavy pages). **Fix:** `markForCheck()` or remove it.

**Lifecycle**
- **FF-RXJS-02 · `KbqPasswordHint` `setTimeout` id never cleared** — `password-hint.ts:148`. No stored id, no `ngOnDestroy`; on rapid create/destroy the deferred callback runs on a torn-down component (`control()` can throw / establishes the FF-RXJS-01 leak on an orphan). **Fix:** replace with `afterNextRender`/`timer(0).pipe(takeUntilDestroyed())` (mirror `KbqReactivePasswordHint`).

**Templates, Styles & Build**
- **FF-STYLE-02 / FF-BUILD-01 · Foreign `styleUrls` bloat and couple the entry point** — `form-field.ts:90`. `styleUrls` pulls in `../input`, `../timepicker`, `../datepicker`, `../textarea`, `../tags` SCSS, so every form-field consumer ships CSS for components they never use and any refactor of those files silently changes form-field output (and breaks its build). **Fix:** move each control's styling into that control's theme entry; if a directive genuinely can't own styles, document and gate it behind the control theme.
- **FF-STYLE-05 · Nested-self descendant selector sets height only for nested fields** — `form-field.scss:74`. `.kbq-form-field .kbq-form-field:not(.kbq-form-field-type-textarea)` only matches a form-field nested in another, so a standalone field never gets `--kbq-form-field-size-height` from this rule; the intent was `&`. **Fix:** change to `&:not(.kbq-form-field-type-textarea)` (verify layout) or delete the dead rule; add an English comment.

**Tests**
- **FF-TEST-02 · Legacy `KbqPasswordHint` rules engine entirely untested** — `password-hint.ts:64`. The tested hint is the *reactive* one; the legacy Length/regex/Custom dispatch, all three throw paths, the `checkValue` state machine, and the exported `hasPasswordStrengthError`/`regExpPasswordValidator` are uncovered. **Fix:** add `password-hint.spec.ts` driving each `PasswordRules` value.
- **FF-TEST-03 · `KbqFieldset`/`KbqLegend`/`KbqFieldsetItem` untested; e2e is screenshot-only** — `fieldset.ts:58`. `role="group"` and the innerText-derived `aria-label` can regress silently. **Fix:** `fieldset.spec.ts` asserting role and aria-label vs legend text, and the host classes.
- **FF-TEST-04 · `KbqTrim` (trim / no-trim / non-string) untested** — `form-field.ts:535`. A regression in the `registerOnChange` interception would silently corrupt values. **Fix:** spec padded value → trimmed; `no-trim` preserves; non-string passthrough.
- **FF-TEST-06 · Prefix/suffix/hint tests are snapshot-only** — `form-field.spec.ts:317`. Snapshots pin serialized structure but assert no contract (host class, `id()` forwarding, `fillTextOff`/`compact` toggles). **Fix:** replace with explicit host-class/attribute assertions.
- **FF-TEST-07 · Zero ARIA/AXE/keyboard assertions in the whole suite** — `form-field.spec.ts:296`. No `aria-describedby`/`aria-invalid`/`role`/AXE checks; the password toggle is only `.click()`ed, never keyed. **Fix:** add ARIA assertions (post Phase 1), key the toggle via Enter/Space, run jest-axe on representative templates, add interactive/reduced-motion e2e.

## 4. Recommended Remediation Phases

**Phase 1 — Accessibility blockers (must land together).**
IDs: FF-A11Y-01..06 + FF-A11Y-10 + FF-I18N-01 + FF-TEST-07 (regression guards). The control → `aria-describedby` → error-live-region chain (01/02/03) ships as one coherent change; 04/05/06 parallelize. **Cross-package:** add a `setDescribedByIds` contract to `KbqFormFieldControl` and `aria-invalid` to `KbqInput`/`KbqSelect`; source accessible names from `KbqLocaleService`. Write the AXE/ARIA specs first (fail → pass). Unblocks the release.

**Phase 2 — Lifecycle & correctness.**
IDs: FF-RXJS-01/03/04 + FF-RXJS-02 (mechanical `takeUntilDestroyed`/`afterNextRender` — copy the `KbqReactivePasswordHint` pattern), FF-LOGIC-03 (error merge — do early), FF-LOGIC-01/02 (Length rule) + FF-TEST-02/04 as regression guards. Low-risk.

**Phase 3 — Performance & styles.**
IDs: FF-PERF-01/03, FF-STYLE-01/03/04/05/10, and the foreign-`styleUrls` extraction (FF-STYLE-02 / FF-BUILD-01). Run `yarn run styles:build-all` and diff.

**Phase 4 — Modern-Angular migration, API & types (SemVer-gated).**
IDs: FF-ARCH-01/02/05..09, FF-ARCH-07 (`mixinColor`), FF-API-01..10, FF-LOGIC-04..10, FF-PERF-02/04, FF-STYLE-06/07/09, FF-SSR-01/02/03, FF-TEST-03/06/08/09. Batch the API-changing items (query migration, `any` removal, dead-export, generics, `exportAs`, deprecations) and run `approve-api` once; schedule the breaking pieces (signal-query types, member-visibility tightening) for a major. FF-A11Y-05 aria-invalid depends on the same control hosts touched in Phase 1.

## 5. Verification Strategy

**General gates (per phase):**
- `npx jest packages/components/form-field` (unit) — and `packages/components/input` / `select` / `textarea` for cross-package a11y work.
- `yarn run eslint && yarn run stylelint && yarn run prettier`.
- `yarn run build:components` **then** `yarn run check-api` (and `yarn run approve-api` only when the public API intentionally changes — Phase 4; the guard reads `dist/*.d.ts`, so build first).

## Appendix A — Review Methodology

This review was produced by 8 parallel review agents (architecture, RxJS/lifecycle, correctness, accessibility, performance, public API/types, tests, templates/styles), each reading the source directly. Every raw finding was then adversarially verified by an independent agent against the actual code (line numbers re-checked, stream ownership re-evaluated, severities re-rated); several were down-rated on verification (e.g. the `contentChild` migration to P3 once its breaking-API cost surfaced, the stepper output-subscription "leak" to hygiene). A completeness critic then surfaced 9 additional candidates (SSR consistency, i18n of accessible names, the `@if (invalid)` live-region interaction, `KbqTrim` value mutation, invalid `<legend>` usage) which were **not** independently re-verified and are tagged *(critic)*. Of 65 raw findings, 63 were confirmed and 2 refuted. The two highest-impact findings (no `aria-describedby` in the package; no `aria-invalid` on `KbqInput`) were additionally hand-verified. The companion monorepo review (`docs/REVIEW/REVIEW.md`) independently flags the same items (`A11Y-19` aria-describedby/invalid/live, `A11Y-22` cleaner semantics, `BUG-40`/`BUG-41` the toggle/form-field leaks).
