# Koobiq `toast` Component — Code Review & Improvement Plan

> Scope: `packages/components/toast` + shared `core/read-state`, `icon/icon-button` touchpoints · Commit `af6e64fe` · 2026-07-05
> Generated by 6-agent review (architecture/API, RxJS & lifecycle, correctness, accessibility, performance/templates & styles, tests) + adversarial verification against installed `@angular/cdk` and `@angular/animations` sources. 55 findings confirmed (P0×2, P1×10, P2×22, P3×21); 9 refuted. Treat locations as verified at this commit; re-check line numbers after rebases.
> Prior monorepo findings disposition: **BUG-08** (container `service.animation` leak) — **re-confirmed, broader impact than recorded** → `TOAST-LEAK-01`; **BUG-09** (hovered/focused leaks, disputed) — **refuted as a leak**, but the same lines hide a real P1 behavior bug → `TOAST-BUG-02`; **A11Y-25** (no reduced motion) — **confirmed for toast at P3** → `TOAST-A11Y-07`.

## 1. Executive Summary

- **Toasts are invisible to assistive technology — two release-blocking WCAG AA failures.** The package contains zero ARIA: no `role="alert"/"status"`, no `aria-live`, no `LiveAnnouncer` anywhere in the repo (`TOAST-A11Y-01`), so screen-reader users never learn a toast appeared before it auto-dismisses. The default close button is an unnamed `<i kbq-icon-button>` with `tabindex=0` but no role, no accessible name, and no Enter/Space activation (`TOAST-A11Y-02`).
- **The documented auto-dismiss semantics break in common multi-toast scenarios.** When any toast expires, every survivor's remaining lifetime is *truncated* to 2 s regardless of its requested duration (`TOAST-BUG-01`); showing a new toast (or destroying a sibling) silently cancels the hover/focus pause because per-toast `BehaviorSubject`s replay `false` into the shared service flags (`TOAST-BUG-02`); and template toasts run on a divergent raw `setTimeout` — they cannot be sticky, never pause on hover/focus (WCAG 2.2.1), and the handle is never cancelled (`TOAST-BUG-03`).
- **Two unbounded-growth defects in a root singleton.** Each "last toast closed → next toast shown" cycle destroys and recreates the container, whose constructor subscription to `service.animation` is never torn down — subscriptions and detached DOM accumulate for the app's lifetime (`TOAST-LEAK-01`, = monorepo BUG-08). The 500 ms heartbeat uses `shareReplay()` with an infinite buffer and `refCount: false`: the interval ticks forever, survives `ngOnDestroy` (micro-frontend re-bootstrap leaks a service instance per teardown), and the public `timer` field replays every buffered tick to late subscribers (`TOAST-LEAK-02`).
- **The public API ships `any` and internal plumbing.** `ttl`, `delay`, `$implicit`, `isTemplateRef(value)`, `createToast(componentType)` are all `any` in the published `.d.ts` (`TOAST-API-01`); raw next-able subjects, the mutable `timer`, and the container's entire toolkit are guard-locked public surface (`TOAST-API-02`); the service generic is unsound with a root-resolved factory token (`TOAST-ARCH-01`).
- **What's strong:** modern baseline (standalone, OnPush, `host` object, `inject()`, native control flow, `viewChild.required`), disciplined zone hygiene (interval outside Angular, re-entry only to hide), economical overlay reuse, clean BEM/token architecture, and three well-shaped regression tests. The skeleton is right; the reactive plumbing and the a11y layer are not.
- **Key next actions:** Phase 1 (a11y blockers) is mandatory before any release gate; Phase 2 (leaks) and Phase 3 (auto-dismiss correctness) are independent of each other.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

**TOAST-A11Y-01 · Toasts are never announced to screen readers** — `toast.component.ts:46-56`, `toast-container.component.ts:27-29`, `toast.service.ts:83-97`
The entire package contains no `role`, no `aria-live`, no `aria-atomic`; nothing in the repo imports CDK `LiveAnnouncer`. A blind user triggers an action, an error toast appears and auto-dismisses after 5 s with zero output from NVDA/JAWS/VoiceOver — WCAG 4.1.3 Status Messages (AA) hard failure. The documented Tab sequence in `toast.en.md` is unreachable because the user never learns the toast exists.
**Fix:** Inject `LiveAnnouncer` (CDK a11y is already a dependency) in `KbqToastService.show()`/`showTemplate()` and announce title + caption (`assertive` for error/warning, `polite` otherwise). `role="alert"` on the host is the only role-based alternative guaranteed to announce content inserted in one shot; a lazily created container cannot host a reliable pre-existing live region — which is exactly why `LiveAnnouncer` is the robust option. Repo precedent for role wiring: `notification-center.html:102-113`.

**TOAST-A11Y-02 · Default close button is an unnamed non-button `<i>` that Enter/Space cannot activate** — `toast.component.html:100`, contributing `icon/icon-button.component.ts:24-32`
`<i kbq-icon-button="kbq-xmark-s_16" kbq-toast-close-button (click)="close()">`: `KbqIconButton` adds only `tabindex` (verified — no `role`, no keydown handling, no label). On an `<i>` element Enter/Space do not synthesize clicks. A keyboard user focuses the visible "×", presses Enter — nothing happens (WCAG 2.1.1); a screen-reader user lands on a nameless generic element (WCAG 4.1.2, 1.1.1). The host `(keydown.esc)` is an undiscoverable partial mitigation.
**Fix:** Render a native `<button type="button" kbq-icon-button="kbq-xmark-s_16" kbq-toast-close-button [attr.aria-label]="…" (click)="close()">` — the attribute selector works on `<button>`, and Enter/Space then work natively. Localize the label via the existing `KBQ_LOCALE_SERVICE` pattern.

### P1 — High

**TOAST-BUG-01 · `updateTTLAfterDelete` truncates every survivor's remaining lifetime to `delay`** — `toast.service.ts:167-171`
The reset `item.instance.ttl = this.toastConfig.delay` is unconditional: it correctly *extends* short remainders (the documented 2 s cascade) but also *truncates* long ones. `show(A, 5000)` at t=0 + `show(B, 30000)` → B, explicitly requested to live 30 s, dies at ~7 s because A expired. Violates the documented "at least 5 seconds on screen" invariant and discards per-toast durations.
**Fix:** `item.instance.ttl = Math.max(item.instance.ttl, this.toastConfig.delay);`

**TOAST-BUG-02 · Hover/focus pause is last-writer-wins: showing a new toast (or destroying a sibling) cancels it** — `toast.component.ts:103-104, 130-131`; gate at `toast.service.ts:52`
`this.hovered.subscribe(this.service.hovered)` wires a per-component `BehaviorSubject(false)` directly into the shared service flag — subscription *replays `false` immediately*, so every new toast's constructor resets the global pause while the user is hovering/reading another toast, and `ngOnDestroy`'s `next(false)` does the same on any programmatic/Esc dismissal of a sibling. The paused stack resumes counting down under the user's cursor with no `mouseenter` to restore it. Resolves monorepo **BUG-09**: not a memory leak (the subscription is component-owned and collectable) — but these lines hide this real behavior bug, plus a latent fragility: a future `complete()`/`error()` on the component subject would silently kill the shared service subject for every future toast.
**Fix:** Delete the forwarding subscriptions; have `processToasts` consult the existing (currently unused) per-toast `isFocusedOrHovered` getter (`toast.component.ts:87-89`), or aggregate with a hover counter/set in the service.

**TOAST-BUG-03 · Template toasts run on a raw, in-zone, untracked `setTimeout`: sticky impossible, no pause, never cancelled** — `toast.service.ts:173-175` (from `showTemplate`, `:110`)
Three divergences from component toasts: (1) `duration: 0` means sticky for components (`filter(ttl > 0)`, `:152`) but "hide on next macrotask" for templates — there is no way to create a sticky template toast, and the regression specs pass only because they assert synchronously inside the one-macrotask window (`toast.spec.ts:257, 272`); (2) hover/focus never pauses template toasts — an interactive template toast vanishes while the user hovers it (WCAG 2.2.1 Timing Adjustable); (3) the timeout is scheduled in the Angular zone (blocking zone stability for its full duration, unlike the deliberately outside-zone component path) and the handle is never stored, so manual `hideTemplate`/service destroy cannot cancel it.
**Fix:** Route template TTLs through the same outside-zone tick pipeline (store `{ viewRef, ttl }`, let `processToasts` handle both) — fixes stickiness, pause, zone, and cancellation in one move. Minimum: skip scheduling when `duration === 0` and store/clear the handle.

**TOAST-LEAK-01 · Container's `service.animation` subscription accumulates across overlay attach cycles** — `toast-container.component.ts:45`; cycle at `toast.service.ts:143-149, 183-188` **(= monorepo BUG-08, re-confirmed)**
Verified against installed CDK sources: `OverlayRef.detach()` synchronously invokes the portal dispose fn (`portal.mjs:217-223, 302-308`) which destroys the container component. The container is therefore destroyed on **every** "last toast dismissed" and recreated on the next `show()` — not only on position change — and each constructor adds another never-removed subscription to the root-singleton `BehaviorSubject`. Each leaked callback retains the destroyed container and its detached DOM subtree, and still dispatches `CustomEvent('scroll')` on it per subsequent animation event. Unbounded growth on the hottest lifecycle path.
**Fix:** `this.service.animation.pipe(takeUntilDestroyed()).subscribe(this.dispatchScrollEvent);` (constructor is an injection context — one line).

**TOAST-LEAK-02 · Eternal 500 ms heartbeat with `shareReplay()` infinite buffer that survives `ngOnDestroy`** — `toast.service.ts:51-55, 66-73`
`timer(500, 500)` is subscribed in the constructor and ticks for the app's lifetime even with zero toasts (the `filter` predicate still allocates two arrays per tick via the `toasts` getter). `shareReplay()` defaults to `bufferSize: Infinity, refCount: false`: every tick passing the filter is buffered forever, and the public `timer` field (`toast.api.md`) replays *all* buffered ticks synchronously to any late subscriber. `refCount: false` means `timerSubscription.unsubscribe()` in `ngOnDestroy` detaches the observer but the interval keeps firing, retaining the service — one immortal interval per bootstrap in the micro-frontend scenario this repo explicitly supports (the specs betray it: both fakeAsync tests need `discardPeriodicTasks()`). The inline `eslint-disable rxjs-x/no-ignored-replay-buffer` suppresses exactly the rule that would have caught this.
**Fix:** Nothing needs replay: gate the interval on toast existence (`switchMap` from a count subject) and use `share()`; make the field `private readonly`. Minimum: `shareReplay({ bufferSize: 1, refCount: true })` and remove the suppression.

**TOAST-A11Y-03 · Focus drops to `<body>` when a toast closes with focus inside** — `toast.component.ts:134-137`, `toast.service.ts:115-127`
`close()` → `hide()` → view destroyed with no focus handling anywhere (the only `FocusMonitor` use is passive monitoring). A keyboard user who tabs into the toast and activates close/Esc is stranded at the top of the document (WCAG 2.4.3); auto-dismiss can do the same the moment focus flags flip.
**Fix:** If `document.activeElement` is inside the removed toast, move focus to the adjacent toast, else restore the previously focused element — restore via `FocusMonitor.focusVia(el, origin)`, not native `.focus()`, to keep the `.cdk-keyboard-focused` ring.

**TOAST-ARCH-01 · Unsound service generic; factory token resolved in the root injector** — `toast.service.ts:20-22, 29-36, 89`
`KbqToastService<T extends KbqToastComponent>` is one root instance, but `T` is chosen freely per injection site — an unchecked cast. `KBQ_TOAST_FACTORY` is injected in the service's root context, so component-level overrides never reach it; the repo's own dev app demonstrates the drift (`components-dev/toast/module.ts` injects `KbqToastService<DevToastComponent>` without providing the factory anywhere — the runtime creates plain `KbqToastComponent` while the type claims otherwise).
**Fix:** Drop the class-level generic; accept a typed `componentType?: ComponentType<T>` per `show()` call, keeping the token as the app-wide default; document root-only provisioning.

**TOAST-API-01 · Untyped members compile to `any` and are published in the `.d.ts`** — `toast.component.ts:76-79, 139`, `toast-container.component.ts:48`
`ttl;`, `delay;`, `$implicit;`, `isTemplateRef(value)`, `createToast(data, componentType, onTop)` — all `any` in `tools/public_api_guard/components/toast.api.md` (`$implicit: any`, `delay: any`, `ttl: any`, `value: any`, `componentType: any`). Direct violation of the repo "no `any`" standard on *exported* symbols.
**Fix:** `ttl: number`, `delay: number`, `readonly $implicit: this = this`, `isTemplateRef(value: unknown): value is TemplateRef<unknown>`, `createToast<C extends KbqToastComponent>(data: KbqToastData, componentType: ComponentType<C>, onTop: boolean)`; then `approve-api`.

**TOAST-API-02 · Over-exposed internals are guard-locked public API** — `toast.service.ts:46-55`, `toast.component.ts:62-70`, `toast-container.component.ts:34, 73-82`
Raw next-able subjects (`read`/`hovered`/`focused`/`animation` — any consumer can `service.hovered.next(true)` and freeze all TTLs forever), the reassignable public `timer`, public `service`/`elementRef` on the component, the container's whole toolkit (`getInjector`, `dispatchScrollEvent`), and template-only helpers that should be `protected` per repo standard. Every one is a breaking change to remove later; the surface grows more expensive each release.
**Fix:** `protected`/`private` + `readonly` sweep; expose subjects as `Observable` getters (`asObservable()`); then `approve-api`.

**TOAST-TEST-01 · The component's core timing UX has zero test coverage** — no test exercises `toast.service.ts:52` (pause filter), `toast.component.ts:103-117` (relay + TTL floor bump), or `toast.service.ts:167-171` (cascade reset)
The suite never dispatches `mouseenter`/focus on a toast, never reads `service.hovered/focused`, never observes a survivor's `ttl` after another expires. The signature behavior — "don't dismiss while the user reads; give them at least `delay` ms after they touch it" — would regress silently (and BUG-01/BUG-02 prove it already has, undetected).
**Fix:** fakeAsync specs: hover pause + TTL floor (`show(3000)`, `tick(2500)`, hover → assert `ttl === delay`, no decrement while hovered); cascade (`show(a,1000); show(b,5000); tick(1000)` → assert `b.ttl === 2000` — pins the `Math.max` fix).

### P2 — Should fix

**TOAST-BUG-04 · Exit animation never plays for the last toast** — `toast.service.ts:115-127`; verified chain: `overlay-module.mjs:981` → `portal.mjs:217-223, 302-308` → `animations/browser.mjs:2242-2294`
`hide()` queues the toast's `* => void` leave transition via `viewContainer.remove()`, then in the same synchronous stack `detachOverlay()` destroys the container. The container has no animation trigger and no animating ancestors, so the engine's `removeNode` takes the immediate-removal branch: `destroyInnerAnimations(container)` kills the queued leave player and `_onRemovalComplete` yanks the subtree from the DOM before flush. Multi-toast dismissal animates; the most common case — the single toast — disappears abruptly, and `@state.done(void)` never reaches `service.animation` consumers. (Arbitrated: one reviewer claimed CDK's MutationObserver rescues this — refuted; it only gates *host* cleanup.)
**Fix:** Material snack-bar pattern: defer `detachOverlay()` until `service.animation` reports the removed toast's `toState === 'void' && phaseName === 'done'` (with a timeout fallback).

**TOAST-BUG-05 · Position change with live toasts silently destroys them and strands dictionary entries** — `toast.service.ts:203-214, 38-44`
`createOverlay` re-reads the mutable config position each `show()`; on change it calls `overlayRef.dispose()` — visible toasts vanish mid-read with no `hide()`, no `read` emission, no animation. Follow-on: `toastsDict` entries for destroyed toasts are never purged, and the `templates` getter does **not** filter destroyed views, so a killed long-duration template keeps `templates.length > 0` and blocks `detachOverlay()` of the *new* overlay until its orphaned `setTimeout` finally fires.
**Fix:** Drain gracefully before dispose (iterate dicts calling `hide`/`hideTemplate`); purge both dicts on dispose; make `templates` filter `destroyed`.

**TOAST-ARCH-02 · Component constructor mutates the caller-owned `KbqToastData`** — `toast.component.ts:94-97`; test-side effect at `toast.spec.ts:12-17`
Defaults are written back into the consumer's object through the `useValue` provider — a reused/serialized `KbqToastData` is silently polluted (`closeButton: true`, `style: 'contrast'` appear on the caller's object); line 96 (`iconClass || undefined`) is a literal no-op. The spec's shared `MOCK_TOAST_DATA` const is mutated by the first test that runs.
**Fix:** Normalize into private derived state (or clone at the container boundary); never write to the injected object; delete the no-op line.

**TOAST-PERF-01 · Synthetic `scroll` broadcast app-wide on every animation start *and* done of every toast** — `toast-container.component.ts:80-82`; producers `toast.component.ts:50-52, 143-145`
Each toast enter/leave fires 2 events into `service.animation` → container dispatches `CustomEvent('scroll')` → `ScrollDispatcher` notifies **all** globally registered scroll consumers — every open connected overlay in the app recomputes its position. A burst of N toasts = 4N app-wide reposition passes; the `BehaviorSubject` replay also fires it spuriously on each fresh container construction (value never inspected — the seeded `null` triggers it too).
**Fix:** Filter to layout-changing events and skip the replayed value; or drop the synthetic event — CDK already registers `CdkScrollable` ancestors for overlays anchored inside toasts.

**TOAST-A11Y-04 · Status icons have no text alternative and are not hidden; warning and error share the same glyph** — `toast.component.html:6-36`
Default icons render as `<i>` with neither `aria-hidden="true"` nor a name; success/warning/error differ only by glyph + token colors, and warning vs error don't even differ in glyph (`kbq-triangle-exclamation_16` at `:23` and `:31`) — status is conveyed by color alone (WCAG 1.4.1, 1.1.1). Docs show caption-only toasts where nothing in the text says "success".
**Fix:** `aria-hidden="true"` on the default icons; include the status in the announcement text (`"Error: " + title`) once A11Y-01 lands; give error a distinct glyph.

**TOAST-A11Y-05 · Auto-dismiss pause never engages for screen-reader virtual-cursor users** — `toast.service.ts:51-55`, default `duration: 5000` (`toast.type.ts:52`)
SR virtual-cursor reading moves neither mouse nor DOM focus, so the countdown runs while an SR user reads (WCAG 2.2.1 residual risk; mitigations exist — hover/focus pause, per-call duration, `duration: 0`).
**Fix:** Document "use `duration: 0` or generous durations for actionable/error toasts"; after A11Y-01, announce at `show()` time so removal doesn't erase the message.

**TOAST-A11Y-06 · Documented action pattern uses role-less pseudo-links without Space support** — `docs-examples/components/toast/toast-actions-overview/toast-actions-overview-example.html:8-28` and siblings
Every example action is `<a kbq-link pseudo (click)="…" (keydown.enter)="…">`: generic role, hand-wired Enter, no Space (WCAG 4.1.2 / 2.1.1 in the de-facto contract consumers copy). Repo precedent exists: `clamped-text.ts:51` adds `role="button"`.
**Fix:** Use `<button kbq-button kbqStyle="transparent">` in examples (no manual key handling), or at least `role="button"` + Space handling.

**TOAST-API-03 · `TemplateRef<any>` throughout + inconsistent `$implicit` between the two render paths** — `toast.type.ts:22-32`, `toast-container.component.ts:57-61`, `toast.component.ts:79, 92`
No template-context typing anywhere, and `$implicit` is the *component instance* for `show()` slot templates but the *data object* for `showTemplate()` — the same template cannot serve both paths and cannot be typed.
**Fix:** Define `KbqToastTemplateContext` types, use them in `KbqToastData`/`showTemplate`; document or unify the context.

**TOAST-API-04 · `EmbeddedViewRef<T>` typed with the wrong parameter** — `toast.service.ts:42-44, 104-112`
`EmbeddedViewRef`'s parameter is the view's **context** type; the actual context is `{ $implicit: KbqToastData }`, not the toast component — `ref.context` is mistyped for every consumer and the lie is published in the API guard.
**Fix:** `EmbeddedViewRef<{ $implicit: KbqToastData }>` via a shared alias.

**TOAST-API-05 · `KbqToastData.id?: string` is a dead field with misleading semantics** — `toast.type.ts:21`
Never read or written anywhere in the package; the working id is the component's numeric counter and `hide(id: number)` takes a number. A consumer setting `data.id` reasonably expects `hide` to honor it — it never will.
**Fix:** Remove (with API approval) or honor it as the toast identity.

**TOAST-API-06 · No typed channel for user payload; subclassing forces shadowing and casts** — `toast.type.ts:20-33`; `docs-examples/…/toast-user-data-example.ts:27`, `components-dev/toast/module.ts:67-78`
The library's own examples resort to `<ExtendedUserData>{…}` angle-bracket casts, and custom factory components must re-declare `data`/`service`.
**Fix:** `KbqToastData<P = unknown>` with `payload?: P` threaded through `show()`; document the subclass pattern.

**TOAST-ARCH-03 · Three-file circular import; `KbqToastService<any>` leaks into emitted types** — `toast.service.ts:16-17` ↔ `toast.component.ts:21`, `toast-container.component.ts:18`
The service↔component↔container cycle survives only via lazy DI references, and DI generic erasure publishes `readonly service: KbqToastService<any>` in `toast.api.md`.
**Fix:** Move `KBQ_TOAST_FACTORY` and shared contracts into `toast.type.ts`; component talks to the service through a narrow token/interface.

**TOAST-ARCH-04 · Pre-signals state: raw `BehaviorSubject` message bus with cross-writes** — `toast.service.ts:46-49`, `toast.component.ts:70-73, 103-104`
Violates the repo "signals for state" standard; component and service cross-write each other's public subjects; `animationState` is a mutable string driving a host binding. State ownership is untraceable.
**Fix:** `signal()`/`computed()` internally; read-only views outward. (Schedule with the API-02 sweep — same breaking-change budget.)

**TOAST-ARCH-05 · Encapsulation inversion: service owns and decrements component's public `ttl`/`delay`** — `toast.service.ts:93-94, 152-153, 167-171` vs `toast.component.ts:112-116`
Two writers, no owner, both fields untyped public API; `KBQ_TOAST_FACTORY` subclasses inherit this implicit mutable contract undocumented.
**Fix:** Keep TTL bookkeeping in the service (`id → ttl` map); pass immutable timing config via the injector.

**TOAST-ARCH-06 · Two disjoint ID namespaces; `hide` vs `hideTemplate` collide numerically** — `toast.service.ts:26, 91, 107`, `toast.component.ts:32, 75`
`show()` and `showTemplate()` both return `{ id: number }` from independent counters; `hide(3)` and `hideTemplate(3)` target different toasts and the wrong call silently no-ops.
**Fix:** Single service-owned sequence, or return an opaque `KbqToastRef` with its own `dismiss()`.

**TOAST-TPL-01 · Broken token deprecation: old stack-margin tokens are consumed nowhere** — `toast-tokens.scss:2-5` vs `toast-container.component.scss:11-37`
`--kbq-toast-stack-size-margin-top/right` are declared "deprecated" but the container reads only the new `-vertical/-horizontal` names — consumers overriding the old tokens (the entire reason they're kept) get **no effect**. A silent behavioral break dressed as a deprecation.
**Fix:** Chain them (`--…-vertical: var(--…-top, var(--kbq-size-m))`) or remove them outright.

**TOAST-TPL-02 · Dead tokens shadowed by an unreadable nested-calc with a magic `16px`** — `toast-tokens.scss:19-20`, `toast.component.scss:96-108, 26`
`--kbq-toast-size-close-button-margin-top` and `--kbq-toast-size-icon-border-radius` are referenced nowhere; the close-button margin is instead computed by triple-nested `kbq-difference/sum-series-css-variables` calls with an inline `16px` — the dedicated override token is a lie for anyone reading the tokens file.
**Fix:** Assign the computed expression *to* the token and consume it; name the `16px`; wire or delete the icon-radius token.

**TOAST-TEST-02 · Vacuous tests: spy-on-then-call, "sticky" never verified, zone assertion that can pass with zero executions** — `toast.spec.ts:128-139, 59-87, 183-196`
`jest.spyOn(service, 'show'); service.show(…); expect(spy)…` can never fail; four "sticky" titles never tick the interval to prove persistence (a `ttl >= 0` regression would pass); the one zone test asserts inside a subscription that may never fire.
**Fix:** Assert outcomes (returned ref/ttl, DOM after `tick(5000)`); add an emission counter to the zone test.

**TOAST-TEST-03 · Real intervals and post-teardown timeouts leak out of tests** — `toast.spec.ts:36-40, 257, 272`
Each test constructs the service on real timers; with `shareReplay()` (no refCount) even teardown doesn't stop the interval — one leaks per test for the Jest worker's life. `showTemplate(…, 0)` schedules real `setTimeout`s that fire after teardown against a destroyed service.
**Fix:** `jest.useFakeTimers()` / construct inside `fakeAsync` + `flush()`; fixing TOAST-LEAK-02 removes the root cause.

**TOAST-TEST-04 · Untested surface: config/factory tokens, all 7 positions, `onTop`, `showTemplate` semantics, ESC/read emissions** — `toast.type.ts:61-69`, `toast.service.ts:195-246`, `toast-container.component.ts:50-60`, `toast.component.ts:55, 119-137`
Zero coverage of `kbqToastConfigurationProvider`, `KBQ_TOAST_FACTORY` substitution (the only "consumer", `e2e.ts:45-50`, redundantly provides the default), position classes/strategies/dispose-on-change, `onTop` ordering, template `$implicit` context, template auto-hide, Esc close, `service.read` emissions.
**Fix:** Parametrized position spec, factory-subclass spec, onTop DOM-order spec, template context/auto-hide specs, Esc + `read` specs.

**TOAST-TEST-05 · Zero accessibility assertions** — whole of `toast.spec.ts`
Repo policy requires AXE-clean WCAG AA; the suite contains no AXE run, no role/ARIA/focus assertion — which is exactly why A11Y-01/02 shipped.
**Fix:** AXE check + assertions on role/label/focus once Phase 1 lands; at minimum assert the close control is a labeled, focusable `<button>`.

**TOAST-TEST-06 · E2E bypasses the service and overlay entirely; screenshots only** — `e2e.playwright-spec.ts:9-16`, `e2e.ts:37-41`
The fixture instantiates containers inline and calls `createToast()` directly — service, overlay, positioning, `toTop`, dismissal are never exercised in a real browser; no interaction e2e (close click, hover pause, ESC, stacking).

## 4. Recommended Remediation Phases

**Phase 1 — Accessibility blockers.** `TOAST-A11Y-01` (LiveAnnouncer in the service), `TOAST-A11Y-02` (native `<button>` + `aria-label`), `TOAST-A11Y-03` (focus restoration via `focusVia`), `TOAST-A11Y-04` (aria-hidden icons + status in announcement + distinct error glyph), `TOAST-A11Y-06` (docs examples → real buttons), `TOAST-A11Y-09` (labelled region). Independent of everything else; ship first.

**Phase 2 — Leaks & lifecycle.** `TOAST-LEAK-01` (one-line `takeUntilDestroyed`), `TOAST-LEAK-02` (`share()` / gated interval), `TOAST-LEAK-03` (`Subject` for `animation`), `TOAST-BUG-04` (defer detach until exit animation done), `TOAST-PERF-01` (filter the scroll broadcast). LEAK-01/02 first — they change the subscription topology BUG-04's fix relies on.

**Phase 3 — Auto-dismiss correctness.** `TOAST-BUG-01` (`Math.max` clamp), `TOAST-BUG-02` (per-toast `isFocusedOrHovered` in `processToasts`, delete forwarding subscriptions), `TOAST-BUG-03` (unify template TTLs into the tick pipeline — the largest item), `TOAST-BUG-05` (graceful drain on position change), `TOAST-BUG-06` (cascade on manual close), `TOAST-A11Y-05` (docs guidance). Land BUG-02 before BUG-03 (the unified pipeline consumes the per-toast pause check).

**Phase 4 — Public API & typing.** Includes `approve-api`. `TOAST-API-01` (type the `any` five), `TOAST-API-02` (protected/readonly/Observable sweep), `TOAST-ARCH-01` (per-call `componentType`), `TOAST-API-03`/`04` (template contexts), `TOAST-API-05`–`09`, `TOAST-ARCH-03` (break the import cycle), `TOAST-ARCH-05`/`06` (service-owned TTL map + unified ids / `KbqToastRef`), `TOAST-BUG-07`/`08`. One breaking-change budget; coordinate a minor/major release. `TOAST-ARCH-04` (signals migration) can ride along or defer.

**Phase 5 — Tests, templates & styles hygiene.** `TOAST-TEST-01` (first — it pins Phase 3's fixes), `TOAST-TEST-02`–`07`, `TOAST-TPL-01`/`02` (token compat chain), `TOAST-TPL-03`–`08`, `TOAST-PERF-02`/`03`, `TOAST-ARCH-07`/`08`, `TOAST-A11Y-07`/`08`. TEST-01 ideally lands *with* Phase 3 as its regression net.

## Appendix A — Review Methodology
