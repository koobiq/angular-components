## 1. Executive Summary

- **Accessibility is the single biggest risk and the only release blocker.** For a navigation component the package ships almost no ARIA: neither `KbqNavbar` nor `KbqVerticalNavbar` sets a landmark/menu `role` or `aria-label`; the icon-only `KbqNavbarToggle` has no accessible name and no `aria-expanded`; collapsed icon-only items expose their label **only through a transient tooltip**, not as a programmatic accessible name; and disabled state is expressed with `[attr.disabled]` on custom (non-form) elements, which assistive technology ignores. This directly violates the project's own "MUST pass AXE / WCAG AA" mandate (AGENTS.md). **2×P0 + 2×P1** cluster here.
- **One real functional bug with multi-instance blast radius.** Every `KbqNavbarToggle` registers a **global** `window` `keydown` listener that calls `this.navbar.toggle()` unconditionally (`navbar-toggle.component.ts:97`), so a single `Ctrl+/` toggles **every** vertical navbar on the page. The shipped `e2e.ts` renders four vertical navbars, confirming the scenario is real, not hypothetical.
- **The responsive-collapse width math is quietly fragile.** `KbqNavbarTitle.getOuterElementWidth` has an operator-precedence bug — `acc + parseInt(item) || 0` parses as `(acc + parseInt(item)) || 0`, so the `|| 0` guards the running *total*, not the individual value; and `KbqNavbarRectangleElement.getOuterElementWidth` omits the guard entirely, so any `'auto'`/`''` computed style produces a `NaN` that poisons `totalItemsWidth` and silently disables the whole collapse decision.
- **Dead code is presented as tested.** `checkTextOverflown` / `isTextOverflown` / the `text.length > 18` heuristic has **no production caller** (verified by grep) — the `.kbq-navbar-title_small` class can never apply at runtime; production overflow uses the separate `isOverflown` (scrollWidth) getter. Two unit tests exercise this dead path, inflating coverage. `KbqNavbarLogo.hovered` / `KbqNavbarTitle.hovered` Subjects have **zero subscribers** repo-wide; `KbqNavbarContainerPositionType` is an unused export.
- **Change-detection & lifecycle hygiene.** `KbqNavbarItem`/`KbqNavbarBrand` call synchronous `detectChanges()` on **every** `rectangleElement.state` emission; during init the parent flips orientation on all elements in one pass → an O(n²) synchronous CD cascade. `markForCheck()` is both sufficient and safer. Option focus/blur subscriptions are dropped only in `resetOptions()`, never on destroy.
- **Modernization debt.** `KbqNavbarItem` and `KbqNavbarBrand` inherit the **entire** `KbqTooltipTrigger` public API instead of composing it — even though the sibling `KbqNavbarToggle` already demonstrates composition via `hostDirectives`. Six legacy `@Input` get/set accessors carry "Skipped for migration" TODOs; `tabIndex` and `configuration` are typed `any`.
- **What's strong.** The focus-origin gating (pointer/touch focus on the host does not steal keyboard focus into the first item and surface its tooltip) is well-designed and well-tested; the locale subscription in `KbqVerticalNavbar` correctly uses `takeUntilDestroyed`; `KbqNavbarToggle` is the reference composition pattern the item/brand should adopt; the dropdown-host (`KBQ_DROPDOWN_HOST` / `demoteOverlay`) wiring is unit-tested.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

**NAV-A11Y-01 · Icon-only `KbqNavbarToggle` has no accessible name and no `aria-expanded`** — `navbar-toggle.component.ts:37` (host object).
The toggle is an interactive control (`(click)="toggle()"`, `keydown` Space/Enter) but the host exposes no `role`, no accessible name, and no `aria-expanded`. Its only label is the `KbqTooltipTrigger` content set in `updateTooltipContent()` (`:91`), a transient hover/focus tooltip that is **not** a programmatic name. A screen-reader user hears an unlabeled control with no indication it expands/collapses the navigation.
**Fix:** add to the host `role: 'button'`, `[attr.aria-expanded]="navbar.expanded"`, and a persistent `[attr.aria-label]="navbar.expanded ? navbar.configuration.toggle.collapse : navbar.configuration.toggle.expand"` (reuse the locale strings already used for the tooltip). Do not rely on the tooltip for the name.

**NAV-A11Y-05 · Collapsed item's label is available only via the transient tooltip, not as an accessible name** — `navbar-item.component.ts:514` (`updateTooltip`).
When an item is collapsed (icon-only), `updateTooltip()` puts the title into the tooltip content and `focus()` calls `tooltip?.show()` on keyboard focus (`:245`). The element's accessible name still comes only from the absent/collapsed title; the tooltip is a transient overlay not wired as the name (no `aria-label`/`aria-labelledby`). A screen-reader user navigating a collapsed vertical navbar hears icon-only items with no reliable name.
**Fix:** set a persistent programmatic name on the focusable item when collapsed, e.g. `[attr.aria-label]="isCollapsed ? titleText : null"`; keep the tooltip as a purely visual affordance.

> NAV-A11Y-01 and NAV-A11Y-05 should land together with the P1 a11y items below — the landmark/role → name → state chain must be coherent to pass AXE.

### P1 — High

**NAV-A11Y-03 · `KbqNavbar` / `KbqVerticalNavbar` have no landmark/menu role or `aria-label`** — `navbar.component.ts:201`, `vertical-navbar.component.ts:57` (host objects).
Both hosts expose only class + `tabindex` + keyboard handlers. Neither sets `role="navigation"` (landmark) / `role="menubar"`, nor an `aria-label`. AT users get no landmark to jump to, no name to distinguish multiple navbars, and the arrow-key roving-tabindex (menubar-like) model is presented as a plain focusable container with no semantics.
**Fix:** add `role="navigation"` (or `role="menubar"` with `role="menuitem"` on items — see NAV-A11Y-06 — if committing to the menu pattern) plus a configurable `aria-label` input on both hosts. Keep the roving-tabindex model consistent with the chosen role.

**NAV-A11Y-04 · Disabled state uses `[attr.disabled]` on a non-form custom element** — `navbar-item.component.ts:119` (`KbqNavbarFocusableItem` host).
The host binds `[attr.disabled]="disabled || null"`. The `disabled` content attribute is only meaningful on native form controls; on the custom elements this directive targets (`kbq-navbar-item`, `kbq-navbar-brand`, `kbq-navbar-toggle`) it is ignored by the browser and by AT — it neither removes the element from interaction nor is exposed as a disabled state.
**Fix:** replace with `[attr.aria-disabled]="disabled || null"` (keep the `.kbq-disabled` class for styling), and ensure disabled items are removed from the roving-tabindex sequence so focus cannot land on them.

**NAV-BUG-01 · Global `Ctrl+/` shortcut toggles every `KbqVerticalNavbar` on the page at once** — `navbar-toggle.component.ts:97` (`windowToggleHandler`).
Each toggle registers its own document-level `window` `keydown` listener (`afterNextRender` → `window.addEventListener`), and `windowToggleHandler` calls `this.navbar.toggle()` with no scoping to focus, hover, or the active navbar. With more than one vertical navbar on a page (a supported scenario — `e2e.ts` renders four), a single `Ctrl+/` fires all N listeners and toggles every navbar.
**Fix:** scope the shortcut — guard `windowToggleHandler` so it only toggles when this navbar (or its toggle) contains `document.activeElement`, e.g. `... && this.navbar.elementRef.nativeElement.contains(document.activeElement)`; or register a single shared listener keyed to the active instance.

### P2 — Should fix

- **NAV-A11Y-06 · Navbar items expose no `role` (link/menuitem) to AT** — `navbar-item.component.ts:359`. Items are interactive (click handlers, roving focus, dropdown triggers) but announced as generic content. **Fix:** assign `role="menuitem"` (if adopting menubar) or render actionable content as native `<a>`/`<button>`; for dropdown-trigger items add `aria-haspopup="menu"` + `aria-expanded`. Overlaps NAV-A11Y-02/03.
- **NAV-A11Y-08 · Native `<a href>` brand is force-disabled and stripped of keyboard focus** — `navbar-brand.component.ts:120`. The constructor sets `navbarFocusableItem.disabled = !isLink`, and the focusable item hard-codes `tabindex=-1` + `[attr.disabled]`; even a genuine link brand gets `tabindex=-1`, leaving the tab order (reachable only via the roving manager). Root-shared with NAV-BRAND-04. **Fix:** for anchor brands keep native focusability/link role (do not force `tabindex=-1`/`disabled`); reserve the roving/disabled treatment for non-interactive brands.
- **NAV-A11Y-09 · `kbq-navbar-divider` is a purely visual separator with no `role`** — `navbar-item.component.ts:107`. Screen readers announce nothing where sighted users perceive a grouping boundary. **Fix:** add `role="separator"` + `[attr.aria-orientation]` to the `KbqNavbarDivider` host (orientation opposite to the navbar axis).
- **NAV-WIDTH-02 · `getOuterElementWidth` `|| 0` guards the accumulator, not the parsed item (operator precedence)** — `navbar-item.component.ts:95` (`KbqNavbarTitle`). `[width, marginLeft, marginRight].reduce((acc, item) => acc + parseInt(item) || 0, 0)` binds as `(acc + parseInt(item)) || 0`, so a single `NaN` collapses the running sum to `0`. **Fix:** `.reduce((acc, item) => acc + (parseInt(item, 10) || 0), 0)`. See NAV-WIDTH-01 for the sibling implementation.
- **NAV-OVERFLOW-03 · `checkTextOverflown` is dead production code using a magic 18-char heuristic that conflicts with `isOverflown`** — `navbar-item.component.ts:98`. `checkTextOverflown()` sets `isTextOverflown = text.length > 18` and drives `.kbq-navbar-title_small`, but it has **no production caller** (only two specs at `navbar.component.spec.ts:434,450`); production overflow uses the `isOverflown` (scrollWidth) getter. **Fix:** either wire it into a real lifecycle/resize hook based on `isOverflown` (drop the magic 18) or delete the method, the `isTextOverflown` host binding, and the specs. *(Merges NAV-TITLE-01, NAV-TEST-02.)*
- **NAV-ARCH-01 · `KbqNavbarItem` and `KbqNavbarBrand` extend `KbqTooltipTrigger` (inheritance-for-reuse, not is-a)** — `navbar-item.component.ts:368`, `navbar-brand.component.ts:23`. This pulls the whole tooltip trigger API (`content`, `arrow`, `offset`, `placement`, `overlayConfig`, `show/hide`, `visibleChange`, all trigger listeners) onto every item/brand's public surface and forces constructors to poke protected tooltip fields — while `KbqNavbarToggle` already composes the tooltip via `hostDirectives` + `inject`. **Fix:** replace inheritance with composition (add `KbqTooltipTrigger` to `hostDirectives`, `inject(KbqTooltipTrigger, { self: true })`, hold it in a private field). SemVer-gated (breaking).
- **NAV-ARCH-06 · Overlapping `disabled` semantics on the same host: `KbqNavbarFocusableItem.disabled` input vs `KbqNavbarItem.disabled` getter** — `navbar-item.component.ts:446`. `KbqNavbarItem.disabled` returns `!isCollapsed && !hasCroppedText` when unset — i.e. "tooltip should be suppressed", not "non-interactive" — yet shares the exact name of the focusable item's real interactive-disabled state. **Fix:** rename the tooltip-suppression getter (e.g. `isTooltipSuppressed`) so it no longer collides with the single real `disabled` owned by the focusable item.
- **NAV-ARCH-07 · `KbqVerticalNavbar.configuration` is untyped (implicit `any`) with no initializer** — `vertical-navbar.component.ts:77`. Assigned from `localeService.getParams('navbar')` / the external token and read as `configuration.toggle.collapse/expand` with no type safety. **Fix:** introduce `interface KbqVerticalNavbarConfiguration { toggle: { expand: string; collapse: string } }`, type the field and the token, and initialize it. Ties to NAV-API-03 / NAV-ARCH-08.
- **NAV-API-01 · `tabIndex` typed `any` on `KbqFocusableComponent` (leaks into both navbars)** — `navbar.component.ts:56`. Only numeric values (0/-1) are ever written, yet the API report surfaces `get tabIndex(): any`. **Fix:** type as `number` (or migrate to a signal input with `numberAttribute`). *(Merges NAV-ARCH-04.)* Regenerate the API snapshot.
- **NAV-API-03 · `KBQ_VERTICAL_NAVBAR_CONFIGURATION` is `InjectionToken<unknown>` and `externalConfiguration` is `unknown`** — `vertical-navbar.component.ts:38`. Consumers providing a config get no type-checking; the token communicates no shape. **Fix:** parameterize with the interface from NAV-ARCH-07: `new InjectionToken<KbqVerticalNavbarConfiguration>('KbqVerticalNavbarConfiguration')`. Ties to NAV-ARCH-08.
- **NAV-API-05 · `contentChildren`/`contentChild` signals typed `readonly any[]` / `Signal<any>` (forwardRef erases the element type)** — `navbar.component.ts:215`. `rectangleElements`/`navbarItems`/`items`/`bento` all collapse to `any`, so internal `.getOuterElementWidth()`/`.icon()`/`.title()`/`.collapsable`/`.button()` calls are unchecked. **Fix:** pass the explicit generic, e.g. `contentChildren<KbqNavbarRectangleElement>(forwardRef(() => KbqNavbarRectangleElement), { descendants: true })`.
- **NAV-CD-01 · `detectChanges()` on every `rectangleElement.state` emission → O(n²) synchronous CD cascade** — `navbar-item.component.ts:486`. `state.next()` fires from the orientation/collapsed setters; during init the parent flips `horizontal=true` on **all** rectangle elements in one `forEach`, so each item forces a full synchronous re-render. **Fix:** use `markForCheck()` instead of `detectChanges()`. *(Merges NAV-LIFECYCLE-03; brand equivalent is NAV-CD-02.)*
- **NAV-LIFECYCLE-01 · `optionFocus`/`optionBlur` subscriptions are never torn down on destroy** — `navbar.component.ts:139`. `dropSubscriptions()` is called only from `resetOptions()`; `ngOnDestroy` never calls it, so the last focus/blur merges (over every item's `onFocus`/`onBlur`) stay subscribed after destroy and the blur callback still calls `markForCheck`. **Fix:** override `ngOnDestroy` in `KbqFocusableComponent` to `dropSubscriptions()`, or pipe both subscriptions through `takeUntilDestroyed(this.destroyRef)`.
- **NAV-PERF-04 · `window:resize` host binding enters the Angular zone for every raw event before the debounce** — `navbar.component.ts:207`. `(window:resize)="resizeStream.next($event)"` runs in-zone per native event; only the expensive `updateExpandedStateForItems` is debounced, so a fast resize drag still triggers a burst of full CD passes. **Fix:** subscribe via `ngZone.runOutsideAngular` + `fromEvent(window, 'resize')` with `debounceTime` outside the zone, re-entering only when work runs.
- **NAV-TEST-01 · No accessibility / ARIA assertions anywhere in the suite** — `navbar.component.spec.ts:23`. Nothing verifies landmark/role, accessible names for icon-only controls, or that disabled state reaches AT — despite the AXE/WCAG mandate. **Fix:** add tests asserting roles/names/landmarks and disabled-state exposure; integrate `axe-core`/`jest-axe`. (Fails until NAV-A11Y-* land.)
- **NAV-TEST-03 · `KbqNavbarToggle` is entirely untested** — `navbar-toggle.component.ts:47`. Click, Space/Enter (+ `preventDefault`/`stopPropagation`), the global `Ctrl+/` shortcut, `updateTooltipContent` label swap, and the `ngOnDestroy` window-listener cleanup are all uncovered. **Fix:** add a `describe` covering each, including the NAV-BUG-01 multi-instance scoping regression.
- **NAV-TEST-04 · `KbqVerticalNavbar` expand/collapse/toggle/openOver/locale-config is untested** — `vertical-navbar.component.ts:71`. `TestVerticalApp` only exercises the inherited focus-origin gating. **Fix:** test that `expanded`/`toggle()` flip container + item collapsed state, `openOver` toggles the host class, and `configuration` falls back to the default / uses external config / uses the locale service.
- **NAV-TEST-05 · Core responsive collapse/expand logic is never exercised** — `navbar.component.ts:307`. `updateExpandedStateForItems`/`collapseItems`/`expandItems`/the resize pipeline/the width getters are untested; the "collapsed elements should have title" test sets `collapsed` manually. **Fix:** stub `getBoundingClientRect`/`getOuterElementWidth`/`getTitleWidth` to controlled numbers and assert collapse/expand decisions and the debounced resize path.
- **NAV-TEST-07 · Tests couple to an internal `setTimeout` via magic `tick(FONT_RENDER_TIMEOUT_MS = 10)`** — `navbar.component.spec.ts:21`. The `10` mirrors an implementation detail (the actual wait is a zero-delay `setTimeout` at `navbar.component.ts:278`) and misleads readers. **Fix:** replace with `tick()`/`flush()` and drop the constant, or export the real delay from the component and import it.
- **NAV-TEST-08 · Playwright e2e only captures static screenshots** — `e2e.playwright-spec.ts:9`. Dropdowns, the toggle, and roving keyboard nav are wired in the fixtures but never opened/pressed. **Fix:** click a `kbqDropdownTrigger` and snapshot the open overlay; click `kbq-navbar-toggle` and snapshot expanded vs collapsed; press Tab/ArrowRight and snapshot the focused item + its collapsed-item tooltip.
- **NAV-TEST-09 · `KbqNavbarBrand` `isLink`/`disabled` behavior is untested** — `navbar-brand.component.ts:55`. `isLink` (tagName === 'A'), the constructor's `navbarFocusableItem.disabled = !isLink`, the `kbq-navbar-brand_link` host class, and the `disabled` getter fallback are all unasserted. **Fix:** test anchor vs non-anchor brands for `isLink`, the link class, focusable-item disabled state, and the getter fallback.

- **NAV-SCSS-02 · Navbar host sits at the CDK overlay z-index; toggle/container hardcode magic z-index** — `navbar.scss:7`. `.kbq-navbar` uses `overlay.$overlay-z-index` (1000, the overlay layer), `navbar-toggle.scss:6` hardcodes `1001`, `vertical-navbar.scss:47` hardcodes `998`. **Fix:** introduce dedicated navbar z-index tokens / a documented layering scale below the overlay layer and reference them.
- **NAV-SCSS-03 · Magic pixel numbers instead of size tokens** — `_navbar-item_vertical.scss:4` (`height: 41px`, `margin-left: -8px`), `vertical-navbar.scss:42` (`width: 240px`), `navbar-brand.scss:79` (`max-width: 200px`), `navbar-divider.scss:16` (`height: 12px`), `navbar-toggle.scss:23-24` (`28px`). **Fix:** replace with nearest `--kbq-size-*` tokens or add component tokens (e.g. `--kbq-navbar-vertical-expanded-width`, `--kbq-navbar-toggle-circle-size`).
- **NAV-SCSS-04 · Duplicated `.kbq-badge` positioning rules across horizontal/vertical partials** — `_navbar-item_horizontal.scss:83` and `_navbar-item_vertical.scss:78`. **Fix:** hoist the common `position: absolute; z-index: 1;` into one rule; keep only the divergent `top`/`right` offsets in each partial.
- **NAV-SCSS-05 · `!important` used for brand-title hide and theme icon color** — `navbar-brand.scss:86` (`display: none !important`), `_navbar-theme.scss:8,16` (`color … !important`). **Fix:** rely on selector specificity for the brand title; raise specificity / reorder the cascade for the icon color instead of `!important`.
- **NAV-TEST-06 · `getOuterElementWidth` NaN regression is not guarded** — `navbar-item.component.ts:347`. The rectangle-element variant lacks the `|| 0` fallback (see NAV-WIDTH-01). **Fix:** add a test asserting a finite result when computed styles are `'auto'`/`''` (mock `KBQ_WINDOW.getComputedStyle`).
- **NAV-TEST-10 · Several class-presence tests are near-vacuous** — `navbar.component.spec.ts:94`. They re-assert static host bindings and pass even when behavior is broken. **Fix:** fold into behavior-driven tests (e.g. assert `kbq-navbar-item_with-title` toggles as a title is added/removed) and reinvest effort in collapse/toggle/a11y coverage.
- **NAV-TMPL-01 · Non-signal getters called in template `@if` re-evaluate every CD pass** — `navbar-item.component.html:8`. `@if (showVerticalDropDownAngle)` / `@if (showHorizontalDropDownAngle)` call getters that dereference orientation/collapsed/DOM. **Fix:** convert to `computed()` signals so the template reads memoized values.
- **NAV-TMPL-02 · Dev template uses inline `style` attribute** — `navbar.component.html:18` (`style="vertical-align: middle"` on the brand logo `<img>`). Dev-app only, but models inline styling for consumers. **Fix:** rely on the existing flex alignment of `.kbq-navbar-logo` or a small demo class.
- **NAV-WIDTH-01 · `KbqNavbarRectangleElement.getOuterElementWidth` has no NaN guard** — `navbar-item.component.ts:347`. `reduce((acc, item) => acc + parseInt(item), 0)` with no fallback; a single `'auto'`/`''` yields `NaN`, poisoning `totalItemsWidth` and the collapse decision. **Fix:** `.reduce((acc, item) => acc + (parseInt(item, 10) || 0), 0)` (per-item guard, as in NAV-WIDTH-02).
