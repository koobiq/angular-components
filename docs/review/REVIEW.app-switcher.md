# Koobiq `app-switcher` Component — Code Review & Improvement Plan

> Scope: `packages/components/app-switcher` (8 source files + tests/styles/docs) and the shared `core` abstractions it extends (`core/pop-up` → `KbqPopUp`/`KbqPopUpTrigger`, `dropdown` → `KbqDropdownItem`) · Commit `18ea72fe` · 2026-06-29
> Generated by an automated multi-agent review (9 review dimensions + adversarial verification of every finding). Of 79 raw findings, 67 were confirmed/kept (deduplicated to ~61 distinct: 3×P0, 5×P1, ~24×P2, ~28×P3) and 12 refuted/reconciled. Treat as a high-signal starting point; spot-check before acting.
> Findings tagged **(shared)** have their root cause in `core`/`dropdown` and also affect sibling components. This document is a review + roadmap; no source is modified by it.

## 1. Executive Summary

- **Security is the single biggest risk and a release blocker.** The component renders the public `KbqAppSwitcherApp.icon` string as raw HTML through `DomSanitizer.bypassSecurityTrustHtml(...)` bound to `[innerHtml]` in **two** places (`kbq-app-switcher-list-item.ts:81`, `app-switcher-dropdown-app.ts:61`). This deliberately disables Angular's sanitizer, so any icon markup containing an event handler (`<img onerror>`, `<svg><script>`) executes. `icon` is part of the documented data contract and the docs feed raw SVG strings — if any consumer populates app data from a backend or remote config this is stored/reflected XSS. There is no sanitization, no security note in the docs, and no XSS regression test. **2×P0 cluster here** (the two sinks). This independently confirms the monorepo review's `SEC-04`/`SEC-05`.
- **Accessibility is the second release-blocking risk.** The component is functionally a keyboard-driven menu of application links but exposes almost none of the required semantics, violating the `AGENTS.md` "MUST pass AXE / WCAG AA" mandate. The hardest failure (P0): the **group expand/collapse toggle is a non-focusable `<div>` whose chevron is `display:none` until `:hover`**, with no `role="button"`, no `aria-expanded`, and no Enter/Space activation — keyboard and touch users cannot operate it (WCAG 2.1.1, Level A). Compounding this, the **entire nested site→app navigation is hover-only** (`(mouseenter)` drives `activeSite`/`activeApp`), so even keyboard-opening the submenus shows stale/empty content. Plus: no menu/list role on the panels, `<img alt="{{app.type}}">` leaks an internal category code instead of the app name, the search input has only a placeholder (no label), and the cleaner button is unnamed.
- **Correctness is mostly edge-case crashes in input setters.** `selectedSite` dereferences `originalSites.find(...)` with no match guard — selecting a stale/removed site id throws `TypeError` (`app-switcher.ts:451`). `currentApps` reads `selectedSite.apps` in multi-site mode even when no site is selected, crashing render (`:342`). The `sites` setter leaves `_parsedSites` stale when switching multi→single (`:375`). Search filters `app.name` only, ignoring the visible `caption`. None fire on the happy path the tests exercise, which is exactly why they survive.
- **The "scroll-leak" reports reconcile to a dead-code bug, not a leak.** `private closeOnScroll: null;` is declared with no initializer, so its runtime value is `undefined`, never `null` — making `if (this.closeOnScroll === null)` in `ngAfterContentInit` **always false**. The nested-scroll auto-hide block it guards (including the `scrollDispatcher.scrolled()` subscription at `:526` that two reviewers flagged as a root-singleton leak) **never executes**. So the "leak" is moot (this is *why* the monorepo's `BUG-34` was disputed), but a real feature is silently disabled. The one genuine teardown gap is the `closingActions()` subscription at `:541`, which leaks into the root `ScrollDispatcher` only if the directive is destroyed while the popup is open.
- **Architecture is mid-migration with real type-looseness.** `KbqAppSwitcherTrigger` is a ~325-line god-class mixing input parsing, the grouping algorithm, overlay positioning and locale concerns. The `configuration` field has no type annotation (implicit `any`) and propagates that `any` through `localeData` into every locale string in the template; both `InjectionToken`s are untyped. Two-way state (`selectedApp`, `selectedSite`, list-item `collapsed`) is still `@Input`+`@Output` where `model()` fits, and the focus-trap providers live only in the legacy `NgModule` so standalone consumers silently lose them.
- **Performance: bounded but real OnPush churn.** `@for` tracks by **object identity** over collections that `makeGroupsForApps`/`filterSites` rebuild as new references, so every search keystroke tears down and recreates the whole row DOM; `filterSites` deep-clones all sites via `structuredClone` per keystroke with no debounce; and `[innerHtml]="getIcon(app.icon)"` allocates a fresh `SafeHtml` every change-detection pass, re-parsing each SVG.
- **Tests are broad on getters but miss the risk surface.** No XSS/sanitization test, no AXE/a11y test, no keyboard/focus-trap test, no rendered grouping collapse/expand or nested-dropdown test, and no `selectedSite` id-not-found test — the exact areas where the P0/P1 issues live. The async harness is cargo-culted (`TestScheduler` is built every `beforeEach` but `.run()` is never called), there is a dead exported fixture, and Playwright is two static screenshots with zero interaction.
- **What's solid.** The base `KbqPopUpTrigger`/`KbqPopUp` lifecycle is disciplined and most teardown there is correct (`takeUntilDestroyed` on `scrollable.elementScrolled`, `positionChanges`, `detachments`); the grouping reducer `defaultGroupBy` is unit-tested in isolation; the SCSS uses design tokens and `kbq-list-item-base()` for most state styling; and the BEM namespacing is consistent. The refactor seams (typed config interface, `model()`, a grouping service) are clean.

## 3. Prioritized Findings (deduplicated, verified)

### P0 — Release blockers

**AS-SEC-01/02 · DOM-XSS: `app.icon` rendered via `bypassSecurityTrustHtml` + `[innerHtml]` (two sinks)** — `kbq-app-switcher-list-item.ts:81-83` (bound `:26`) and `app-switcher-dropdown-app.ts:61-63` (bound `:16`). *(Confirms monorepo `SEC-04`/`SEC-05`.)*
`getIcon()` returns `this.sanitizer.bypassSecurityTrustHtml(icon || '')` over the public `KbqAppSwitcherApp.icon` string, bound via `[innerHtml]`. This disables Angular's HTML sanitizer entirely, so `app.icon = '<img src=x onerror=alert(document.cookie)>'` (or an inline `<svg><script>`) executes in the user's context. `icon` is documented public data (`app-switcher.ts:64`) and the examples feed raw SVG, so any server/remote/partially-attacker-controlled source makes this stored/reflected XSS. Two sinks render the same data on two paths (single-site list + sites-mode dropdown); fixing one leaves the other exploitable.
**Fix:** Do not blanket-trust raw markup. Preferred — change the contract to a `KbqIcon` **name** reference and render via `<i kbq-icon>`. If inline SVG must stay, route both sinks through **one** shared sanitization helper using a strict SVG allowlist (e.g. DOMPurify `USE_PROFILES:{svg:true,svgFilters:true}`, event attributes/scripts stripped) before `bypassSecurityTrustHtml`. At minimum, document loudly that `icon` MUST be trusted developer-controlled markup. Add the XSS regression test (AS-SEC-05/AS-TEST-03).

**AS-A11Y-01 · Group expand/collapse toggle is a non-focusable `<div>`, hidden until hover, with no `aria-expanded`** — `app-switcher.html:45-50`, `kbq-app-switcher-list-item.ts:72`, `kbq-app-switcher-list-item.scss:62-65,118-129`.
When an app has `aliases` the group header renders as `<div kbq-app-switcher-list-item [toggle]="true">`; the toggle chevron (`.kbq-app-switcher-list-item__toggle`) is `display:none` and only becomes visible on `:hover`/`.kbq-hover`/`.kbq-focused`. Expand/collapse is driven by a `(click)` `clickHandler` on the `<div>` — not a `<button>`, no `role="button"`, no `aria-expanded`, no Enter/Space activation. A screen reader announces a static item with no state, and the affordance is invisible without a pointer. Breaks WCAG 2.1.1 (Keyboard, Level A) and 4.1.2; fails AXE → violates the `AGENTS.md` mandate.
**Fix:** Render the group header as a real `<button type="button">` (or add host `role="button"`, `tabindex=0`, `(keydown.enter)`/`(keydown.space)` activation) and bind `[attr.aria-expanded]="!collapsed"`. Keep the chevron perceivable without hover (visible, or on `:focus-visible`).

> AS-SEC-01/02 and AS-A11Y-01 are the two hard release blockers. The a11y P1 cluster below (AS-A11Y-02/04/05/06 + the hover-only nav AS-A11Y-NAV) must land alongside AS-A11Y-01 for the open popup to actually pass AXE.

### P1 — High

**AS-A11Y-NAV · No keyboard/touch path for nested site→app navigation (hover-driven content)** *(consolidates AS-A11Y-09, AS-TPL-03, AS-TPL-09.)* — `app-switcher.html:2,21,85,102`, `kbq-app-switcher-list-item.scss:62-65,118-129`.
The "other sites" flyout and grouped-app submenus are populated from `activeSite`/`activeApp`, which are set **only** via `(mouseenter)` (`:85`, `:102`); `(mouseenter)="otherSites()?.close()"` (`:2`,`:21`) is likewise pointer-only. `KbqDropdownTrigger` supports keyboard opening, but with `activeSite`/`activeApp` never set on focus the connected `dropdownWithSelectedSite`/`dropdownWithGroupedApps` panels render stale/empty content for keyboard users — so a keyboard user of a multi-site switcher cannot reach other sites' apps. On touch (no hover) the same applies, and the group toggle (AS-A11Y-01) is also unreachable. WCAG 2.1.1 (Level A).
**Fix:** Mirror every `(mouseenter)` driver with `focus`/keyboard activation — set `activeSite`/`activeApp` when the corresponding trigger gains focus or opens via keyboard; close the other-sites flyout on focus-out, not only `mouseenter`. Keep the toggle in layout (`visibility`/opacity or `@media (hover:none)` always-visible) rather than `display:none`.

**AS-A11Y-02 · Overlay/menu panels expose no role (no `menu`/`list`/`listbox`)** **(shared)** — `app-switcher.html:33-66`; `kbq-app-switcher-list-item.ts:55` strips `kbq-dropdown-item` via `[class.kbq-dropdown-item]="false"` without substituting a role; shared dropdown panel sets only `tabindex="-1"`.
The popup is a list of application links but no container or row carries a landmark/widget role, so AT announces a flat group of links with no "menu"/"list" semantics or item count. WCAG 1.3.1 / 4.1.2.
**Fix:** Give the scrollable list a `role="menu"` (or `role="list"`) and the link rows `role="menuitem"`/`listitem` (or wrap in `<ul>`/`<li>`). Coordinate the container/item roles with the shared dropdown panel.

**AS-A11Y-04 · Image `alt` uses `app.type` (a grouping code), producing empty or wrong alt text** — `kbq-app-switcher-list-item.ts:29`, `app-switcher-dropdown-app.ts:19`.
The icon `<img>` uses `alt="{{ app.type }}"`. `type` is an optional grouping discriminator (`app-switcher.ts:62`), frequently `undefined`/`''` (see `e2e.ts`, many apps set `type:''`), so `alt` is empty or, worse, exposes an internal code like `NAD`/`SIEM` instead of the application name. WCAG 1.1.1.
**Fix:** Use `alt="{{ app.name }}"`, or mark the image decorative (`alt=""` + `aria-hidden` on the inline-SVG span) since the adjacent `.__name` text already names the app. Never leak `app.type`.

**AS-A11Y-05 · Search input has no programmatic label (placeholder only)** — `app-switcher.html:5-11`.
The `<input kbqInput>` has only `placeholder`; no `<label>`, `aria-label`, or `aria-labelledby`. Placeholder is not a reliable accessible name. WCAG 1.3.1 / 3.3.2 / 4.1.2.
**Fix:** Add `[attr.aria-label]="localeData.searchPlaceholder"` (or a dedicated `searchAriaLabel` locale string), or a visually-hidden `<label>` tied to the input id.

**AS-A11Y-06 · Cleaner (clear-search) button has no accessible name** **(shared)** — `app-switcher.html:12`.
`<kbq-cleaner />` extends `KbqIconButton` (focusable, `tabindex=0`) but is given no `aria-label`, so a keyboard/AT user hears an unnamed button. WCAG 4.1.2.
**Fix:** `<kbq-cleaner [attr.aria-label]="localeData.clearSearch" />` (add a localized `clearSearch` string), or set a default `aria-label` inside `KbqCleaner` (shared).

### P2 — Should fix

- **AS-BUG-02 · `selectedSite` setter dereferences `originalSites.find()` with no match guard** — `app-switcher.ts:451-458`. `const originValue = this.originalSites.find(s => value.id === s.id)` then `{ ...originValue, apps: [] }` + `makeGroupsForApps(originValue.apps, …)`. A stale/removed id (or `selectedSite` set before `sites`) makes `originValue` undefined → `originValue.apps` throws. **Fix:** `if (!originValue) { this._parsedSelectedSite = value; return; }`; ensure `originalSites` is initialised first.
- **AS-BUG-06 · `currentApps` reads `selectedSite.apps` in sitesMode when `selectedSite` may be unset** — `app-switcher.ts:342-344`. The template iterates `trigger.currentApps` on open, so a multi-site switcher opened without a `selectedSite` crashes render. **Fix:** `return this.sitesMode ? (this.selectedSite?.apps ?? []) : this._parsedApps;` or default `selectedSite` to `originalSites[0]`.
- **AS-BUG-05 · `sites` setter leaves `_parsedSites` stale when switching multi→single** — `app-switcher.ts:375-394`. The single-site branch sets `_parsedApps` but never resets `_parsedSites`, so `get sites()` returns outdated data after a multi→single reassignment. **Fix:** set `this._parsedSites = []` (or rebuild) in the single-site branch.
- **AS-BUG-08 · Search matches only `app.name`, ignoring the visible `app.caption`** — `app-switcher.ts:265`. The list-item renders `caption` as a secondary line, but users can't search it. (The alias/group concern is *not* a bug — search runs over the flat `originalSites`, so grouped apps are reachable.) **Fix:** `app.name…includes(q) || (app.caption?.toLowerCase().includes(q) ?? false)`.
- **AS-ARCH-04 · Dead `closeOnScroll === null` guard disables the nested-scroll auto-hide and moots the "leak" reports** — `app-switcher.ts:322,525`. `private closeOnScroll: null;` is never assigned → runtime `undefined` → `=== null` always false → the `ngAfterContentInit` block (`:526-535`, the `kbq-hide-nested-popup` viewport check) **never runs**. This silently disables a feature *and* explains why the `scrollDispatcher.scrolled()` leak at `:526` (monorepo `BUG-34`) is moot. **Fix:** decide intent — if the auto-hide is wanted, declare `closeOnScroll: boolean | null = null` (and add `takeUntilDestroyed` to the now-live subscription); if not, delete the field and the dead block. Never type a field as the bare `null` literal.
- **AS-RXJS-02 · Nested `closingActions()` subscription leaks into root `ScrollDispatcher` on destroy-while-open** — `app-switcher.ts:538-551`. On `visible===true`, `preventClosingByInnerScrollSubscription = this.closingActions().subscribe(...)` (`:541`); `closingActions()` merges the root `scrollDispatcher.scrolled()` (`:599-605`). It is unsubscribed only in the `visible===false` branch (`:548`), so destroying the directive while the popup is open (host removed via `@if`/route change) never tears it down. **Fix:** pipe the inner subscription with `takeUntilDestroyed(this.destroyRef)` (also lets you drop the manual `else`-branch unsubscribe), or unsubscribe in an `ngOnDestroy` override.
- **AS-TYPE-01 · `configuration` field is implicit `any`, propagated through `localeData` into the template; both `InjectionToken`s untyped** *(merges AS-ARCH-01 + AS-API-01 + AS-API-04.)* — `app-switcher.ts:169-175,130,134`. `configuration;` has no type annotation; `get localeData()` returns it; the template reads `localeData.searchPlaceholder/sitesHeader/searchEmptyResult` (`html:6,74,137`) with zero checking. `KBQ_APP_SWITCHER_CONFIGURATION = new InjectionToken('…')` has no generic, so `externalConfiguration` (the public provider hook) is untyped too. Violates the strict-typing mandate. **Fix:** define `interface KbqAppSwitcherConfiguration { searchPlaceholder; searchEmptyResult; sitesHeader; … }`, type the token `InjectionToken<KbqAppSwitcherConfiguration>`, and annotate `configuration`/`externalConfiguration`/`localeData`. Prefer a `readonly` signal + `computed()` over the mutable reassigned field.
- **AS-API-03 · Two-way bindings implemented via `@Input` + separate `@Output` instead of `model()`** *(merges AS-ARCH-05.)* — `app-switcher.ts:349,446-458,490-492`; list-item `collapsed` `kbq-app-switcher-list-item.ts:70`. `[(selectedApp)]`/`[(selectedSite)]` are real two-way contracts (used in `e2e.ts:16,100-101`) hand-wired with manual `emit()`. The "writes to the input prevents migration" TODOs reflect the migration tool's limitation, not a real block. **Fix:** migrate `selectedApp`/`selectedSite` to `model<…>()` (the `*_Change` outputs become implicit), `collapsed` to `model()`/writable signal, and the read-only `app`/`site` inputs to `input()`. Leave `placement`/`backdropClass`/`offset` (genuinely blocked — base-field overrides / `OverlayConfig` signature) with accurate rationale.
- **AS-API-05 · `KbqAppSwitcherApp.type` is `string | number` but used as `alt` text and group key** — `app-switcher.ts:62,92-99`. `type` is the synthetic group `name`/`Record` key via `.toString()` *and* the `<img alt>`. A numeric category id as an accessible label and a display heading is semantically wrong. **Fix:** narrow `type` to `string` (categories are identifiers); stop using `type` as `alt`/heading — use `app.name`/an explicit label. (Cross-refs AS-A11Y-04.)
- **AS-ARCH-11 · Focus-trap providers live only in the `NgModule`, so standalone consumers silently lose them** — `app-switcher.module.ts:21-25`. The module provides `KBQ_APP_SWITCHER_SCROLL_STRATEGY_FACTORY_PROVIDER`, `FocusTrapFactory → ConfigurableFocusTrapFactory`, and `FOCUS_TRAP_INERT_STRATEGY → EmptyFocusTrapStrategy`. A consumer importing the standalone directive/component directly (the documented v19+ path) never receives them; the scroll strategy is `inject(KBQ_APP_SWITCHER_SCROLL_STRATEGY)` (`:304`) and will throw/fall back without the factory. **Fix:** expose a `provideKbqAppSwitcher()` provider function (or attach the scroll-strategy factory to the directive's `providers`), and document the focus-trap providers for standalone use.
- **AS-A11Y-07 · Empty-search-result not announced (no `role="status"`/live region)** — `app-switcher.html:136-138`. The "nothing found" message is a plain `<div>`. WCAG 4.1.3. **Fix:** add `role="status"` (or `aria-live="polite"`).
- **AS-A11Y-08 · Selected app conveyed by CSS class only (no `aria-current`)** — `app-switcher.html:40,58`. `[class.kbq-selected]` only changes background color (color-alone). WCAG 1.4.1 / 4.1.2. **Fix:** also bind `[attr.aria-current]="app.id === trigger.selectedApp?.id ? 'true' : null"` on the link rows.
- **AS-A11Y-10 · `isTrapFocus` computed and stored but never bound — focus is not actually trapped** — `app-switcher.ts:193,242-244,564`. `updateTrapFocus()` sets `isTrapFocus`, but nothing in `app-switcher.html` consumes it (no `[cdkTrapFocus]`), so focus can escape the open overlay. WCAG 2.4.3. **Fix:** wrap the popup content with `[cdkTrapFocus]="isTrapFocus"` (import `A11yModule`), or remove the dead machinery if trapping is intentionally unwanted.
- **AS-A11Y-11 · Inline-SVG icon container has no `aria-hidden`** — `kbq-app-switcher-list-item.ts:26`, `app-switcher-dropdown-app.ts:16`. Caller SVG (no role/aria) surfaces as an unlabeled graphic beside the visible name. **Fix:** `aria-hidden="true"` on the `…__icon` span (the name is the accessible label). Bundle with AS-A11Y-04.
- **AS-PERF-02 · `filterSites` deep-clones all sites via `structuredClone` on every keystroke, with no debounce** — `app-switcher.ts:261,233`. `structuredClone(originalSites)` is an O(total apps) deep copy per `searchControl.valueChanges` emission, and the subscription is undebounced — and search only ever appears for `appsCount > 7` (dozens–hundreds of apps), exactly the case where it bites. (The "DataCloneError on non-cloneable apps" concern is refuted — the interfaces are plain data — but the cost stands. An isolated perf pass rated this P1; kept P2 to match this repo's review rubric, where per-CD/per-keystroke hotspots are P2.) **Fix:** build the result from shallow copies: `originalSites.map(s => ({ ...s, apps: s.apps.filter(...) })).filter(s => s.apps.length)`; add `debounceTime(...)`/`distinctUntilChanged()`; return `originalSites` directly on the empty query.
- **AS-PERF-01 · Search-results `@for` tracks by object identity over the `structuredClone`d `filteredSites` → full row teardown/rebuild per keystroke** — `app-switcher.html:128,133` (search); cross-refs `:35,79,94,115`. The acute case is the search view: `@for (site of filteredSites; track site)` / `@for (app of site.apps; track app)` iterate the freshly deep-cloned `filteredSites` (AS-PERF-02), so **no** node ever matches the previous reference — Angular destroys and recreates every row (and re-parses every icon, AS-PERF-03) on each keystroke, losing focus/scroll. (The grouped/single-site lists use stable backing-field references — `trigger.sites`→`_parsedSites`, `currentApps`→`selectedSite.apps` — so those are fine *except* when re-parsed, e.g. on a `selectedSite` change; see AS-PERF-07.) **Fix:** fix AS-PERF-02 so references are preserved (identity tracking then reuses rows), or `track` a stable key — careful that synthetic groups use `id:''`, so use `track app.id || app.name` and `track site.id`.
- **AS-PERF-03 · `[innerHtml]="getIcon(app.icon)"` allocates a fresh `SafeHtml` every CD pass** — `kbq-app-switcher-list-item.ts:26,81`, `app-switcher-dropdown-app.ts:16,61`. `getIcon()` is a method call in a binding, returning a new `bypassSecurityTrustHtml(...)` object each change-detection cycle; `[innerHTML]` compares by reference and re-parses the SVG every time (compounding AS-PERF-01: every rebuilt row re-parses too). **Fix:** memoize per app — compute the `SafeHtml` once on input change (a `computed()`/`Map` keyed by the raw icon string), not in the template. (Folds into the AS-SEC-01/02 sanitization rework.)
- **AS-TEST-01 · Cargo-culted `TestScheduler`/`AsyncScheduler` harness — `.run()` never called** — `app-switcher.spec.ts:37,43,110,278,387,536,578,640,682`. A `TestScheduler` is built every `beforeEach` and provided as `AsyncScheduler`, but `.run()` is never invoked and time is driven by `fakeAsync`/`tick`; the marble assertion callback never executes. Dead wiring that implies virtual-time control that isn't there. **Fix:** remove the `TestScheduler`/`AsyncScheduler` import, the per-`beforeEach` construction, and the provider; keep `fakeAsync`/`tick`.
- **AS-TEST-03 · No XSS/sanitization test for `getIcon`** — `app-switcher.spec.ts:427`. The only icon test asserts the span exists; nothing checks that `<img onerror>`/`<script>` markup in `app.icon` is neutralized — the highest-risk behavior is unguarded. **Fix:** set `app.icon` to `<img src=x onerror="window.__xss=1">`, render, assert the handler did not fire / attribute stripped. (Pairs with AS-SEC-05.)
- **AS-TEST-05 · No keyboard-navigation / focus-trap test** — `app-switcher.spec.ts` (absent). No test for opening via keyboard, search-input focus on open, Escape closing + returning focus, arrow navigation, or Tab containment. **Fix:** add keyboard-open, focus-on-open, Escape-close-and-restore-focus, and arrow-navigation tests.
- **AS-TEST-06 · Grouping collapse/expand not covered in a rendered popup** — `app-switcher.spec.ts:57-102` (reducer only), `488-502` (isolated `clickHandler`). `makeGroupsForApps` (`:398-418`) and the rendered group toggle are never exercised end-to-end, including the `> 3` boundary. **Fix:** integration test — site with 4+ same-type apps, open popup, assert one group with a toggle, click it, assert aliases show/hide; boundary test with exactly 3 (no group).
- **AS-TEST-07 · Nested site→app→grouped-app dropdown navigation not tested** — `app-switcher.spec.ts` (absent; only isolated `KbqAppSwitcherDropdownSite` render). **Fix:** open popup → other-sites dropdown → site → grouped app's nested submenu → click alias; assert `selectedAppChange`/`selectedSiteChange` emit and menus close.
- **AS-TEST-09 · `selectedSite` setter id-not-found path untested (the AS-BUG-02 crash)** — `app-switcher.spec.ts:229-245`. Only the present-id path is covered. **Fix:** assign `selectedSite = { id:'does-not-exist', … }` against a known `originalSites` and assert the intended contract (graceful no-op), pinning the AS-BUG-02 fix.
- **AS-TEST-12 · Playwright is two static open-state screenshots — zero interaction** — `e2e.playwright-spec.ts:9-31`. No typed-search/empty-result/nested-dropdown/expanded-group/keyboard-focus/reduced-motion coverage. **Fix:** add interaction snapshots (type a query → results + empty state; open sites dropdown + expand group; keyboard-focused option; `emulateMedia` reduced-motion).

### P3 — Nice to have / hygiene

- **AS-ARCH-07 · God-class directive** — `app-switcher.ts:299-624`. `KbqAppSwitcherTrigger` owns input parsing, the grouping algorithm (`makeGroupsForApps`, `defaultGroupBy` plumbing), overlay positioning, scroll wiring, viewport-hide and class-map. *Umbrella for the modernization phase.* **Fix:** extract grouping/parsing into a pure helper/injectable (also makes it unit-testable without the directive).

- **AS-ARCH-03 / AS-API-07 · Dead/no-op fields + dead `updateData()` writes** — `app-switcher.ts:306-322,558-562`. `arrow`/`customClass`/`hasBackdrop` are `// not used`; `content`/`header`/`footer` are written into the instance in `updateData()` but never populated (and `header`/`footer` aren't even on the base). **Fix:** drop the dead `updateData()` writes and the local `header`/`footer` fields; keep only the abstract base members (`arrow`/`customClass`/`content`) with a clarifying comment (avoid `TemplateRef<any>` → `unknown`).
- **AS-ARCH-12 · `updatePosition()` override duplicates base logic + untracked `setTimeout`** — `app-switcher.ts:573-583`. Near-copy of the base that drops `subscribeOnClosingActions()` (harmless — `show()`/`createOverlay()` already wire closing actions, so monorepo `BUG-55`'s "lost wiring" claim is refuted) and reapplies position via a bare `setTimeout` that can fire post-destroy. **Fix:** call `super.updatePosition()` and layer only the delta; guard the `setTimeout` with `destroyRef`/`overlayRef?.hasAttached()`.
- **AS-BUG-DEFENSIVE (AS-BUG-01 / AS-RXJS-05) · `preventClosingByInnerScrollSubscription.unsubscribe()` not defensively guarded** — `app-switcher.ts:548`. *Two verifiers disagreed; reconciled:* under `distinctUntilChanged`, the trigger's `visibleChange` cannot emit `false` before `true`, so the field is always assigned before the `else` branch — **not a live crash**. - **AS-BUG-09 · `activeSite`/`activeApp` never reset → stale nested-dropdown content** — `app-switcher.html:85,94,103,115`. Set on `mouseenter`, never cleared, so after hovering away the connected dropdown retains the last content until the next `mouseenter`. **Fix:** reset on the dropdown's `closed` event, or drive nested content off the trigger context instead of shared mutable fields. (Cross-refs AS-A11Y-NAV.)
- **AS-BUG-10 · `defaultGroupBy`/`makeGroupsForApps` rely on `aliases!` non-null assertion (fragile for custom `groupBy`)** — `app-switcher.ts:95,411`. Safe for the built-in reducer, but a consumer `groupBy` (validated only as "a function") can emit a group without `aliases` → `aliases!.push`/spread throws. **Fix:** defend in `makeGroupsForApps` (`if (group.aliases?.length > min) …  else if (group.aliases) … else untyped.push(group)`); document the contract.
- **AS-API-02 · Public component + two-way outputs mismarked `@docs-private`** — `app-switcher.ts:136,490,492`. `KbqAppSwitcherComponent` (required in consumer templates as `<kbq-app-switcher [trigger]>`) and `selectedSiteChange`/`selectedAppChange` (the change-half of the public two-way bindings) are `@docs-private`, so consumers get no generated docs for the contract they must use. *(The broader "blanket `@docs-private`" critique is refuted — the pattern is intentional.)* **Fix:** remove `@docs-private` from the component element and the two `*_Change` outputs and document them.
- **AS-API-06 · `groupBy` setter runtime type-check the input type already guarantees** — `app-switcher.ts:431-439`. `throw new Error('The argument must be a function')` on a statically-typed function input converts a compile-time error into a runtime throw; the getter also lacks a return type. **Fix:** drop the throw (or make it a dev-only assert); add the getter's return type.
- **AS-ARCH-02 · Confusing dual meaning of `trigger`** — `app-switcher.ts:190,495`. `@Input() trigger: KbqAppSwitcherTrigger` (component back-reference) vs `trigger: string = 'click, keydown'` (directive event-type) — both relate to base `KbqPopUp.trigger`. Compiles fine (distinct classes) and follows the library's pop-up pattern, but reads as a trap. **Fix:** rename the directive's event-type field to `triggers` / the component back-reference to `triggerDirective`, or at least comment the distinction.
- **AS-ARCH-08 / AS-TPL-02 · Dead `<i class="kbq kbq-icon" [className]="">` element** — `app-switcher-dropdown-app.ts:14`. `[className]=""` wipes the static classes at runtime → renders nothing; ships in every dropdown-app instance. **Fix:** delete the element (the real icon is the `@if (app.icon)` block below).
- **AS-ARCH-09 · File-naming inconsistency** — `kbq-app-switcher-list-item.ts` vs sibling `app-switcher-dropdown-*.ts`. **Fix:** rename to `app-switcher-list-item.ts` (+ `.scss` and imports in `app-switcher.ts:57`, `module.ts:11`, `public-api.ts:6`).
- **AS-A11Y-03 · Decorative icons not `aria-hidden`** **(shared)** — `app-switcher.html:4`, chevrons in `kbq-app-switcher-list-item.ts:42`, `app-switcher-dropdown-app.ts:28`, `app-switcher-dropdown-site.ts:23`. `KbqIcon`'s host sets no `aria-hidden`, so decorative glyphs leak into AT. - **AS-TPL-01 · `href="{{ app.link }}"` renders `href="undefined"` and bypasses `[href]` sanitization context** — `app-switcher.html:38,55,106,117,134`. `link` is optional, so a missing link yields a navigable `href="undefined"`. *(The `javascript:` injection angle is refuted — interpolated `href` is still URL-sanitized by Angular.)* **Fix:** use `[href]="app.link"` (undefined → absent attribute) and guard with `@if (app.link)`; add `rel="noopener noreferrer"` (AS-SEC-03).

No immediate risk (no `target` set), but external app links are the canonical use case; a consumer adding `target="_blank"` gets reverse-tabnabbing + referrer leak. **Fix:** add `rel="noopener noreferrer"` (optionally expose `target`/`rel` on the contract).
