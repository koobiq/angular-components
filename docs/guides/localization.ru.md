## Локализация

Компоненты Koobiq выводят собственные строки — меню фильтров в filter bar, подсказки в code block,
доступные имена всех кнопок-иконок, плейсхолдер поля даты и так далее. Все они приходят из одного места:
`KbqLocaleService`.

Ваши данные не переводятся. Названия опций, значения фильтров, ячейки таблиц и всё остальное, что вы
передаёте в компонент, остаётся ровно таким, как вы его написали.

Доступные идентификаторы локали: `en-US`, `es-LA`, `pt-BR`, `ru-RU` и `tk-TM`.

### Подключение локали

`KbqLocaleService` объявлен как `providedIn: 'root'`, но компоненты читают его через токен
`KBQ_LOCALE_SERVICE`, у которого нет фабрики. Пока вы не предоставите его, локализация не работает:

```ts
import { kbqLocaleServiceProvider } from '@koobiq/components/core';

bootstrapApplication(AppComponent, {
    providers: [kbqLocaleServiceProvider()]
});
```

Без этого провайдера каждый компонент использует собственные значения по умолчанию (`ru-RU`), а смена
локали во время работы приложения ничего не меняет.

Используйте эту функцию, а не `{ provide: KBQ_LOCALE_SERVICE, useClass: KbqLocaleService }`: `useClass` создаёт
**второй** экземпляр, независимый от `providedIn: 'root'`, поэтому `setLocale()`, вызванный на экземпляре из
`inject(KbqLocaleService)`, не двигает ничего отрисованного. `kbqLocaleServiceProvider()` объявляет сервис
рядом с токеном, и обе ссылки указывают на один экземпляр.

Управлять активной локалью можно тремя способами:

- **`KBQ_DEFAULT_LOCALE_ID`** — значение по умолчанию, `ru-RU`. Это обычная экспортируемая константа, а не
  injection token: её нельзя предоставить, только прочитать.
- **`KBQ_LOCALE_ID`**, в виде `kbqLocaleIDProvider(id)`, фиксирует локаль один раз, в момент создания
  `KbqLocaleService`. Провайдер должен лежать в **том же массиве `providers`**, что и сам сервис, потому что
  сервис читает токен из создавшего инжектора.
- **`setLocale(id)`** меняет локаль во время работы приложения.

```ts
providers: [kbqLocaleIDProvider('en-US'), kbqLocaleServiceProvider()];
```

Та же пара в `providers` компонента ограничивает локаль его поддеревом, а остальное приложение сохраняет
свою локаль.

Чтение активной локали:

```ts
readonly localeService = kbqInjectLocaleService();

readonly currentLocale = this.localeService.localeId;   // Signal<KbqLocaleIdLike>
readonly localeData = this.localeService.data;          // Signal<KbqLocaleData>
readonly available = this.localeService.items;          // Signal<KbqLocaleItem[]>, для выбора локали
```

`kbqInjectLocaleService()` читает токен `KBQ_LOCALE_SERVICE`, а не класс. Передайте `{ optional: true }` в коде,
который должен работать и в приложении без сервиса локали.

`changes` — `BehaviorSubject` с идентификатором активной локали; это рабочий способ узнать о смене локали
вне шаблона. А вот геттеры `id` и `current` устарели в пользу сигналов `localeId` и `data`. Сигнал,
прочитанный в шаблоне, регистрируется на читающем представлении, поэтому `setLocale()` во время работы
приложения доходит до `OnPush`-потомков, чего подписка в родителе сделать не может.

### Из чего состоит локаль

Локаль — это набор секций, по одной на область строк. Секция и есть единица переопределения: её имя стоит
и в данных локали, и в `getParams()`, и в `[localeOverrides]`.

| Секция               | Что переводит                                                             | Пакет                 |
| -------------------- | ------------------------------------------------------------------------- | --------------------- |
| `a11y`               | доступные имена кнопок-иконок и областей, которые библиотека рисует сама  | `core`                |
| `select`             | подпись «Выбрать все» и счётчик скрытых значений                          | `core`                |
| `popoverConfirm`     | вопрос и кнопку подтверждающего поповера                                  | `core`                |
| `formatters`         | разделители и сокращения `kbqNumber`, `kbqTableNumber` и `kbqRoundNumber` | `core`                |
| `sizeUnits`          | единицы размера `kbqDataSize`                                             | `core`                |
| `input`              | разделители числового поля ввода                                          | `input`               |
| `datepicker`         | плейсхолдер и формат поля даты                                            | `datepicker`          |
| `timepicker`         | плейсхолдеры поля времени                                                 | `timepicker`          |
| `timezone`           | плейсхолдер поиска часового пояса                                         | `timezone`            |
| `timeRange`          | заголовок и редактор диапазона времени                                    | `time-range`          |
| `codeBlock`          | подсказки кнопок блока кода                                               | `code-block`          |
| `fileUpload`         | тексты областей загрузки одного файла и нескольких                        | `file-upload`         |
| `filterBar`          | поиск, сброс и меню сохранённых фильтров                                  | `filter-bar`          |
| `actionsPanel`       | подсказку закрытия панели действий                                        | `actions-panel`       |
| `clampedText`        | «ещё» и «свернуть» усечённого текста                                      | `clamped-text`        |
| `navbar`             | подсказку сворачивания вертикального navbar                               | `navbar`              |
| `searchExpandable`   | подсказку и плейсхолдер раскрывающегося поиска                            | `search-expandable`   |
| `appSwitcher`        | поиск и заголовок переключателя приложений                                | `app-switcher`        |
| `notificationCenter` | подписи центра уведомлений                                                | `notification-center` |

Полный контракт секции описан её типом `Kbq<Секция>LocaleConfiguration`, где задокументирован каждый ключ.
Токен секции и утилита-провайдер называются механически: `KBQ_<СЕКЦИЯ>_LOCALE_CONFIGURATION` и
`kbq<Секция>LocaleConfigurationProvider()`.

### Переопределение строк одного компонента

Провайдер секции переопределяет только переданные ключи — остальные сохраняют значения по умолчанию:

```ts
import { kbqCodeBlockLocaleConfigurationProvider } from '@koobiq/components/code-block';

providers: [kbqCodeBlockLocaleConfigurationProvider({ copyTooltip: 'Скопировать фрагмент' })];
```

Эти провайдеры работают и в element injector, поэтому провайдер на компоненте ограничивает переопределение
его поддеревом.

<!-- example(code-block-with-custom-locale-configuration) -->

Каждая такая функция поставляется из пакета своего компонента. Исключение —
`kbqSelectLocaleConfigurationProvider`, который живёт в `@koobiq/components/core`: секцию `select` выводят
четыре независимых друг от друга пакета — `kbq-select`, `kbq-tree-select`, `kbq-tree-selection` и
`kbq-list-selection`.

Переопределение накладывается поверх того, что активно: поверх сервиса локали, если приложение его
предоставляет, иначе поверх значений по умолчанию из токена. Поэтому переданные вами ключи остаются
закреплёнными при вызове `setLocale()` во время работы, а все остальные следуют за локалью. Переопределите
секцию целиком, если она вообще не должна следовать за локалью, либо зарегистрируйте собственную локаль
(см. ниже), если переопределение должно переключаться вместе с остальными строками.

### Переопределение строк одного экземпляра

Провайдер можно повесить только на инжектор, поэтому ограничить его одним компонентом — значит завести
отдельную компонентную границу. Все локализованные компоненты принимают строки ещё и как привязку в шаблоне:

```html
<kbq-select [localeOverrides]="{ select: { selectAll: 'Выбрать все' } }" />
```

Значение задаётся по секциям — в том же виде, который принимают `addLocale()` и `KBQ_LOCALE_DATA`, — поэтому
одной привязкой задаются и доступные имена, которые компонент выводит через своих потомков:

```html
<kbq-select
    [localeOverrides]="{
        select: { selectAll: 'Выбрать все' },
        a11y: { clear: 'Очистить выбор' }
    }"
/>
```

<!-- example(select-locale-configuration) -->

Чтобы ограничить переопределение целой областью, а не одним компонентом, повесьте
`KbqLocaleOverridesDirective` на любой свой элемент. Всё, что отображается внутри него, — в том числе
панель, которая открывается в overlay-контейнере, — разрешается относительно него:

```ts
import { KbqLocaleOverridesDirective } from '@koobiq/components/core';
```

```html
<div [kbqLocaleOverrides]="{ a11y: { close: 'Закрыть' } }">
    <kbq-code-block [files]="files" />
    <kbq-filter-bar [filter]="filter" />
</div>
```

Эти два имени не взаимозаменяемы. `[localeOverrides]` — инпут, который открывает компонент Koobiq;
`[kbqLocaleOverrides]` — собственный селектор директивы, для ваших элементов. Селектор, написанный на
компоненте, который уже несёт директиву, сопоставляет её на одном элементе дважды, и Angular отклоняет это
ошибкой `NG0309`.

Источники применяются от самого общего к самому локальному:

1. значения по умолчанию из токена конфигурации;
2. активная локаль;
3. `kbq<Component>LocaleConfigurationProvider()`, начиная с самого внешнего инжектора;
4. `KbqLocaleOverridesDirective`, начиная с самого внешнего элемента;
5. собственный `[localeOverrides]` компонента.

Шаги с 3 по 5 переопределяют только те ключи, которые называют. Шаг 2 — исключение: активная локаль
заменяет значения токена целиком, а не накладывается на них, поэтому значение, переданное в токен
конфигурации, отбрасывается, как только появляется сервис локали. Переопределяйте секцию, а не токен.

Пайп — не элемент, поэтому своего `[localeOverrides]` у `kbqNumber`, `kbqRoundNumber` и `kbqDataSize` нет.
Носитель на предке до них доходит: пайп разрешает секцию по тому же инжектору, что и обычный читатель.

### Регистрация собственной локали

`addLocale()` принимает частичные данные — каждая секция и каждый ключ внутри секции необязательны. Всё,
что вы не указали, дополняется из поставляемой локали с тем же идентификатором, а для нового
идентификатора — из `KBQ_DEFAULT_LOCALE_ID`. Поэтому `getParams()` всегда возвращает полную секцию,
что бы вы ни зарегистрировали:

```ts
localeService.addLocale('en-GB', {
    select: { selectAll: 'Select everything' },
    a11y: { close: 'Dismiss' }
});
```

Параметр типизирован как `KbqPartialLocaleData`, поэтому опечатка в названии секции или ключа — это ошибка
компиляции, а не строка, которая молча никогда не появится.

Те же данные можно передать заранее через `KBQ_LOCALE_DATA`. Токен читается один раз, конструктором
`KbqLocaleService`, поэтому провайдер должен лежать в том же массиве `providers`, что и сам сервис:

```ts
const localeData = {
    'en-GB': { select: { selectAll: 'Select everything' } }
} satisfies KbqLocaleDataInput;

providers: [{ provide: KBQ_LOCALE_DATA, useValue: localeData }, kbqLocaleServiceProvider()];
```

`satisfies` здесь несущий: `useValue` объявлен как `any`, и без него та же опечатка пройдёт молча.

Локаль, добавленная таким образом, регистрируется, но в список `items` не попадает — а именно его читает
пикер локали. Если новая локаль должна быть доступна для выбора, перечислите `items` целиком, вместе с
поставляемыми локалями.

### Чтение секции напрямую

```ts
const { selectAll } = localeService.getParams('select'); // KbqSelectLocaleConfiguration
const select = localeService.params('select'); // Signal<KbqSelectLocaleConfiguration>
```

Название секции проверяется по `KbqLocaleSection`, а тип результата выводится из него.

Оба варианта читают только локаль. Компонент, которому нужны и переопределения выше — провайдеры и
`[localeOverrides]`, — объявляет директиву и читает через неё:

```ts
import { inject } from '@angular/core';
import { KBQ_SELECT_LOCALE_CONFIGURATION, KbqLocaleOverridesDirective } from '@koobiq/components/core';

@Component({
    selector: 'my-widget',
    hostDirectives: [
        { directive: KbqLocaleOverridesDirective, inputs: ['kbqLocaleOverrides: localeOverrides'] }
    ]
})
export class MyWidget {
    protected readonly localeConfiguration = inject(KbqLocaleOverridesDirective, { self: true }).read(
        'select',
        KBQ_SELECT_LOCALE_CONFIGURATION
    );
}
```

`{ self: true }` здесь обязательно: с `{ host: true }` Angular поднимется до хост-элемента охватывающего
компонента и вернёт **его** носитель, так что компонент прочитает чужие переопределения вместо своих.
Запись `hostDirectives` приходится повторять литералом в каждом компоненте: вынесенная в константу, она
падает с `NG1010` при использовании из другой точки входа.

Называйте член `localeConfiguration` — это принятое в библиотеке имя разрешённых строк, которые компонент
читает; оно отделено от `[localeOverrides]`, который задаёт частичное переопределение. Компонент, читающий вторую
секцию, уточняет имя — как это делает `a11yLocaleConfiguration`.

`read()` возвращает сигнал, поэтому `setLocale()` доходит до шаблона сам, а источники сливаются в
перечисленном выше порядке. Чтение через носитель — это и есть то, что заставляет `[localeOverrides]`
работать на вашем компоненте: одно без другого не бывает. Там, где носитель поставить некуда — в пайпе или
в содержимом, которое вы создаёте сами, — те же источники читает
`kbqInjectLocaleConfiguration(section, token)`.

### Даты и числа

Адаптеры дат и числовые пайпы используют тот же сервис, но им нужны собственные провайдеры.
`KbqLocaleServiceModule` — его подключают модули адаптеров дат — объявляет сервис за вас.

<!-- example(number-formatter-locale) -->

Чтобы ограничить локаль поддеревом, в котором есть даты, объявите адаптер и форматтер в `providers` того же
компонента, что и `kbqLocaleIDProvider`. Импорт модуля для этого не годится: `imports: [KbqLuxonDateModule]`
помещает адаптер в environment injector, где он получит корневой сервис локали, и названия месяцев
останутся на языке всего приложения, а не этого поддерева.
