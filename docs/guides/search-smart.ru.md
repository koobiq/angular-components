Поле поиска оставляет сопоставление на усмотрение потребителя, и по умолчанию обычно используется поиск подстроки.

Такой поиск не справляется с запросами из нескольких слов. Например, запрос `10.125 all` не найдёт `10.125.123.0/24 - all` — строка не содержит его целиком как подстроку. А по смыслу это именно то, что искал пользователь.

Ниже — принципы, которые мы реализовали для поиска. Их эталонная реализация — набор функций `normalizeSearchValue`, `tokenizeSearchQuery` и `createSearchPredicate` из `@koobiq/components/core`. Реализация опциональна и не меняет поведение компонентов по умолчанию — подключайте её в свою логику фильтрации так же, как сегодня подключаете поиск подстроки.

### Регистр не должен иметь значения

Поиск, чувствительный к регистру, пропускает совпадения только из-за разницы в регистре символов, хотя по смыслу строки совпадают. Сравнение приводит `WORLD`, `world` и `World` к одному и тому же значению.

### Обрезка краёв без схлопывания середины

Обрезаются только пробелы по краям введённой строки. Пробелы внутри значения не затрагиваются: их схлопывание могло бы слить два отдельных слова в одно и незаметно изменить смысл фразы.

### Токенизация запроса с совпадением по всем токенам

Многословный запрос разбивается на независимые токены, которые сопоставляются по отдельности. Совпадением считается результат, в котором найдены все токены (логическое И между токенами).

Токены в двойных кавычках — это одна неразрывная фраза. Она требует точного совпадения текста вместе с пробелами, когда обычной токенизации недостаточно.

### Диакритика сворачивается, а не игнорируется

Диакритические знаки — это надстрочные, подстрочные или внутри строчные пометки при буквах. Они уточняют произношение: например, `é`, `ü` или `ç`. Такой знак можно отделить от базовой буквы Unicode-нормализацией (`é` → `e` + отдельный «плавающий» акцент), а затем убрать.

</div>
</div>

Пользователи часто не набирают диакритические знаки, а данные не всегда хранят их последовательно. Поэтому `cafe` и `café` должны находить друг друга — независимо от того, что ввели и что хранится.

Диакритика сворачивается к базовой букве, а не вырезается вместе с остальными символами. Пунктуация вроде `/`, `-` и `.` не затрагивается, поэтому IP-диапазоны и похожие значения не ломаются тем же проходом.

Подсветка совпадения, если она есть в интерфейсе, тоже должна знать о свёртке: подсветка, которая сравнивает буквально, не найдёт, что помечать в совпадении, найденном через свёртку, — токен и значение отличаются ровно на тот акцент, из-за которого они совпали. У `kbqHighlightBackground`/`mcHighlight` для этого есть аргумент `foldDiacritics`: передайте `true`, если ключевые слова сопоставлялись со свёрткой (например, через `createSearchPredicate`), — тогда поиск `cafe` подсветит `Café`, а не оставит его без пометки, как в примерах ниже.

### Токен проверяется сразу по нескольким полям

Какие поля участвуют в поиске — решение вызывающего кода, а не логики сопоставления: это зависит от структуры данных. Токен засчитывается, если он найден хотя бы в одном из полей (ИЛИ по полям, И по токенам):

```ts
const matches = createSearchPredicate('10.125 guest');
matches(['10.125.11.0/24', 'guest network']); // true — «10.125» найден в первом поле, «guest» — во втором
matches(['10.125.11.0/24', 'production']); // false — «guest» не найден ни в одном поле
```

### Ранжирование по релевантности

Логика сопоставления отвечает только на вопрос «подходит или нет» — она не ранжирует результаты. Порядок по релевантности можно добавить поверх, например отдельной библиотекой скоринга, которая работает параллельно с `createSearchPredicate`/`tokenizeSearchQuery`:

```ts
const tokens = tokenizeSearchQuery(query);

options.filter(createSearchPredicate(query)).sort(rankByRelevance(tokens));
```

### Чего здесь осознанно нет

/* cspell:disable-next-line */
Толерантность к опечаткам в эти принципы не входит — например, поиск по расстоянию редактирования, при котором `developr` находит `developer`. Это отдельная и куда более крупная задача. Если она нужна продукту, лучше подключить специализированную библиотеку fuzzy-поиска, чем наращивать собственную логику сопоставления.
