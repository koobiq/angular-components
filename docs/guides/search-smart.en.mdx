Substring search works for simple queries, but it does not find a value whose query parts are separated by other characters. For example, the query `10.125 all` does not find `10.125.123.0/24 - all`, even though both fragments are in the value.

Smart search splits a multi-word query into tokens and looks for each token separately. That is why it finds the values that match the query.

The `normalizeSearchValue`, `tokenizeSearchQuery` and `createSearchPredicate` functions from `@koobiq/components/core` implement these principles. The implementation is opt-in and does not change how components behave by default. You can add it to your own filtering logic.

### Case

A case-sensitive search treats strings as different because of a difference in case, even though they mean the same. For comparison, `WORLD`, `world` and `World` are reduced to one value.

### Spaces at the edges

The algorithm removes spaces at the start and end of the entered string. Inner spaces are kept: removing or collapsing them can change the meaning of a phrase.

### Query tokens

A multi-word query is split into independent tokens. A value counts as a match only if all the tokens are found in it.

The order of tokens does not matter. For example, the queries `10.125 all` and `all 10.125` find the value `10.125.123.0/24 - all`.

Text in double quotes counts as one token. The spaces inside it take part in the comparison, so a quoted query requires an exact match of the phrase.

There is no minimum token length. For example, the token `a` finds `all`.

### Diacritics

Diacritics are marks above, below or inside letters. They include, for example, the marks in `é`, `ü` and `ç`.

Smart search separates diacritics from the base letters and compares the result without them. So the value `Café Wi-Fi` is found by the queries `cafe` and `café`, whichever of them is typed.

Punctuation is not removed. The characters `/`, `-` and `.` are kept, so IP ranges and similar values stay unchanged.

Match highlighting also has to take diacritic folding into account. The `kbqHighlightBackground` and `kbqHighlightBold` functions have a `foldDiacritics` argument. Pass `true` to it if the keywords were matched with folding, for example through `createSearchPredicate`. The query `cafe` then highlights `Café`.

### Search across several fields

Which fields take part in a search is decided by the calling code. It depends on the structure of the data.

A token counts as found if it matches at least one field. All tokens have to be found in at least one of the fields:

```ts
const matches = createSearchPredicate('10.125 guest');

matches(['10.125.11.0/24', 'guest network']); // true — "10.125" is found in the first field, "guest" in the second
matches(['10.125.11.0/24', 'production']); // false — "guest" is not found in any field
```

### Ranking results

The matching logic determines whether a value matches the query, but does not rank the results.

To order the results by relevance, add a separate ranking algorithm:

```ts
const tokens = tokenizeSearchQuery(query);
options.filter(createSearchPredicate(query)).sort(rankByRelevance(tokens));
```

### Limitations

{/* cspell:disable-next-line */}

Smart search does not correct typos. For example, the query `developr` does not find `developer`.

Edit-distance search is a separate task. A dedicated fuzzy-search library suits it better than extending your own matching logic.
