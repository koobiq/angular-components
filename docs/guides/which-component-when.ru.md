# Какой компонент когда

Сопоставляет **задачу** с компонентом Koobiq и называет соседний компонент, с которым его путают.

Написан для инструмента `which_component_when` MCP-сервера Koobiq. Агент без этой карты берёт компонент, чьё имя
похоже на слово из запроса, — частая ошибка не «ничего не нашёл», а «нашёл соседа»: `autocomplete` вместо
множественного выбора, `toast` для сообщения, которое нужно подтвердить, `tabs` вместо элемента формы.

## Как читать

- [Разграничение](#разграничение) — кластеры, где берут соседа. Полезная часть, читать первой.
- [Указатель компонентов](#указатель-компонентов) — по строке на компонент, сгруппированы по выполняемой работе.
- [Указатель слов](#указатель-слов) — слова, которые вероятно будут в запросе, и кластер, который их решает.

Каждая строка разграничения отвечает на три вопроса: что взять, что не брать и почему не брать. «Почему не» —
именно то, что агент не может восстановить из имён компонентов.

## Откуда это взято

Документация компонентов содержит прозу об использовании примерно для трети библиотеки:

| Источник                                            | Что там на самом деле                                                                                                                                                              |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/components/*/<id>.ru.mdx` — вводный абзац | Есть у каждого компонента. Одно предложение, говорит _что_ это; _когда_ — только по смыслу                                                                                         |
| `### Когда использовать`                            | 7 компонентов: `tree`, `modal`, `sidepanel`, `timepicker`, `loader-overlay`, `link`, `dynamic-translation`                                                                         |
| `### Рекомендации`                                  | 15 компонентов: `accordion`, `badge`, `button-group`, `inline-edit`, `list`, `popover`, `radio`, `select`, `skeleton`, `split-button`, `tabs`, `tag`, `title`, `toggle`, `tooltip` |
| `modal.ru.mdx` → `### Связанные компоненты`         | Самый богатый сравнительный текст в репозитории: modal против popover, sidepanel, встроенных форм, accordion, toast, новой страницы, отмены действия                               |
| Перекрёстные ссылки в прозе                         | Разрозненные «используйте X вместо»: `list` → `select`/`tree`, `title` → `tooltip`/`popover`, `tag` → `badge`, `tabs` → `navbar`                                                   |
| `*.en.mdx`                                          | Точное зеркало русских страниц — те же разделы, то же количество. Дополнительных указаний нет                                                                                      |
| `packages/docs-examples/**` `@title`                | 623 заголовка, но они называют возможности («Select multiple»), а не задачи. Годятся только как ключевые слова                                                                     |
| `apps/docs/src/llms.txt`, `llms-full.txt`           | Указатель ссылок и тот же текст MDX. Своих формулировок нет                                                                                                                        |

Всё остальное ниже — кластеры, «почему не», построчные описания примерно 50 компонентов, которые документируют
только что они такое, — написано для этого гайда по документации, публичному API и коду компонентов. Держим это
здесь, а не растаскиваем обратно по страницам MDX: сравнения пересекают границы компонентов, и страница про один
компонент — неподходящее место, чтобы говорить, какой другой компонент выигрывает.

Файл читается MCP-сервером как обычный гайд: `build-guides.ts` берёт его из `docs/guides` вместе с остальными,
на двух языках. Единственный источник правды — этот файл, не копия внутри сервера.

## Разграничение

### Выбрать значение из набора

| Задача                                                          | Взять                                                 | Не брать              | Почему не                                                                               |
| --------------------------------------------------------------- | ----------------------------------------------------- | --------------------- | --------------------------------------------------------------------------------------- |
| Одно значение из закрытого списка, в форме                      | `select`                                              | `autocomplete`        | Автокомплит — текстовое поле с подсказками; он принимает то, что вводит пользователь    |
| Несколько значений из закрытого списка                          | `select` + `multiple`                                 | `autocomplete`        | У автокомплита вообще нет входа `multiple`                                              |
| Несколько значений из длинного списка (сотни)                   | `select` + `multiple` + поиск + виртуальная прокрутка | `tree-select`         | Tree select — для данных, которые _являются_ иерархией, а не просто длинные             |
| Несколько значений из иерархии                                  | `tree-select` + `multiple`                            | `select`              | Select уплощает: связь родитель-потомок теряется                                        |
| Одно значение, список приходит с сервера по мере ввода          | `autocomplete`                                        | `select`              | Select владеет своим списком опций; у него нет текстового поля для запроса              |
| Несколько значений, пользователь может ввести своё              | `tag-autocomplete`                                    | `select` + `multiple` | Select не может принять значение, которого нет среди опций                              |
| Несколько произвольных значений, словаря нет                    | `tag-input`                                           | `tag-autocomplete`    | Выпадающий список автокомплита, которому нечего подсказать, — это шум                   |
| Показать и удалять значения, выбранные в другом месте           | `tag-list`                                            | `tag-input`           | Tag input ещё и _вводит_ значения; набору только для чтения это не нужно                |
| 2–7 взаимоисключающих опций, все видны                          | `radio`                                               | `select`              | Прятать горстку опций за триггером — лишний клик без выгоды                             |
| Больше 7 взаимоисключающих опций                                | `select`                                              | `radio`               | Документация ограничивает группу радиокнопок примерно 7 строками                        |
| 3–5 взаимоисключающих опций, короткие подписи, есть место в ряд | `button-toggle`                                       | `radio`, `tabs`       | Radio тратит строку на опцию; tabs переключают содержимое и не являются элементом формы |
| Независимые опции вкл/выкл, сохраняются вместе с формой         | `checkbox`                                            | `toggle`              | Тоггл обещает, что изменение уже применилось                                            |
| Одна настройка, применяется сразу                               | `toggle`                                              | `checkbox`            | Чекбокс подразумевает последующее «Сохранить»                                           |
| Частично выбранный заголовок группы                             | `checkbox` + `indeterminate`                          | два чекбокса          | Третье состояние встроено                                                               |
| Выбрать строки содержимого страницы, а не значение формы        | `list` + `multiple="checkbox"`                        | `select`              | Select — элемент формы за триггером; список — это содержимое                            |
| Сотни элементов в иерархии                                      | `tree`                                                | `list`                | Документация: без иерархии и объёма обычный список лучше                                |
| Меню команд                                                     | `dropdown`                                            | `select`              | Select хранит значение; dropdown запускает действия                                     |

Для длинного множественного выбора: спроецируйте `[kbqSelectSearch]` в панель (документация рекомендует поиск
начиная с 10 опций) и оберните опции в `cdk-virtual-scroll-viewport`. При объектных значениях передайте
`virtualOptionFactory`, чтобы триггер мог подписать значение, чья опция не отрисована. Строка «выбрать всё» не
отрисовывается вместе с виртуальной прокруткой — она может действовать только на отрисованные опции.

### Показать, что что-то выполняется

| Задача                                                               | Взять                            | Не брать              | Почему не                                                                              |
| -------------------------------------------------------------------- | -------------------------------- | --------------------- | -------------------------------------------------------------------------------------- |
| Доля работы известна и её стоит показать                             | `progress-bar`                   | `progress-spinner`    | Спиннер не может показать, сколько осталось; поставьте время рядом с полосой           |
| Длительность неизвестна, ожидание короткое, мало места, один элемент | `progress-spinner`               | `progress-bar`        | Полоса с `indeterminate` заявляет ширину, которой у неё нет                            |
| Целый блок занят и его нельзя трогать                                | `loader-overlay`                 | `progress-spinner`    | Голый спиннер не блокирует взаимодействие с блоком под ним                             |
| Загрузка содержимого страницы или раздела, 2–10 с                    | `skeleton`                       | `progress-spinner`    | Документация: скелетоны подходят для загрузки целой страницы и не дают вёрстке прыгать |
| Загрузка занимает меньше 1 с                                         | ничего                           | `skeleton`            | Документация: меньше секунды индикатор не нужен                                        |
| Собственное действие кнопки занимает больше 1–2 с                    | `class="kbq-progress"` на кнопке | `loader-overlay`      | Перекрывать страницу ради одной кнопки непропорционально                               |
| Долгая загрузка файлов                                               | `file-upload` (свой прогресс)    | только `progress-bar` | Компонент уже сообщает состояние по каждому файлу                                      |

| ------------------------------------------------------------------------ | -------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------ |

| Ошибки валидации одного поля                                             | подсказки `form-field` + `ErrorStateMatcher` | `alert`               | Матчер решает, _когда_ показать ошибки; поле их отрисовывает                               |

## Указатель компонентов

По строке на каждый: когда за ним тянуться. `→` называет соседа, которого стоит предпочесть в следующем случае.

### Выбор значений

- `select` — одно или несколько значений из списка, которым владеет приложение; поиск начиная с 10 опций, виртуальная прокрутка для длинных списков. → `autocomplete`, когда значение вводят, `tree-select`, когда данные иерархичны.
- `tree-select` — одно или несколько значений из иерархических данных, дерево остаётся видимым при поиске.
- `autocomplete` — текстовое поле, подсказывающее совпадения при вводе, в том числе с сервера; одно значение.
- `tag-autocomplete` — несколько значений из словаря с возможностью своих значений; выпадающий список — панель автокомплита.
- `tag-input` — несколько произвольных значений, вводимых как теги.
- `tag-list` — набор тегов с навигацией с клавиатуры, выделением и удалением; своего ввода нет.
- `tag` — один токен внутри элемента ввода. → `badge` для самостоятельной метки.
- `list` — связанные элементы как содержимое страницы, одиночный или множественный выбор (`multiple="checkbox"`, когда состояние должно быть видно сразу); виртуальная прокрутка для длинных списков, но не вместе с перетаскиванием.
- `tree` — сотни элементов, по которым пользователь ходит как по каталогу. → `list` без иерархии и объёма.
- `radio` — до примерно 7 взаимоисключающих опций, все видны.
- `checkbox` — независимые опции и состояние группы через `indeterminate`.
- `toggle` — двоичная настройка, применяемая немедленно, без сохранения.
- `button-toggle` — 3–5 коротких взаимоисключающих опций в один ряд, в форме или фильтре.
- `dropdown` — меню действий или опций рядом с триггером, с состояниями отключения, загрузки и подвалом.
- `timezone` — выбор часового пояса; `kbq-select` с шаблоном опции часового пояса, без множественного выбора.
- `time-range` — период: предустановка или границы, введённые вручную.

### Ввод данных

- `form-field` — обёртка, дающая элементу управления подпись, подсказку, ошибку и очистку; input, select, textarea, autocomplete, tag input, tag autocomplete, timepicker, timezone и tree select сделаны, чтобы стоять внутри неё.
- `input` — ввод текста, чисел и паролей с форматированием, масками и валидацией.
- `textarea` — многострочный текст.
- `datepicker` — дата, введённая или выбранная в календаре; `minDate`/`maxDate` ограничивают календарь, `min`/`max` на поле управляют валидацией.
- `timepicker` — время, вводимое в поле с маской.
- `file-upload` — файлы, один или несколько, с областью перетаскивания, размерами, иконками и ошибками по каждому файлу.
- `search-expandable` — поле поиска, раскрывающееся из иконки-кнопки; это элемент формы и без неё он падает.
- `inline-edit` — редактирование значения там, где оно показано, с немедленным сохранением. → форма для создания, зависимых полей, сложной валидации или критичных данных.
- `filter-bar` — фильтрация таблицы или списка: типизированные пайпы, поиск внутри пайпов, обязательные и заблокированные фильтры, сохранённые фильтры, восстановление состояния.

### Действия

- `button` — действие, на нативном `<button>` или `<a>`; `kbq-progress` для действий дольше 1–2 с.
- `icon-button` — действие, которому не нужна подпись.
- `button-group` — кнопки, которые относятся друг к другу, оформленные как один элемент. → `split-button` для основного действия и его вариантов, `button-toggle` для выбора значения.
- `split-button` — одно доминирующее действие плюс меню его вариантов. Только когда одно действие покрывает большую часть случаев; иначе `dropdown`.
- `actions-panel` — панель массовых действий над текущим выделением, со счётчиком.
- `link` — навигация между страницами; вариант псевдоссылки для кнопки внутри текста.

### Обратная связь и состояние

- `alert` — постоянное сообщение в странице: подсказка, изменение статуса, проблема. Незакрываемый, когда о проблеме сообщает система.
- `toast` — исчезающее сообщение в углу, когда ответ не требуется и пропустить его допустимо.
- `modal` — окно, блокирующее страницу, для короткой задачи или ответа, которого ждёт система. → `popover`, `sidepanel`, встроенная форма или отмена везде, где модальности можно избежать.
- `notification-center` — список уведомлений приложения, открывается из navbar, сгруппирован по датам, со счётчиком непрочитанных.
- `empty-state` — заглушка там, где нет содержимого, результатов или успешной загрузки.
- `progress-bar` — измеримая доля долгого процесса, лучше с оставшимся временем рядом.
- `progress-spinner` — неизмеримое или короткое ожидание либо загрузка одного элемента.
- `loader-overlay` — занятый блок с подавленным взаимодействием.
- `skeleton` — форма содержимого, которое грузится 2–10 с, чтобы вёрстка не прыгала.
- `badge` — статус, счётчик или характеристика объекта, сам по себе.

### Слои поверх страницы

- `popover` — немодальный диалог у триггера, может содержать поля и кнопки; захватывает фокус и поддерживает Tab внутри.
- `tooltip` — короткая подсказка по наведению или фокусу, только текст.
- `kbq-title` — тот же тултип, но только когда текст элемента действительно обрезан.
- `sidepanel` — окно, выезжающее от края поверх страницы, модальное или нет; немодальные панели складываются со смещением. Для большого объёма данных в высоком макете.
- `content-panel` — панель, которая выезжает и сдвигает соседнее содержимое, обычно быстрый предпросмотр строки таблицы.
- `dropdown` — см. «Выбор значений».

### Макет и структура

- `sidebar` — сворачиваемое боковое содержимое, часть макета, с сохранением состояния.
- `splitter` — соседние панели, размер которых меняют перетаскиванием разделителя, с ограничениями, примагничиванием и сворачиванием.
- `resizer` — директива, меняющая размер одного элемента в заданном направлении перетаскиванием.
- `divider` — разделительная линия, горизонтальная или вертикальная.
- `accordion` — блоки содержимого, которые пользователь раскрывает по необходимости, в логическом порядке и с заголовками, говорящими что внутри.
- `tabs` — группы содержимого на одной странице, переключаются без перезагрузки. → `navbar` для основной навигации, `button-toggle` или `dropdown` для переключения вида одних данных, `radio`/`button-toggle` в формах.
- `scrollbar` — стилизованная полоса прокрутки (`hover`, `always`, `native`, `hidden`), программная прокрутка и события; `kbqScrollbarViewport` для `cdk-virtual-scroll-viewport`, `kbqNativeScrollbar` чтобы перекрасить браузерную.
- `overflow-items` — ряд элементов, сворачивающийся по ширине контейнера, с конца или с начала.
- `clamped-text` — длинный текст, свёрнутый до количества строк, с триггером раскрытия.
- `clamped-list` — длинный список, свёрнутый до количества элементов, с триггером раскрытия.
- `ellipsis-center` — одна строка, обрезанная посередине, с читаемыми началом и концом.
- `layout-flex` — CSS-классы для расположения, выравнивания и порядка flex-потомков.

### Навигация

- `navbar` — основное меню продукта, сверху или слева, с местом для свитчера приложений, главного действия, центра уведомлений и поиска.
- `top-bar` — панель инструментов, остающаяся видимой на экране: логотип, заголовок, хлебные крошки, действия.
- `breadcrumbs` — путь до текущей страницы, сворачивается в dropdown по `max`; каждому элементу нужен `routerLink`.
- `app-switcher` — переключение между приложениями и платформами.

### Отображение данных

- `table` — обычная HTML-таблица со стилями Koobiq, залипающей шапкой и настройками границ; без сортировки и изменения ширины колонок. → AG Grid для любого из двух.
- `dl` — пары «термин — описание», адаптивные, горизонтальные или вертикальные, при желании с изменяемой шириной колонок.
- `username` — атрибуты, идентифицирующие внутреннего пользователя системы.
- `flag` — флаг страны, оформленный и кадрированный из изображения, которое вы проецируете или передаёте в `svg`.
- `icon` — иконка из шрифта `@koobiq/icons`.
- `icon-item` — иконка на подложке, когда графика должна привлекать внимание вместо иллюстрации.

### Отрисовка содержимого

- `markdown` — строка Markdown, отрисованная как HTML; нужен `marked`.
- `code-block` — исходный код с подсветкой синтаксиса; нужен `highlight.js@^11`.
- `dynamic-translation` — компоненты, ссылки и оформленные фрагменты, встроенные в уже переведённую строку.
- пайпы `kbqHighlightBackground` / `mcHighlight` — найденная подстрока, размеченная в результате фоном или жирным.

### Не компоненты

- `core` — общая точка входа: поведения, доступность, коды клавиш, локали, помощники оверлеев, модели выделения, темизация, форматтеры, валидаторы и тестовые помощники.
- `DateFormatter` — даты и время в корпоративном формате, с учётом активной локали.
- Форматтеры чисел и размеров файлов — числа и размеры в байтах по правилам текущей локали.
- `ErrorStateMatcher` — политика, решающая, _когда_ элемент управления показывает уже имеющиеся у него ошибки.
- Утилиты раскладки форм — расположение полей, подписей, подсказок и сообщений в горизонтальных, вертикальных или сгруппированных раскладках.
- Типографика и темизация — шкала шрифтов и темы на токенах; см. гайд по темизации.

## Указатель слов

Слова, которые вероятно будут в запросе → кластер, который их решает.

- мультиселект, множественный выбор, несколько значений, чипсы, токены, 500 опций, длинный список, виртуальная прокрутка → Выбрать значение из набора
- поле поиска, подсказки при вводе, автодополнение, словарь, своё значение → Выбрать значение из набора
- вкл/выкл, переключатель, мгновенная настройка, группа чекбоксов, частично выбрано → Выбрать значение из набора
- загрузка, спиннер, проценты, оставшееся время, заглушка, скелетон, занятый блок → Показать, что что-то выполняется
- ошибка, предупреждение, успех, подтвердить, «вы уверены», уведомить, пропущенное сообщение, история сообщений → Сообщить пользователю
- пусто, нет данных, нет результатов, ничего не найдено, не удалось загрузить → Сообщить пользователю
- диалог, окно, шторка, панель, предпросмотр, блокирует страницу, стопка → Дополнительный слой над страницей
- подсказка, наведение, обрезан, многоточие, три точки, «показать ещё», свернуть, по ширине → Текст, который не помещается
- таблица, грид, сортировка, ширина колонок, ключ-значение, атрибуты, фильтры, подсветка совпадений → Табличные и структурированные данные
- меню, основная навигация, панель инструментов, хлебные крошки, вкладки, разделы, переключить вид, другое приложение → Навигация
- редактирование на месте, карандаш, сохранить сразу, форма, дата, время, период, часовой пояс, загрузка файлов → Редактирование существующих данных
- метка, статус, счётчик, страна, аватар, пользователь, кликабельная иконка → Метки, обозначения, личность
