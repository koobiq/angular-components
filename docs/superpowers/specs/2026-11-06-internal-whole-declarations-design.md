# `@internal` только для целых сущностей — дизайн

Дата: 2026-11-06. Статус: утверждён. Reviewer: важных незакрытых вопросов нет.

## Зачем

В опубликованных пакетах включён `stripInternal`: `@internal` удаляет объявление из `.d.ts`, но оставляет его в JavaScript. Сейчас тег стоит не только на целых сущностях, но и на методах, полях и accessors экспортируемых классов. Это создаёт разницу между исходным/runtime-обликом класса и его опубликованным типом, а на переопределениях может вообще не скрывать член: объявление базового класса остаётся унаследованным.

Принятое продуктовое решение: `@internal` должен скрывать только целые сущности, а не отдельные члены типов. Для членов, которые должны остаться в типах, но не должны попадать на API-вкладку документации, используется `@docs-private`.

## Текущее состояние

В `packages/components` найден 101 соответствующий declaration с `@internal`:

- 39 целых declarations: классы, интерфейсы, enum, функции и переменные;
- 62 члена классов в 30 файлах: 7 public-методов, 7 protected-методов и 48 полей/accessors.

В `packages/components-experimental` и обоих date adapters сейчас применений нет. Общий JSDoc ESLint-config действует и на них.

Уже существуют ограничения: нельзя ссылаться на `@internal` из другого entry point или публичной сигнатуры, удалять члены, необходимые интерфейсам и структурным типам, и удалять declarations с именованным реэкспортом. `check-typings` проверяет собранные `.d.ts` с `skipLibCheck: false`.

## Цели

- Запретить `@internal` у членов классов, интерфейсов/type literals и enum, включая методы, поля, accessors и parameter properties.
- Перевести все 62 существующих члена классов на `@docs-private` без изменения runtime-кода и архитектуры компонентов.
- Оставить `@internal` на целых declarations, которые действительно являются внутренними и не нужны восстановленным сигнатурам.
- Закрепить правило в ESLint и `.claude/rules/components.md`; adapters уже ссылаются на JSDoc-правила этого файла.
- Обновить сгенерированные API-снимки штатными командами и проверить целостность опубликованных типов.

## Не-цели и анти-цели

- Не менять поведение, шаблоны, DI, видимость членов в TypeScript и взаимодействие классов.
- Не выносить public-методы в отдельные сущности и не делать члены `private` ради соблюдения правила о теге.
- Не отключать `stripInternal` и не заменять `@internal` на `@docs-private` без разбора на всех целых сущностях.
- Не считать `@internal` механизмом runtime-инкапсуляции: JavaScript по-прежнему содержит реализацию.
- Не оставлять публичную или protected-сигнатуру, ссылающуюся на удалённый из `.d.ts` тип.
- Не редактировать вручную `tools/public_api_guard/**` и baseline-файлы.
- Не увеличивать счётчики `any`/`unknown` ради механической миграции.

## Подходы

### 1. Единая миграция без изменения кода — выбран

Заменить `@internal` на `@docs-private` у всех существующих членов классов, добавить запрет в ESLint и восстановить зависимости сигнатур. Runtime и документация не меняются; опубликованные типы расширяются. Это позволяет проверить само правило без побочных изменений компонентов.

### 2. Гибрид с изменением public-методов — отклонён

Protected-члены переводятся на `@docs-private`, а 7 public-методов по возможности выносятся из классов или становятся `private`. Так типы расширились бы меньше, но изменилась бы рабочая кооперация классов и появился бы риск регрессий. Часть методов всё равно потребовала бы `@docs-private`.

## Устройство изменений

### Миграция существующих declarations

- В 30 файлах заменить только тег `@internal` на `@docs-private` у 62 членов классов, сохранив описания и форматирование JSDoc.
- Не менять 39 целых declarations автоматически. Если восстановленная сигнатура требует такой declaration в опубликованных типах, перевести необходимый тип на `@docs-private` и объяснить это в итоговом diff.
- Пример необходимых зависимостей: после восстановления `KbqSidepanelContainer.animationState`, `animationStateChanged` и `setAnimationState()` типы `KbqSidepanelAnimationState` и `KbqSidepanelAnimationEvent` должны остаться в `.d.ts`. Внутренняя `kbqSidepanelTransformAnimation` сама по себе в восстановленной сигнатуре не участвует и может остаться `@internal`.
- У переопределений использовать `@docs-private`, как у остальных членов. Не полагаться на удаление override как на скрытие унаследованного контракта.
- Если восстановленная сигнатура добавляет `any`/`unknown` в публичную поверхность, использовать точный существующий тип без изменения runtime. Не повышать baseline автоматически; невозможность сохранить текущие счётчики — повод вернуться к пользователю, а не silently утвердить рост.

### ESLint

- Расширить существующий custom JSDoc-набор в `tools/eslint/jsdoc.ts` отдельным запретом `jsdoc/forbid-*` для `@internal` на членах типов.
- Покрыть public/protected члены классов, abstract-члены, parameter properties, члены интерфейсов/type literals и enum. Private и `#private` уже обрабатываются правилом `forbid-hiding-tag-on-private-member`; не создавать для них дублирующие диагностики.
- Сообщение должно предлагать `@docs-private`, если член нужен в typings, и напоминать, что `@internal` предназначен для целой сущности.
- Целые declarations с `@internal` должны проходить lint без предупреждений.
- Добавить кейсы в `tools/eslint/jsdoc.spec.ts`: public/protected method и property, accessor, abstract/parameter property, interface/type member, enum member, допустимая целая сущность и отсутствие двойного сообщения для private/`#private`.
- Не добавлять autofix: выбор между удалением тега и `@docs-private` зависит от контракта, а lint-staged запускает `--fix`.

### Правила и сгенерированные файлы

- Обновить packaging/JSDoc-правила в `.claude/rules/components.md`: `@internal` только для целых declarations, `@docs-private` для скрытия членов из документации с сохранением typings.
- Сохранить существующие ограничения по entry points, `implements`, структурной совместимости и именованным реэкспортам.
- После сборки обновить API golden files через `yarn run approve-api`, не вручную. Дополнительные baseline-файлы менять только их штатными командами и только после разбора причины.

## Что остаётся исполнителю

- Конкретные ESTree-selectors и распределение diagnostics между двумя custom-правилами, при условии полного покрытия и отсутствия дублей.
- Полный список дополнительных целых типов, которые нельзя оставить `@internal` после восстановления членов; определить его сборкой, `check-typings` и API guard.
- Точные типовые уточнения, если они понадобятся для запрета роста `any`/`unknown`, без runtime-изменений.
- Объём API golden files определяется генератором; не сокращать его вручную.

## Проверка

- `npx vitest run tools/eslint/jsdoc.spec.ts` — новые запреты и допустимые целые сущности.
- `yarn run eslint` и `yarn run prettier` — весь diff, включая отсутствие старых нарушений вне unit-fixtures.
- `yarn run build:components` — реальная генерация declarations и flattened typings.
- `yarn run check-typings` — опубликованные `.d.ts` целостны с `skipLibCheck: false`.
- `yarn run check-api` — снимки обновлены и соответствуют собранному API; перед этим `yarn run approve-api`.
- `yarn run check-public-api-any` — отсутствие неутверждённого роста `any`/`unknown`.
- `yarn run docs:api-gen` и `yarn run check-api-docs` — документационный manifest и ratchet остаются согласованными; `@docs-private` по-прежнему скрывает члены.
- Просмотреть итоговый API diff отдельно: восстановленные members и необходимые зависимости должны соответствовать выбранной политике, без случайных публичных сущностей.
- Component unit/e2e не нужны: runtime-код, шаблоны и стили не меняются. Если исполнителю всё же потребуется изменить больше чем JSDoc/типовые аннотации, остановиться и пересмотреть дизайн.

## Ожидаемый результат

`@internal` остаётся способом убрать самостоятельную внутреннюю сущность из опубликованных типов. Ни один член типа не скрывается этим тегом; члены, не предназначенные для документации, видны в typings и помечены `@docs-private`. Нарушение новой границы обнаруживается ESLint до сборки.
