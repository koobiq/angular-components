# DS-3564: новая документация Input

## Контекст

Переписываем страницу Input по [макету Figma](https://www.figma.com/design/HxMaLxGvkFuopugeFHNqVJ/koobiq-guides?node-id=5735-4322). За образец организации работы взят DS-3539 для Link, но структура и тексты берутся из актуального макета Input и решений ниже.

Работа ограничена документацией Angular и живыми примерами. Поведение и публичный API компонентов не меняются; React-документация не затрагивается.

## Структура Input Overview

Обе версии, `input.ru.mdx` и `input.en.mdx`, содержат одинаковые блоки в следующем порядке.

### Введение

Короткое определение поля ввода из макета. Пример `input-overview` содержит только пустой `<input kbqInput />`: без лейбла, плейсхолдера, иконки, cleaner и начального значения.

### Свойства

1. **Валидация** — новый пример `input-validation`: подписи Valid/Invalid, обычное поле и поле с ошибкой. Ошибка видна в исходном состоянии; для этого невалидный контрол помечается touched.
2. **Заблокированное состояние** — новый пример `input-disabled`: пустое и заполненное disabled-поля с подписями Empty/Filled.
3. **Только для чтения** — существующий `input-readonly`, расположен сразу после disabled по решению пользователя.
4. **Сброс значения** — `input-with-cleaner`, перенесённый и переименованный из `form-field-with-cleaner`; пояснение о скрытой по умолчанию кнопке сброса.
5. **Поле поиска** — новый пример `input-search` с иконкой `kbq-magnifying-glass_16` и подписью/плейсхолдером по макету. Текст отличает постоянно видимое поле от [Search Expandable](/ru/components/search-expandable), которое разворачивается из кнопки-иконки при ограниченном месте.
6. **Поле ввода без заливки и границ** — `input-without-borders`, перенесённый и переименованный из `form-field-without-borders`; пояснение из макета.
7. **Числовое поле** — существующий `input-number-overview` с четырьмя вариантами: границы и разделитель, разделитель, без разделителя, целое число. Начальные значения соответствуют макету (`10000.7` и `10000`). Подробные разделы «API числового поля» и «Форматирование числа и локаль» удаляются; краткие пояснения о форматировании и `kbqNormalizeWhitespace` остаются.
8. **Пароль** — существующий `input-password-overview` упрощается по макету до лейбла, поля пароля, переключателя видимости и проверки минимальной длины 16. Пример считает графемы через `Intl.Segmenter`, поэтому простые и составные emoji считаются одним символом. `input-password-template-driven` не изменяет эту логику.
9. **Маска ввода** — существующий `input-with-mask`, команда установки Maskito и пояснение из макета. Пример приводится к порядку макета: Amount, Percent, Phone, IPv4, IPv6, MAC, Port, License key; добавляются недостающие маски суммы, процентов и телефона.
10. **Автозаполнение** — новый пример `input-autocomplete`: два пустых email-поля с `autocomplete="email"` и `autocomplete="off"`, лейблы по макету. В первом поле `admin@admin.ai` — подсказка под полем, а не значение или плейсхолдер. Текст объясняет браузерное автозаполнение и его отключение.

### Примеры использования

1. **Подпись и подсказка для поля** — новый единый пример `input-label-and-hint`: одно поле с `kbq-label` и `kbq-hint`, подписи по макету. Текст раздела ссылается на раздел Form Field с примером `form-field-with-label`: `/ru/components/form-field#лейбл` и `/en/components/form-field#label`.
2. **Подсказка требований к паролю** — существующий `input-password-template-driven` переносится на Overview. Тексты и правила примера приводятся к макету: от 8 до 128 символов, заглавная и строчная латинские буквы, цифра, только латинские буквы, цифры, пробелы и спецсимволы.
3. **Моноширинный текст** — новый пример `input-monospace` с `kbqInputMonospace`. Перед примером сохраняется смысл текущего описания: Input поддерживает моноширинный стиль текста для идентификаторов, хешей и ключей. Поле предзаполнено статическим 40-символьным хешем коммита и содержит suffix с кнопкой-иконкой `kbq-square-multiple-o_16`.

### Рекомендации

Пять рекомендаций из макета: не использовать плейсхолдер как пример допустимого значения; размещать подсказки под полем; ссылаться на Textarea для многострочного текста; объяснить отличие сценария Autocomplete; ссылаться на Datepicker и Timepicker для даты и времени.

### Вкладка Input Examples

Из `examples.input.ru.mdx` и `examples.input.en.mdx` удаляется раздел с `input-password-template-driven`, поскольку пример переносится на Overview. Остаётся форма смены пароля `validation-cross-field-password`.

## Изменения Form Field

Разделы «Лейбл» / Label и «Подсказки» / Hints остаются на странице Form Field без изменений, включая `form-field-with-label` и `form-field-with-hint`. Ссылка из нового раздела Input ведёт именно на якорь примера `form-field-with-label`.

Со страницы `form-field.{ru,en}.mdx` удаляются два раздела:

- «Очистка поля» / Field cleaning;
- «Отключение рамок» / Disabling borders.

Их примеры полностью переносятся в Input и переименовываются:

| Старый ID                    | Новый ID                | Новый класс                  |
| ---------------------------- | ----------------------- | ---------------------------- |
| `form-field-with-cleaner`    | `input-with-cleaner`    | `InputWithCleanerExample`    |
| `form-field-without-borders` | `input-without-borders` | `InputWithoutBordersExample` |

Директории переезжают из `docs-examples/components/form-field/` в `docs-examples/components/input/`. Вместе с ID обновляются имена файлов, селекторы, классы, `@title` и комментарии локализации. Старые записи удаляются из Form Field `index.ts`, новые добавляются в Input `index.ts`; старые ID больше нигде не используются.

Из `components-dev/form-field/module.ts` удаляются переехавшие компоненты. Новые и переехавшие примеры добавляются в демонстрацию `components-dev/input/module.ts` для локальной проверки.

Остальные разделы Form Field и ссылки Validation на `#label` / `#лейбл` не меняются.

## Организация примеров

Новые примеры размещаются в `packages/docs-examples/components/input/<example-name>/` и регистрируются в `packages/docs-examples/components/input/index.ts`. Каждый содержит `@title`, standalone-компонент и собственный `l10n.ts`; пользовательские подписи получают RU/EN-переводы через `injectTranslation`.

`packages/docs-examples/example-module.ts` и `packages/docs-examples/loader/index.ts` не редактируются вручную: они регенерируются через `build:docs-examples-module`.

Новые примеры не содержат неиспользуемого состояния и импортов. Состояние ограничено формой конкретного демо; общее состояние и новые сервисы не нужны. Все Input-примеры центрируются layout-классами Koobiq по образцу `tag-overview`: `layout-margin-5xl` и `layout-align-center-center`, с `layout-row` для одиночных полей и `layout-column` для составных форм.

## Метаданные и сгенерированные файлы

- В `apps/docs/src/app/structure.ts` обновляется `isUpdated` только для Input; срок — `2026-12-03`. Form Field не получает Updated-бейдж: удаление двух переехавших примеров не требует привлекать внимание пользователя к странице.
- После изменения первого абзаца Input запускается `docs:generate-seo-descriptions`.
- После изменений MDX запускается `docs:generate-llms`; результаты в `apps/docs/src/llms.txt` и других предусмотренных генератором файлах не редактируются вручную.
- Маршруты не меняются, поэтому отдельная генерация sitemap и prerender-routes не требуется.

## Проверки

Минимальный набор доказательств:

1. `build:docs-examples-module` и сборка docs examples — новые примеры зарегистрированы и компилируются.
2. `check-examples-l10n` — у каждого нового примера есть собственная локализация.
3. `check-docs-pages` — RU/EN-структуры совпадают, ссылки и якоря после удаления разделов Form Field действительны.
4. `check-llms` — сгенерированные материалы соответствуют страницам.
5. `cspell` и `prettier` для изменённых файлов.
6. Production-сборка документации и docs smoke/E2E — страницы и живые примеры работают после генерации.
7. Визуальная проверка Input в RU и EN: порядок разделов, отсутствие лейбла/плейсхолдера в первом примере, начальные числовые значения, хеш в Monospace и отсутствие перенесённых примеров на Form Field.

Проверки публичного API не нужны: сигнатуры и JSDoc публичных компонентов не изменяются.

## Вне области

- Изменения поведения Input, Form Field, валидаторов или их публичного API.
- Перенос или переименование примеров `form-field-with-label` и `form-field-with-hint`: они остаются у Form Field.
- Изменения React и других компонентов, кроме перечисленных MDX Input и Form Field.
- Удаление `input-readonly`, Monospace или иных согласованных здесь сценариев.
