Что решено

Эти вопросы закрыты. К ним не возвращаемся

1
Живой API — из .d.ts в node_modules проектасделано
Источник правды о том API, который у человека реально установлен. Весь пакет разбирается за 40 мс, одна точка входа за 13; читается лениво и кешируется на процесс. Парсер построчный, без зависимости от typescript — и сверяется с настоящим компилятором в тесте
2
История API — data/history.json, едет внутри пакета
Собирается из golden-файлов tools/public_api_guard/** по git-тегам. Они проходят ревью в CI, поэтому отчёт на теге и есть публичная поверхность того релиза. 78 тегов читаются за 2,7 с без сборки и установки чего-либо
3
Гайды — текущий текст, с указанием релизасделано
Гайда нет в node_modules, читать с машины пользователя нечего — значит он едет в пакете. Берётся с последнего релизного тега, не из рабочего дерева. Хранить все ревизии пробовали и отказались — замер ниже
4
Иконки и токены — из установленной версии
kbq-icons-info.json и компилированный CSS токенов. Мажоры иконок 9–12, каждый со своим ридером и фикстурами из реальных тарболов. Карта переименований 10→11 работает в обе стороны
5
Фреймворк — определяется, не спрашиваетсясделано
По node_modules: @koobiq/components → Angular, @koobiq/react-components → React. React-проект получает явный отказ вместо Angular-разметки. Иконки и токены общие для обеих линий, поэтому по ним фреймворк не определить — только по этим пакетам

Отклонено: api-manifest как источник живого API — это несохраняемый артефакт сборки, его нет ни в пакете, ни у пользователя. Полный манифест — 1,84 млн токенов, урезанный — 198 тыс.; против 22 мс парсинга .d.ts на машине пользователя это не окупается.

Ранжирование: частичные совпадения вместо строгого И

Непопавший терм обнулял весь хит. Это выглядит как точность, а работает как молчание — из тринадцати вопросов, которые человек реально задаёт, пять возвращали пустоту.

Приёмочные запросыБылоСтало

Покрытие умножает, а не отсекает: хит, совпавший по всем термам, сохраняет ровно прежний балл, а совпавший по одному из трёх получает около девятой части. Плюс относительный пол — результат ниже 20% от лучшего не показывается, иначе список добивается мусором до лимита.

Два провала оказались не ранжированием, а дырами в данных. Ни одна иконка не помечена тегом «корзина» — там удалить, убрать, мусор. В 41 токене тени кириллицы нет вовсе. Появился словарь на ~50 слов для того, чего в данных нет по-русски: «тень для оверлея» теперь первым отдаёт --kbq-shadow-overlay. Совпадение через словарь дисконтировано — буквальное всегда выше.

Русский словоизменяется: «корзины» не содержит «корзина» ни как подстрока, ни наоборот. Допуск на окончание растёт с длиной слова — «редактировать»/«редактирование» расходятся на четыре буквы. Порог держит честность: «список» и «списать» совпадают на четырёх буквах и не должны матчиться.

which_component_when

Ошибка, которую инструмент предотвращает, — не «ничего не нашёл», а «нашёл соседа»: autocomplete вместо множественного выбора, toast для сообщения, которое нужно подтвердить. Поэтому ответ — это строка таблицы целиком: что взять, что не брать и почему не.

Разобрано79 строк разграничения, 12 маршрутов по словам, 75 описаний компонентов — одинаково в обоих языках

Колонка «не брать» намеренно не участвует в скоринге. Она называет то, что использовать нельзя, — и матчинг по ней ранжирует строку по тому самому слову, от которого она предостерегает: запрос на множественный выбор ставил radio первым, потому что select стоит в той строке как ошибка.

Части документа опознаются по форме, а не по заголовку. Поиск по английским заголовкам работал, пока у гайда не появился русский текст: ## Разграничение — это не ## Disambiguation, и каждый русский вопрос молча возвращал пустоту.

Живой API из .d.ts

Читается тот пакет, который стоит у человека. Angular пишет метаданные прямо в .d.ts — ɵcmp и ɵdir содержат селектор, exportAs, карту входов с алиасами, выходы и host-директивы.

Разбор всего пакета40 мс, 1047 экспортированных символов, 310 компонентов и директив
Входов / выходов1020 / 188
Имя свойства ≠ атрибут шаблона230 — все они назывались неверно
Унаследованных входов269 — приходят от базового класса, часто из другой точки входа
Через host-директиву10 — старый путь их не видел вовсе

KbqAutocompleteTrigger.connectedTo в шаблоне пишется как kbqAutocompleteConnectedTo. Раньше сервер называл имя свойства — атрибут, который молча ничего не делает. Теперь и get_component, и поиск работают по имени из шаблона.

Цепочка наследования обязательна. color у кнопки объявлен не в KbqButton, а в KbqColorDirective в core. Парсер, читающий только собственное объявление класса, потерял бы вход, который старый путь находил.

Парсер сверяется с компилятором

typescript весит ~22 МБ, а сервер запускают через npx — поэтому парсер построчный, без этой зависимости в рантайме. Чтобы срез оставался честным, настоящий компилятор стоит в devDependencies, и тест прогоняет обе реализации по всем 64 точкам входа установленного пакета: больше 250 объявлений, селекторы и карты входов и выходов сравниваются поэлементно. Если Angular поменяет формат, упадёт тест, а не ответ пользователю.

Инструмент migrate

Две половины, отвечающие на разные вопросы. history.json говорит, что сдвинулось — механически, из отчётов, одобренных в CI на каждом теге. Гайд миграции говорит, что писать вместо. Обновлению нужны обе.

18.4.0 → 19.0.0, сырых изменений2930 по 57 точкам входа
Размер сводки358 токенов
Что в ней ведётточки входа, которые потеряли API — это и ломает сборку

Служебное компилятора отфильтровано. ngAcceptInputType_* и ɵ* составляли 72 из 728 удалений — десятую часть числа, по которому планируют обновление. Показывать их как удалённый API значит сообщать о поломке там, где ничего не ломалось.

Заголовок наследует релиз от родителя. #### Running the migration встречается в гайде под тремя разными ###, каждый про свой релиз. В плоском списке они неразличимы, и читателя, идущего на 19.x, отправляло к инструкциям для 21.0.0. Разбор теперь хранит уровень заголовка.

Почему отказались хранить все ревизии гайдов

Сначала хранили каждую ревизию с 18.0.0, чтобы проект на 18.x получал текст 18.x. Замер показал, что платить за это нечем.

Русская темизация, 9 ревизий 18.0.0–20.3.0
Ревизий с одинаковым набором заголовков7 из 9
Код в сниппетах с 18.4.0 по 20.3.0побайтово одинаков
Размер guides.json1056 КБ → 168 КБ
Время сборки1,7 с → 0,1 с

Ревизии отличались формулировками, а не механизмом: ни import path, ни имена классов, ни примеры кода за шесть релизов не менялись. 888 КБ уходило на то, что агент всё равно написал бы правильно. Осталось поле since — ответ называет релиз, из которого взят текст, и предупреждает, если проект на другом мажоре.

Разбивка на разделы осталась и остаётся обязательной: migration.en это 218 КБ ≈ 62 000 токенов одним куском. Она не требует ручной работы — это регулярка по заголовкам.

Новый гайд попадёт в индекс сам?

Нумерованные — да, отсеиваются правилом. Именованные — нет: «для нас или для людей» это редакторское решение, из файла его не вывести. Но потеряться гайд не может: если появляется именованный файл, которого нет ни в списке публичных, ни в списке исключённых, сборка индекса падает с ошибкой и называет его. Молчаливый пропуск — ровно та поломка, ради которой весь этот пункт и делался.

Попутно: баг, из-за которого история была занижена вчетверо

git cat-file --batch отдаёт размер блоба в байтах, а чтение резало строку по символам. Пока содержимое ASCII, это одно и то же. На первом русском файле курсор уезжал на один символ за каждую не-ASCII букву, заголовок следующей записи попадал в середину текста, размер парсился в NaN — и остаток пачки молча терялся.

Данные, которые могут устареть

Примеры — один срез, и это самое версионно-опасное место

Механика. packages/docs-examples/example-module.ts перечисляет каждый пример и его файлы; индексатор читает список, затем сами файлы, и пишет data/examples.json. Файл едет в npm-пакете и читается лениво. Сервер никогда не ходит в документацию по сети.

Почему не все версии, как у гайдов. За 78 релизов набор примеров менялся в 70 из них, разных файлов за всю историю — 4025. Дедупликация не работает, приём не окупается.

Чем это грозит. Между 19.x и 20.x 90 из 607 символов, на которые ссылаются примеры, перестали существовать — 15%. Пример отдаётся с указанием версии и сверяется с живым API проекта.

symbols в индексе — 512 КБ из 725, и теперь только запасной путь

До перехода на .d.ts индекс был единственным источником API. Теперь он срабатывает, только если @koobiq/components не установлен — то есть почти никогда. 70% размера index.json лежит ради этого случая. Варианта два: выбросить их и честно отвечать «пакет не установлен», либо оставить как есть. Второе стоит 512 КБ в каждой установке пакета.

История называет свойства, живой API — атрибуты

История собирается из api.md и называет входы по имени свойства; живой API читает .d.ts и называет их по атрибуту шаблона. Для 230 входов это разные слова. Чтобы история говорила атрибутами, нужны .d.ts старых релизов — 78 скачанных тарболов. Делать стоит тогда, когда в migrate это окажется помехой.

Пробелы в самих данных, не в коде

Теги иконок по-русски неполны

Ни одна иконка в 11.7.1 не помечена тегом «корзина», хотя по-русски её так и называют — там удалить, убрать, мусор. Словарь на ~50 слов это прикрывает, но настоящее место правки — сами теги. В токенах кириллицы нет вовсе, и там словарь не заплатка, а единственный мост.

Русский which_component_when слабее английского

Английский — 11 из 11 первым, русский — 6 из 9, 9 из 9 в топ-3. Разница не в ранжировании, а в словах: «редактировать значение на месте» и формулировка гайда «Изменить одно-два поля из многих» не пересекаются ни одним словом.

Лечится двумя способами, оба в гайде, а не в коде: дописать в русский указатель слов те формулировки, которыми спрашивают на самом деле, либо переписать задачи в таблицах ближе к живой речи. Код для этого уже всё делает — указатель слов разбирается и даёт буст кластеру.

Гайд может сослаться на исчезнувший пример

Гайд и примеры собираются из одного релиза, но расходились раньше и могут разойтись снова. Ответ сверяет ссылки с тем, что реально есть, и помечает недостающие строкой «Referenced but no longer shipped».

Незавершённое в репозитории компонентов

Два гайда не закоммичены

docs/guides/which-component-when.en.md и .ru.md существуют только в рабочем дереве. Сборщик их видит — он читает и неотслеживаемые файлы — но помечает unreleased, и ответ честно говорит, что гайда нет ни в одном релизе. То же с localization. Коммит и релиз снимут пометку сам собой.

Индекс собран с untagged-чекаута

Два чекаута монорепы на машине

angular-components — main, теги до 20.4.0. components-angular — ветка feat/DS-4087 от 24 сентября, теги до 20.3.1. Все сборки до этой итерации шли из второго: устаревшего и не с main. Сборщики теперь указывают на первый; второй стоит убрать, чтобы это не повторилось.

Код, который стоит упростить

get_example — 1802 токена, фильтра по умолчанию нет

Отдаёт все файлы примера целиком. Это самый дорогой ответ сервера, вдвое дороже следующего. Нужен разумный умолчательный срез — обычно нужен только *.html и *.ts компонента, а не спеки и не стили.

src/indexer/git.ts наполовину перестал быть нужен

Ценность там одна — readBlobs, пакетное чтение блобов. Для build-history оно окупается целиком: 78 тегов × ~60 отчётов, иначе 4700 запусков git. Для build-guides после отказа от ревизий читается один тег и ~18 файлов — экономия 17 запусков, то есть ничего. Оставлено ради одного места, где решена ловушка «байты против символов»; разведи их — и в простом пути она вернётся при первой же оптимизации.

parse-api-md.ts — временные леса, которые остались

223 строки. Живой API его больше не использует; он кормит только историю и те самые symbols в индексе. Если symbols выбросить, останется один потребитель — и тогда файл честно переедет в историю.

Поиск

Частотный вес работает только в which_component_when

Редкое слово перевешивает частое при выборе компонента, но не в общем поиске. В поиске коллекция — весь индекс, частоты пришлось бы считать заранее при сборке. Выигрыш неочевиден, замера нет.

Открытые вопросы

Требуют решения, но не блокируют порядок работ выше

Koobiq для React
Определение фреймворка сделано, отказ для React-проекта работает. Что именно индексировать из ~/Dev/work-opensource/react-components — следующая итерация, как договорились
Публикация в npm
Пакет собирается тарболлом и ставится из файла. Версия привязана к релизу, из которого собран индекс — 20.4.0. Перед публикацией сборку надо делать с тега, иначе индекс описывает неопубликованный API
run_drift_audit
Проверка проекта на отставшие паттерны и deprecated-токены. При 1862 deprecated из 2004 наивная реализация даст столько шума, что ей не будут пользоваться. Отложено сознательно
Где запускать сборку индексов
Нужен чекаут монорепы с тегами — значит, только CI репозитория MCP. Полный пересбор обоих индексов около 4 с, инкрементальность не нужна. Коммитить результат, а не генерировать на prepack: хук сломал бы npm pack всем, у кого нет монорепы рядом, и лишил бы ревью диффа
