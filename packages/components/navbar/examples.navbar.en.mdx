### Adding items from a template

You can declare `kbq-navbar-item` elements inside an `<ng-template>` and insert them with `*ngTemplateOutlet` — for example, to render the items from a data array. Declare the template inside `<kbq-navbar>` so the navbar keeps managing keyboard navigation, layout, and responsive collapsing of the items.

### Icon after the title

To show an icon after the item title — for example, on a link to an external resource — add `kbqNavbarItemSuffix` to it. An icon without this attribute is shown before the title, wherever it is written.

### Custom content instead of the icon

An item can show something other than an icon in the spot before the title: mark the content with `kbqNavbarItemContent`. The navbar reserves a 40×40px square for it — the `--kbq-navbar-item-size-custom-content-width` and `--kbq-navbar-item-size-custom-content-height` tokens — and leaves the positioning inside the square to the content itself: it can fill the whole square or render smaller with its own paddings. The content stays visible when the menu collapses, replacing the icon in the collapsed item.

### Custom component as the item

To keep logic in your own component — a notifications center, a site switcher — implement `KbqNavbarItemTrigger` on it and provide the class as `KBQ_NAVBAR_ITEM_TRIGGER`. The component's host element becomes the trigger: it owns the overlay and takes the keyboard focus, so it does not need an inner button. Keep the host and any inner controls out of the tab order with `tabindex="-1"`; the item moves focus to it programmatically. The item paints the hover, pressed, selected and keyboard-focus states around the component, exactly as it does for a plain item, so do not add a focus outline to the component itself. Inside the component, attach a dropdown, a popover, or any other overlay as usual.

A titled item sizes its leading area like an icon: set `--kbq-navbar-item-size-custom-content-width` and `--kbq-navbar-item-size-custom-content-height` to 16px on the expanded item, and the title starts on the same text axis as in a plain item. The collapsed item keeps the full square.

A plain item with the same content — no custom component — renders identically: mark the leading area with `kbqNavbarItemContent` and set the same tokens, so the title and the badge line up with the component's in both the expanded and the collapsed navbar.

In a horizontal navbar, automatic collapsing still relies on an icon, so items with custom content or a custom component do not collapse automatically.
