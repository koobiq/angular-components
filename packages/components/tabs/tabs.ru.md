### Состояния

#### Вертикальные вкладки

Длинный список вкладок можно разместить вертикально, чтобы все элементы были видны без прокрутки. Для включения используется атрибут `vertical`.

<!-- example(tabs-vertical) -->

Вертикальные вкладки можно использовать и без подписи. В таком случае лучше добавить тултип для иконок, чтобы пояснить название каждого раздела.

<!-- example(tabs-vertical-icons) -->

#### Вкладки с полоской

Настраивается при помощи атрибута `underlined`.

<!-- example(tabs-underlined) -->

Если вкладка содержит только иконку без подписи, добавьте атрибут `iconOnly` к директиве `kbqTabLabel` - это задаёт фиксированный размер 32×32px для области нажатия.

#### Disabled

Неактивную вкладку нельзя выбрать, она не имеет интерактивных состояний.

<!-- example(tabs-disabled) -->

#### Пустая вкладка

Если нужно обозначить, что внутри вкладки пусто, используйте атрибут `empty`. Такую вкладку можно выбрать, она имеет интерактивные состояния.

<!-- example(tabs-empty-label) -->

Не используйте пустые вкладки вместе с неактивными. Они внешне похожи — это запутает пользователя.

#### Прокрутка

Горизонтальные вкладки не переносятся и не сжимаются. Если места не хватает, часть скрывается, а по краям появляются кнопки прокрутки. Вкладки также прокручиваются на тачпаде, колесом мыши с нажатой клавишей Shift или перетаскиванием.

<!-- example(tabs-with-scroll) -->

Вертикальные вкладки можно прокручивать, если они не помещаются по высоте.

<!-- example(tabs-with-scroll-vertical) -->

#### По ширине контейнера

По умолчанию ширина горизонтальных вкладок зависит от подписей внутри элементов, но при необходимости панель табов может заполнять все пространство контейнера, для включения используйте атрибут `kbq-stretch-tabs`.

### Сохранение состояния

Группа вкладок запоминает, какая вкладка была выбрана, и восстанавливает её при следующей отрисовке. Это включено по умолчанию — передайте `[useStateSaving]="false"` для группы, выбором в которой распоряжается приложение.

<!-- example(tabs-state-saving) -->

Пока привязаны `selectedIndex` или `activeTab`, не сохраняется ничего: выбор принадлежит тому, кто управляет привязкой, и восстановление поверх неё спорило бы с приложением.

Задавайте вкладкам `tabId`. Выбор хранится и по идентификатору, и по позиции, но только идентификатор переживает перестановку вкладок — без него по позиции восстановится другая вкладка, о чём в dev-режиме выводится предупреждение. Если сохранённый идентификатор больше не соответствует ни одной вкладке, используется позиция; если не подходит ни то ни другое, не восстанавливается ничего и группа выбирает то же, что выбрала бы сама.

`kbq-tab-nav-bar` не сохраняет состояние никогда. Это навигационный вариант, где активную ссылку определяет роутер, а восстанавливать имеет смысл URL.

Ключ хранения берётся из `stateSavingKey`. Без него он выводится из положения группы в документе: цепочка имён тегов до `<body>`, обрезанная первым встреченным `id`, который становится якорем. Группа внутри `<section id="report">` сохраняется под ключом `#report/kbq-tab-group`, поэтому всё, что выше этого `id`, можно перестраивать, не сдвигая ключ. Перестройка ниже якоря ключ сдвигает, а сохранённое под прежним остаётся лежать до истечения срока — задайте `stateSavingKey` или `id` там, где это важно.

Группа вкладок, отрисованная внутри оверлея, состояние не сохраняет: на момент инициализации она не находится в документе, а значит, не имеет стабильного ключа. Чтобы удалить сохранённое состояние, используйте `clearSavedState()`.

Состояние хранится в `localStorage` под префиксом `kbq.state.`, а запись, которую 90 дней не читали и не перезаписывали, удаляется (`KBQ_STATE_SAVING_TTL`). Чтобы состояние жило только в пределах вкладки браузера, предоставьте `KbqSessionStorageStateStore`:

```ts
providers: [{ provide: KBQ_STATE_STORE, useExisting: KbqSessionStorageStateStore }];
```

Своё хранилище — например, серверное — реализует интерфейс `KbqStateStore` и предоставляется через тот же токен. Указанное в `providers` самой группы, оно заменяет хранилище только для неё, а не для всего приложения. Если это одно из браузерных хранилищ, наследуйтесь от `KbqWebStorageStateStore`: он уже защищён от SSR, недоступного хранилища и нечитаемых данных.

### Рекомендации

Используйте вкладки:

- Для навигации по контенту на странице, когда важно дать быстрый доступ к отдельным частям.
- Для второстепенной навигации.

Не используйте вкладки:

- Когда весь контент можно разместить на одной странице, на одном экране. Незачем прятать отдельные части во вкладки.
- Для выбора значения в формах. Не путай вкладки с полями ввода: [радиокнопками](/ru/components/radio), [кнопками-переключателями](/ru/components/button-toggle).
- Для основной навигации. Для этого есть компонент [Navbar](/ru/components/navbar).
- Когда надо изменить представление одних и тех же данных (список, плитка, таблица). Взамен используйте [кнопку-меню](/ru/components/dropdown) или [кнопку-переключатель](/ru/components/button-toggle).
- Когда контент уже вложен во вкладку. В том числе нельзя одновременно использовать вертикальные и горизонтальные вкладки. Вместо этого сократите количество вкладок, используйте только один вид вкладок или кнопку-переключатель, кнопку-меню.
- Когда предполагается всего один таб. В этом случае панель вкладок вовсе не нужна.
- Для обозначения шагов в форме-мастере. По внешним признакам вкладки похожи на шаги, и дизайнеру стоит избегать этой путаницы, поэтому стилизовать эти элементы нужно по‑разному. Полезно подстраховаться и оставить заметку для разработчика. Например: обрати внимание, это не вкладки, а шаги формы.
