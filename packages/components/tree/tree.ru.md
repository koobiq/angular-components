Иерархический список (дерево) — древовидный каталог с большим количеством данных.

<!-- example(tree-overview) -->

### Когда использовать

Когда нужно обеспечить пользователю удобную работу с большим количеством данных (сотни элементов). При этом либо пользователь имеет возможность структурировать эти данные в древовидный каталог, либо данные уже приходят к нему в таком виде из системы. Если эти условия не соблюдаются, то лучше использовать [обычный список](/ru/components/list).

### Структура компонента

- Название
- Иконки элемента _(опционально)_
- Кнопка дополнительных действий над элементом _(опционально)_
- Кнопки «Развернуть» и «Свернуть»
- Чекбокс _(опционально)_
- Поиск по элементам _(опционально)_

### Описание работы

#### Список с деревом и текстовым поиском по нему

Если введен поисковый запрос — в дереве показываются только элементы:

- которые соответствуют поисковому запросу;
- являются родительскими по отношению к найденным в поисковом запросе.

Текст, совпавший с поисковым запросом в названии элемента, выделяется жирным.

#### Список с деревом и множественным выбором элементов

Может быть одиночный или множественный выбор (ограничивается на уровне дерева).

Элемент можно выбрать, нажав на него (в любую область, кроме иконки «Развернуть» («Свернуть») и кнопки доп. действий). Чтобы выбрать несколько элементов мышью, используются клавиши Ctrl или Shift, чтобы выбрать несколько элементов с клавиатуры — клавиша Space.

Нелистовые элементы можно разворачивать и сворачивать по клику на иконку «стрелка».

<!-- example(tree-multiple-keyboard) -->

Если в древовидном списке включены чекбоксы, то выбор нескольких элементов возможен через клик на чекбокс.

<!-- example(tree-multiple-checkbox) -->

Режим задаётся через `multiple`: `checkbox` или `keyboard` для множественного выбора. Одиночный выбор —
режим по умолчанию, поэтому просить о нём нужно отсутствием атрибута. Это обычный input, поэтому `[multiple]` можно связать и менять в любой момент. Если было
выбрано несколько узлов, при переходе к одиночному выбору остаётся первый выбранный, а укороченное значение
уходит в форму; при одиночном выборе значение приходит скаляром, при множественном — массивом, поэтому смена
режима меняет форму значения в форм-контроле. Дерево внутри `kbq-tree-select` делит модель выбора с
селектом, поэтому число выбираемых узлов задаёт селект: переключение дерева между одиночным и множественным
выбором там бросает исключение, а переключение между `checkbox` и `keyboard` разрешено.

Это касается только `kbq-tree-selection` и `kbq-list-selection`. У [Select](/ru/components/select) и
`kbq-tree-select` свойство `multiple` по-прежнему нельзя менять после инициализации — будет исключение.

### Доступность

Дерево передаёт вспомогательным технологиям структуру, которую отрисовывает, поэтому скринридер
сообщает уровень вложенности элемента и то, раскрыт ли он, выбран ли и отмечен ли.

- Дерево — это `role="tree"`, каждая строка — `role="treeitem"`.
- Табуляция останавливается на самом дереве, а строки остаются с `tabindex="-1"`, но строка, на которую
  переходят стрелки, получает настоящий фокус и вдобавок сообщается через `aria-activedescendant`.
- У строк-веток есть `aria-expanded` — в том числе при активном фильтре, который отключает стрелки
  раскрытия, но не превращает ветки в листья, — а у каждой строки есть `aria-level`.
- Строки с чекбоксом сообщают `aria-checked`, в том числе `mixed` для частично выбранной ветки; строки
  без чекбокса — `aria-selected`.
- Стрелки раскрытия скрыты от вспомогательных технологий: их состояние уже есть на строке, а управляют
  ими клавиши ← и →.
- У дерева нет собственной видимой подписи, поэтому задайте ему доступное имя через `aria-label` или
  укажите в `aria-labelledby` элемент, который его подписывает. Дереву внутри `kbq-tree-select` не
  нужно ни то, ни другое — его подписывает сам селект.

### Отрисовка

Отрисовываются все раскрытые элементы, без виртуализации: закрытая ветка не стоит ничего, раскрытая —
по строке DOM на элемент. Дерево, показывающее тысячи строк сразу, стоит держать закрытым или сужать
данные поиском.

По умолчанию узлы отслеживаются по идентичности, поэтому источник данных, который пересоздаёт объекты
узлов на каждой эмиссии — например, flattener, — пересоздаёт и все строки. Чтобы строки
переиспользовались между обновлениями данных, передайте функцию `trackBy`, возвращающую стабильный ключ.
