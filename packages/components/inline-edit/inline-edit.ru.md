### Незаполненное состояние

Незаполненное значение параметра нельзя оставлять пустым в режиме просмотра. Вставляйте текстовую заглушку, которая даст понять пользователю, что параметр можно изменить.

По умолчанию используется формулировка «Не заполнено», но лучше под каждый параметр придумать осмысленный текст. Например: «Ответственный: Не назначен», «Окончание работы: Не определено».

Для полей без подписи вместо заглушки можно использовать формулировку с названием поля: описание, оператор, тип инцидента.

### Валидация

Выход из режима редактирования запускает попытку применить изменения. Невалидное значение не сохраняется: редактор остаётся открытым, поле подсвечивается, а фокус остаётся там, куда его привело взаимодействие.

Сообщение об ошибке подключается вручную. Красный тултип из примера ниже появляется, только если задан `validationTooltip`; без него ничего не показывается, а альтернатива — `kbq-error` внутри form-field. Вход `showTooltipOnError` выключает тултип, не убирая само сообщение.

Валидация проверяет сам контрол, а не состояние подсветки ошибки, поэтому значение, которого пользователь не касался, тоже отклоняется — селект, сохраняющийся по `(selectionChange)`, не сможет записать невалидную опцию.

<!-- example(inline-edit-validation) -->

Когда заранее известно, какие символы точно не подходят для ввода в поле, система предотвращает ввод некорректных значений. Для этого нужно запрещать ввод определенных символов, например букв в IP-адрес. При этом запрещенные символы не вводятся и показывается желтый тултип.

Если пользователь очистил значение, чтобы избежать ошибки можно при сохранении подставить значение по умолчанию или предыдущее валидное.

### Клавиатура

Поле — одна точка табуляции. `Enter` и `Space` открывают редактор, `Escape` закрывает его и возвращает прежнее значение, `Enter` сохраняет и возвращает в режим просмотра. В `textarea` `Enter` вставляет перенос строки, поэтому сохраняет `Ctrl`/`Cmd` + `Enter` — это правило заменяется входом `canSaveOnEnter`. `Tab` с первого или последнего контрола редактора сохраняет значение и выходит из режима редактирования — так же работает клик снаружи. При выходе из режима редактирования фокус возвращается на поле.

Содержимое, которое само обрабатывает клики — ссылка, тег — сохраняет своё поведение и не открывает редактор. Список такого содержимого задаёт вход `interactiveSelectors`, по умолчанию `['a', 'kbq-tag']`; он заменяет список целиком, а не дополняет его, поэтому нужные значения по умолчанию повторите явно. Когда в режиме просмотра есть такое содержимое, собственная точка табуляции поля переезжает на соседний визуально скрытый элемент, чтобы с клавиатуры были доступны и содержимое, и редактор.

### Доступность

Режим просмотра объявляется как `button` с `aria-expanded`, поэтому вспомогательные технологии сообщают и то, что значение можно изменить, и то, открыт ли редактор. Имя по умолчанию — локализованное «Редактировать»; задайте полю собственное через `aria-label` там, где по одному значению непонятно, что именно редактируется:

```html
<kbq-inline-edit aria-label="Ответственный">…</kbq-inline-edit>
```

Отключённое поле сообщает `aria-disabled` и выходит из порядка табуляции. Иконочные кнопки сохранения и отмены из `showActions` берут имена из секции локали `a11y`, там же живёт и имя `edit`.

Элементу с `kbqInlineEditMenu` библиотека проставляет `role="button"`, но не даёт имени, поэтому задайте ему `aria-label` самостоятельно.

### Рекомендации

Поле с инлайн-редактированием должны сохраняться сразу после изменения без общей для всего экрана кнопки «Сохранить».

**Не используйте:**

- Внутри форм
- При создании сущности — спроектируйте форму для заполнения информации.
- Когда в поле сложная валидация. Например, пароль, эл. почта, уникальные поля, а также когда требуются маски, подсказки.
- Для зависимых полей — если изменение одного поля влияет на другие, лучше использовать форму.
- Для изменения важных данных.
- Когда требуется дополнительно подтверждения для сохранения. Например, диалог «Вы точно уверены?»

**Заменой инлайн-редактированию может быть:**

- Модальное окно или поповер с формой — для сложных или многострочных данных.
- Отдельная страница редактирования — когда нужен контроль над вводом.
- Инлайн-форма — поле раскрывается в более крупный редактор
